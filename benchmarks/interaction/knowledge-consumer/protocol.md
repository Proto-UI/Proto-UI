# Controlled consumer study protocol

This is an unexecuted public-development protocol for [#734](https://github.com/Proto-UI/Proto-UI/issues/734), separate from the existing calibration archive and result schemas. The runnable library recipe demonstrates how to consume interaction knowledge. It is not a timed model output or evidence that knowledge improves implementation.

## Research question and selected task

The primary question is whether access to the declared interaction facts changes implementation effort or correctness for the same task. A separate practical comparison asks how mature-library delivery compares with those implementations. Representation quality and deterministic realization are different questions.

Start with **Tabs**, because the current root/list/trigger/content definitions and mapped tests can be inspected. It exposes focus versus selection, disabled movement, manual activation, accessible relationships and application removal without an overlay, compiler or Adapter prerequisite. Do not add Dialog, Select, Combobox or Tooltip to fill a quota; inspect each candidate's criteria and evidence before selecting it.

Use `task.txt` unchanged in all arms. Its base requirements come from the public `tabs-manual-activation` development case. The additional React/tool versions, source layout and host action-count requirement are declared ordinary information for every arm. Manual activation and looping are task configuration, not new Base defaults.

This public task already states most required behavior. A difference here can speak to bounded implementation assistance; it cannot measure blind discovery recall or establish that one condition received otherwise unavailable requirements. This near-complete task, model familiarity and public answers can mask a useful knowledge effect or favor either condition. Keep #748's blind-discovery work separate.

## Freeze before a measured cell

The supplied `study.json` is a plan, with `frozen: false` and no results. Before either AI condition, an operator must retain an immutable, externally bound copy of:

- Exact task/prompt bytes, source map and knowledge projection; all independently reviewed facts and their draft lifecycle remain visible as such.
- Complete target dependency lock, Node/npm/OS image, tool/harness versions, Chromium binary hash and actual browser version.
- Provider and exact model/snapshot, run date, reasoning/effort, sampling/seed controls, context/tool limits and permitted retrieval/toolset. Record unavailable provider metadata with a reason; a display name is not authenticated backend identity.
- Equal tool/token/compute/time and repair budgets; exact independent oracle/check vector, conflict policy and severity rubric; chosen order/repetitions and exclusion policy.
- Exposure manifests identifying permitted ordinary material and condition-specific knowledge by path, bytes and digest. Retain the access log showing what was actually read, not just what the coordinator intended to send.

Main chooses the actual configured participant and affordable budget before running. No model endpoint is selected or invoked by these files. Preserve current model constraints; do not silently fall back to a different model when an attempt fails. A new model or budget is a new declared cell/deviation, not a repair to old evidence.

## Three paths and exposure

| Path | Supplied material | Delivery and comparison role |
| --- | --- | --- |
| Mature library | Same task, exact target versions and permitted public ecosystem material; no Proto knowledge | A fresh library integration using Radix Tabs 1.1.13 or a documented equally suitable pinned alternative. The authored example can validate the recipe but cannot masquerade as a fresh timed task. |
| Unassisted AI | Same task and permitted public ecosystem information; no Proto criteria/contracts/knowledge or finished implementation | Control for the paired knowledge-access question. Implementation method remains flexible, including suitable libraries if the identical permission exists in the other arm. |
| Knowledge-assisted AI | The same control material plus exactly `knowledge.md` and its stable source references | Measures the effect of the declared extra interaction knowledge. Neither the final Proto implementation nor this clean example/evaluator may be copied or retrieved. |

The public WAI-ARIA Tabs Pattern and target API documentation are permitted ordinary material for both AI conditions. Record their actual retrieved bytes/revisions and retrieval cost equally. Keep evaluator-only metadata, `example/check.mjs`, final outputs, raw validation artifacts and the complete repository out of participant packets. Do not send this coordinator protocol as a blind participant prompt.

A new directory, a new agent on the same seat, an access-policy string or a packet hash does **not** establish isolation. This repository, its Git history, public Issues, network and prior context expose answers. Formal blind/evaluation/held-out execution remains blocked until a separately reviewed executor enforces filesystem, Git, network, context/history and tool boundaries, with negative leakage probes. The current public case remains development/calibration even then; genuine evaluation/held-out cases require independently maintained private answers and a fresh participant who has not read them.

For the existing formal policy, retain at least three independent repetitions per selected task × AI condition × model. The library comparison needs independently timed deliveries under a declared comparable operator/model policy; fixture reruns are not independent implementations. Rotate condition order across repetitions where practical. One model can provide a bounded initial result; a small capability ladder may later test model sensitivity, without replacing old rows or creating a leaderboard requirement. There is no 36+9 gate, improvement floor or user-count threshold.

## Independent expectations and controls

The public WAI-ARIA Tabs Pattern supplies independent accessibility/keyboard guidance. The ordinary task supplies its specific labels, disabled item, manual/loop choices and host extension. Proto facts provide a separately identified draft knowledge layer. The existing Proto test suite is supporting evidence; it is not the sole ground truth.

`example/check.mjs` is a proposed public consumer observation command. Its 22 planned checks cover ordered/disabled controls, initial state, real keyboard entry, forward/back wrapping and Home/End movement without selection, Enter/Space/pointer activation, repeated selections, tab exit through the active panel, application removal, continued keyboard access and a real host action. It retains accessible-role/DOM snapshots and intermediate focus/selection observations. It uses semantic roles and accessible names rather than calibration fixture IDs. This source alone does not establish an independently reviewed general oracle, formal result admission or a working participant executor.

Main must have an independent reviewer inspect the expectations, the task extension, source projection and all injected controls before making an oracle claim. The three mutations in the README must fail for their named behavioral reasons; setup failures do not count. Keep raw positive/negative evidence. Do not include these mutation answers in a measured participant's context.

Freeze severity before outcomes: **blocking** means the task cannot be completed or host interaction is stranded; **major** means an observable required interaction/accessibility/cleanup property fails while some use remains; **minor** means a reviewed nonblocking defect within the declared task. Report counts/types and exact failures separately; do not turn these labels into an opaque aggregate score. Ambiguous authority, unsupported host behavior and harness defects have distinct dispositions, not an automatic product failure or pass.

Check only applicable dimensions. Dismissal/presence is relevant to an overlay, not automatically to this Tabs task. Cleanup here observes view removal and host continuation, not retained Proto owner lifetime or proof of no resource leaks. Browser roles/relationships are not assistive-technology testing. Visual captures support inspected rendering claims only; record viewport, theme and state pairs. Business-composition quality and overall product usability are outside the hypothesis.

## Retained run record

Keep one immutable run ID per attempted cell/repetition. Store raw first-pass output before repairs and raw final output separately. Bind each to the frozen task, actual exposure/access manifest, model/tool/environment identity, source snapshots, dependency lock and evaluator revision. Keep original tool/test traces and all human/evaluator interventions with their order.

Record these dimensions separately for every attempt:

| Dimension | Required evidence or unavailable reason |
| --- | --- |
| Outcome | Completed, failed, aborted, blocked or excluded, with actual reason and first divergence |
| Correctness | First-pass and final per-check vectors for interaction, keyboard/focus, accessibility, host and cleanup; unknown/unrun is not passing |
| Requirements | Initially omitted clauses, unsupported/invented requirements or APIs, and the source authority for each classification |
| Defects and repairs | Severity/type, affected clause, source path, observed transition, repair iterations and evaluator interventions |
| Cost | Input/output tokens, cache/reasoning accounting if exposed, compute and actual provider price/version, elapsed/human time and currency; unavailable fields carry reasons |
| Maintenance | Observed repair/integration work, changed sources/dependency/version sensitivity and human intervention; longer-term burden stays unmeasured unless actually observed |
| Exposure | Exact supplied files/materials, actual reads/tool calls, missing inputs and prohibited/leaked retrieval |
| Integrity | Raw outputs/artifacts, lock/source hashes, environment, evaluator source, screenshots, DOM/role observations and trace where produced |
| Deviations | Every budget/model/source/target/order change, omitted cell, excluded/aborted/neutral/failed attempt and predeclared exclusion reason |

Measure elapsed time from participant start to first output and to final submission; distinguish setup and evaluator time. Do not equate browser journey duration with model implementation cost. Compute token prices only from actual usage and the declared pricing basis; unavailable usage is not zero cost. Requirements already explicit in the task cannot be counted as newly discovered knowledge.

Retain the complete planned cell denominator and every collected record. Failed runs, outliers and missing evidence stay in the accounting. No failed cell is overwritten by a rerun. Report distributions and paired differences across independent runs, not the best run or repeated checks of one source.

## Interpretation and feedback

The per-primitive table must show each arm's raw run IDs, first/final check outcomes, defects/omissions, iterations, token/compute/cost and elapsed/human time, maintenance observations, deviations and uncertainty. There are currently **no run rows**. Do not assign even an `inconclusive` measured classification to an unexecuted study.

After real observations, classify the narrow knowledge hypothesis as **supported**, **weakened**, **inconclusive** or **falsified**, with the actual comparison and uncertainty explaining the choice. No favorable direction, minimum effect, statistical significance or successful Proto implementation is required. Equivalent results are useful. A result driven by a missing input is a handoff finding; it is not evidence that Markdown or JSON is intrinsically worse.

For a representation claim, optionally compare one independently reviewed fact set as readable documentation and as a source-mapped projection from #505. Keep the facts, API context, examples, task, model/tools/budget and reliable handoff equal. Record size, retrieval cost and actual accesses. A screenshot-only condition is exploratory and is not a matched-information control. Deterministic realization remains the separate #749/#732 question; this slice supplies no compiler result.

Feed every real divergence back with a stable finding ID, task clause, independent authority, exact expected/actual transition, source revision, failing artifact and proposed owning knowledge/test change. Distinguish implementation defect, insufficient knowledge, incomplete oracle, task ambiguity, host limitation and handoff failure. Preserve disputed outcomes for independent adjudication. Do not manufacture a knowledge gap merely because a model failed.

Core interaction facts stay under existing governed definitions. Business-specific blocks/scenario skills remain application/community work with an explicit accepting owner. The experiment creates no repository, maintenance promise, stable semantic promotion or release gate. Review/integration and original-condition accounting remain required after technical source delivery.

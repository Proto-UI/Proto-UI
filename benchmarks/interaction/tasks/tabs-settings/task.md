# Add live navigation settings to an existing tabbed reference

Modify the supplied standalone HTML file. It already provides accessible, manually activated horizontal tabs, but its arrow navigation always wraps. Add live navigation settings and fix that regression while preserving the existing reference and removal flow. Return the complete modified standalone HTML. Keep all changes in that file: no libraries, external resources, build tools, or other project files.

## Required external behavior

- Add a visibly labeled, accessible **Orientation** select with **Horizontal** and **Vertical** options. Its initial choice is Horizontal. Add a visibly labeled, accessible **Wrap navigation** checkbox that is initially unchecked (false). Both controls must remain usable and must change navigation immediately, without reloading or rebuilding the reference.
- Keep one tablist named **Reference sections**, containing four tabs in this order: **Overview**, **Unavailable**, **Details**, **History**. Unavailable remains disabled. Initially Overview alone is selected and its panel alone is visible. Maintain one enabled tab in sequential Tab order through roving focus; disabled tabs are not sequential tab stops.
- Horizontal orientation uses Left/Right arrows; Vertical uses Up/Down. The other axis must not move tab focus or change selection. Set `aria-orientation` explicitly to `horizontal` or `vertical` to match the live choice. Changing either setting must preserve the selected value, visible panel, tab names, and tab/panel identities. An orientation change must not leave a formerly applicable arrow key active.
- With Wrap navigation false, an arrow at either eligible endpoint keeps focus at that endpoint. With it true, arrows wrap between the first and last eligible tab. Both modes skip Unavailable in both directions, including after live toggles. **Home** and **End** move to the first and last enabled tabs in either orientation and either wrap mode.
- Keep manual activation: arrow, Home, and End focus movement never selects a tab or changes its visible panel. Focused enabled tabs activate on **Enter** or **Space**; Space keydown must prevent the browser default action (including scrolling). Enabled pointer activation selects that tab. Repeated activation of an already selected tab is stable: no duplicate tabs or panels, deselection, visibility changes, or identity changes.
- Unavailable must not select or change the selected panel through pointer or keyboard interaction, nor become a roving tab stop or a navigation destination. Suppress its key handling; if the host permits it to receive focus, activation and arrow keys on it must not change selection or move roving focus.
- Preserve accessible roles and names: tablist, tab, and tabpanel. Keep every tab and all four panels in the DOM throughout selection and setting changes, with stable unique IDs. Each tab's `aria-controls` must resolve to its own panel, and that panel's `aria-labelledby` must resolve back to its controlling tab. Project `aria-selected` true/false on every tab and disabled semantics on Unavailable. Only the selected panel is visible; hidden panels and their IDs remain present.
- **Remove reference** removes the reference fixture, all its tabs and panels, and its interaction behavior. Settings may be inside the removed fixture or survive outside it; any surviving settings must be inert toward the removed reference and must not recreate it or throw. **After** must remain accessible and keyboard reachable: after removal, focus may already be restored to After, or Tab from the surviving Remove reference control must reach After. No stale focus trap or later keyboard selection may recreate the reference.

Keep the existing section text and meaningful headings. Styling and implementation organization are up to you; the behavior above is the acceptance boundary. Do not add another reference fixture or tablist.

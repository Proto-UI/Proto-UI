# Coverage matrix validation

`node scripts/coverage-matrices/check-coverage-matrices.mjs` validates the retained matrices. `node --test scripts/coverage-matrices/test/*.test.mjs` exercises the negative controls. Source scanning is deliberately bounded static analysis, not an arbitrary runtime/data-flow proof; ordinary PR checks still need independent review when their checker, inputs or workflow change.

## Static resource and dependency scope

The resource collector currently covers direct property assignment, `setAttribute`, `Object.assign`, and unshadowed `Reflect.set` on statically proven script/link elements. Unknown resource property/value/spread inputs fail closed within those modeled forms; business objects and locally shadowed built-ins do not establish DOM provenance. This is not a proof of arbitrary JavaScript or factory aliases. Vite-root imports retain their application-root context through the evidence closure. Package-local Vite globs share the existing 500-module traversal budget. Their directory enumeration additionally uses single-entry buffered reads with a shared 10,000-entry budget, 64-component depth, 1,024-byte paths/patterns and 128 patterns per package inspection; over-budget, symlinked or outside-package trees are unverified. Exclusion patterns filter admitted matches without enumerating another tree. Package self-references resolve exact/wildcard export targets conservatively across conditions, including `imports` aliases, into the same 500-module queue; cycles do not reset that budget and unresolved self-targets remain unverified. An unfinished queue is unverified, not a successful partial scan. Vite-root/public candidates form a conservative closure. All reachable local/alias targets are checked against the canonical repository boundary before reading source bytes, including symlinked filenames with glob characters; reachable globs use the streaming enumeration budget above. Harness forbidden-state checks include repository-local shared helpers outside the app directory, while only app-owned surfaces enter its component inventory. Root/public Harness HTML uses the same external/dynamic document-base rejection as Website markup. It also rejects production import maps using the Website predicate. Until the #532 preview ruling, Harness native iframe/object/embed/webview markup and JSX are rejected; standard document.createElement/createElementNS calls use the existing unshadowed global/local-alias resolver, and unresolved native tag names stay unverified. Quoted examples, HTML comments, ordinary JSON scripts, business factories and custom JSX component names do not establish a native embed. This bounded check does not generally model React factory aliases, string-to-DOM injection or dynamically authored markup.

DOM-created script receivers also keep executable body mutations unverified: direct `text`, `textContent`, `innerText` and `innerHTML` assignment, the existing bounded aliases and global `Object.assign`/`Reflect.set` forms, plus direct append/prepend/child-replacement methods. This uses the existing proven DOM receiver scope, including unshadowed `window.document`, `self.document`, `globalThis.document` and bounded local aliases, and does not evaluate body strings or infer a stable script type/insertion lifecycle. Ordinary DOM text, business objects, shadowed document receivers and data attributes are not reclassified. Arbitrary factories, DOM lookups and general interprocedural mutation tracking remain outside this collector.

Promotion closure additionally follows the checked-in Website `@proto.ui/*` workspace source-export convention, binds each package manifest and the Website resolver configuration, and recursively includes relative and workspace-package source dependencies with a 500-source/context cap. Promotion globs also use the enumeration-time budgets above, shared across that closure. The resolver is mirrored as data-only logic, not loaded by evaluating candidate configuration. An exact reviewed fingerprint of the full Astro configuration admits only the known resolver/plugin shape: any config change, including an otherwise harmless edit, stays unverified until the fingerprint and parity controls receive source review. Merely recording a new config at capture time cannot authorize a different resolver. Unsupported or missing package exports, untracked/outside-repository sources, and installed external bare packages remain **unverified**; current `node_modules` bytes or lockfile metadata alone are not historical capture proof. This is an explicit validator limit, not proof of arbitrary resolver/plugin behavior.

External-package consumer-wall inspection resolves both the CommonJS target and the production client ESM target using the already-locked MIT `import-meta-resolve@4.2.0` development dependency. Its `moduleResolve` API receives `browser`, `import`, `module` and `production` conditions, honoring exact/wildcard export-key precedence and authored condition order. It only returns a target URL; candidate package code is never imported or executed. Existing conservative inspection of literal manifest targets and package self-references remains in place. Node 24 native-resolution controls cover the modeled precedence cases; custom resolver plugins and arbitrary additional conditions are not certified.

Promotion evidence also binds local CSS `url(...)` resource bytes, including images and fonts reached through imported stylesheets or embedded style blocks. The bounded lexical collector distinguishes comments and quoted examples, decodes CSS escapes, applies the existing browser URL preprocessing, decodes local URL percent encoding, and removes query/fragment suffixes before locating the resource. Relative URLs use the stylesheet directory; root URLs use the application's public/Vite roots. Missing files, malformed or dynamic URL forms, repository or application-root escapes, image-set functions (including the WebKit-prefixed form), and remote resource URLs remain **unverified**. Resource paths with any symlink component inside the repository remain unverified because current canonical bytes do not bind a historical link target. Raw NUL in CSS is rejected before scanning: [CSS input preprocessing](https://www.w3.org/TR/css-syntax-3/#input-preprocessing) replaces it with U+FFFD, so generic URL trimming cannot choose a lookalike filename. Inline data and same-document fragments are covered by the already-bound stylesheet bytes. Resource-only edges are compared as raw bytes, including NUL bytes, and do not become JavaScript traversal roots. This is not complete CSS parsing, an image/font decoder, an inline-style-attribute closure, or active-document SVG admission; the separate public SVG guard remains unchanged.

The Harness ownership scan follows class-local literal `this.method()`/`this['method']()` calls from the existing render/lifecycle roots, including arrow-property helpers; visited callables terminate cycles and a 500-callable cap rejects an incomplete execution closure. Inheritance, dynamic method names, extracted/bound methods and arbitrary `this` rebinding are not generally modeled. Harness-only `getBoundingClientRect`/`getClientRects` reads on proven DOM receivers enter the existing geometry-ownership gate; ordinary business methods and Website geometry reads are not reclassified. Browser entry scanning recognizes unshadowed direct and `window`/`self`/`globalThis`-qualified Worker/SharedWorker constructors, plus `CSS.paintWorklet` and `AudioContext`/`OfflineAudioContext.audioWorklet` acquisition, including bounded local aliases. Static external worklet URLs are rejected; local/dynamic URLs stay unverified because browser URL resolution cannot be inferred from Vite import resolution. Arbitrary factories or custom `addModule` receivers are not modeled.

Native JSX script sources join the existing executable-resource check in Website and Harness source: literal external URLs are rejected; relative/dynamic sources, spreads, opaque types, import maps and executable inline payloads remain unverified. Static JSON data scripts and custom component names are not inferred to execute browser code. Website native iframe/object/embed/webview markup and JSX require review. The sole allowance binds the exact path and checked-in opening-tag bytes of the static style-isolation browser-default srcdoc baseline; copying it elsewhere, changing its attributes/content, or duplicating the frame requires a new review. Comments, fenced examples and ordinary JSON script text are excluded. This does not generally model imperative Website embed creation or arbitrary markup factories.

Harness member addEventListener calls enter the state-ownership gate only through the existing DOM receiver provenance (such as known document/window, acquired elements, typed DOM parameters and bounded aliases). WebSocket/EventSource/BroadcastChannel/AbortSignal and ordinary business receivers are not treated as UI solely by the method name. This keeps the distinction within recognized syntax, without proving arbitrary receiver data flow. Astro head shorthand is conservatively unverified, including benign refactors, until a supported static representation is reviewed; the validator does not evaluate the shorthand binding.

Resource URL attributes (script `src`, stylesheet/base `href`), CSS `@import` URL values, and the modeled JSX/DOM script/link forms apply the [URL Standard basic-parser preprocessing](https://url.spec.whatwg.org/#concept-basic-url-parser): remove leading/trailing C0 controls and ASCII space, remove embedded TAB/LF/CR, and treat reverse solidus as a separator for relative/special URLs against an HTTP(S) document base. Non-ASCII whitespace, ECMAScript import specifiers, and Sass `@use`/`@forward` module specifiers are not trimmed by this resource rule. Character references and opaque values retain the existing unverified handling; this does not claim complete HTML/CSS parsing. Local normalized resources still enter the existing dependency closure.

The live governance reader rejects the REST Issues endpoint's `pull_request` marker before serializing a dependency Issue. GitHub's [Issues API](https://docs.github.com/en/rest/issues/issues#get-an-issue) also returns pull requests through that endpoint; their issue-shaped metadata cannot certify the required dependency-Issue identity. Reviewed owners and the existing explicit snapshot refresh policy are unchanged.

Recognized unshadowed `eval(...)`, `Function(...)` and `new Function(...)` calls are unsupported compilation entries and fail as **unverified**, including direct `window`/`self`/`globalThis` forms and the existing bounded local-alias resolution. The checker never parses or executes their payload strings. Business methods and lexically shadowed globals do not establish that native entry. This conservative admission rule can require review of future build-time compilation too; it does not assert the payload is malicious or add a Proto UI behavior guarantee. Reflective constructors, bind/call/apply indirection and arbitrary generated execution are not generally modeled. Current production-source search found no direct global compilation dependency; ordinary test-only `window.eval` fixtures remain outside the production set unless reached by it.

Harness native event-property assignments, including compound assignments, use the same DOM receiver requirement as member listeners. Transport/business properties such as WebSocket `onmessage` are not UI ownership solely by name. Markup script types containing character references or template-bound values fail as unverified even without `src`, because they can become import maps. Native JSX applies the same conservative character-reference boundary; literal JSON data script types and custom component tags stay separate. The checker does not decode candidate entities or execute template expressions. Standard Astro frontmatter is already extracted as a module segment, including in the promotion dependency closure; new raw-import controls and the retained changed-workspace-dependency regression verify that existing path rather than changing it.

## Public SVG source inventory

Website `public/**/*.svg` files enter a dedicated bounded XML-text inventory scan, including when their current consumer is an ordinary `<img>`. Recognized script elements (inline or SVG `href` / legacy `xlink:href`), event attributes, foreign content, declarative animation, non-fragment document resources, stylesheet imports/URLs and image-set functions, unreviewed external document types, entity declarations/internal subsets and unsupported encodings remain **unverified and not admitted**. Prefix-qualified element and resource-attribute names are matched conservatively by local name, including non-ASCII prefixes; this is not namespace resolution. Opaque character references in resource attributes and escapes/entities in modeled CSS resource inputs are not decoded into admission. A valid source fingerprint and matrix owner make these sources visible but cannot authorize active-document execution. Script elements remain unverified even with an HTML data-script type.

Static geometry, local paint/use fragments, ordinary CSS, and embedded base64 image/font resources retain their existing image-mode treatment. The exact conventional SVG 1.1 PUBLIC declaration already present in retained whitepaper art is preserved; this does not fetch or certify the external DTD. Other SYSTEM/PUBLIC targets and every internal subset remain unverified. Embedded SVG bytes in an `image` resource are not opened as active documents. Comments, text CDATA and escaped markup examples do not establish executable elements; a single XML lexical pass distinguishes processing instructions, true comments, CDATA and quoted tags, while style CDATA remains stylesheet input. Processing-instruction payloads are opaque; only genuine XML declarations and xml-stylesheet targets enter their respective encoding/resource checks. CSS comment removal respects quoted strings and escapes; image-set functions remain unverified, including string resource arguments. The existing whitepaper artwork and image-preview serializer are unchanged. Detection uses bounded lexical forms, not a complete XML/CSS parser, sanitizer, browser execution proof, or new positive SVG execution profile. Unknown active-document admission still requires a separate semantic decision. SVG script resource semantics follow the [SVG script element](https://www.w3.org/TR/SVG2/interact.html#ScriptElement) and [SVG linking attributes](https://www.w3.org/TR/SVG2/linking.html#XLinkRefAttrs), rather than HTML `script src` assumptions.

## Retained raster and video evidence

Raster validation captures a bounded immutable input, validates PNG structure and palette indices, and uses the already-declared Website `sharp` dependency to normalize/decode pixels. Multi-frame image manifests require distinct normalized pixel content with dimensions/channels bound to the digest; changed filenames, metadata or compression alone are insufficient.

Video evidence requires the supported **Linux** verification environment: Node 22, Python 3 with Linux `memfd_create`/seals/resource limits, and FFmpeg/ffprobe with seekable `fd:` input. The validator uses `/usr/bin/python3`, `/usr/bin/ffmpeg`, and `/usr/bin/ffprobe` explicitly; pnpm/project PATH entries cannot replace them. CI uses Ubuntu 24.04's official FFmpeg **6.1.x** package line, records the exact distro/Python/FFmpeg versions, and must decode the retained real fixtures before the repository suite. A version string alone is not proof. The distro patch build can advance with security updates; this is a recorded baseline, not a claim of bit-for-bit immutable package installation. No decoder binary is bundled in the repository. Local prototype validation used FFmpeg 7.1.5; that does not replace the actual CI 6.1.x receipt.

Missing Linux/kernel/Python/decoder support is reported as **unverified** and fails retained-video validation. The required fixture gate does not skip on an unsupported platform. Contributors using another OS can run this gate in the supported Linux environment; no native-platform execution is inferred.

The decoder receives a sealed, seekable copy of bounded input through `fd:`. Only the `fd` input protocol is allowed, so nested file/network URLs are excluded. Both faststart and moov-at-end MP4/MOV layouts remain supported; WebM/MKV are also covered. Audio, subtitle and data streams are excluded from the chosen video stream's frame receipt.

Current validator constraints are: 32 MiB input, 4,194,304 pixels/frame, 1,200 frames, 60 seconds metadata and decoded presentation span, 15 seconds per child wall time, 20 seconds CPU, 1 GiB child address space and 256 KiB result output. Exceeding a limit is unverified, never successful truncated-prefix validation. At least two fully decoded, content-distinct frames are required. These are resource/evidence constraints, not a Proto UI behavior guarantee or sufficient proof of the captured interaction's correctness. Before adoption, the retained Website evidence tree and documentation were audited: no accepted video files were present, and the matrix explicitly marked transition recordings missing. Future evidence outside these constraints needs an explicitly reviewed limit or format change rather than a weakened validation result.

Primary references: [FFmpeg fd protocol](https://ffmpeg.org/ffmpeg-all.html#fd), [FFmpeg 6.1.1 protocol source](https://github.com/FFmpeg/FFmpeg/blob/n6.1.1/libavformat/file.c), [Python memfd](https://docs.python.org/3/library/os.html#os.memfd_create), and [Python resource limits](https://docs.python.org/3/library/resource.html#resource.setrlimit).

The native-state scan includes direct and Object.assign writes to visibility, enablement, selection, focus-order and class properties, plus equivalent known native attribute mutations, only with the existing DOM provenance. Render-evaluated React hooks check direct Agent action references as well as callback bodies; useCallback remains deferred. These are modeled static forms, not arbitrary JavaScript execution proof. Astro config head entries are inspected as static arrays/objects without evaluating configuration code: import maps must use the exact reviewed React 18 / react-dom client / Vue 3 URL mappings, with no extra map fields, scopes or mappings. Dynamic heads/entries/scripts and nonliteral computed config fields remain unverified; static-string computed keys stay supported. This is an exact URL agreement, not remote-content integrity or a general interpreter for configuration-generated output.

## Native Website resource entry points

Imperative creation of recognized `iframe`, `object`, `embed` and `webview` elements is rejected for Website sources as well as Harness sources. The scanner retains its browser-document receiver and literal-tag provenance checks; shadowed business methods are not executable embeds, and the existing exact static style-isolation fixture is not a general imperative exception.

Native HTML event attributes are inspected from the `parse5` HTML tree, including browser recovery and foreign-content integration points. Astro attributes are inspected from the official Astro compiler AST, which keeps frontmatter, component callback props, expression text and self-closing template elements distinct. Markup-bearing raw text under foreign content remains unverified because an Astro text node is not proof of inert browser markup. Recognized native handler bodies must have source locations and quoted literal syntax. Encoded, dynamic or malformed bodies and recognized executable resource entries remain unverified; native handler URLs cannot inherit a component source file's module base. Parsing never runs candidate scripts or template expressions and creates no general template-execution guarantee. This addition covers direct native attributes; it does not establish admission for spread attributes, parser-recovered incomplete templates or evaluated template expressions. Existing Vue/Svelte script-segment behavior is outside this bounded native-attribute addition.

The scanner directly declares the already-locked MIT packages `parse5@7.3.0` and `@astrojs/compiler@2.13.1` as development dependencies. The package manager generates the lockfile projection; existing resolutions and public package runtime surfaces are preserved. The governance reconciliation workflow uses the repository's Node 24 baseline.

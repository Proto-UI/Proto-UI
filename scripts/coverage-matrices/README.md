# Coverage matrix validation

The independent prototype/projection portfolio is [documented here](../../internal/coverage-matrices/README.md). Validate its JSON/source/consumer links with `node scripts/coverage-matrices/prototype-coverage.mjs --check`; regenerate the readable view with `--write`. Its negative controls run with the existing test glob. This source inventory is separate from the Website/Harness runtime ownership checks below.

`node scripts/coverage-matrices/check-coverage-matrices.mjs` validates the retained matrices. `node --test scripts/coverage-matrices/test/*.test.mjs` exercises the negative controls. Source scanning is deliberately bounded static analysis, not an arbitrary runtime/data-flow proof; ordinary PR checks still need independent review when their checker, inputs or workflow change.

## Verified GPUI rows and portable native source proofs

A GPUI row may be `verified` only when every mapped projection has a passing implementation receipt at that row's main/candidate snapshot revision, with no unresolved blockers, and the row has a passing HTTPS-linked native receipt at the same revision. Delivery-item completion reuses these gates; leaving the item unchecked does not relax row verification. Native and implementation receipt links must be strings with a parseable HTTPS URL, a nonempty host and no credentials; malformed authorities, whitespace/control characters and backslash normalization are rejected. This is URL syntax validation, not authentication of the linked native execution.

Each implementation receipt retains `baseIdentity`, `projectionIdentity`, `revision`, `result`, `source` and nonempty `paths`, and now requires its own `sourceObjectProof`. Its shape is the existing self-verifying Git proof: `objectType` (`commit` or `tree`), `rootTree`, `commitBase64` for a commit only, and `trees` containing `{ sha, contentBase64 }` entries for every traversed tree. The receipt proof is separate from the Prototype candidate inventory proof; its path set does not expand or rewrite that inventory. `captureGitObjectProof(repoRoot, revision, paths)` in `prototype-coverage.mjs` can collect the proof from available Git objects. Capture creates source evidence only, never implementation or native acceptance.

Validation recomputes commit/tree object hashes, binds the exact snapshot object/type, and resolves each allowed native/GPUI-peer source path to a regular Git blob. Historical main rows use that immutable proof rather than unrelated current file bytes. Candidate rows additionally require current source bytes to match the proven blob; missing files and symlinked path components fail closed. Proof validation does not invoke Git or require older objects in a shallow/offline checkout. A present worktree path, arbitrary revision-shaped string, missing proof, or a native receipt at another revision cannot verify a row.

This tightens the admission shape for `verified` receipts. Existing `required-unassessed` rows need no new proof, and this change neither generates acceptance records nor changes portfolio counts. HTTPS receipt links and declared identity/scope still require independent review of actual native evidence: the checker does not fetch those URLs, authenticate an execution, prove semantic capability from source presence, or certify full GPUI parity.

## Static resource and dependency scope

The resource collector currently covers direct property assignment, `setAttribute`, `Object.assign`, and unshadowed `Reflect.set` on statically proven script/link elements. Unknown resource property/value/spread inputs fail closed within those modeled forms; business objects and locally shadowed built-ins do not establish DOM provenance. This is not a proof of arbitrary JavaScript or factory aliases. Vite-root imports retain their application-root context through the evidence closure. Package-local Vite globs share the existing 500-module traversal budget. Their directory enumeration additionally uses single-entry buffered reads with a shared 10,000-entry budget, 64-component depth, 1,024-byte paths/patterns and 128 patterns per package inspection; over-budget, symlinked or outside-package trees are unverified. Exclusion patterns filter admitted matches without enumerating another tree. Package self-references resolve exact/wildcard export targets conservatively across conditions, including `imports` aliases, into the same 500-module queue; cycles do not reset that budget and unresolved self-targets remain unverified. An unfinished queue is unverified, not a successful partial scan. Vite-root/public candidates form a conservative closure. All reachable local/alias targets are checked against the canonical repository boundary before reading source bytes, including symlinked filenames with glob characters; reachable globs use the streaming enumeration budget above. Harness forbidden-state checks include repository-local shared helpers outside the app directory, while only app-owned surfaces enter its component inventory. Root/public Harness HTML uses the same external/dynamic document-base rejection as Website markup. It also rejects production import maps using the Website predicate. Until the #532 preview ruling, Harness native iframe/object/embed/webview markup and JSX are rejected; standard document.createElement/createElementNS calls use the existing unshadowed global/local-alias resolver, and unresolved native tag names stay unverified. Quoted examples, HTML comments, ordinary JSON scripts, business factories and custom JSX component names do not establish a native embed. This bounded check does not generally model React factory aliases, string-to-DOM injection or dynamically authored markup.

DOM-created script receivers also keep executable body mutations unverified: direct `text`, `textContent`, `innerText` and `innerHTML` assignment, the existing bounded aliases and global `Object.assign`/`Reflect.set` forms, plus direct append/prepend/child-replacement methods. This uses the existing proven DOM receiver scope, including unshadowed `window.document`, `self.document`, `globalThis.document` and bounded local aliases, and does not evaluate body strings or infer a stable script type/insertion lifecycle. Ordinary DOM text, business objects, shadowed document receivers and data attributes are not reclassified. Arbitrary factories, DOM lookups and general interprocedural mutation tracking remain outside this collector.

Promotion closure additionally follows the checked-in Website `@proto.ui/*` workspace source-export convention, binds each package manifest and the Website resolver configuration, and recursively includes relative and workspace-package source dependencies with a 500-source/context cap. Promotion globs also use the enumeration-time budgets above, shared across that closure. The resolver is mirrored as data-only logic, not loaded by evaluating candidate configuration. An exact reviewed fingerprint of the full Astro configuration admits only the known resolver/plugin shape: any config change, including an otherwise harmless edit, stays unverified until the fingerprint and parity controls receive source review. Merely recording a new config at capture time cannot authorize a different resolver. Unsupported or missing package exports, untracked/outside-repository sources, and installed external bare packages remain **unverified**; current `node_modules` bytes or lockfile metadata alone are not historical capture proof. This is an explicit validator limit, not proof of arbitrary resolver/plugin behavior.

External-package consumer-wall inspection resolves both the CommonJS target and the production client ESM target using the already-locked MIT `import-meta-resolve@4.2.0` development dependency. Its `moduleResolve` API receives `browser`, `import`, `module` and `production` conditions, honoring exact/wildcard export-key precedence and authored condition order. It only returns a target URL; candidate package code is never imported or executed. Existing conservative inspection of literal manifest targets and package self-references remains in place. Node 24 native-resolution controls cover the modeled precedence cases; custom resolver plugins and arbitrary additional conditions are not certified.

Promotion evidence also binds local CSS `url(...)` resource bytes, including images and fonts reached through imported stylesheets or embedded style blocks. The bounded lexical collector distinguishes comments and quoted examples, decodes CSS escapes, applies the existing browser URL preprocessing, decodes local URL percent encoding, and removes query/fragment suffixes before locating the resource. Relative URLs use the stylesheet directory; root URLs use the application's public/Vite roots. Missing files, malformed or dynamic URL forms, repository or application-root escapes, image-set functions (including the WebKit-prefixed form), and remote resource URLs remain **unverified**. Resource paths with any symlink component inside the repository remain unverified because current canonical bytes do not bind a historical link target. Raw NUL in CSS is rejected before scanning: [CSS input preprocessing](https://www.w3.org/TR/css-syntax-3/#input-preprocessing) replaces it with U+FFFD, so generic URL trimming cannot choose a lookalike filename. Inline data and same-document fragments are covered by the already-bound stylesheet bytes. Resource-only edges are compared as raw bytes, including NUL bytes, and do not become JavaScript traversal roots. This is not complete CSS parsing, an image/font decoder, an inline-style-attribute closure, or active-document SVG admission; the separate public SVG guard remains unchanged.

The same promotion byte closure covers authored native image/media resources (`img`/`source` `src` and `srcset`, audio/video `src`, video `poster`, track/input `src`, and SVG `image` hrefs in markup). Native JSX tags are read as syntax; component props, ESM/example strings, comments and Markdown code remain separate. Markdown and MDX image/reference nodes use the Website's already-locked MIT `@mdx-js/mdx@3.1.1` parser, now an explicit root development dependency, with separate `md`/`mdx` formats. Only `createProcessor(...).parse` is used: candidate ESM, configuration and plugins are never compiled, loaded or evaluated. Full/collapsed/shortcut references, nested alt text, escapes and angle destinations follow that parser rather than a parallel image regex. The same AST selects authored HTML/JSX for resource and native-control inventory: raw HTML blocks retain their literal backticks, while actual code/inline-code nodes stay inert. Static Markdown HTML styles and direct MDX style string/template-literal children reuse the CSS resource collector; opaque expressions, content props and Markdown-generated markup inside CSS stay unverified. No candidate expression or ESM body is evaluated. Malformed MDX and opaque resource expressions remain unverified. Static srcset URL/width/density candidates are bound; unsupported candidate syntax remains unverified. Local URLs share the CSS percent/query/fragment, public/application-root, repository containment and symlink checks above; relative markup resources use their source directory. Resource bytes do not become executable roots. Inline data URLs and same-document fragments are already bound by their source. This is source-level evidence closure, not a production emitted-byte auditor.

The Harness ownership scan follows class-local literal `this.method()`/`this['method']()` calls from the existing render/lifecycle roots, including arrow-property helpers; visited callables terminate cycles and a 500-callable cap rejects an incomplete execution closure. Inheritance, dynamic method names, extracted/bound methods and arbitrary `this` rebinding are not generally modeled. Harness-only `getBoundingClientRect`/`getClientRects` reads on proven DOM receivers enter the existing geometry-ownership gate; ordinary business methods and Website geometry reads are not reclassified. Browser entry scanning recognizes unshadowed direct and `window`/`self`/`globalThis`-qualified Worker/SharedWorker constructors, plus `CSS.paintWorklet` and `AudioContext`/`OfflineAudioContext.audioWorklet` acquisition, including bounded local aliases. Static external worklet URLs are rejected; local/dynamic URLs stay unverified because browser URL resolution cannot be inferred from Vite import resolution. Arbitrary factories or custom `addModule` receivers are not modeled.

Native JSX script sources join the existing executable-resource check in Website and Harness source: literal external URLs are rejected; relative/dynamic sources, spreads, opaque types, import maps and executable inline payloads remain unverified. Static JSON data scripts and custom component names are not inferred to execute browser code. Website native iframe/object/embed/webview markup and JSX require review. The sole allowance binds the exact path and checked-in opening-tag bytes of the static style-isolation browser-default srcdoc baseline; copying it elsewhere, changing its attributes/content, or duplicating the frame requires a new review. Comments, fenced examples and ordinary JSON script text are excluded. This does not generally model imperative Website embed creation or arbitrary markup factories.

Harness member addEventListener calls enter the state-ownership gate only through the existing DOM receiver provenance (such as known document/window, acquired elements, typed DOM parameters and bounded aliases). WebSocket/EventSource/BroadcastChannel/AbortSignal and ordinary business receivers are not treated as UI solely by the method name. This keeps the distinction within recognized syntax, without proving arbitrary receiver data flow. Astro head shorthand is conservatively unverified, including benign refactors, until a supported static representation is reviewed; the validator does not evaluate the shorthand binding.

Resource URL attributes (script `src`, stylesheet/base `href`), CSS `@import` URL values, and the modeled JSX/DOM script/link forms apply the [URL Standard basic-parser preprocessing](https://url.spec.whatwg.org/#concept-basic-url-parser): remove leading/trailing C0 controls and ASCII space, remove embedded TAB/LF/CR, and treat reverse solidus as a separator for relative/special URLs against an HTTP(S) document base. Non-ASCII whitespace, ECMAScript import specifiers, and Sass `@use`/`@forward` module specifiers are not trimmed by this resource rule. Character references and opaque values retain the existing unverified handling; this does not claim complete HTML/CSS parsing. Local normalized resources still enter the existing dependency closure.

The live governance reader rejects the REST Issues endpoint's `pull_request` marker before serializing a dependency Issue. GitHub's [Issues API](https://docs.github.com/en/rest/issues/issues#get-an-issue) also returns pull requests through that endpoint; their issue-shaped metadata cannot certify the required dependency-Issue identity. Reviewed owners and the existing explicit snapshot refresh policy are unchanged.

Recognized unshadowed `eval(...)`, `Function(...)` and `new Function(...)` calls are unsupported compilation entries and fail as **unverified**, including direct `window`/`self`/`globalThis` forms and the existing bounded local-alias resolution. The checker never parses or executes their payload strings. Business methods and lexically shadowed globals do not establish that native entry. This conservative admission rule can require review of future build-time compilation too; it does not assert the payload is malicious or add a Proto UI behavior guarantee. Reflective constructors, bind/call/apply indirection and arbitrary generated execution are not generally modeled. Current production-source search found no direct global compilation dependency; ordinary test-only `window.eval` fixtures remain outside the production set unless reached by it.

Harness native event-property assignments, including compound assignments, use the same DOM receiver requirement as member listeners. Transport/business properties such as WebSocket `onmessage` are not UI ownership solely by name. Markup script types containing character references or template-bound values fail as unverified even without `src`, because they can become import maps. Native JSX applies the same conservative character-reference boundary; literal JSON data script types and custom component tags stay separate. The checker does not decode candidate entities or execute template expressions. Standard Astro frontmatter is already extracted as a module segment, including in the promotion dependency closure; new raw-import controls and the retained changed-workspace-dependency regression verify that existing path rather than changing it.

## Bounded loader and navigation profiles

Calls through an ESM-imported Node `createRequire` factory (`node:module` or `module`) cannot silently add a consumer dependency. The source scanner follows direct/renamed imports, namespace/default members (including renamed default imports), static namespace destructuring and bounded lexical factory/loader aliases. Actual loader consumption is unresolved for consumer-wall and promotion evidence; literal `@proto.ui/*` identities also enter the existing governed-layer check. It does not treat a Node loader's arbitrary resolution base as the Website Vite resolver. Inert factory acquisition and `.resolve` path lookup are not consumption. Business factories, erased imports and lexical shadows are not classified by spelling. Captured outer bindings and assignments retain possible native provenance across function text order; the scanner does not infer when that function runs. Reassigned native provenance and depth exhaustion remain unverified; this is not a CommonJS interpreter or arbitrary aggregate/getter/bind/call/apply proof. See [Node createRequire](https://nodejs.org/docs/latest-v24.x/api/module.html#modulecreaterequirefilename).

The modeled executable-navigation profile currently covers proven native Location writes and `assign`/`replace`, not `window.open`. Likewise, the worklet profile covers Paint and Audio, not the CSS Animation/Layout Worklet drafts. Reproductions for [window.open](https://github.com/Proto-UI/Proto-UI/pull/563#discussion_r4182138198) and [Animation/Layout](https://github.com/Proto-UI/Proto-UI/pull/563#discussion_r4182138211) remain explicitly unmodeled research; a passing scan does not certify those entry points. A future consumer using them requires source review and a reviewed profile/evidence decision before promotion. Absence from today's sources is not a safety argument. The bounded source checker is not a general JavaScript execution proof, and production validation still inspects the Rollup graph rather than emitted bytes. Research scope and acceptance work are retained in [the follow-up record](../../internal/records/2026-10-05-coverage-post-ci-followups.md); the originating review comments remain open pending formal explanation and follow-up publication.

## Document bases and runtime graph entries

Promotion does not infer a rendered document's base URL from a component source directory. An authored native `base` with `href`, a bound href or opaque attributes remains unverified for promotion, including case-insensitive HTML href names, local bases and bases supplied through the modeled Astro head configuration. Parser-proven style/text/title regions and template contents retain their inert document context; a Vue structural template stays active, and foreign-content text is not automatically treated as HTML raw text. This also protects inline-style resources on the page. Ordinary source inventory still permits static local bases; target-only bases, inert examples and custom components do not become document-base evidence. A future supported document-base profile needs separate resolution proof before these pages can be promoted. See the [HTML base element](https://html.spec.whatwg.org/multipage/semantics.html#the-base-element).

The production Rollup graph requires reviewed demonstration runtime chunks, including named facades and module-proven null facades, to be dynamic-only. `isEntry` and `isDynamicEntry` are independent flags: a dual-flag chunk is still a direct static entry, and demonstration reachability does not exempt it from the lazy-runtime boundary. Route-owned demonstration entries and the reviewed static Web Component host retain their existing roles. This validates graph placement, not emitted code bytes.

## Public SVG source inventory

Website `public/**/*.svg` files enter a dedicated bounded XML-text inventory scan, including when their current consumer is an ordinary `<img>`. Recognized script elements (inline or SVG `href` / legacy `xlink:href`), event attributes, foreign content, declarative animation, non-fragment document resources, stylesheet imports/URLs and image-set functions, unreviewed external document types, entity declarations/internal subsets and unsupported encodings remain **unverified and not admitted**. Prefix-qualified element and resource-attribute names are matched conservatively by local name, including non-ASCII prefixes; this is not namespace resolution. Opaque character references in resource attributes and escapes/entities in modeled CSS resource inputs are not decoded into admission. A valid source fingerprint and matrix owner make these sources visible but cannot authorize active-document execution. Script elements remain unverified even with an HTML data-script type.

Static geometry, local paint/use fragments, ordinary CSS, and embedded base64 image/font resources retain their existing image-mode treatment. The exact conventional SVG 1.1 PUBLIC declaration already present in retained whitepaper art is preserved; this does not fetch or certify the external DTD. Other SYSTEM/PUBLIC targets and every internal subset remain unverified. Embedded SVG bytes in an `image` resource are not opened as active documents. Comments, text CDATA and escaped markup examples do not establish executable elements; a single XML lexical pass distinguishes processing instructions, true comments, CDATA and quoted tags, while style CDATA remains stylesheet input. Processing-instruction payloads are opaque; only genuine XML declarations and xml-stylesheet targets enter their respective encoding/resource checks. CSS comment removal respects quoted strings and escapes; image-set functions remain unverified, including string resource arguments. The existing whitepaper artwork and image-preview serializer are unchanged. Detection uses bounded lexical forms, not a complete XML/CSS parser, sanitizer, browser execution proof, or new positive SVG execution profile. Unknown active-document admission still requires a separate semantic decision. SVG script resource semantics follow the [SVG script element](https://www.w3.org/TR/SVG2/interact.html#ScriptElement) and [SVG linking attributes](https://www.w3.org/TR/SVG2/linking.html#XLinkRefAttrs), rather than HTML `script src` assumptions.

## Retained raster and video evidence

Raster validation captures a bounded immutable input, validates PNG structure and palette indices, and uses the already-declared Website `sharp` dependency to normalize/decode pixels. Multi-frame image manifests require distinct normalized pixel content with dimensions/channels bound to the digest; changed filenames, metadata or compression alone are insufficient.

Video evidence requires the supported **Linux** verification environment: Node 24, Python 3 with Linux `memfd_create`/seals/resource limits, and FFmpeg/ffprobe with seekable `fd:` input. The validator uses `/usr/bin/python3`, `/usr/bin/ffmpeg`, and `/usr/bin/ffprobe` explicitly; pnpm/project PATH entries cannot replace them. CI uses Ubuntu 24.04's official FFmpeg **6.1.x** package line, records the exact distro/Python/FFmpeg versions, and must decode the retained real fixtures before the repository suite. A version string alone is not proof. The distro patch build can advance with security updates; this is a recorded baseline, not a claim of bit-for-bit immutable package installation. No decoder binary is bundled in the repository. Local prototype validation used FFmpeg 7.1.5; that does not replace the actual CI 6.1.x receipt.

Missing Linux/kernel/Python/decoder support is reported as **unverified** and fails retained-video validation. The required fixture gate, `node --test scripts/coverage-matrices/test/decode-video-evidence.integration.mjs`, does not skip on an unsupported platform or when tools are missing. CI runs it explicitly before the repository suite. The generic `*.test.mjs` suite runs portable fail-closed controls and reports real media integration as **not run**; a green portable suite is not decoder verification. Its unsupported-platform and missing-tool CLI controls are simulations, not native-platform execution. Contributors on another OS, or Linux without the supported tools, can run ordinary tests without installing media binaries, but must use the supported Linux environment for real decoder verification.

The decoder receives a sealed, seekable copy of bounded input through `fd:`. Only the `fd` input protocol is allowed, so nested file/network URLs are excluded. Both faststart and moov-at-end MP4/MOV layouts remain supported; WebM/MKV are also covered. Audio, subtitle and data streams are excluded from the chosen video stream's frame receipt.

Current validator constraints are: 32 MiB input, 4,194,304 pixels/frame, 1,200 frames, 60 seconds metadata and decoded presentation span, 15 seconds per child wall time, 20 seconds CPU, 1 GiB child address space and 256 KiB result output. Exceeding a limit is unverified, never successful truncated-prefix validation. At least two fully decoded, content-distinct frames are required. These are resource/evidence constraints, not a Proto UI behavior guarantee or sufficient proof of the captured interaction's correctness. Before adoption, the retained Website evidence tree and documentation were audited: no accepted video files were present, and the matrix explicitly marked transition recordings missing. Future evidence outside these constraints needs an explicitly reviewed limit or format change rather than a weakened validation result.

Primary references: [FFmpeg fd protocol](https://ffmpeg.org/ffmpeg-all.html#fd), [FFmpeg 6.1.1 protocol source](https://github.com/FFmpeg/FFmpeg/blob/n6.1.1/libavformat/file.c), [Python memfd](https://docs.python.org/3/library/os.html#os.memfd_create), and [Python resource limits](https://docs.python.org/3/library/resource.html#resource.setrlimit).

The native-state scan includes direct and Object.assign writes to visibility, enablement, selection, focus-order and class properties, plus equivalent known native attribute mutations, only with the existing DOM provenance. Render-evaluated React hooks check direct Agent action references as well as callback bodies; useCallback remains deferred. These are modeled static forms, not arbitrary JavaScript execution proof. Astro config head entries are inspected as static arrays/objects without evaluating configuration code: import maps must use the exact reviewed React 18 / react-dom client / Vue 3 URL mappings, with no extra map fields, scopes or mappings. Dynamic heads/entries/scripts and nonliteral computed config fields remain unverified; static-string computed keys stay supported. This is an exact URL agreement, not remote-content integrity or a general interpreter for configuration-generated output. Static head stylesheet links, style imports and document-base URLs use the equivalent markup consumer-wall rules; local head stylesheets, inline head styles and their CSS resources also enter promotion byte closure without treating the whole Astro config as an executable traversal root. Inspection is scoped to exported inline Astro configuration and Starlight options, including imported naming aliases. Unrelated business `head` fields are not emitted-head evidence. Indirect default exports, mutable object aliases, dynamic/spread/conditional integrations, getters/shorthand fields and opaque resource attrs remain unverified; static HTML boolean flags retain presence semantics, while boolean URL/relation values remain unverified. Ordinary static meta/icon entries and the current real configuration remain supported. This is not a general integration/plugin interpreter.

## Native Website resource entry points

Imperative creation of recognized `iframe`, `object`, `embed` and `webview` elements is rejected for Website sources as well as Harness sources. The scanner retains its browser-document receiver and literal-tag provenance checks; shadowed business methods are not executable embeds, and the existing exact static style-isolation fixture is not a general imperative exception.

Native HTML event attributes are inspected from the `parse5` HTML tree, including browser recovery and foreign-content integration points. Astro attributes are inspected from the official Astro compiler AST, which keeps frontmatter, component callback props, expression text and self-closing template elements distinct. Markup-bearing raw text under foreign content remains unverified because an Astro text node is not proof of inert browser markup. Recognized native handler bodies must have source locations and quoted literal syntax. Encoded, dynamic or malformed bodies and recognized executable resource entries remain unverified; native handler URLs cannot inherit a component source file's module base. Parsing never runs candidate scripts or template expressions and creates no general template-execution guarantee. This addition covers direct native attributes; it does not establish admission for spread attributes, parser-recovered incomplete templates or evaluated template expressions. Svelte script-segment behavior is outside this bounded native-attribute addition. Direct Vue directives have the separate bounded inspection described below.

The scanner directly declares the already-locked MIT packages `parse5@7.3.0` and `@astrojs/compiler@2.13.1` as development dependencies. The package manager generates the lockfile projection; existing resolutions and public package runtime surfaces are preserved. The governance reconciliation workflow uses the repository's Node 24 baseline.

## Bounded template, execution and resource entries

Vue SFC template ancestry and directive attributes (`@`, `:`, and `v-`) are read with the already-locked MIT `@vue/compiler-dom@3.5.31` parser, declared directly as a development dependency. Only `parse()` is used, without compiling templates, running transforms/plugins, or evaluating expressions; quoted directive values enter the existing JavaScript source checks. Self-closing Vue elements and table-context tags retain their actual AST identity. Recognized module/runtime entries, encoded or malformed bodies and dynamic directive arguments remain unverified. `v-html` is an unverified markup sink. Ordinary callback/binding expressions and inert comments stay supported. `v-pre` makes Vue directives inert only within their actual ancestry; native handler and static style attributes remain live. This is a direct-attribute source gate, not a Vue compiler, plugin interpreter, or proof of arbitrary template execution.

Direct `document.write`/`writeln` calls and `insertAdjacentHTML` calls on an existing statically proven DOM receiver stay unverified because their strings can become executable markup without Rollup edges. Qualified document receivers and bounded receiver aliases retain the existing lexical shadow checks. Method aliases, arbitrary generated markup and general HTML sanitization/data flow are not certified. The later DOM property entry section below distinguishes static markup from opaque serializer/highlighter values without blanket admission or removal of those consumers.

The existing render/effect execution walk recognizes direct Agent action member references passed to its modeled scheduler and Promise-reaction arguments before attempting callback-body resolution. Passing an action through an ordinary deferred component event remains distinct from scheduling it during render/effect. The scheduled-member check follows visible lexical bindings so a concrete local business object cannot inherit a same-named Agent import. This extends the existing provenance and callback boundaries rather than proving arbitrary asynchronous JavaScript.

CSS module targets and the existing promotion URL collector share CSS escape decoding. Import collection keeps string/comment boundaries and consumes complete escapes, including a hex escape's optional whitespace terminator, before classifying quoted or `url(...)` targets; recognized escaped directive/function names, adjacent string targets and comment-separated targets follow the same bounded path. Promotion closure also collects static native `style` attributes in the existing HTML, Astro, Markdown/MDX, Vue, Svelte and JSX source formats. Those attributes reuse CSS URL byte closure, with unchanged/changed asset controls. Encoded, dynamic, spread-obscured or unsupported style values stay unverified. Markdown code examples and JavaScript literal examples remain inert. The locked Markdown/MDX processor is parse-only; no candidate expression is evaluated.

Promotion also binds raw bytes for recognized `new URL(target, import.meta.url)` resources, including direct unshadowed `globalThis.URL`, `window.URL` and `self.URL`. Literal targets and the existing lexical `const` string resolution use the same percent/query, repository containment and symlink checks as other resources; opaque, external, malformed or missing targets remain unverified. These are resource-only edges: images, fonts and even code-like bytes do not become module traversal roots. Runtime lexical shadows retain business semantics, while erased declarations or conditional TypeScript rewrites cannot certify a shadow. Ordinary location/localization bases are outside this profile. Explicit base metadata and directories proven to be trees at the evidence commit remain metadata; replacing an evidenced file with a directory cannot erase its byte obligation. Historical resource modes must be ordinary files (100644/100755); symlink path text cannot serve as captured file bytes after replacement. Constructor aliases, arbitrary URL/data flow and render execution are not certified by this bounded source profile.

Only alias values consumed by the exported Astro -> Vite -> resolve configuration participate in alias resolution; unused business objects and functions do not. Actual shorthand/getter/method containers, opaque object entries and overriding array-entry spreads fail closed instead of silently disappearing from source resolution. Supported explicit object/array aliases preserve their existing resolution behavior; configuration code is never evaluated. These remain source/evidence gates only. The separate production audit continues to inspect Rollup module/import relationships, without a new chunk-code or emitted-HTML byte gate.

## Bounded DOM markup and authored-script closure

The source collector now inspects literal strings and lexically resolved local `const` strings assigned to `innerHTML` or `outerHTML` on an existing proven DOM receiver, including static-key `Object.assign` and unshadowed `Reflect.set` forms. `parse5` reads both a default template-fragment view and a document view without executing markup; the former retains context-sensitive table nodes, while the latter retains document-wrapper attributes. Neither view infers the actual receiver insertion context, and raw-text/foreign-context equivalence is not certified. The union is a conservative entry check; recognized scripts, native event attributes, executable navigation URLs, stylesheet imports/links and document/embed entries remain unverified. Empty strings, ordinary static markup and static SVG icon geometry remain supported. Compound HTML writes remain unverified because an isolated right-hand fragment cannot prove the completed markup. `outerHTML` is an element-replacement sink even on a proven script/style receiver; only script `innerHTML` is routed to the separate executable-body rule. The pre-existing `document.write`/`writeln`/`insertAdjacentHTML` rule is unchanged. This is a bounded entry detector, not a general HTML sanitizer or a proof of every browser parsing context.

Opaque HTML values produce a distinct research sentinel rather than being interpreted as module/resource URLs. The ordinary source check does not decide that an unknown value is executable or safe. Unknown source/spread/computed-key writes in the already-modeled `Object.assign`, `Reflect.set` and direct computed-property forms on proven DOM receivers also retain the sentinel; known local-constant keys use the literal-property rule. Business targets do not establish DOM provenance. The newly modeled body, handler and unknown-write boundaries require the target itself to be a node: `Record`/`Map`/array/generic containers that merely mention `HTMLElement` do not qualify, including through aliases. Explicit element types/intersections and actual DOM acquisitions retain their existing treatment; the older ownership classifier is unchanged. This avoids treating business mappings or business handler methods as native sinks just because one value/property is typed as an element. Promotion dependency closure explicitly rejects a proven opaque HTML sink, including a same-element serialized snapshot; passing the bounded source check is not promotion admission. Receiver paths outside the existing DOM proof, arbitrary property/method aliases and general interprocedural flow are still unverified research scope. [#834](https://github.com/Proto-UI/Proto-UI/issues/834) tracks the existing Previewer highlighter and copy-icon producer/consumer paths. Shiki/`safeRaw` provenance and same-element snapshots are observations, not trusted-source exceptions. Existing blocked code/copy/runtime controls are not covered by demo/build infrastructure exemptions. No file-hash, directory, helper-name or variable-name allowance was added, and no production component was changed.

DOM-created HTML/XHTML `style` receivers use the existing CSS import lexer for literal `textContent`, `innerText` and `innerHTML` assignments, including bounded aliases and the modeled `Object.assign`/`Reflect.set` forms. Static CSS without module imports stays supported. External imports are rejected after CSS escape and browser URL normalization; local imports remain unverified because browser-inserted CSS resolves against the document, not the source module. Opaque bodies, compound writes and append/prepend/child replacement stay unverified, since separate text fragments can form an import. An ordinary business object or a non-native `style.text` data property does not establish a stylesheet body. This HTML/XHTML style-body profile does not admit or inspect `createElementNS` SVG style bodies; that remains an explicit unsupported research boundary. The exact style-isolation baseline boundary is unchanged. Resource-bearing DOM-authored CSS or static HTML (including style attributes/blocks and the modeled native media attributes) retains a separate unverified-resource sentinel. The existing CSS URL lexer is reused, but these browser-relative resources are not rebound to the JavaScript module directory. Promotion rejects that sentinel; passing the source executable-entry check does not claim complete rendered-byte closure for generated markup. Resource-free static markup/CSS retains its existing promotion treatment.

Imperative `setAttribute` and null/empty-namespace `setAttributeNS` calls reject recognized native event-handler names on proven DOM receivers, using the existing `lib.dom.d.ts` native-name set and complete static names (including local constant strings). `setAttributeNS` preserves exact local-name case, so uppercase/mixed-case names do not impersonate lowercase native handlers. Ordinary `setAttribute` ASCII folding uses visible HTML element type/creation/document-member evidence; known foreign-namespace receivers retain exact case, and an unresolved namespace with a native-looking case variant stays unverified rather than claiming a compiled handler. These distinctions follow the [DOM attribute algorithms](https://dom.spec.whatwg.org/#dom-element-setattributens) and [HTML handler synchronization](https://html.spec.whatwg.org/multipage/webappapis.html#event-handler-content-attributes). `data-*`, unknown business event names, non-null namespaces and business receivers are distinct. Event-handler IDL property assignment does not compile a string as a content attribute does. This does not establish admission for unknown attribute names or arbitrary reflective mutation.

Resource opening tags are tokenized into complete attribute names and values. Attribute-looking bytes inside another quoted/expression value and suffixes such as `data-type`, `data-rel` or `data-href` cannot impersonate native `type`, `rel` or `href`. Native HTML first-duplicate semantics are retained. Opaque expression-valued resource attributes remain unverified. This shared lexical extraction does not replace the format-specific HTML, Astro, Vue or Markdown parsers.

Classic-worker `importScripts.call`/`apply` forms use the native global/method provenance checks and recognize unshadowed `self`/`globalThis` receivers. Direct calls and bounded local method aliases share the same shadow checks; literal `apply` arrays expose each target and opaque/spread lists remain unverified. Empty lists remain valid controls. This is not arbitrary `bind`/prototype or Worker execution-context inference, and it never executes imported scripts.

Authored Markdown/MDX executable script bodies are selected by the locked parse-only Markdown processor and HTML AST before entering the JavaScript scanner. Raw Markdown HTML script blocks retain their literal bytes; fenced/inline code stays inert. MDX native script text and static string/template-literal children are inspected, opaque payloads remain unverified, and ESM/JSX expressions remain executable source even beneath inert data-script types. Literal text in data scripts stays inert. Malformed MDX is unverified; native JSON braces are not valid MDX expression syntax, so MDX data examples must use a valid string expression. Neither Markdown/MDX expressions nor any candidate configuration/scripts are compiled or run. These source/promotion checks do not extend the separate production Rollup module-graph guard into an emitted-HTML or chunk-byte auditor.

## SVG script, WebAssembly and historical module identity

Native inline SVG script resources use `href`, or legacy `xlink:href` only when `href` is absent. HTML/Markdown namespace inspection uses parse-only HTML document and fragment views; framework expression strings and capitalized component names do not establish native SVG identity. Foreign-content integration points keep their HTML script semantics. JSX uses native element ancestry and its `xlinkHref`/`xlink:href` spellings; authored MDX also recognizes `xlinkHref`. Opaque source/type values stay unverified. This closes authored resource entry detection, not DOM-created SVG script admission or a general framework-rendering proof. The previously bounded HTML/XHTML DOM-creation profile is unchanged. [SVG2 script](https://www.w3.org/TR/SVG2/interact.html#ScriptElement) and [link precedence](https://www.w3.org/TR/SVG2/linking.html#XLinkRefAttrs) define the distinction from HTML `src`.

Unshadowed native `WebAssembly.compile`, `compileStreaming`, `instantiate` and `instantiateStreaming`, plus `new WebAssembly.Module`/`Instance`, join the existing unverified runtime-compilation gate. Qualified browser globals, bounded local aliases and the modeled method `call`/`apply`/`bind` and `Reflect.apply` forms retain lexical shadow checks. Static and unknown byte/response inputs are both unverified; the checker neither compiles nor executes WebAssembly or fetches its source. `Memory`, `Table`, `validate`, feature tests and business/shadowed receivers do not establish executable entries. Arbitrary reflective/interprocedural invocation remains outside the bounded model. [WebAssembly's Web API](https://www.w3.org/TR/wasm-web-api-1/) distinguishes compilation from instantiation, whose module start function can run.

The current installed-package consumer walk still detects governed Proto UI layer identities; it does not newly certify or reject every third-party compilation call. The existing locked Shiki Oniguruma/compiler flows receive no new package/path/helper allowance or trusted-source status. In particular, normal source acceptance is not promotion evidence: installed external package bytes remain unverified under the existing promotion contract.

Promotion rejects a module dependency with any repository-local symlink component before canonical resolution, including relative, alias, Vite-root and workspace source-export paths. Comparing today's canonical target with the same historical target file cannot bind which file a historical link selected. Ordinary consumer-wall canonical resolution remains unchanged. Regular unchanged/changed sibling modules retain their byte comparison behavior; retargeted, dangling, cyclic and escaping links cannot certify promotion evidence.

The WebAssembly branch separately records all bound names in object/array/nested/renamed/rest/default patterns, parameters and catch bindings, with block/loop/catch lifetimes, function/static-block/namespace-scoped `var`, runtime value declarations versus type-only names, TDZ/hoisting and named function/class-expression scope. The branch projects static keys from known browser-global/WebAssembly objects and syntax-local literal aggregates, including renamed namespace/method/constructor aliases. Possible native defaults/rest values stay unverified; explicit rest exclusions and definitely present business/safe values preserve their negative controls. Unknown computed native projections remain unsupported; an unknown member called directly on window/self/globalThis alone is not evidence of a WebAssembly entry. This is a bounded possible-value check, not execution, enumerability proof, arbitrary getter interpretation or general control-flow evaluation. It does not upgrade or replace the older DOM/ownership lexical helpers.

The native-entry binding predicate excludes erased ambient/`declare` ancestry, bodyless function signatures and explicit type-only import names, including mixed type/value imports. Pure-type/empty namespaces use the already-locked TypeScript namespace-instance classifier (`getModuleInstanceState`); an instantiated namespace still binds a value even when a particular member is erased. Real imports, classes, business declarations and ordinary const-enum value/reference-rewrite cases keep their distinct boundary. Ambient const enums and const-enum-only namespaces are emit-option-sensitive, so they cannot certify replacement of a same-named browser value and remain unverified when a possible native entry is reached. Static emission oracles generate text only and are tests, not a new production emit gate or a project-wide TypeScript compiler/interpreter guarantee. Older DOM/ownership predicates remain unchanged.

Aggregate WebAssembly projection carries its branch's visited aggregate identities through spread/rest/member traversal. This termination guard is not a general interpreter or a trusted-package allowance.

Static-key and possible-native-content caches retain only complete conclusions; depth/cycle-truncated results cannot poison later shallow native or business probes. Namespaced local names preserve case; non-null namespaces and business receivers remain distinct. Literal/const namespace and attribute strings are inspected without executing expressions. Unknown namespace/resource values cannot supply promotion evidence.

The same native-entry lexical inventory also supports bounded aliases and static object destructuring of browser `navigator.serviceWorker` and `location` receivers. Literal/const `javascript:` writes to native location/href and `assign`/`replace` calls remain unverified executable navigation; service-worker registrations retain the existing unresolved/external worker entry rules. Business/shadowed receivers and ordinary navigation are controls. Opaque navigation arguments remain unverified for promotion. Arbitrary getter, aggregate-object, reflective, bound-function and interprocedural receiver provenance is outside this profile.

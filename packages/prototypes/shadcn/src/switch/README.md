# Public Switch style profiles

The ordinary `switchRoot` + `switchThumb` composition and optional-Field `fieldSwitch` + the same `switchThumb` reuse Base Switch behavior. `fieldSwitch` is exported from `@proto.ui/prototypes-shadcn/field`; it uses the existing nearest Field for invalid/disabled/readOnly/label relations, not a second validator or checked owner.

`styleProfile` defaults to `inherit`. The source-mapped profiles are `vega`, `nova`, `maia`, `lyra`, `mira`, `luma`, `sera`, `rhea`, and independently retained `new-york-v4` (`new-york` alias). Explicit selection wins over the nearest shared style scope, then the compatibility New York fallback. `size` is `default` or `sm` and belongs to the actual Switch Root. Removing raw `size` resets it to `default`; removing raw `styleProfile` restores inheritance. Thumb reads its actual anatomy owner, not an unrelated nearby scope, and has no separate profile selector.

Fixed source: shadcn-ui/ui `3d98900e9b73c45f035f8109e9d41ba6a51685e7`, `apps/v4/registry/new-york-v4/ui/switch.tsx`, `apps/v4/registry/bases/base/ui/switch.tsx`, and `.cn-switch` / `.cn-switch-thumb` in each `apps/v4/registry/styles/style-{id}.css`. No upstream runtime is imported. Modern profile geometry is not normalized to root-16 pixel equivalents: Vega/Nova/Maia/Lyra use literal 18.4/14px track heights and 32/24px widths; Mira uses 16.6/14px and 28/24px; Luma uses spacing 5×11 / 4×7; Sera uses spacing 4.5×8.25 / 3.5×6.25; Rhea uses spacing 5×8 / 4×6. New York retains 1.15rem×2rem / .875rem×1.5rem. Thumb dimensions retain the source spacing units, with per-profile checked travel: ordinary/New York `100%-2px`, Luma `100%-8px`, Sera `100%+2px` (unchecked .25 spacing), and Rhea `100%-4px`.

Only mounted Rhea acquires the existing bounded owner-relative self-region lease from #983. Every other profile keeps a border-box hit region; the shared modern upstream wrapper's expanded pseudo-element hit area is not claimed for those profiles. A persistent relative-positioned Root box is an explicit host baseline extension supporting safe dynamic acquisition. It does not itself grant any profile an expanded hit region. Leaving Rhea, view detach, and disposal release its current lease without replacing checked, focus, or caller Thumb ownership.

All profiles retain the fixed source CSS transition declarations instead of the earlier narrower resident motion writer. The generic transform transition includes independent translate, scale and rotate. Reduced-motion CSS removes transform transitions. Native intermediate motion is a separate acceptance gate.

## Supported composition boundary

Ordinary standalone controls and sibling FieldLabel/FieldSwitch composition retain their own keyboard focus ring. Modern-profile invalid paint is available only through real optional Field facts; New York preserves its established no-invalid-paint baseline. Ring widths and opacity follow each profile rather than mapping all profiles to Rhea. The wrapped card-label outer-ring composition is not supported: upstream ancestor `group-has(:focus-visible)` cannot be replaced by sibling Label focus or a Field-wide focused flag. This limitation remains separate from ordinary profile support and requires a public wrapping-label composition contract.

The opt-in Base `draggable` enhancement (#498) is projected as an explicit direction + percentage preview only: with `draggable` true, the Thumb's fixed checked endpoints are replaced by the recipe's checked travel scaled by `--pui-percentage` (Sera keeps its 1px unchecked base), RTL mirrors the travel, and `dragging` suppresses the transform transition so paint follows the owner without a trailing animation. `draggable=false` retains the source-bound endpoints. No arbitrary CSS, new validation state, caller-node replacement or website-specific paint is introduced. Source/token tests, four-adapter DOM tests, and exact-head native evidence are separate claims.

## Draft dynamic-theme evidence debt

The fixed modern upstream globals use multiplicative radii (`2xl = radius * 1.8`), while the existing generic Proto theme variable uses `radius + 8px`. They agree only at the default 10px radius. This draft's default-radius measurements must not be presented as arbitrary-radius conformance. The shared modern-family radius projection is being reconciled separately without changing generic or legacy New York theme meaning; non-default-radius parity remains an acceptance blocker for this draft.

## Related binary family scope

Checkbox Root also uses the shared profile selector while its unchanged explicit Indicator borrows checked/mixed from the one Base owner. The historical Checkbox default keeps its separately adopted New York pin and exact 4px radius; modern Maia's 6px radius applies only when Maia is selected. Checkbox Group Root propagates the scope, while Item and All use the actual Group facts and the same source-bound checkbox box shapes and SVG check/dash grammar. The Group's ordinary label row and row-level focus ring are retained Proto composition choices: exact dark-only unchecked tint and focus styling of its internal glyph box remain gaps because Template child styles cannot consume live Rule metadata without a separately admitted target/lifetime solution. No Checkbox protocol, validator, raw CSS selector, or extra semantic owner is installed for that passive glyph.

Radio Group's compatibility fallback remains its independently retained base-nova snapshot, not New York. Explicit `new-york-v4` projects the pinned outlined Item and primary dot; modern profiles use their distinct filled or Sera foreground-outline recipe. Root remains the sole value/Collection/roving-focus owner. Each explicit Indicator receives the containing styled Item's resolved presentation and cannot accidentally disagree with an explicit Item profile. Luma/Rhea's dot grows from spacing 2 to 2.5 in dark mode through live metadata. Checkbox and Radio have no invented Field-invalid fact; the unowned upstream invalid and wrapped-label variants remain outside their accepted semantic boundary.

`test/binary-profile-transitions.test.ts` covers real Web Component runtime profile precedence, raw selector/size removal, contribution withdrawal, controlled refusal, disabled/Field policy, checked/mixed/value-handle preservation, actual Root/Item indicator binding, and live palette changes. Source coverage, finite vocabulary closure, exact-head runtime checks, rendered/native input, and optics are separate acceptance axes; adding this source and test does not establish an executed pass.

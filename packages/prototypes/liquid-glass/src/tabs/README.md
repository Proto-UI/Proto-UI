# Tabs projection

Draft Root/List/Trigger/Content/Indicator projection of the existing Base Tabs contract. The default Liquid Glass recipe uses a rounded translucent segmented surface, with the existing material declaration and ordinary style fallback. `appearance="underline"` on List and Trigger is the opt-in Runtime Box recipe; that recipe does not activate the material effect. The Indicator is a semantic-only part: the segmented recipe marks selection on the Trigger itself and a decorative child gets no material owner, so it keeps the real Base protocol (derived value/activeValue/orientation) with no paint.

Only the functional navigation List requests the regular material candidate. `material="auto"` (default) uses the existing shared host admission, source-lease, preference and contrast policy; `material="opaque"` withdraws that candidate while preserving the same readable fallback. The List observes Base Root orientation for vertical paint without writing semantic orientation. Root, Content and Indicator do not acquire material owners. Content remains neutral, following [Apple's Materials guidance](https://developer.apple.com/design/human-interface-guidelines/materials): Liquid Glass belongs to controls/navigation, not the content layer. This is public design guidance, not a public Apple shader or native parity claim.

Root selection, manual/automatic activation, disabled, roving focus and panel relations remain owned by the Base hooks. No additional keyboard/press owner. The inherited contract is `spec/prototypes/P-BASE-TABS*.yaml`; this addition does not revise that contract or its lifecycle. Same-state browser screenshots and native material verification remain pending. This is an authored projection, not a claim of an official Apple Tabs implementation.

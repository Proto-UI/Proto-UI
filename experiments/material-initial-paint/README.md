# Internal initial optical paint experiment

This is an unexported experiment for one static Liquid Glass Surface, over one visible repository-owned Canvas scene. It addresses the missing initial optical plane without identifying an arbitrary background image as a live material receipt. It does not change the production Library gallery, claim that Liquid Glass visual feedback is complete, enable a public API, or widen the existing draft material contracts.

The producer uses the real Liquid Surface Prototype, the Web Component Adapter, the existing guarded material sink and its existing renderer. Only a successful decoded live paint can be captured. Capture checks the actual Canvas RGBA against its lease, then binds the source PNG/RGBA, finite layout, resolved geometry/DPR, tokens, material candidate, opaque fallback and output PNG. Artifact SHA and source/bundle metadata accompany the output. These hashes record product provenance; they are not an authentication boundary or proof of optical quality.

The Node renderer writes the actual consumer HTML before navigation. Its Surface background is the captured optical PNG; the visible Canvas initially displays its captured source PNG as a CSS background. These are server-owned planes already present with JavaScript disabled. The client draws the same deterministic owned Canvas scene. Verification preserves the initial plane, compares exact source pixels and current input/owner facts, then grants a one-use internal lease. The ordinary sink must pass all of its existing guards and replay the same renderer to exactly the same output before adopting the already visible tuple. Live `self-optical` quality is reported only after the normal decoder succeeds. A different browser encoder, GPU output, profile, source, style, geometry or preference may reject this experiment; it must not be called an equivalent optical pass.

The server CSS starts opaque. It permits the PNG only for the captured 1000×800 CSS-pixel viewport, DPR 1, exact theme, affirmative no-reduction/no-contrast/forced-colors-none preferences and the built fixture layout. Unknown preferences, other viewport/DPR combinations and reduced transparency use the opaque family fallback before JavaScript. Forced colors uses Canvas/CanvasText. The fixture does not establish arbitrary responsive geometry, mobile Card layout, text-zoom coverage, pointer/contact seeds, four-runtime parity or Compiler SSR. It deliberately keeps the existing native anchor as the single interaction owner and uses the Surface only for passive paint.

Local controls use synthetic valid PNGs and a mock GPU. They exercise integrity, dimensions, strict unknown-field refusal, actual family candidate production, visible source capture, duplicate/concurrent ownership, preference/source/palette/style/geometry invalidation, late verification/decode and restoration. They do not prove native CSS media behavior, first paint, image continuity, optical beauty or accessibility acceptance. The browser driver is prepared for official execution only; no local Chromium restriction is bypassed.

With the standard CLI already built, prepare this isolated source bundle using `node --import tsx experiments/material-initial-paint/build-browser.mjs <bundle-directory>`. Run the targeted type closure with `node experiments/material-initial-paint/typecheck.mjs`. The official runner can use `node --import tsx experiments/material-initial-paint/browser.test.mjs <bundle-directory> <fresh-evidence-directory>`. It rejects an uncommitted input tree and a nonempty evidence directory. It produces light/dark renderer artifacts, actual static HTML, no-script and preference/profile screenshots, held/enhanced screenshots, rAF owner/paint/geometry traces, source/bundle metadata and SHA manifests. Original failure and partial evidence are retained. A prepared driver is not a completed browser result.

A production Card implementation still needs its approved responsive source scene, exact supported layout generation, integration with the actual Card family recipes and all current native first-frame/readability/focus assertions. The ordinary providers register no initial-paint lease, and the other five production families remain untouched by this experiment.

The preparation stage uses independent, short-lived native observers. It does not register a second lease in the ordinary sink's per-host shared geometry maps. Before any hash await it fixes document/source identity and subscribes to revocation; synchronous callbacks and delayed notifications cannot leave subscriptions behind or retire a later owner. Consumption checks both actual Canvas RGBA and its exact current PNG against the receipt.

Before native execution the driver verifies the current repository head/tree and clean state, every existing JS/CSS/HTML asset, and the client/HTML-generator source hashes. The local server hashes each response again. Generated dark and consumer HTML receive their own SHA records. These are byte-level reproducibility checks, not signatures or an authentication claim; a `dirty:false` metadata field alone is insufficient.

The build manifest also carries the independently generated `serverPaint` identity and exact image value. This is trusted build-side ownership metadata, separate from the receipt being checked. Preparation snapshots it before parsing/awaiting so broken JSON, missing payload, unknown fields or hash rejection still revoke the correct own selector without touching a foreign marker or an author's replacement. Successful validation requires the receipt output to agree with that plane. Callers must obtain this descriptor from checked producer output; arbitrary JSON/DOM discoveries cannot establish ownership. Earlier private fixture artifacts without this descriptor are intentionally refused.

# Liquid Surface elevation control

Agent: dot ModelTrace: not measured — owner-authorized dot exemption (2026-10-06)

This isolated CI-only experiment compares the existing Liquid Surface `elevation: none` with `raised`. Both variants are produced through the actual `LibraryCardPart` and Liquid family prototype, including compiled SSR style tokens. No equivalent handwritten shadow CSS is used. The current owned deterministic Canvas scene (gradients and thin curved lines) is reused; no external images or reference artwork are included.

The four profiles use 156.046875×45 and 222×64 CSS-pixel capsules over identical 536×160 scenes, with the same text and half-height corner radius. The only within-size recipe difference is elevation. The unchanged Material renderer owns optical output; ordinary elevation is distinct from optical shadows and does not repair refraction/highlights by itself.

Default entry has optical initialization off. `?optical=1` explicitly enters the experiment. The actual sink keeps preference, source, contrast and failure fallback rules. Product routes, public optical admission, SSR admission, Material APIs and receipt validation are unchanged. This is not an Apple-parity test and is not a shipping docs page. No native adapter acceptance follows from Chromium results.

The dedicated workflow builds only this isolated route, then runs exactly six cases: default off, no script, optical on, reduced transparency, forced colors and source revocation. Every case retains all four profiles. It checks genuine prototype tokens/computed shadow, source-relative geometry, optical quality and fallback backgrounds, and captures raw browser PNGs with source/head/tree binding. In the normal optical-on case, matching-size none/raised use identical optical image and source PNG; only prototype-owned external elevation differs. Failures and uncompleted cases remain visible.

Artifacts include full comparison PNGs, each scene PNG, source-only canvas PNGs and observations. Source-only PNGs from default/no-script are explicitly uninitialized (metadata reports sourceState null); they are not evidence of an optical source. Review edge light, center/backdrop detail and color, external shadow falloff and clipping from actual optical-on screenshots. Rendering failures are failures, not evidence that a visual candidate works.

Use the existing locked toolchain. The workflow links the installed website dependencies, builds with Astro, serves only the resulting local static assets, and aborts non-local browser requests. It does not deploy a service. Browser inventory assigns this suite to the dedicated workflow instead of omitting it from required coverage.

Source revocation is the explicit failure/fallback case. Shader-compilation, GPU-context-loss and other injected renderer failures are not covered by these six cases and are not claimed as tested.

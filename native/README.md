# Native host workspaces

[`gpui/`](gpui/README.md) is a separate Rust/Cargo workspace for the GPUI host Adapter direction. Its [`Cargo.toml`](gpui/Cargo.toml), lockfile and toolchain file own the native dependency/build configuration. The JavaScript workspace remains defined by [`pnpm-workspace.yaml`](../pnpm-workspace.yaml).

## Current boundary

| Surface | Responsibility |
| --- | --- |
| [`gpui/crates/proto-ui-host-protocol/`](gpui/crates/proto-ui-host-protocol/) | Wire messages, framing and session/epoch/lease state. |
| [`gpui/crates/proto-ui-style/`](gpui/crates/proto-ui-style/) | Token/theme data and native color/length resolution. |
| [`gpui/crates/proto-ui-gpui/`](gpui/crates/proto-ui-gpui/) | GPUI host layout, composition, input, focus and bounded accessibility projection. |
| [`packages/adapters/gpui-peer/`](../packages/adapters/gpui-peer/README.md) | Companion private TypeScript peer using the existing Runtime semantics. |
| [`packages/compiler/`](../packages/compiler/README.md) | 0.4 compiler availability boundary. The old GPUI source emitter and native SDK are retired; replacement lowering is not implemented. |

The peer-driven host workspace remains a Runtime/Adapter product. The future compiler-generated native components follow the [0.4 compiler foundation](../internal/compiler/README.md); existing Adapter evidence does not establish replacement compiler support.

## Fixtures and verification

Shared JSON fixtures under [`gpui/fixtures/`](gpui/fixtures/) are generated by [`scripts/gpui/`](../scripts/gpui/). Change their source/generator and regenerate, then run the corresponding `check:gpui-*` commands. The [GPUI README](gpui/README.md) describes protocol, Rust, interop and real-window checks and their platform requirements.

New native host implementation belongs in an explicitly scoped workspace here. Compiler lowering belongs in the compiler, and portable behavioral contracts belong in the [`spec/` catalog](../spec/README.md). See the [documentation policy](../internal/governance/documentation-policy.md) for documentation placement.

# Documentation image preview

This site composition completed [#780](https://github.com/Proto-UI/Proto-UI/issues/780) and now follows the borderless media presentation requested in [#796](https://github.com/Proto-UI/Proto-UI/issues/796), within [#420](https://github.com/Proto-UI/Proto-UI/issues/420). It is monorepo-HEAD dogfood of draft PUI prototypes, not a lifecycle promotion or a generic SVG sanitizer.

## Ownership

- `DocumentationImagePreview.astro` installs one disposable service for a page. `PageFrame.astro` mounts it on all documentation routes.
- `documentation-image-controls.ts` is the bounded WC integration bridge. The thumbnail uses public Base Button for interaction and a public family Surface for focus-visible feedback, composed around the original media with passive website geometry. Keyboard Close retains the selected family Button with a supported variant (Shadcn `ghost`, Brutalist `surface`). The image uses public Base Dialog Content/Mask directly, with the selected family Root/Title/Description/Close parts and public family Surface/Text for passive presentation. It does not duplicate keyboard, focus, dismissal or presence semantics.
- Base Dialog Content/Mask own outside-press dismissal, FocusScope restoration and presence. The passive scrim Surface does not receive pointer events or become a second interaction owner; the application never calls raw focus or retries focus after a delay.
- The runtime service owns image selection, native image load/error data, measured source/visual-viewport geometry, authored caption text, object URLs and route cleanup. Each new media request gets a fresh image element and abortable listeners; old events cannot update the new request.
- Base Dialog Content/Mask retain presence and motion clocks. The website geometry asset `documentation-image-zoom.css` consumes the public Transition phase projection for the measured 220ms linear image transform. Public family Surface owns the scrim color/opacity and media background, with no frame, shadow or blur. General image previews have no persistent toolbar; the bounded whitepaper reading exception is defined below. `bindPreviewSurface` mirrors the Base-owned transition state and `setPreviewSurfaceDuration` supplies its validated duration; neither creates another clock. It is not a reset of the public family Dialogs. CSS transitions reverse from the current interpolated position; `@starting-style` supplies the first materialized frame. Reduced motion sends zero-duration Transition props and disables sustained visual motion. No private timer owns logical open or view presence.
- `documentation-image-geometry.ts` computes viewport contain and a transform from the actual source rectangle. Resize/scroll and content mutations remeasure the visual viewport and source. Removed, empty, nonfinite or wholly offscreen origins use contain/fade instead of a flight toward invalid geometry. An invalid return destination stays invalid for that presentation, even if focus restoration later scrolls it into view; the next open starts a new measurement. This is website-local Web geometry, not a new portable Prototype promise.
- The image itself composites transparent pixels on the current theme background, without padding, a border or a shadow. This retains text contrast for transparent diagrams over the dimmed page; it does not introduce a surrounding Dialog panel or change the image URL/SVG data.
- The source stays in the authored layout and is temporarily made transparent through its owned thumbnail wrapper while the preview is present (opacity preserves source alt/nameFromContent and the trigger focus ring); afterLeave and terminal cleanup restore it. Alt, caption and close instructions stay available through accessible Dialog content. The Close action is visually clipped until keyboard focus is visible. General image previews retain contain presentation without an original-size mode or persistent header/control bar.
- The current `data-site-library-family` document signal selects actual family facades. Without that signal, Brutalist library routes choose Brutalist and other routes choose Shadcn. A family change closes/disposes the old protocol and remounts the public controls and passive family surfaces around the same media and measured geometry. This does not claim state transfer or page-runtime switching.

## Bounded whitepaper reading presentation

An otherwise eligible image in an authored `.whitepaper-diagram` may open in a reading-size viewport with explicit Fit, reading-size and zoom controls. This exception addresses diagram labels that become too small when a whole figure is contained in a narrow display. It is limited to the documentation composition; ordinary raster and other image previews keep the general contain presentation and no persistent toolbar required by #796. The exception does not broaden image or inline-SVG admission.

The composition nests the public Base ScrollArea Root, the app Prototype `docs-image-reading-viewport`, and the unchanged image. `documentation-image-controls.ts` registers the Root as `readingRoot` and the app Prototype as `readingViewport` for both selected families. The app Prototype inherits `asScrollAreaViewport()` and selects `asScrollSurface().configure({ projection: 'system' })` on that same surface lease, retaining the host-owned scrolling engine and scrollbar chrome. It adds only an accessible `region`, its localized `a11yLabel` prop (default: `Illustration reading viewport`), and focus-visible feedback derived from the inherited `focusVisible` fact. The feedback uses the existing `outline-2`, `outline-ring` and `forced-colors-focus-outline` tokens; an inset shadow alone could be covered by the image. It retains the public ScrollArea anatomy and inherited scroll/focus exposes; it does not introduce a second focus owner or a custom scrollbar.

Base owns sequential navigation from the actual four directional scroll facts. A viewport with no real scroll range stays out of sequential navigation. If fitting or resizing removes the last scrollable direction, the application must not force focus elsewhere. The application does not assign `tabIndex`, install raw keyboard/focus/wheel handlers, or synthesize scroll facts to make the viewport reachable. Native wheel and keyboard scrolling remain host behavior of the admitted public scroll surface.

Public family Buttons own Fit and zoom activation, disabled state, naming and focus feedback. A diagram-only layout frame keeps a 40px toolbar row, a 6px row gap and the native ScrollArea inside the existing Dialog. A 6px focus gutter leaves room for the viewport's external outline without changing the Dialog's overflow policy. The ScrollArea fills the remaining space in reading mode; Fit sizes and centers it around the contained image. The toolbar stays inside the Dialog's actual content rectangle, rather than being positioned beyond its clipping edge. This frame is passive application geometry and owns no keyboard, focus or scroll input.

The runtime service owns only the selected image's pixel dimensions, reading/fit mode, scale and measured center-preserving scroll position when those dimensions change. This geometry does not become a portable zoom or pan protocol. Fit must expose the complete figure inside its own scrollport with no remaining scroll range, as well as inside the window. Reading mode must offer real overflow and permit its content to be reached through the native scroll surface. The combined toolbar and scrollport use the existing Surface fade; they do not fly as if the whole frame were the source image. Ordinary contained images retain their existing image transform. The reading controls are disposed with their image presentation and participate in the existing family replacement and route cleanup; a removed, replaced or closing presentation cannot change the next image through a retained control callback.

Authored diagram layout, source URL, alt text and caption remain unchanged. Generated responsive variants come from their source generator and preserve the figure's owners, channels, conditions and qualifications. Neither reading-size presentation nor a complete-fit screenshot alone proves the reading goal: acceptance must inspect the actual reading viewport, readable labels, native wheel and keyboard reachability, focus-visible feedback and the no-empty-tab-stop case, as well as the retained Fit screenshot and ordinary-image regression.

## Automatic eligibility

All rendered `img` and top-level static SVG elements in `[data-doc-flow]` are considered, including Markdown output and MDX-native HTML. A `picture` remains intact and its selected `currentSrc` is reused. Authored `figure` and `figcaption` are not reconstructed. Only standalone Markdown image paragraphs receive the historical enhanced-image figure styling.

Images inside links, native controls, custom elements/demos, contenteditable regions, role/tabindex owners, image maps/native image controls, code or pre blocks are not enhanced. Empty `alt`, hidden/inert/editable/presentational media and `data-image-preview="off"` opt out. Known whitepaper `button[data-diagram-open]` wrappers are migrated only when they contain one image and no other interactive controls. Native click handlers in the authored attributes are not taken over. DOM listeners installed by other application code cannot generally be inferred; such owners must declare an interactive boundary or explicit opt-out.

Image source URL, alt and figure caption are preserved as data. Original CORS and referrer policy are copied before setting the preview src, preserving the image request policy. Candidate ownership is rechecked both on document mutations and immediately before activation; a later-authored link or hidden/interactive boundary removes the old trigger without dropping new descendants. There is intentionally no “open original” navigation, download, iframe, object or embed path. Existing external image URLs remain image-mode resources; the viewer neither fetches SVG source nor creates active SVG documents.

## Bounded inline-SVG profile

The runtime accepts a small inert presentation subset: `svg`, `g`, basic shapes, paths, text/tspan, title and desc, with explicit presentation/geometry attributes. It rejects unsupported elements and attributes without rewriting them. Script, handlers, animation, foreignObject, nested svg, class/style, defs/use/image, references (including local fragments), namespace expansion, processing instructions and URL/CSS escape forms are unsupported. The serialized SVG is loaded only through a revocable blob URL on an `img`.

This profile does not admit arbitrary SVG, prove the original inline document safe, rewrite content, or resolve [#563's public SVG active-document admission](https://github.com/Proto-UI/Proto-UI/pull/563#discussion_r4160559595). An unsupported source keeps its original display and gets no preview control. Changing the subset requires an independent safety review and negative fixtures; do not silently whitelist existing artwork.

## Evidence

- `documentation-image-source.test.ts`: admission, unsupported boundaries and candidate exclusions
- `rehype-enhanced-image.test.ts`: links, figures, pictures, captions and phrasing structure; the six baseline regressions were red before repair
- `documentation-image-preview.test.ts`: actual PUI activation, modal state, contain presentation, focus return, family replacement, stale load/error rejection and cleanup (DOM harness, not pixels)
- `documentation-image-preview.browser.test.ts`: real Chromium at 320/390/1280px, light/dark, both families, source fixtures, touch/keyboard, modal focus, linear forward/reverse frame sampling, image-versus-background hit ownership, interrupted reopen, resize and invalid-origin fallback, repeated dismissal, reduced motion and no-JavaScript content
- `documentation-image-geometry.test.ts` and `documentation-image-zoom.test.ts`: contain geometry, invalid-origin fallback, accessible chrome removal and interrupted/terminal ownership
- `.github/workflows/documentation-image-preview.yml`: read-only exact-head public fixture captures and native video with revision/environment metadata and 14-day artifact retention

The browser fixture injects the documented family/theme signal to isolate those axes; it does not claim a user-operated family selector journey. Runtime suite registration prevents the browser test from being silently skipped in the repository plan. Final-head browser captures and independent review are required before visual acceptance. The unmerged #563 matrix must separately reconcile this integration path/surface; no admission allowlist is changed here.

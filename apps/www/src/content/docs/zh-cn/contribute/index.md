参与 Proto UI 不要求先看懂整个仓库，但任务边界必须与你能安全判断的范围相符。

仓库里的 [CONTRIBUTING.md](https://github.com/Proto-UI/Proto-UI/blob/main/CONTRIBUTING.md) 是人类贡献流程的准确入口。这里负责解释各部分如何配合。

## 先看是否就绪

Starter 任务的结果已经固定，几乎不需要协议判断。Contributor-ready 任务的语义已经决定，但实现可能仍然很大。Maintainer-guided 任务还涉及准入、所有权、兼容性或架构决定。

工作量不等于就绪度。小改动可能仍在等设计结论；较大的完整切片也可能已经可以实施。

领取前应阅读 Issue、近期评论、assignee、关联 PR，以及 Project 启用后的实时状态。如果目标、排除范围、实施授权或验证边界缺失，应先请维护者把任务塑形清楚。

## 选择入口

- [协作模型](/zh-cn/contribute/collaboration/) 说明 Issue、label、Project、milestone、review 和 Actions 各自负责什么。
- [交付一个改动](/zh-cn/contribute/deliver/) 说明开发、验收、回归、部署与发布。
- [贡献者 Agent](/zh-cn/contribute/agents/) 说明可组合 skill、能力测评和自动领取。
- [Agent Skill 目录](/zh-cn/contribute/skills/) 列出每个懒加载状态转换及其职责。
- [Agent 自动化](/zh-cn/contribute/automation/) 区分已部署的 shadow、手动协议与候选周期任务。
- [Prototype 编写指南](/zh-cn/build/prototypes/) 详细说明受治理的组件工作。

尚未形成任务边界的问题和想法可以进入 [GitHub Discussions](https://github.com/Proto-UI/Proto-UI/discussions)。已经可以跟踪的工作进入 [GitHub Issues](https://github.com/Proto-UI/Proto-UI/issues)。Discord 适合快速同步，但会改变实施范围的结论仍要写回仓库。

`base-select` 是一个已经编目的 select-only 复合原型，也是 base 原型库里首个正式定义 `value` 类呈现部件的 family。

它使用 APG select-only combobox 语义：Trigger 投影 `combobox`，Content 投影 `listbox`，Item 投影 `option`。选中值是持久状态；打开后的 active item 是瞬时导航状态，两者不会混为一谈。

## 当前源码的安装与 Usage

Code 面板使用当前工作区中的公开包导出。请先安装 `@proto.ui/cli`、`@proto.ui/prototypes-base`、`@proto.ui/prototypes-lucide` 和所选宿主的 Adapter，并确保这些 Proto UI 包和 CLI 来自同一份审阅过的源码修订。对于源码检出版本，可以使用仓库的[仅打包流程](https://github.com/Proto-UI/Proto-UI/blob/main/scripts/release/publish.mjs)和[干净消费者安装流程](https://github.com/Proto-UI/Proto-UI/blob/main/scripts/release/consumer-smoke-cli.mjs)准备本地包及其声明的完整依赖。这里不承诺工作区版本已经发布到 npm；已发布版本的接入方式见[稳定版 Quick Start](/zh-cn/start-here/quick-start/)。

每个面板都提供用于已有应用构建配置的完整文件。React 和 Vue 沿用应用原有的挂载入口；Vue 2 使用 Vue `>=2.6.0 <2.7`。

| 宿主           | Adapter 包                        | 复制到的文件  |
| -------------- | --------------------------------- | ------------- |
| Web Components | `@proto.ui/adapter-web-component` | `index.html`  |
| React          | `@proto.ui/adapter-react`         | `src/App.tsx` |
| Vue            | `@proto.ui/adapter-vue`           | `src/App.vue` |
| Vue 2          | `@proto.ui/adapter-vue2`          | `src/App.vue` |

首次接入 Proto UI 时，在应用目录运行已经安装的同版本 CLI：

```sh
node node_modules/@proto.ui/cli/bin/proto-ui.js init --yes --no-interactive --prototypes shadcn
```

保留生成的 `src/styles/proto-ui-style.css`：示例通过导入它取得 Proto UI 的结构规则；如果应用入口已经导入，保留一次导入即可。每份示例还包含应用自身的 Base Select 布局与装饰样式，初始化预设不会改变所适配的 Base 原型。

选择一个宿主并复制完整面板。WC 注册应用自己的 `app-base-select-*` 元素，并在连接到文档前通过 `setElementProps` 设置 `accessibleLabel`、`placeholder`、图标尺寸和各选项值。React 将 `react-dom` 的 `createPortal` 传给 `createReactAdapter`，由 React 持有 Content 的 portal。两种 Vue 示例都注册了自身使用的全部组件。Trigger 的 `accessibleLabel` 为控件提供独立于选中值的名称。

## Family Parts

- `select-root`：持有受控/非受控 `open`、`value`、`textValue`，并裁决变更请求
- `select-trigger`：独立 command surface，投影 combobox ARIA，并负责键盘/指针开合
- `select-value`：通过显式 `run.update()` 渲染 `displayValue` 或 placeholder，不拥有输入行为
- `select-content`：组合 `asOverlay`、`asTransition`、`asFocusRoving` 与锚点定位
- `select-item`：投影 option，区分瞬时 `active` 与持久 `selected`，并提交选择请求

## 为什么它重要

这个 family 不只是为了扩充 base 库，还承担了一次 value 类组件的实践验证：

- 选中值文本由原型 family 自己定义
- 宿主应用不需要手动渲染这段文本
- value 呈现可以通过显式 update 驱动重渲染完成刷新

因此，`select-value` 是一个明确的 `render-consumed-value` 样本，而不只是 exposed-state 样本。

## 当前 v0 边界

`base-select` 目前包含：

- 单选语义
- 鼠标与 select-only 键盘交互，包括方向键、Home/End 与 typeahead
- Escape、Tab、外部点击关闭及所需的焦点恢复
- 打开后优先聚焦 selected item，否则从边界项开始
- combobox/listbox/option 的 ARIA 关系和选中状态
- 受控值只发送请求、不制造临时成功状态
- family 内部自带的 value 呈现部件

它暂时不包含：

- 表单语义
- 原生 `<select>` 等价行为
- 可编辑 combobox / 搜索能力
- 滚动按钮与 `ItemIndicator`
- 表单提交与 hidden input
- 多选

## 可选分组与结构 parts

`select-surface`、`select-viewport`、`select-item-text` 提供显式对齐结构。`select-group` 是被动容器；`select-label` 保留子内容，仅命名所属 Group，不是 control label，也没有激活行为。`select-separator` 是隐藏于无障碍树、无子内容的装饰性分隔。

它们提供 `asSelectGroup`、`asSelectLabel`、`asSelectSeparator`；asHook 继承语义声明，使用 `asSelectSeparator` 的作者必须显式返回空 renderer。标签缺失或重复时命名 fail closed，嵌套 Select 根之间不串名。选择、collection 与焦点仍由原 owner 持有。原生辅助技术验收仍待完成；GPUI peer 当前尚未传输 Separator 的 hidden-tree 事实。

## API

Select 是工作区源码。当前工作区 CLI 目标为 `base-select`。CLI 与依赖包必须来自同一版本；安装前确认所选发布版包含该家族。传入 `open` 或 `value` 会使对应事实进入受控模式。

<ApiPropsTable
  headers={{ name: '属性', type: '类型', default: '默认值' }}
  rows={[
    { name: 'defaultOpen', type: 'boolean', default: 'false' },
    { name: 'defaultValue', type: 'string', default: "''" },
    { name: 'disabled', type: 'boolean', default: 'false' },
    { name: 'readOnly', type: 'boolean', default: 'false' },
    { name: 'closeOnSelect', type: 'boolean', default: 'true' },
  ]}
/>

这些属性属于 Root。Trigger 的 `accessibleLabel` 默认 `''`。Value 的 `placeholder` 默认 `''`。Content 接受 Transition 属性，`position` 默认 `popper`，`side` 默认 `bottom`，`align` 默认 `center`，`sideOffset` 默认 `4`，`alignOffset` 默认 `0`，`avoidCollisions` 默认 `true`，`collisionPadding` 默认 `10`。Item 的 `disabled` 默认 `false`，`value` 与 `textValue` 默认 `''`；`closeOnSelect` 没有默认值，回退到 Root 策略。Group、Label、Surface、ItemText、Viewport 与 Separator 没有属性。

## 用法

### 受控、非受控与 IME 组合输入

值模式在实例创建时确定并在生命周期内保持一致：

- **非受控模式**：传入 `defaultValue` 初始化一次，后续直接接纳用户输入，无关属性更新不会重置已编辑内容。
- **受控模式**：传入 `value`，用户输入以提案形式通过事件发出，由外部回传新 `value` 后生效。在 IME 组合输入期间会保留候选文本，直到 `compositionEnd` 后若外部未接纳新值才恢复为当前受控 `value`，不打断输入法。
- 仅更新无关属性或值未变化时，会保留当前光标位置与选区；长按选区、系统剪贴板菜单与软键盘行为由宿主原生编辑器负责。

### 原生属性、焦点与自定义封装

- `disabled`、`readOnly`、`required`、`name`、`placeholder`、`autoComplete`、`minLength`、`maxLength`、`rows` 和 `wrap` 会直接映射到原生 `<textarea>`，同时保留 `textbox` 角色并映射 `ariaLabel`、`labelledBy` 与 `describedBy`。
- 控件本身不包含子节点插槽，请在外部包裹标签与样式。基于 `asTextareaRoot()` 封装风格组件时，需在原型定义上复用 `asTextareaRoot.modules`。

### 复位与表单组合

- 调用 `resetValue()` 可将非受控编辑器恢复为初始值（或在受控模式下发出初始值提案），在 `readOnly` / `disabled` 状态下也可用，并结束进行中的组合输入。
- 如需接入标签、描述、错误提示与表单校验，请从 `@proto.ui/prototypes-base/field` 导入 `fieldTextarea`（参考 [Form 示例](../form/)）。

传入 `value` 可受控管理文本内容。

- **暴露状态**：`value`、`disabled`、`readOnly`、`focused`、`focusVisible`、`composing`。
- **暴露方法**：`focusSelf()`、`blurSelf()`、`resetValue()`。
- **事件**：
  - `valueChange`：随原生 `input` 触发，载荷为 `{ value, composing, data, inputType }`。
  - `change`：随原生 `change` 触发，载荷为 `{ value }`。
  - `compositionStart`、`compositionUpdate`、`compositionEnd`：载荷均为 `{ value, data }`。

Message Scroller 复用 Scroll Surface 的 end-follow。读者位于末端时跟随追加；离开末端后可以通过 Jump to latest 显式恢复。newContentCount 由应用提供，不推断未读业务事实。跳转不会主动请求焦点。

当前是功能源码 WIP。完整 Adapter/Compiler、原生 GPUI、包消费者、无障碍与绑定提交的视觉验收仍待补齐。

Root 的 a11yLabel 为滚动区域提供无障碍名称，默认值是 Messages。

## 稳定 key 阅读组合

`asMessageScrollerReading` 是 `@proto.ui/prototypes-base/message-scroller` 的公开可选 Hook。在 authored prototype 中把它组合在实际 Base 或 Shadcn viewport **之后**。它复用同一 Scroll Surface，并关闭 generic `preserve-visible`，使稳定 key 恢复只有一个 owner。Compiler 消费者编译这个组合，不在应用内再导入 planner 建立第二个运行时控制器。

该 Hook 接受 `readingCapture`（默认 `first-crossing`，也可为 `visible-preferred`）、`readingInset`（默认 `0`）和 `readingPredecessor`（默认 `true`）。first-crossing 选择第一个 end 越过 inset 的条目；visible-preferred 优先选择 viewport 内第一个可见 primary，之后才回退第一个可见条目。应用提供身份和 primary 分类事实，Hook 决定如何据此选择锚点。

宿主提供 `MessageReadingFrame`：挂载 `epoch`、`scrollOffset`、`viewportSize`，以及按顺序排列的 `{ key, start, end, primary }`；start/end 相对 viewport 测量。锚点为 `{ key, previousKey, index, offset, scrollOffset }`。恢复先匹配精确 key，再按配置查保存的前驱，最后使用已保存的绝对位置；index 不会充当替代身份。移动通过 `Scroll.request({ kind: 'by', ... })` 发出，clamp 和实际执行时机由共享宿主处理。

| 公开方法／事实 | 职责 |
| --- | --- |
| `beginReading(following, anchor)` | 仅初始化一次阅读会话和可选恢复 hint。 |
| `syncReadingFollowing(following)`、`resumeReading()` | 接收外部阅读模式变化或显式回到末尾。共享 Jump 在组合了此 Hook 时调用 `resumeReading`。 |
| `readingInput(input, frame)` | 接收 pointer/key/wheel、内容 focus、selection 或 backfill 事实，决定暂停及 hint 退休。 |
| `captureReading(frame)`、`observeReadingScroll(frame)` | 保存当前阅读位置并处理滚动报告，不覆盖仍有效的初始 hint。 |
| `restoreReading(frame)`、`commitReadingRestore(ticket, actualFrame)` | 发出恢复请求后接收真实 offset；ticket 与挂载 epoch 拒绝过期回报，并阻断异步 scroll 的重复记锚点。 |
| `readingAnchorForPersistence(frame)` | 仅在历史阅读可以替换旧 hint 时返回可保存位置；存储和 schema 归应用。 |
| `planSelectionRestore(facts)`、`commitSelectionRestore(ticket)` | 判断选区恢复资格，对成功执行的宿主 Range 操作去重。 |
| `readingMode`、`restoringReading`、`getReadingEpoch()` | 公开阅读模式、hint 生命周期和测量 lease。 |

初始 hint 穿过空内容、后到内容、缺失 key 回退和零高精确命中，直到明确读者输入才退休。宿主提供选区身份、偏移、长度、端点可用性和前缀一致事实；Hook 拒绝改写后的文本、已经存在的非折叠选区和重复恢复记录。DOM 测量、Range、指纹编码、持久化 key 和存储仍由应用负责。程序恢复的 selectionchange 不冒充新输入，也不重复 pause。

公开纯函数 `captureMessageReadingAnchor`、`resolveMessageReadingAnchor`、`planMessageReadingRestore` 和 `messageSelectionRestoreEligible` 与 Hook 使用同一有限数据策略。存在这些接口或通过源码编译不代表浏览器或 native 验收已完成；本 family 仍为 draft。

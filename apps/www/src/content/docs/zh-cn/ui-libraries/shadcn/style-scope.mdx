Style Scope 通过逻辑 Context 树向下传递 Shadcn 视觉预设（`styleProfile`），让你在一组后代组件间统一配置或实时切换外观，而无需在每个子部件上重复传参。本页默认示例采用 **Shadcn Rhea** 风格。

## 安装

当前仅在源码工作区提供，尚未进入 0.2.0 稳定版。在应用入口处导入一次生成的 `proto-ui-style.css`，然后从 `@proto.ui/prototypes-shadcn/style-scope`（或包根入口）导入 `styleScope`：

```ts
import {
  styleScope,
  SHADCN_STYLE_IDS,
  normalizeShadcnStyle,
} from '@proto.ui/prototypes-shadcn/style-scope';
```

## 用法

使用与子组件相同的 Adapter 适配 `styleScope`（别名 `shadcnStyleScope`），并将其包裹在需要统一外观的子树外层：

```tsx
import * as React from 'react';
import { createReactAdapter } from '@proto.ui/adapter-react';
import { styleScope } from '@proto.ui/prototypes-shadcn/style-scope';
import { ShadcnCardRoot, ShadcnCardContent } from '@proto.ui/prototypes-shadcn/card';

const adapt = createReactAdapter(React);
const StyleScope = adapt(styleScope);
const Card = adapt(ShadcnCardRoot);
const CardContent = adapt(ShadcnCardContent);

export function ProjectCards() {
  return (
    <StyleScope styleProfile="rhea" className="contents">
      <Card>
        <CardContent>继承外层作用域的 Rhea。</CardContent>
      </Card>
      <StyleScope styleProfile="new-york" className="contents">
        <Card>
          <CardContent>继承更近作用域的 New York。</CardContent>
        </Card>
      </StyleScope>
      <Card styleProfile="new-york-v4">
        <CardContent>这张 Card 的显式选择优先。</CardContent>
      </Card>
    </StyleScope>
  );
}
```

- **宿主元素与布局透明性**：`styleScope` 本身不输出宿主 CSS（Web Components 自定义元素默认为 `display: inline`，框架适配器默认渲染包裹元素）。在 Flex 或 Grid 容器中使用时，请添加 `class="contents"`（React 中为 `className="contents"`）以保持外层布局流不受影响。
- **复合组件作用域**：支持样式作用域的复合组件 `Root`（如 [Card](../card/) 与 [Select](../select/)）会自动将解析后的预设向下发布给内部部件及嵌套后代。

## 预设选择与继承规则

`styleProfile` 为可选属性，默认值为 `inherit`，按以下三级优先级解析：

1. 组件自身显式传入的具体 `styleProfile`。
2. 最近的祖先样式作用域提供的具体选择。
3. 组件自身的兼容默认风格。

将组件或嵌套作用域的 `styleProfile` 改回 `inherit` 时，会撤销本地覆盖并恢复继承。若自身与祖先均未指定具体预设，作用域发布 `{ style: null }`，各组件继续使用各自的默认风格。

| 预设值 | 说明 |
| --- | --- |
| `vega`、`nova`、`maia`、`lyra`、`mira`、`luma`、`sera`、`rhea` | 八个现代 Shadcn 风格 ID，具体支持范围以各组件为准。 |
| `new-york-v4` | 独立的 New York 兼容风格。 |
| `new-york` | `new-york-v4` 的别名，会自动归一化为 `new-york-v4`。 |
| `inherit` 或省略 | 不显式覆盖，依次回退到最近作用域与组件默认风格。 |

### 组件预设支持范围

配置了 `options.supportedStyles` 的组件遇到未实现的预设时会直接抛出错误，而不会静默替换为其他风格。当前主要组件的预设支持如下：

| 组件 | 支持的 `styleProfile` | 无作用域（`{ style: null }`）回退 |
| --- | --- | --- |
| [Button](../button/) | 全部 9 种预设（`vega`–`rhea`、`new-york-v4`） | `rhea` |
| [Tabs](../tabs/) | 全部 9 种预设（`vega`–`rhea`、`new-york-v4`） | `new-york-v4` |
| [Select](../select/) | 全部 9 种预设（`vega`–`rhea`、`new-york-v4`） | `new-york-v4` |
| [Dialog](../dialog/) | 全部 9 种预设（`vega`–`rhea`、`new-york-v4`） | `new-york-v4` |
| [Input Shell](../input-shell/) | 全部 9 种预设（`vega`–`rhea`、`new-york-v4`） | `new-york-v4` |
| [Card](../card/) | `new-york-v4`、`rhea` | `new-york-v4` |

## 样式隔离、生命周期边界与 CSS Layer 顺序

- **无重建切换**：切换 `styleProfile` 仅更新视觉样式，不会丢失组件实例、已编辑值、文本选区或键盘焦点。请直接更新 `styleProfile` 属性，避免通过修改 `key` 重建子树。
- **家族隔离**：Style Scope 仅作为 Shadcn 家族的逻辑 Context 边界，而非 CSS Reset、Shadow DOM 边界或全局主题存储；[Input Shell](../input-shell/) 等 Shadcn 组件通过该通道解析预设，不会影响其他组件家族。
- **动态祖先与 Portal 边界**：作用域在组件创建、挂载、更新和 Context 订阅回调中同步祖先预设。运行时将节点跨作用域重挂、移除祖先提供者而未触发后代更新，以及原生 Portal 弹层沿逻辑归属继承作用域的能力仍在持续演进中；请在同一逻辑子树内稳定挂载并就地更新 `styleProfile`。
- **CSS Layer 顺序**：使用具名 CSS Layer 时，请在加载首个相关样式表前固定声明顺序：`生成的主题默认值` → `reset/base` → `proto-ui` → `应用自定义层`。

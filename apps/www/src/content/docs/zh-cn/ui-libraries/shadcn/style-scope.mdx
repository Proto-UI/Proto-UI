Style Scope 通过逻辑 Context 树向下传递 Shadcn 视觉预设（`styleProfile`），让你无需在每个子组件上重复声明风格，同时各组件依然保持自身的行为和状态。本页示例使用 **Shadcn Rhea** 风格。

## 安装

当前仅在源码工作区提供，尚未进入 0.2.0 稳定版。

## 用法

从 `@proto.ui/prototypes-shadcn/style-scope`（或包根）导入 `styleScope`（别名 `shadcnStyleScope`），并使用与子组件相同的 Adapter 进行适配：

```tsx
import * as React from 'react';
import { createReactAdapter } from '@proto.ui/adapter-react';
import { styleScope } from '@proto.ui/prototypes-shadcn/style-scope';
import { ShadcnCardRoot, ShadcnCardContent } from '@proto.ui/prototypes-shadcn/card';

const adapt = createReactAdapter(React);
const StyleScope = adapt(styleScope);
const Card = adapt(ShadcnCardRoot);
const CardContent = adapt(ShadcnCardContent);

export function ProjectCards() {
  return (
    <StyleScope styleProfile="rhea">
      <Card>
        <CardContent>继承外层作用域的 Rhea。</CardContent>
      </Card>
      <StyleScope styleProfile="new-york">
        <Card>
          <CardContent>继承更近作用域的 New York。</CardContent>
        </Card>
      </StyleScope>
      <Card styleProfile="new-york-v4">
        <CardContent>这张 Card 的显式选择优先。</CardContent>
      </Card>
    </StyleScope>
  );
}
```

支持样式作用域的复合组件 `Root`（如 `Card`）也会自动为内部子部件及嵌套后代建立作用域。外层布局和页面间距仍由应用代码控制。

### 预设选择与继承规则

`styleProfile` 为可选属性，默认值为 `inherit`，按以下优先级解析：

1. 组件自身显式传入的具体 `styleProfile`。
2. 最近的祖先样式作用域提供的具体选择。
3. 组件自身的兼容默认风格。

将组件或嵌套作用域的 `styleProfile` 改回 `inherit` 时，会撤销本地覆盖并恢复继承。若自身与祖先均未指定具体预设，作用域将发布 `{ style: null }`，各组件继续使用各自的默认风格。

| 预设值 | 说明 |
| --- | --- |
| `vega`、`nova`、`maia`、`lyra`、`mira`、`luma`、`sera`、`rhea` | 八个现代 Shadcn 风格 ID，具体支持范围以各组件文档为准。 |
| `new-york-v4` | 独立的 New York 兼容风格。 |
| `new-york` | `new-york-v4` 的别名，会自动归一化为 `new-york-v4`。 |
| `inherit` 或省略 | 不显式覆盖，依次回退到最近作用域和组件默认风格。 |

### 样式隔离与 CSS Layer 顺序

- 切换 `styleProfile` 仅更新视觉样式，不会重建组件实例，也不会丢失已编辑的值、文本选区或键盘焦点。请直接更新 `styleProfile` 属性，避免通过修改组件 `key` 来切换风格。
- Style Scope 只传递 Shadcn 家族的逻辑样式上下文，不创建 Shadow DOM 或全局主题存储，也不会影响 [Input Shell](/zh-cn/ui-libraries/shadcn/input-shell/) 等组件以外的其他组件家族。
- 使用具名 CSS Layer 时，请按以下顺序声明：`生成的主题默认值` → `reset/base` → `proto-ui` → `应用自定义层`，并在首次加载相关样式表之前固定该顺序。

## API

除 `styleScope` 外，`@proto.ui/prototypes-shadcn/style-scope` 还导出以下工具函数与类型：

| 导出 | 用途 |
| --- | --- |
| `setupShadcnStyleScope(def)` | 在复合原型的 `setup` 中调用，发布自身有效选择并从祖先继承。 |
| `setupShadcnStyleSelection(def, compatibilityStyle, options?)` | 在组件 `setup` 中调用，派生供规则使用的视觉状态；可通过 `options.supportedStyles` 限定该组件支持的预设集合。 |
| `SHADCN_STYLE_SCOPE` | 承载 `{ style: ShadcnStyleId \| null }` 的单例 Context Key（必须直接导入此 Key）。 |
| `SHADCN_STYLE_IDS` | 规范风格 ID 列表（包含 `new-york-v4`）。 |
| `normalizeShadcnStyle(value)` | 归一化已知 ID 与别名；对 `undefined`、`null` 或 `inherit` 返回 `null`，遇到未知 ID 时抛出错误。 |
| `ShadcnStyleId`、`ShadcnStyleChoice` | 规范风格 ID 类型，以及包含 `new-york` 与 `inherit` 的可选联合类型。 |
| `ShadcnStyleProps`、`ShadcnStyleContext` | 分别描述可选 `styleProfile` 属性形状与 Context 值类型。 |

```ts
import { normalizeShadcnStyle } from '@proto.ui/prototypes-shadcn/style-scope';

const legacy = normalizeShadcnStyle('new-york'); // 'new-york-v4'
const inherited = normalizeShadcnStyle('inherit'); // null
```

`setupShadcnStyleSelection` 配置了 `options.supportedStyles` 时，若传入了该组件未实现的预设会直接拒绝，而不会静默替换为其他风格。使用 Portal 渲染弹层时，弹层内容会沿逻辑树继承所属作用域，而非物理挂载节点的样式上下文。

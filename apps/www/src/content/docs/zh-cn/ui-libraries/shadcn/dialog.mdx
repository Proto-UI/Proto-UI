## 安装

先按[快速开始](../../../start-here/quick-start/)完成初始化并在应用入口引入生成的 `proto-ui-style.css`，然后生成 Dialog 组件：

<InstallCommandCard command="npx @proto.ui/cli@0.2.0 add wc shadcn-dialog" manager="npm" />

已发布的 `0.2.0` CLI 支持 `wc`、`react` 和 `vue`；把 `wc` 替换为 `react` 或 `vue` 可生成对应宿主的组件。命令从 `@proto.ui/prototypes-shadcn/dialog` 生成复合部件，同时提供带默认关闭图标的 `ShadcnDialogContent` 与无默认关闭图标的 `ShadcnDialogContentRaw`。

Vue 2.6（`>=2.6.0 <2.7`）、Rhea 预设以及下文的 Mask 指针默认行为，需要匹配的 `0.3.0-alpha.2` 工作区 CLI、适配器和原型源码。请将这部分工作区预览与上方固定版本的稳定版安装区分开。

## 用法

### 部件结构

| 生成部件 | 职责 |
| --- | --- |
| `ShadcnDialogRoot` | 统一管理受控或非受控 `open`、`disabled`、`alert` 模式、兜底无障碍名称及开关方法。 |
| `ShadcnDialogTrigger` | 触发打开的语义封装（默认无样式，可内嵌 `ShadcnButton` 作为可见触发按钮）。 |
| `ShadcnDialogMask` | 模态遮罩层，自带 150 ms 离场过渡动画并阻止底层交互。 |
| `ShadcnDialogContentRaw` | 居中对话框面板，自带 200 ms 离场过渡、焦点陷阱与关闭交互，不含默认关闭图标。 |
| `ShadcnDialogContent` | CLI 在 `ContentRaw` 上生成的便捷封装，默认内含可替换的 `ShadcnDialogCloseIcon`。 |
| `ShadcnDialogHeader` / `ShadcnDialogFooter` | 可选的头部与底部布局分组。 |
| `ShadcnDialogTitle` / `ShadcnDialogDescription` | 自动通过 `aria-labelledby` / `aria-describedby` 关联到对话框面板。 |
| `ShadcnDialogClose` | 触发关闭的语义封装（默认无样式，可内嵌按钮作为确认或取消操作）。 |
| `ShadcnDialogCloseIcon` | 独立的右上角 `X` 关闭按钮，自带无障碍名称 `Close`。 |

### 自定义默认关闭按钮

`ShadcnDialogContent` 的默认关闭图标支持三种配置方式：

- **默认**：不传覆盖项时自动渲染 `ShadcnDialogCloseIcon`。
- **替换**：直接传入 `ShadcnDialogCloseIcon` 子元素、React `close` 属性或 Vue `#close` 插槽即可替换默认按钮。
- **隐藏**：传入 React `close={null}`、空 Vue `#close` 插槽，或在 Web Components 上添加 `data-pui-no-default-close` 属性；若完全不需要默认预设，可直接使用 `ShadcnDialogContentRaw`。

### 焦点、关闭与 Alert 模式

- 打开期间 `Content` 会将焦点限制在对话框内循环，关闭后自动把焦点归还给触发按钮。
- 普通对话框可通过 `Escape` 或点击外部遮罩关闭；在 `ShadcnDialogRoot` 上设置 `alert={true}` 会切换为 `role="alertdialog"`，保留 `Escape` 关闭但禁止点击外部关闭（此时建议提供 `Description` 说明核心信息）。
- 缺少 `Title` 时，可通过 `Root` 的 `a11yLabel` 提供兜底无障碍名称。
- `Mask` 与 `Content` 会分别在 150 ms 与 200 ms 离场过渡结束后再卸载节点；参与遮罩的 `Mask` 不会在点击时夺走已恢复的焦点。

### 兼容性与无障碍覆盖

[当前 Dialog Content 测试覆盖](https://github.com/Proto-UI/Proto-UI/blob/main/spec/tests/T-BASE-DIALOG-CONTENT-0001.yaml)记录了已检查的行为与待完成的浏览器验证。四种预览宿主的完整键盘流程、受控拒绝、响应式/主题/语言组合以及安装包集成仍有待验证项。屏幕阅读器行为需要使用应用实际的浏览器与辅助技术组合单独验证。

请组合独立的 Mask 与 Content 部件；当前不支持 upstream 的 `asChild` 和 `modal` 属性。Header 与 Footer 负责布局；应用持有校验与持久化，并决定操作何时成功、何时请求关闭。

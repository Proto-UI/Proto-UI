## Installation

Available starting in `0.3.0-rc.1` and later releases (`@proto.ui/prototypes-bootstrap-2-3-2/autocomplete`).

## Usage

```html
<proto-ui-bootstrap-2-3-2-autocomplete-root a11y-label="Framework">
  <proto-ui-bootstrap-2-3-2-autocomplete-input
    placeholder="Search frameworks…"
  ></proto-ui-bootstrap-2-3-2-autocomplete-input>
  <proto-ui-bootstrap-2-3-2-autocomplete-trigger
    >Options</proto-ui-bootstrap-2-3-2-autocomplete-trigger
  >
  <proto-ui-bootstrap-2-3-2-autocomplete-content>
    <proto-ui-bootstrap-2-3-2-autocomplete-item
      value="next"
      text-value="Next.js"
      keywords="react ssr"
    >
      Next.js
    </proto-ui-bootstrap-2-3-2-autocomplete-item>
    <proto-ui-bootstrap-2-3-2-autocomplete-item
      value="astro"
      text-value="Astro"
      keywords="islands static"
    >
      Astro
    </proto-ui-bootstrap-2-3-2-autocomplete-item>
    <proto-ui-bootstrap-2-3-2-autocomplete-empty
      >No matching frameworks.</proto-ui-bootstrap-2-3-2-autocomplete-empty
    >
  </proto-ui-bootstrap-2-3-2-autocomplete-content>
</proto-ui-bootstrap-2-3-2-autocomplete-root>
```

### Parts and behavior

- **Parts**: Compose `Root`, `Input`, `Trigger`, `Content`, `Item`, and `Empty`.
- **Committed value vs. query**: `value` holds committed text while `inputValue` holds the live query. Selecting a suggestion commits `textValue`; pressing `Enter` without an active option commits free text.
- **Filtering, keyboard, and IME**: Built-in filtering folds case and diacritics across `textValue` and `keywords`; focus stays in `Input` during arrow navigation and IME composition never prematurely commits an item.

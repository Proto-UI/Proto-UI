Resizable coordinates two or more percentage-sized panels separated by draggable handles, supporting pointer dragging, arrow keys, `Shift` acceleration, `Home` / `End`, panel collapsing, and nested orientations.

Currently available from workspace source; not yet included in the 0.2.0 stable release.

## Usage

- **Indexed panels and handles**: Render `N` panels (`index: 0..N-1`) and `N - 1` handles (`index: 0..N-2`). Each handle resizes only its adjacent pair while preserving all other panels, with `Resize panels` as the default accessible name.
- **Constraints and collapsing**: Pass per-panel `min`, `max`, `collapsible`, and `collapsedSize` in `constraints` (defaults `0`, `100`, `false`, `0`). Percentages normalize to `100`; infeasible configurations keep the last valid layout. Collapsing acts as a discrete stop bounded by the neighbor's `max`.
- **Controlled state and nesting**: Supply `sizes` for controlled mode and handle `sizesChange` / `sizesCommit` (`{ sizes }`). Cancelled drags do not emit `sizesCommit`. Nested roots manage independent sizes and orientations. Panel sizing drives a static Web CSS `flex-basis` via `--pui-size`, excluding fixed handle widths from drag math.

## API

| Part | Props / Methods / Events | Description |
| --- | --- | --- |
| `Root` | `sizes` / `defaultSizes` | Full percentage vector (legacy 2-panel `value` / `defaultValue` also supported; `sizes` takes precedence) |
| `Root` | `constraints` | Per-panel `{ min, max, collapsible, collapsedSize }` rules |
| `Root` | `requestResize(index, nextSize, commit)` / `requestSizes(nextSizes, commit)` | Programmatic single-panel or full-vector resize requests |
| `Root` | `sizesChange` / `sizesCommit` | Live and committed percentage events with payload `{ sizes }` |
| `Panel` | `index` | `0..N-1` panel index applying its size via `--pui-size` |
| `Handle` | `index` | `0..N-2` separator handle between adjacent panels |

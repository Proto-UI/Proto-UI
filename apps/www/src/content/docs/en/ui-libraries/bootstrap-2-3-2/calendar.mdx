## Usage

### Composition and date format

Compose `Root`, `Caption`, `Heading`, `Previous`, `Next`, `Grid`, `Weekdays`, `Weekday`, `Row`, and `Day`:

- **Date strings**: Dates use `YYYY-MM-DD` and visible months use `YYYY-MM`. Selection and `month` can be controlled independently.
- **Week layout**: Displays the minimum 4, 5, or 6 weeks needed for the active month by default; set `fixedWeeks={true}` to always show 6 rows. You can render 6 indexed `Row` slots (`index` `0`–`5`) and 42 `Day` slots (`offset` `0`–`41`) as capacity; unused rows and days automatically expose `hidden` and leave the focus order.
- **Locale and direction**: Configure `weekStartsOn` (`0` = Sunday), `locale`, and `direction="rtl"` for weekday order, localized cell labels, and mirrored Left/Right navigation. Provide `a11yLabel` on icon-only navigation buttons.
- **Today**: Pass `today` as a `YYYY-MM-DD` string from your app (Calendar never reads the system clock). Initial visible month priority is `month` → `defaultMonth` → active selection → `today` → `1970-01`.

### Range and multiple selection

- **Multiple (`multiple`)**: Activating a day toggles it in a deduplicated, chronologically sorted array. Constrain counts with `minSelected` (default `0`) and `maxSelected`; adding can build up from empty toward `minSelected`, while removals must stay at or above `minSelected`.
- **Range (`range`)**: The first click sets `{ from }`, the second completes an inclusive `{ from, to }` (reordering reversed picks), and a subsequent click starts a new range. Pass `{}` to clear. `minNights` (default `0`, allowing single-day ranges) and `maxNights` limit the day span between endpoints.
- **Availability**: Use `min`, `max`, and `Root` `unavailable` for whole-date rules (ranges crossing an unavailable date are rejected while keeping the anchor). Local `Day` `disabled` disables only that cell. `readOnly` allows browsing without editing selection.
- **Range states**: Each `Day` exposes `selected`, `rangeStart`, `rangeEnd`, `rangeMiddle`, and `rangePending`.

### Composing month and year selectors

Use `bindCalendarCaption(source, { month, year })` to connect two family `Select` controls to Calendar's public `month`, `disabled`, and `requestMonth` APIs, and call `dispose()` on teardown. Name icon/caption triggers using `Select`'s `accessibleLabel` prop.

## API

| Mode       | Controlled / initial props                  | Change event                 |
| ---------- | ------------------------------------------- | ---------------------------- |
| `single`   | `value` / `defaultValue` (`YYYY-MM-DD`)     | `onValueChange({ value })`   |
| `multiple` | `values` / `defaultValues` (`string[]`)     | `onValuesChange({ values })` |
| `range`    | `range` / `defaultRange` (`{ from?, to? }`) | `onRangeChange({ range })`   |

- **Common `Root` props**: `mode`, `month` / `defaultMonth`, `today`, `min`, `max`, `unavailable`, `minSelected`, `maxSelected`, `minNights`, `maxNights`, `fixedWeeks`, `weekStartsOn`, `locale`, `direction`, `disabled`, `readOnly`.
- **State & methods**: `Root` exposes `mode`, `weekCount`, `selectedCount`, `rangeComplete`, plus `requestMonth(month)`, `requestValue(date)`, `requestValues(dates)`, `requestRange(range)`, `getValues()`, and `getRange()`. In controlled mode, `request*` emits a proposal and visual state updates once the parent supplies the new prop.

## Usage

### Composition

Place one `Control` inside `Root`, optionally paired with one `Label`, one `Description`, one `Error`, and any number of `Validity` readers:

- **Automatic ARIA wiring**: Automatically links and cleans up `aria-labelledby`, `aria-describedby`, and `aria-errormessage` (only while invalid) without manual DOM IDs.
- **Custom controls**: The default `Control` is a single-line text input. To connect other value-bearing controls, bridge them with `asFieldControl` or `asFieldTextControl` from Base.
- **State management**: `Root` manages `invalid`, `pending`, `dirty`, `touched`, `filled`, and `focused`, while `Control` manages its value and editor. Duplicate singleton parts ignore invalid configuration and stay inactive.

### Validation and async checks

- **Built-in constraints**: Supports `required`, `minLength`, and `maxLength` (measured in UTF-16 code units; optional empty strings skip length checks). `required` treats `null`, `false`, `""`, and `[]` as empty while treating `0` and whitespace as filled without trimming. Built-in flags are `valueMissing`, `tooShort`, and `tooLong`.
- **Validation timing**: Set `validationMode` to `'onBlur'` (default), `'onChange'` (waits until IME composition ends), or `'manual'`.
- **Controlled validity**: Supply `invalid` to control validity externally. Completed checks emit `validityChange` and take effect when the parent updates `invalid`.
- **Asynchronous checks**: Enable `externalValidation={true}` to emit `validationRequest` (`{ requestId, value, reason }`) after built-in checks pass, then call `resolveValidation(requestId, { invalid, errors })`. Value changes, newer requests, disable/readOnly transitions, cancellation, or resets automatically invalidate stale requests.
- **Error display**: `Error` renders explicit `message`, then current `errors`, then a built-in English fallback (pass localized messages for other locales). It unmounts content when closed; set `keepMounted` to keep it mounted while hidden. Pair with `LiveRegion` if you want live announcements.

> For group disabling or form-wide submission and reset, compose Field inside `Fieldset` or `Form`.

## API

| Part | Props | Defaults and behavior |
| --- | --- | --- |
| `Root` | `invalid` / `errors` | Supplying `invalid` enables controlled validity; `errors` holds messages |
| `Root` | `defaultInvalid` / `defaultErrors` | Initial uncontrolled validity and error messages |
| `Root` | `disabled` / `readOnly` / `required` | Default `false`; combines with local `Control` policy |
| `Root` | `minLength` / `maxLength` | Default `-1` (unbounded); UTF-16 code-unit length bounds |
| `Root` | `validationMode` | `'onBlur'` (default), `'onChange'`, or `'manual'` |
| `Root` | `externalValidation` | Default `false`; emits `validationRequest` after built-in checks pass |
| `Control` | `value` / `defaultValue` | Controlled or uncontrolled value (fixed on initialization) |
| `Control` | `disabled` / `readOnly` / `required` | Local flags; cannot relax an enabled `Root` restriction |
| `Control` | `placeholder` / `name` / `autoComplete` / `inputMode` / `enterKeyHint` / `ariaLabel` | Text input hints and accessible naming |
| `Label` | `activation` | Default `true`; clicking focuses the associated control |
| `Description` | — | Passive, selectable help text |
| `Error` | `message` / `keepMounted` | Custom message override; `keepMounted` defaults to `false` |
| `Validity` | — | Passive validity display and `getValidity()` reader |

- **Methods**: `Root` exposes `validate(reason?)`, `resolveValidation(requestId, result)`, `cancelValidation()`, `resetValidation()` (clears validation and `touched` without altering the value or `dirty` baseline), `focusControl(options?)`, and `getValidity()`.
- **Events**: `validityChange`, `validationRequest` (`{ requestId, value, reason }`).

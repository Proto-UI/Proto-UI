## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release.

## Usage

- **Parts**: `Root`, `Trigger`, `Content`, `Item`.
- **Triggers and anchoring**:
  - Right-click and a 600ms touch/pen hold within movement tolerance anchor the menu at the input point (default `bottom`/`start`, zero offset). Moving, releasing, cancelling, disabling, or unmounting cancels a pending hold; ordinary left clicks and scrolling remain untouched.
  - `ContextMenu`, `Shift+F10`, and programmatic `openContextMenu()` fall back to anchoring against the trigger region.
- **Keyboard and dismissal**: `Content` supports arrow-key navigation, typeahead, outside-press dismissal, and focus restoration on Escape or item activation.
- **Controlled mode**: with controlled `open`, an accepted request suppresses the native menu even if you keep `open={false}`; opening later reuses the latest live input anchor.

## API

| Part | Prop / Method | Description |
| --- | --- | --- |
| Root | `open`, `defaultOpen` | Controlled / uncontrolled open state |
| Root | `disabled` | Prevents opening the context menu |
| Root | `closeOnItemCommit` | Controls whether committing an item requests closing |
| Root | `openContextMenu()` | Programmatically opens the menu anchored to the trigger |
| Trigger / Content / Item | — | Context target area, menu overlay, and actionable menu items |

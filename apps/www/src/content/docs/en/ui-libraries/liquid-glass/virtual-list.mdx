Liquid Glass Virtual List separates a stable logical key sequence from mounted DOM rows so your application instantiates only items within the visible window and overscan buffer. Following Liquid Glass layering principles, the scrollable list remains an opaque grouped content surface (`rounded-2xl` with clipped corners), reserving translucent glass strictly for floating companion controls above the content.

## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release. Import the prototypes from `@proto.ui/prototypes-liquid-glass/virtual-list` and connect a Web scroll viewport through `@proto.ui/prototypes-base/virtual-list/web`.

## Usage

Virtual List consists of `Root`, `Viewport`, and `Content`: `Root` tracks the ordered `itemKeys` sequence inside a rounded grouped content surface, `Viewport` handles vertical scrolling and inset focus feedback, and `Content` hosts materialized row elements.

```ts
import { AdaptToWebComponent, setElementProps } from '@proto.ui/adapter-web-component';
import {
  virtualListRoot,
  virtualListViewport,
  virtualListContent,
} from '@proto.ui/prototypes-liquid-glass/virtual-list';
import { attachWebVirtualList } from '@proto.ui/prototypes-base/virtual-list/web';

AdaptToWebComponent(virtualListRoot);
AdaptToWebComponent(virtualListViewport);
AdaptToWebComponent(virtualListContent);

const list = document.querySelector('liquid-glass-virtual-list-root')!;
const viewport = document.querySelector('liquid-glass-virtual-list-viewport')!;
const content = document.querySelector('liquid-glass-virtual-list-content')!;

setElementProps(list, {
  itemKeys: Array.from({ length: 1000 }, (_, i) => `event-${i + 1}`),
  overscanItems: 3,
  maxMaterializedItems: 60,
});

const host = attachWebVirtualList({
  viewport,
  content,
  collection: list.getExposes().getCollection(),
  estimateSize: 64,
  renderItem(key) {
    const row = document.createElement('div');
    row.className = 'border-b border-border/50 px-4 py-3 text-sm';
    row.textContent = key;
    return row;
  },
});

// Scroll to a key on demand and dispose on teardown
host.ensureVisible('event-250', 'center');
// host.dispose();
```

### Layering, Motion & Accessibility

- **Content vs. Control Layer**: The scrolling list stays opaque without a glass-coated viewport and never stacks glass on glass; floating navigation or filter pills above it use `regular` and `prominent` Liquid Glass controls.
- **Accessibility Fallbacks**: Reduced transparency and forced-colors preferences reinforce the container border and drop soft shadows; reduced motion disables focus transitions automatically.
- **Semantics**: `Root` sets `role="region"` with `a11yLabel`, `Viewport` inherits `Scroll Area` scrolling with an inset focus ring, and `Content` sets `role="list"` while mounted rows receive `role="listitem"`, `aria-posinset`, and `aria-setsize`.

### Advanced: Custom Materializers

- Each logical list allows one active materializer at a time; `attachWebVirtualList` manages the lease automatically and cleans up rows and observers when `Root` unmounts or disposes.
- Dispose an active materializer before attaching a replacement. Non-Web hosts can integrate through `collection.acquireMaterializer(onRetired)`.

Liquid Glass Toggle inherits persistent selection semantics and keyboard behavior from [Base Toggle](/en/ui-libraries/base/toggle/). Inactive buttons use neutral `regular` glass (`secondary` fill and foreground), while active buttons switch to a tinted glass treatment driven by `primary` and `primary-foreground`.

A small decorative `currentColor` check mark uses symmetric reserved space in both states so labels and icons stay centered, outer geometry remains stable, and active selection stays recognizable without relying on color or optics alone. Transient press deformation stays independent of the persistent `active` state.

## Usage

### Material and accessibility

- The shared Web material provider samples only the explicit visible canvas supplied by the application, never arbitrary DOM.
- When the backdrop source is unavailable or overlapping, when the button is disabled or uses `material="opaque"`, or when reduced transparency, increased contrast, or forced colors are active, the toggle falls back cleanly to its opaque color pair (`primary`/`primary-foreground` when active, `secondary`/`secondary-foreground` when inactive) while keeping the check mark visible.
- Reduced motion disables elastic press deformation while preserving static optics.
- Leave space between adjacent glass controls for expanded optical paint (the preview uses a `32px` gap; wider controls may need more) so surfaces do not overlap.
- Provide an explicit accessible name (such as `aria-labelledby`) for icon-only toggles. Design choices follow Apple's [Materials](https://developer.apple.com/design/human-interface-guidelines/materials) and [Meet Liquid Glass](https://developer.apple.com/videos/play/wwdc2025/219/) guidance.

## API

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `active` | `boolean` | — | Controlled selection state; `activeChange` proposes updates for the caller to apply |
| `defaultActive` | `boolean` | `false` | Initial uncontrolled selection state |
| `disabled` | `boolean` | `false` | Suppresses activation, clears transient press state, and preserves `active` |
| `material` | `'auto' \| 'opaque'` | `'auto'` | Set to `'opaque'` to opt out of optical enhancement |

### Events and states

- `activeChange`: payload `{ active: boolean }`. In host adapters, listen via `onActiveChange`.
- Accessibility and exposed state: `role="button"` and `aria-pressed` reflect persistent `active`, while exposed `pressed` tracks transient pointer press. Focus and keyboard handling come from Base Toggle.

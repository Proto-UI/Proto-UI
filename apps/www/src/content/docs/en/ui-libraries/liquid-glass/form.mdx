Liquid Glass Form composes `Root`, `Field`, `Submit`, and `Reset` to validate registered fields (including async checks), emit form values keyed by field name on submit, and reset fields cleanly while keeping fields on a legible content surface and reserving glass for floating actions.

Currently available from workspace source via `@proto.ui/prototypes-liquid-glass/form` (not yet included in the 0.2.0 stable release).

## Usage

```tsx
import {
  LiquidGlassFormRoot,
  LiquidGlassFormField,
  LiquidGlassFormSubmit,
  LiquidGlassFormReset,
  LiquidGlassFieldLabel,
  LiquidGlassFieldControl,
  LiquidGlassFieldError,
} from '../proto-ui/components/react';

export function ExampleLiquidGlassForm() {
  return (
    <LiquidGlassFormRoot
      ariaLabel="Workspace settings"
      onSubmit={({ values }) => console.log(values)}
    >
      <LiquidGlassFormField name="workspace" required>
        <LiquidGlassFieldLabel>Workspace name</LiquidGlassFieldLabel>
        <LiquidGlassFieldControl placeholder="Design Systems" />
        <LiquidGlassFieldError />
      </LiquidGlassFormField>
      <div className="flex items-center gap-2">
        <LiquidGlassFormSubmit variant="prominent" material="auto">
          Save workspace
        </LiquidGlassFormSubmit>
        <LiquidGlassFormReset variant="regular" material="auto">
          Reset
        </LiquidGlassFormReset>
      </div>
    </LiquidGlassFormRoot>
  );
}
```

### Material Hierarchy & Accessibility Fallbacks

- **Avoid glass-on-glass**: Keep form fields and helper text on a legible content surface, and use `material="auto"` on floating action buttons (`Submit` defaults to tinted `prominent` glass; `Reset` defaults to `regular` glass). Inside translucent sheets or cards, switch action controls to `material="opaque"` so glass layers never stack.
- **System preference fallbacks**: When Reduce Transparency (`reducedTransparency`) or Increase Contrast (`increasedContrast`) is active, action buttons withdraw optical glass to their opaque style fills. When Reduce Motion (`reducedMotion`) is active, press deformation is suppressed. Disabled buttons withdraw glass while preserving readable contrast.
- **Validation and submission**: Activating `Submit` (or pressing `Enter` in a focused single-line input) validates all enabled registered fields and emits `submit` with keyed values. Disabled fields are excluded, duplicate names throw `FORM_DUPLICATE_NAME` during serialization, and invalid `FormField` parts switch to `text-destructive`.

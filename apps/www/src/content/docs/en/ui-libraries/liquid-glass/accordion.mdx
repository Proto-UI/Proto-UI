Liquid Glass Accordion composes five parts—Root, Item, Heading, Trigger, and Content—built on Base Accordion semantics. Only the interactive `Trigger` carries Liquid Glass optical material and press deformation, while `Content` stays opaque for legibility and never stacks glass on glass.

## Installation

Available from workspace source by importing the five prototypes from `@proto.ui/prototypes-liquid-glass/accordion`:

```ts
import {
  accordionRoot,
  accordionItem,
  accordionHeading,
  accordionTrigger,
  accordionContent,
} from '@proto.ui/prototypes-liquid-glass/accordion';
```

## Usage

```tsx
import {
  LiquidGlassAccordionRoot,
  LiquidGlassAccordionItem,
  LiquidGlassAccordionHeading,
  LiquidGlassAccordionTrigger,
  LiquidGlassAccordionContent,
} from '@/components/proto-ui/react';

export function LiquidGlassAccordionUsage() {
  return (
    <div className="rounded-2xl bg-gradient-to-br from-sky-500/20 via-indigo-500/15 to-fuchsia-500/20 p-6">
      <LiquidGlassAccordionRoot defaultOpenItems={['item-1']}>
        <LiquidGlassAccordionItem value="item-1">
          <LiquidGlassAccordionHeading level={3}>
            <LiquidGlassAccordionTrigger>How do I reset my password?</LiquidGlassAccordionTrigger>
          </LiquidGlassAccordionHeading>
          <LiquidGlassAccordionContent>
            Click on 'Forgot Password' on the login page to receive a reset link.
          </LiquidGlassAccordionContent>
        </LiquidGlassAccordionItem>
      </LiquidGlassAccordionRoot>
    </div>
  );
}
```

### Anatomy and material layering

```text
AccordionRoot
└── AccordionItem (transparent structural frame)
    ├── AccordionHeading (paint reservation boundary)
    │   └── AccordionTrigger (optical Liquid Glass interactive surface)
    └── AccordionContent (opaque readable content surface)
```

- **Single optical layer**: `Item` stays transparent so it never obscures backdrop sampling or stacks glass on glass; `Content` owns its opaque surface, subtle top divider, and reading padding.
- **Prominence and accessibility fallbacks**: `Trigger` supports `prominence="regular" | "prominent"` and an explicit `material="opaque"` opt-out. Under `prefers-reduced-transparency: reduce`, `forced-colors: active`, disabled/collapse-blocked states, or hosts without an optical sink, optical candidates withdraw cleanly to readable opaque theme tokens.
- **Readable disabled state**: Disabled triggers withdraw optical elevation and pointer interaction without dimming the entire host via `opacity-50`.

### Keyboard and accessibility

- Enabled triggers and focusable elements inside open content stay in the natural `Tab` order; `Enter` and `Space` toggle the focused item.
- `ArrowUp` / `ArrowDown` (vertical) or `ArrowLeft` / `ArrowRight` (horizontal, reversed in RTL) plus `Home` / `End` move focus between enabled headers without changing open items.
- Disabled headers are skipped; when `allowEmpty={false}`, the last remaining open header stays focusable with `aria-disabled` preventing collapse.

### Methods and events (Root)

- `getOpenItems()`: Returns a copy of the current open key array.
- `openCount`: Number of open keys (including dormant keys).
- `requestOpen(value, open, reason?)`: Proposes opening or closing an item (`reason` is `'pointer' | 'keyboard' | 'programmatic'`).
- `openChange`: Payload `{ openItems, value, open, reason }`. Initialization, controlled sync, and no-op requests do not emit.

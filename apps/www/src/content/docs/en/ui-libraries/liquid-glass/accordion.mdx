Currently available from workspace source; not yet included in the 0.2.0 stable release. Import `accordionRoot`, `accordionItem`, `accordionHeading`, `accordionTrigger`, and `accordionContent` from `@proto.ui/prototypes-liquid-glass/accordion`.

## Usage

### Composition and state

Compose `Root → Item → Heading → Trigger` with `Content` beside `Heading`. Give every `Item` a unique, stable, non-empty `value`. Root manages the expanded key set and nested Roots stay independent. Keep only the controlling `Trigger` inside `Heading` and place persistent secondary actions alongside it.

- Duplicate input keys are deduplicated, and duplicate `Item` registrations are ignored. In `single` mode, the first unique key is used.
- Unknown keys stay dormant to support progressive mounting; requests targeting missing keys are ignored.
- In controlled mode, interactions emit `openChange` without mutating state optimistically; pass the updated `openItems` back to Root to accept the change.

### Keyboard and accessibility

- Enabled headers and focusable elements inside your children stay in the natural Tab order. Enter and Space toggle the focused item.
- Up/Down (vertical) or Left/Right (horizontal, reversed in RTL), plus Home/End, move focus across enabled headers without changing open items.
- Disabled headers are skipped. When `allowEmpty={false}`, the last remaining open header stays focusable with `aria-disabled` preventing collapse.
- `Heading` sets the heading level and `Trigger` wires button semantics, expanded state, and item-scoped `aria-controls`. Opt into a landmark on `Content` with `region={true}` when appropriate.

### Content lifecycle and material

- Closed Content unmounts when closed by default (set `keepMounted={true}` to keep a hidden node mounted). Accordion does not relocate focus or add a delayed-close timer.
- Only `Trigger` declares `liquid-glass` optical intent and press deformation; other parts stay opaque and readable. Hosts without optical support use the declared opaque fallback.

## API

| Part | Props | Defaults and notes |
| --- | --- | --- |
| Root | `mode` | `'single'`; `'multiple'` allows independent open items |
| Root | `openItems`, `defaultOpenItems` | String arrays; supplying `openItems` enables controlled mode, `defaultOpenItems` initializes once |
| Root | `allowEmpty` | `true`; `false` prevents closing the last open item |
| Root | `disabled` | `false`; suppresses activation without modifying controlled input |
| Root | `orientation`, `direction`, `loop` | `'vertical'`, `'ltr'`, `true`; governs header arrow navigation |
| Item | `value`, `disabled` | Required non-empty stable `value`; `disabled` defaults to `false` |
| Heading | `level` | Integer `1–6`, default `3` |
| Trigger | — | Derives state from Item and Root |
| Content | `keepMounted`, `region` | Both `false`; keeps hidden node mounted / opts into landmark role |

### Events and methods

- `getOpenItems()`: returns a copy of the current open key array.
- `openCount`: number of open keys (including dormant keys).
- `requestOpen(value, open, reason?)`: proposes opening or closing an item (`reason` is `'pointer' | 'keyboard' | 'programmatic'`).
- `openChange`: payload `{ openItems, value, open, reason }`. Initialization, controlled sync, and no-op requests do not emit.

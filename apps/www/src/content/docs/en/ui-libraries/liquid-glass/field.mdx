## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release. Import `fieldRoot`, `fieldLabel`, `fieldControl`, `fieldDescription`, `fieldError`, and `fieldValidity` from `@proto.ui/prototypes-liquid-glass/field`.

## Usage

### Composition and accessible wiring

- Place one `Control` inside `Root`, with an optional `Label`, `Description`, aggregate `Error`, and any number of passive `Validity` readers. Nested Roots maintain independent scopes and duplicate singleton parts are ignored.
- `Control` provides a built-in single-line text editor. Custom value controls (such as Number Field, Input OTP, Slider, or Checkbox Group) integrate through `asFieldControl` and `asControlLabel().target(..., FIELD_LABEL_PAIR)`.
- Field automatically links and cleans up `aria-labelledby`, `aria-describedby`, and (only while `invalid` is true) `aria-errormessage` without manual DOM IDs, while syncing `aria-required`, `aria-invalid`, `aria-busy`, and `aria-readonly`.
- Clicking `Label` focuses the paired enabled `Control` without adding a Tab stop, ignoring drags, modified clicks, and nested interactive elements.

### Built-in and asynchronous validation

- **Built-in rules**: `required` treats `null`, `false`, empty strings, and empty arrays as empty (`0` and whitespace are filled; no implicit trimming). `minLength` and `maxLength` count UTF-16 code units and skip optional empty strings. Built-in flags are `valueMissing`, `tooShort`, and `tooLong`; external errors use `customError`.
- **Timing and controlled state**: `validationMode` defaults to `'onBlur'` and also supports `'onChange'` (waiting for IME `compositionend`) and `'manual'`. When `invalid` is controlled, `validityChange` emits proposals without overwriting your prop. `resetValidation()` clears validation and `touched` without changing the value or `dirty` baseline.
- **Asynchronous checks**: with `externalValidation={true}`, passing built-in checks emits `validationRequest` (`{ requestId, value, reason }`). Call `resolveValidation(requestId, { invalid, errors })` when your check completes; stale replies are automatically discarded after value changes, newer requests, unmount, or disable/readOnly transitions.
- **Error rendering**: `Error` displays `message`, then current `errors`, then a built-in English fallback. Error unmounts when closed by default (set `keepMounted={true}` to keep a hidden node mounted). Pair with a LiveRegion when live announcements are required.

For grouped disabled state see [Fieldset](/en/ui-libraries/liquid-glass/fieldset/); for submission and reset see [Form](/en/ui-libraries/liquid-glass/form/).

## API

| Part | Props | Defaults and notes |
| --- | --- | --- |
| Root | `invalid`, `errors` | Providing `invalid` enables controlled validity; `errors` supplies messages |
| Root | `defaultInvalid`, `defaultErrors` | Initialization-only uncontrolled defaults |
| Root | `disabled`, `readOnly`, `required` | All `false`; combine with local Control policy |
| Root | `minLength`, `maxLength` | Default `-1` (unbounded); non-negative UTF-16 code-unit bounds |
| Root | `validationMode` | `'onBlur'` (default), `'onChange'`, or `'manual'` |
| Root | `externalValidation` | `false`; emits `validationRequest` after built-in checks pass |
| Control | `value`, `defaultValue` | Controlled or uncontrolled text value (fixed on initialization) |
| Control | `disabled`, `readOnly`, `required` | Local policy (cannot override an active Root constraint) |
| Control | `placeholder`, `name`, `autoComplete`, `inputMode`, `enterKeyHint`, `ariaLabel` | Supported text-editor hints |
| Label | `activation` | `true`; pointer click requests focus on the enabled Control |
| Description | — | Passive, selectable help content from your children |
| Error | `message`, `keepMounted` | Optional localized override; `keepMounted` defaults to `false` |
| Validity | — | Passive state and `getValidity()` snapshot reader |

### Events and methods

- Root methods: `validate(reason?)`, `resolveValidation(requestId, result)`, `cancelValidation()`, `resetValidation()`, `focusControl(options?)`, `getValidity()`.
- Root states: `invalid`, `pending`, `dirty`, `touched`, `filled`, `focused`, `disabled`, `readOnly`, `required`.
- Root events: `validityChange` (status, flags, and errors snapshot) and `validationRequest` (`{ requestId, value, reason }`), mapped to `onValidityChange`, `onValidationRequest`, and `onValueChange` in adapters.

Ordinary demos on this page explicitly use **Shadcn Rhea**, with matching examples. This does not change public compatibility defaults or imply complete browser, native-host or visual acceptance. Neutral Surface/Text atoms retain their own public semantics; the consumer composition supplies the family presentation theme.

This entry shows the current `shadcn` toggle implementation in Proto UI.

The selected Rhea recipe maps to the pinned [Rhea style source](https://github.com/shadcn-ui/ui/blob/3d98900e9b73c45f035f8109e9d41ba6a51685e7/apps/v4/registry/styles/style-rhea.css): default/sm/lg heights are 2rem/1.75rem/2.25rem (16px root font), min-width matches height, inline padding is 0.625rem on every size, gap is 0.25rem and the radius is `rounded-2xl` (upstream contract `--radius` ×1.8; Proto currently approximates it as `--pui-radius` +8px — the two agree only at the pinned 0.625rem/10px base, so no dynamic-base parity is claimed); outline keeps `border-input` with no shadow; pressed uses a muted surface and hover uses the foreground ink, with upstream adding a muted hover surface only on the outline recipe while the current Proto hover adds it on both variants — the default-variant hover surface stays ungoverned and is recorded, not accepted. The separate [02cad611 New York source](https://github.com/shadcn-ui/ui/blob/02cad61166c4c20edbc8a3f71bd720eed4c1f49b/apps/v4/registry/new-york-v4/ui/toggle.tsx) retains its 36/32/40px heights, accent active paint, outline shadow-xs and muted-foreground default hover as the compatibility profile. These are distinct profiles, not a claim of cross-target rendered parity.

Toggle active, disabled, keyboard and a11y remain Base-owned. `asChild` is intentionally unavailable; native-prop and pressed-API aliases, invalid handling and arbitrary nested-SVG styling remain compatibility differences. This page and source tests are not four-runtime, two-theme native pixel acceptance.

Combine a label, form control, helper description, and validation errors into one accessible field unit supporting vertical and horizontal layouts, built-in constraints, controlled validity, and async validation. The examples on this page use the **Shadcn Rhea** style preset.

## Installation

This component is available from workspace source. In your application, install the CLI, Shadcn prototypes and target adapter built from the same workspace revision, then initialize the project with that CLI. Run the locally installed CLI to generate the facade.

<InstallCommandCard command="npm exec -- proto-ui add wc shadcn-field" manager="npm" />

Replace `wc` with `react`, `vue`, or `vue2` to generate the local facade for your framework.

You can also import `fieldRoot`, `fieldLabel`, `fieldControl`, `fieldDescription`, `fieldError`, and `fieldValidity` directly from `@proto.ui/prototypes-shadcn/field`.

## Usage

```tsx
import {
  FieldRoot,
  FieldLabel,
  FieldControl,
  FieldDescription,
  FieldError,
} from '@/components/ui/shadcn-field';

export function ProfileField() {
  return (
    <FieldRoot required minLength={3}>
      <FieldLabel>Username</FieldLabel>
      <FieldControl placeholder="Max Leiter" />
      <FieldDescription>Choose a unique username for your account.</FieldDescription>
      <FieldError />
    </FieldRoot>
  );
}
```

### Anatomy

```text
FieldRoot
├── FieldLabel
├── FieldControl | FieldTextarea | FieldSelectTrigger | FieldSwitch | FieldCheckbox | FieldRadioGroup
├── FieldDescription
├── FieldError
└── FieldValidity (optional, repeatable)
```

- **Root**: Manages `invalid`, `pending`, `dirty`, `touched`, `filled`, and `focused` states along with `disabled`, `readOnly`, `required`, `orientation`, and `styleProfile`. Nested roots maintain isolated scopes.
- **Control**: Renders a single-line text editor by default, or pair with `fieldTextarea`, `fieldSelectTrigger`, `fieldSwitch`, `fieldCheckbox`, `fieldRadioGroup`, or custom controls bridged via Base `asFieldControl`.
- **Label**: Automatically wires `aria-labelledby` to the paired control and focuses it on click (disable with `activation={false}`).
- **Description & Error**: Automatically wire and clean up `aria-describedby` and (while invalid) `aria-errormessage`. `Error` unmounts when hidden by default (set `keepMounted` to retain a hidden node).
- **Validity**: Passive reader exposing `getValidity()`.

### Synchronous and asynchronous validation

- **Built-in rules**: Supports `required`, `minLength`, and `maxLength` (UTF-16 code units; optional empty strings skip length checks). Built-in flags are `valueMissing`, `tooShort`, and `tooLong`; external errors use `customError`.
- **Triggers**: `validationMode` supports `'onBlur'` (default), `'onChange'` (waits for IME `compositionend`), and `'manual'`.
- **Async validation**: With `externalValidation={true}`, passing built-in checks emits `validationRequest` (`{ requestId, value, reason }`). Call `resolveValidation(requestId, { invalid, errors })` once complete; stale replies are discarded automatically.
- **Controlled validity**: Pass `invalid` and `errors` to manage validity externally; `validityChange` emits proposed updates. Pair with [Fieldset](../fieldset/) and [Form](../form/) for grouped disabling, submission, and form reset.

### Other parts

- **Control**: `value` / `defaultValue`, `disabled`, `readOnly`, `required`, `placeholder`, `name`, `autoComplete`, `inputMode`, `enterKeyHint`, `ariaLabel`, `styleProfile` (local flags cannot override an active `Root` constraint).
- **Bound controls**: `fieldTextarea`, `fieldSelectTrigger`, `fieldSwitch`, `fieldCheckbox`, and `fieldRadioGroup` inherit their control props and integrate with Field validation and ARIA wiring.
- **Label**: `activation?: boolean` (default `true`), `styleProfile`.
- **Description / Validity**: `styleProfile`.
- **Error**: `message?: string` (explicit localized override), `keepMounted?: boolean` (default `false`), `styleProfile`.

### Methods and events (Root)

- **Methods**: `validate(reason?)`, `resolveValidation(requestId, result)`, `cancelValidation()`, `resetValidation()`, `focusControl(options?)`, `getValidity()`.
- **Events**: `validityChange` (validation snapshot), `validationRequest` (`{ requestId, value, reason }`).

## Usage

Currently available from workspace source; not yet included in the 0.2.0 stable release.

### Anatomy

Compose `Form` from `Root`, `Field`, `Submit`, and `Reset`:

- **Root**: Collects explicitly registered `FormField` parts, validates enabled fields, and emits form values keyed by field name on `submit` once all checks pass. Disabled fields (including those inside a disabled `Fieldset`) are omitted, and duplicate field names are rejected. Setting `disabled` on `Root` disables all contained fields.
- **Field**: Declares the field's `name` and connects it to form submission and reset. Standalone `Checkbox`, `RadioGroup`, and `Switch` controls stay independent unless wrapped with `fieldCheckbox`, `fieldRadioGroup`, or `fieldSwitch`.
- **Submit / Reset**: Styled with the matching button appearance, supporting pointer/keyboard activation and exposing `disabled`, `hovered`, `pressed`, `focused`, `focusVisible`, and `focusSelf`.

### Submission, async validation, and reset

- **Implicit Enter submit**: Pressing `Enter` inside a focused single-line `Field`, `Number Field`, or `Input OTP` submits the form (ignoring IME composition, modifier keys, and key repeat).
- **Async coordination**: Submission waits for active async validation requests and automatically cancels superseded attempts on edits, field removal, cancellation, or a newer submission.
- **Reset**: `requestReset()` (or `Reset`) restores initial values for uncontrolled fields, proposes initial values for controlled fields, cancels pending validation, and emits `reset` without triggering change validation. Use `resetValidation()` to clear errors without modifying values.

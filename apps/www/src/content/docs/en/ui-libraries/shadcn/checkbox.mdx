## Usage

### Anatomy

Compose `Checkbox` from `Root` and `Indicator`:

- **Root**: Manages `checked`, `indeterminate`, `disabled`, `readOnly`, `required`, and focus/activation behavior.
- **Indicator**: Derives its visual state from the nearest `Root` and renders either a checkmark or a dash. `indeterminate` takes precedence over `checked` when both are true.

### Read-only and form integration

- `readOnly={true}` keeps the checkbox focusable while blocking value changes; `disabled={true}` also removes it from the tab order.
- A standalone `Checkbox` does not auto-register with a form. Inside a `FormField`, use `fieldCheckbox` from `@proto.ui/prototypes-shadcn/field` to connect required validation, label/description/error links, and reset (see the [Form choice recipe](../form/)). Calling `resetValue()` proposes the initial baseline without forcing a controlled owner to accept it.
- Provide an accessible name by pairing the checkbox with a [Label](../label/) or adjacent label text.

## API

Passing `checked` or `indeterminate` controls that state independently while allowing the other to remain uncontrolled.

<ApiPropsTable
  headers={{ name: 'Prop', type: 'Type', default: 'Default' }}
  rows={[
    { name: 'checked', type: 'boolean | undefined', default: 'uncontrolled' },
    { name: 'defaultChecked', type: 'boolean', default: 'false' },
    { name: 'indeterminate', type: 'boolean | undefined', default: 'uncontrolled' },
    { name: 'defaultIndeterminate', type: 'boolean', default: 'false' },
    { name: 'disabled', type: 'boolean', default: 'false' },
    { name: 'readOnly', type: 'boolean', default: 'false' },
    { name: 'required', type: 'boolean', default: 'false' },
  ]}
/>

`Root` exposes `checked`, `indeterminate`, `disabled`, `required`, `hovered`, `focused`, `focusVisible`, and `pressed`, plus `checkedChange` and `indeterminateChange`. Updating `required` reflects the required attribute without toggling `checked`.

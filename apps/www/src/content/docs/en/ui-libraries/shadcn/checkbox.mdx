A checkbox supporting unchecked, checked, and `indeterminate` (`mixed`) states with pointer and `Space` activation and full `checkbox` accessibility semantics. The examples on this page use the **Shadcn Rhea** style preset.

## Installation

The stable 0.2.0 CLI has no entry for this component. To reproduce the workspace preview in an application, install the CLI, Shadcn prototypes and target adapter built from the same revision, initialize with that CLI, then generate the facade locally.

<InstallCommandCard command="npm exec -- proto-ui add wc shadcn-checkbox" manager="npm" />

Replace `wc` with `react`, `vue`, or `vue2` to generate the local facade for your framework.

## Usage

```tsx
import {
  ShadcnCheckboxIndicator,
  ShadcnCheckboxRoot,
  ShadcnLabelRoot,
} from '../proto-ui/components/react';

export function Example() {
  return (
    <div className="flex items-center gap-3">
      <ShadcnCheckboxRoot styleProfile="rhea" defaultChecked>
        <ShadcnCheckboxIndicator styleProfile="rhea" />
      </ShadcnCheckboxRoot>
      <ShadcnLabelRoot styleProfile="rhea">Accept terms and conditions</ShadcnLabelRoot>
    </div>
  );
}
```

### Anatomy and keyboard behavior

- **Root**: Manages `checked`, `indeterminate`, `disabled`, `readOnly`, `required`, and focus/activation behavior with pointer clicks and `Space`.
- **Indicator**: Derives its state from the nearest `Root` and renders either a checkmark or a dash. `indeterminate` takes precedence over `checked` (`aria-checked="mixed"`).
- **Read-only and form integration**: `readOnly={true}` keeps the checkbox focusable while blocking changes; `disabled={true}` also removes it from the tab order. For form validation and error messages, use `fieldCheckbox` from `@proto.ui/prototypes-shadcn/field` inside `FormField` or `Field` (see [Form](../form/) and [Checkbox Group](../checkbox-group/)).
- **Label association**: Pair with [Label](../label/) or `shadcnCheckboxLabelComposition` so clicking the visible label text toggles the checkbox.

## API

Passing `checked` or `indeterminate` controls that state independently while allowing the other to remain uncontrolled.

### Root

<ApiPropsTable
  headers={{ name: 'Prop', type: 'Type', default: 'Default' }}
  rows={[
    { name: 'checked', type: 'boolean | undefined', default: 'uncontrolled' },
    { name: 'defaultChecked', type: 'boolean', default: 'false' },
    { name: 'indeterminate', type: 'boolean | undefined', default: 'uncontrolled' },
    { name: 'defaultIndeterminate', type: 'boolean', default: 'false' },
    { name: 'disabled', type: 'boolean', default: 'false' },
    { name: 'readOnly', type: 'boolean', default: 'false' },
    { name: 'required', type: 'boolean', default: 'false' },
    {
      name: 'styleProfile',
      type: "'inherit' | 'new-york-v4' | 'vega' | 'nova' | 'maia' | 'lyra' | 'mira' | 'luma' | 'sera' | 'rhea'",
      default: "'new-york-v4'",
    },
  ]}
/>

`Root` exposes `checked`, `indeterminate`, `disabled`, `readOnly`, `required`, `hovered`, `focused`, `focusVisible`, and `pressed` states, `focusSelf(options?)` and `resetValue()` methods, and `checkedChange` (`{ checked, indeterminate }`) and `indeterminateChange` (`{ indeterminate }`) events.

### Indicator

`Indicator` declares no props of its own. It subscribes to the nearest `Root` context and exposes `checked`, `indeterminate`, `isChecked()`, and `isIndeterminate()`.

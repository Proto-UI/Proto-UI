## Usage

Currently available from workspace source; not yet included in the 0.2.0 stable release.

### Anatomy

Compose `AlertDialog` from `Root`, `Trigger`, `Mask`, `Content`, `Header`, `Footer`, `Title`, `Description`, `Cancel`, and `Action`:

- **Root**: Manages open state with alert-dialog modality always enabled.
- **Mask**: Renders the modal backdrop overlay.
- **Content**: Traps focus inside the dialog, blocks dismissal on outside clicks, and focuses `Cancel` by default when opened. Uses the Shadcn Rhea panel styling (`p-6`, `gap-6`, `radius-4xl` capped at 24px, popover colors, and ring/shadow).
- **Header / Footer / Title / Description**: Structure the heading, accessible description, and action bar.
- **Cancel / Action**: `Cancel` and `Escape` request closing the dialog. `Action` emits an `action` event before requesting close; your application performs the actual operation in the handler. Disabled buttons do not activate.

### Controlled and uncontrolled state

- Use `defaultOpen` for uncontrolled usage.
- Pass `open` to control the dialog externally; listen to `openChange` and provide the next value to `Root`.

## API

Passing `open` selects controlled mode. Unlike `Dialog`, this `Root` has no `alert` prop because alert modality is always active.

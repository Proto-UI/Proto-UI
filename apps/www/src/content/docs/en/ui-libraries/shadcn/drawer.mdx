Rhea Content uses transparent outer padding (`p-4`) around its owned inset popover surface, whose radius is capped at 24px and whose shadow belongs to the public prototype. Header/Footer keep their profile-owned padding. The bottom Handle remains a real resize control: its shared 100px width and 1rem top margin pair with Rhea's 0.375rem height, rather than the old New York 0.5rem height. Non-bottom resize controls are retained. The handle is not yet the upstream bottom-only decorative indicator or full-Content drag surface; accepted extent/side semantics and those remaining interaction differences stay explicit.

The short example uses the upstream demo's centered full-width max-w-sm interior; this is consumer composition, not a width imposed on every Drawer. The historical New York Trigger/Close Button paint (2.25rem default height, 1rem inline padding, optional wrap) remains only in that compatibility profile. Modern Rhea Trigger/Close are headless semantic owners. A shared passive Rhea action body must be composed before this page can claim complete Rhea button presentation; no second Button hook or nested focus owner is added to hide that gap.

Top/bottom Content fits its content by default. Its retained compatibility maximum is the available height minus 6 root-text units, always bounded by the safe available region. This does not implement New York’s viewport-relative max-h-80vh and separate mt-24/mb-24 spacing. Content.minExtent and maxExtent accept neutral lengths with unit logical, root-text, available or available-minus-root-text and a nonnegative finite value. A minimum above the safe cap is clamped. Left/right retain the existing capped 20rem presentation in this vertical-only draft.

The project composes Content as a vertical Scroll surface. The pinned New York DrawerContent wrapper does not itself declare an overflow utility. The long example keeps Close inside the same scrollport.

Root supports controlled open or uncontrolled defaultOpen. Disabled commands do not activate. Controlled close requests can be refused; drag preview then returns to the accepted owner state.

Omitted, null or empty snapPoints selects content-fit mode. A nonempty valid array selects explicit snaps: positive fractions up to one, sorted and deduplicated. snapPoint alone does not enable snapping. Explicit snap fractions use the full capped extent, not an implicit 85% multiplier. defaultSnapPoint is local; snapPoint with snapPointChange is owner-controlled. Invalid vertical point arrays or length records are rejected, not converted to full height.

In content-fit mode Handle is a pointer-only, aria-hidden drag affordance, without keyboard resizing or an Enter/Space close action. Explicit snaps retain the named separator, arrows, Home/End and range values. Content.dragDismissible=false prevents drag dismissal; independent Close, Escape and outside dismissal retain their existing protocol. Interrupted gestures and rejected controlled requests restore the accepted presentation.

Runtime invalid extent updates expose extentValid=false, cancel Handle input and retain the last valid intent while current safety constraints still apply. Initial malformed input is rejected before presentation: Root keeps its logical open value, while Mask waits for one valid Content declaration. These examples use statically validated legal inputs. This draft does not claim arbitrary-input safety or native, compiler, packed-consumer or full Finf acceptance.

## API

Drawer is workspace source. There is no public `proto-ui add` target. Passing `open` selects controlled mode.

<ApiPropsTable
  headers={{ name: 'Prop', type: 'Type', default: 'Default' }}
  rows={[
    { name: 'defaultOpen', type: 'boolean', default: 'false' },
    { name: 'disabled', type: 'boolean', default: 'false' },
    { name: 'a11yLabel', type: 'string', default: "''" },
  ]}
/>

These props belong to Root. Content defaults `side` to `bottom`. Trigger and Close default `disabled` to `false`. Handle defaults `disabled` to `false` and `a11yLabel` to `Resize drawer`. Overlay defaults `passthrough` to `false`. Title, Description, Header, and Footer have no props.

Resizable divides a container into two or more percentage-sized panels with draggable, keyboard-accessible split handles and support for nested split groups. The examples on this page use the **Shadcn Rhea** style preset.

## Usage

Resizable consists of `Root`, `Panel`, and `Handle`:

- `Root` manages panel proportions, orientation, and constraints.
- Place N `Panel` elements (`index: 0..N-1`) and N−1 `Handle` elements (`index: 0..N-2`). Each `Handle` resizes only its two adjacent panels while preserving their combined size and every other panel.
- Each `Panel` exposes its dimensionless size via the `--pui-size` CSS variable for static `flex-basis` layout rules.

### Multi-panel layout and constraints

- Use `sizes` (controlled) or `defaultSizes` (uncontrolled) to pass a complete percentage vector. The two-panel `value` / `defaultValue` API remains available; when `sizes` is supplied, it takes precedence.
- Pass `constraints` to configure per-panel `min` (`0`), `max` (`100`), `collapsible` (`false`), and `collapsedSize` (`0`). Percentages normalize to `100`; infeasible configurations keep the last valid layout and ignore invalid resize requests.
- Collapsing acts as a discrete stop and respects the adjacent panel's `max` limit.

### Interaction and nesting

- Pointer dragging, arrow keys, `Shift` acceleration, `Home`/`End`, and collapse share one constrained resize pipeline. Drag deltas are normalized against total panel extents, excluding fixed handle widths.
- Each `Handle` carries the default accessible name `Resize panels`.
- Nested `Root` groups manage their own ratios, constraints, and orientation independently so horizontal and vertical splits compose cleanly.

### Controlled mode and methods

- Passing `sizes` enables controlled mode: listen to `sizesChange` and `sizesCommit` (payload `{ sizes }`) and pass updated values back to accept changes. Canceled gestures emit no `sizesCommit`.
- Programmatic resizing is available via `requestResize(index, nextSize, commit)` and `requestSizes(nextSizes, commit)`.

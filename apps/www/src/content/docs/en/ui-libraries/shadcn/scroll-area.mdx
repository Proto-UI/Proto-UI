Scroll Area pairs native host scrolling—wheel, touch, keyboard, inertia, and overscroll—with styled custom scrollbar tracks and thumbs. The examples on this page use the **Shadcn Rhea** style preset.

## Installation

The stable 0.2.0 CLI has no entry for this component. To reproduce the workspace preview in an application, install the CLI, Shadcn prototypes and target adapter built from the same revision, initialize with that CLI, then generate the facade locally.

<InstallCommandCard command="npm exec -- proto-ui add wc shadcn-scroll-area" manager="npm" />

Replace `wc` with `react`, `vue`, or `vue2` to generate the facade for your target framework.

## Usage

Import the family from `@proto.ui/prototypes-shadcn/scroll-area`. It consists of four parts: `Root`, `Viewport`, `Scrollbar`, and `Thumb`:

- `Root` provides the outer clipped frame.
- `Viewport` wraps the scrollable content, participates in `Tab` focus, and renders the focus-visible ring.
- `Scrollbar` renders a vertical or horizontal track based on `orientation`.
- `Thumb` tracks scroll progress and supports pointer dragging; it stays outside the tab order and keeps a visible outline in forced-colors mode.

### Scrollbar behavior

- `Viewport` prefers composed custom scrollbars and gracefully falls back to native system scrollbars on hosts that do not support composed chrome.
- When both vertical and horizontal tracks are rendered on the Web, they automatically reserve the lower-right corner intersection transparently—no separate corner element is needed—and release that space if the opposite track is absent or hidden.
- When content does not overflow, `Thumb` hides automatically.

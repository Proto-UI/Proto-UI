Tooltip displays brief supplementary text when a user hovers or focuses a trigger, with shared open/close delay coordination across sibling tooltips in a group. The examples on this page use the **Shadcn Rhea** style preset.

For a local source checkout, use the repository's [pack-only flow](https://github.com/Proto-UI/Proto-UI/blob/main/scripts/release/publish.mjs) and [clean consumer installation](https://github.com/Proto-UI/Proto-UI/blob/main/scripts/release/consumer-smoke-cli.mjs). ## Usage

```tsx
import {
  ShadcnTooltipGroup,
  ShadcnTooltipRoot,
  ShadcnTooltipTrigger,
  ShadcnTooltipContent,
} from '../proto-ui/components/react';

export function Example() {
  return (
    <ShadcnTooltipGroup>
      <ShadcnTooltipRoot>
        <ShadcnTooltipTrigger styleProfile="rhea">Hover</ShadcnTooltipTrigger>
        <ShadcnTooltipContent side="top" styleProfile="rhea">
          Add to library
        </ShadcnTooltipContent>
      </ShadcnTooltipRoot>
    </ShadcnTooltipGroup>
  );
}
```

### Composition

```text
TooltipGroup (optional)
└── TooltipRoot
    ├── TooltipTrigger
    └── TooltipContent
```

- `Group` coordinates timing across sibling tooltips: a cold hover opens after `700ms`, closes after `100ms`, and switches immediately across siblings within the `300ms` skip window so at most one tooltip stays open at once.
- Focusing a `Trigger` via `Tab` opens its tooltip immediately; pressing `Escape` dismisses it while keeping focus on the trigger.
- `Content` renders in a portal and automatically manages `aria-describedby`. Keep content brief and non-interactive; use Popover or a non-modal Dialog for interactive content.

### Tooltip on a Button

When attaching a tooltip to a focusable button, compose `useTooltipTrigger()` directly with `asButton()` on the same prototype rather than nesting a button inside a separate `Trigger` (which would create two `Tab` stops):

```ts
import { definePrototype } from '@proto.ui/core';
import { asButton, type ButtonProps, type ButtonExposes } from '@proto.ui/prototypes-base/button';
import { useTooltipTrigger } from '@proto.ui/prototypes-base/tooltip';

export const tooltipButton = definePrototype<ButtonProps, ButtonExposes>({
  name: 'app-tooltip-button',
  setup() {
    asButton();
    useTooltipTrigger();
  },
});
```

- The button retains its role, accessible name, click behavior, disabled state, and single focus target, while `useTooltipTrigger()` adds hover/focus intent and `aria-describedby`. Disabling Tooltip `Root` suppresses only the tooltip; disabling the button suppresses both.
- To wrap an existing styled button prototype, preserve its static `modules` declaration, call its `setup(def)` followed by `useTooltipTrigger()`, and return its render function.
- When the button lives inside a `ShadowRoot`, use the [same-tree portal recipe](/en/ui-libraries/base/tooltip/#shadowroot) so `aria-describedby` resolves across the shadow boundary.

### Events, States & Methods

- **Root**: Exposes read-only state `open`, event `openChange` (`{ open, reason }`), and methods `openTooltip(reason?)`, `close(reason?)`, `toggle(reason?)`.
- **Trigger**: Exposes read-only states `disabled`, `hovered`, `focused`, `focusVisible`, and method `focusSelf(options?)`.
- **Content**: Exposes read-only state `open` and Transition handles (`transitionState`, `isPresent`, `controls`).

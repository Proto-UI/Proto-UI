## Installation

The complete examples below target the current workspace 0.3 source packages (including the Vue 2.6 Adapter). For the published 0.2.0 release, see [Quick Start](/en/start-here/quick-start/).

When installing from workspace source in an existing app, install the CLI, `@proto.ui/prototypes-shadcn`, and your host Adapter (`@proto.ui/adapter-web-component`, `@proto.ui/adapter-react`, `@proto.ui/adapter-vue`, or `@proto.ui/adapter-vue2`, where Vue 2 requires Vue `>=2.6.0 <2.7`) from the same source revision. See [scripts/release/publish.mjs](https://github.com/Proto-UI/Proto-UI/blob/main/scripts/release/publish.mjs) and [scripts/release/consumer-smoke-cli.mjs](https://github.com/Proto-UI/Proto-UI/blob/main/scripts/release/consumer-smoke-cli.mjs) for the local tarball pack and clean consumer install flow.

Once those packages are installed, run the local CLI in your app directory and keep the generated `proto-ui-style.css` (which provides the layout and positioning rules):

```sh
node node_modules/@proto.ui/cli/bin/proto-ui.js init --yes --no-interactive --prototypes shadcn
node node_modules/@proto.ui/cli/bin/proto-ui.js add wc shadcn-tooltip --no-install --no-interactive
```

Replace `wc` with `react`, `vue`, or `vue2` to generate the facade for your target framework.

## Usage

Tooltip consists of `Group`, `Root`, `Trigger`, and `Content`:

- `Group` coordinates timing across sibling tooltips: a cold hover opens after `700ms`, closes after `100ms`, and opens sibling tooltips immediately within the `300ms` skip window so at most one tooltip stays open at once.
- Focusing a `Trigger` via `Tab` opens its tooltip immediately; pressing `Escape` closes it while keeping focus on the trigger.
- `Content` renders in a portal and automatically links and cleans up `aria-describedby`. Keep tooltip content brief and non-interactive; use Popover or a non-modal Dialog for interactive content.

### Tooltip on a Button

When attaching a tooltip to a focusable button, compose `useTooltipTrigger()` directly with `asButton()` on the same prototype rather than nesting a button inside a separate `Trigger` (which would create two `Tab` stops):

```ts
import { definePrototype } from '@proto.ui/core';
import { asButton, type ButtonProps, type ButtonExposes } from '@proto.ui/prototypes-base/button';
import { useTooltipTrigger } from '@proto.ui/prototypes-base/tooltip';

export const tooltipButton = definePrototype<ButtonProps, ButtonExposes>({
  name: 'app-tooltip-button',
  setup() {
    asButton();
    useTooltipTrigger();
  },
});
```

- The button retains its role, accessible name, click behavior, disabled state, and single focus target, while `useTooltipTrigger()` adds hover/focus intent and `aria-describedby`. Disabling Tooltip `Root` suppresses only the tooltip; disabling the button suppresses both.
- To wrap an existing styled button prototype, preserve its static `modules` declaration, call its `setup(def)` followed by `useTooltipTrigger()`, and return its render function.
- When the button lives inside a `ShadowRoot`, use the [same-tree portal recipe](/en/ui-libraries/base/tooltip/#shadowroot) so `aria-describedby` resolves across the shadow boundary.

## API

Pass `open` on `Root` for controlled mode. `Root` inherits `Group` delays unless overridden:

<ApiPropsTable
  headers={{ name: 'Prop', type: 'Type', default: 'Default' }}
  rows={[
    { name: 'defaultOpen', type: 'boolean', default: 'false' },
    { name: 'disabled', type: 'boolean', default: 'false' },
    { name: 'openDelay', type: 'number', default: '700' },
    { name: 'closeDelay', type: 'number', default: '100' },
    { name: 'skipDelay', type: 'number', default: '300' },
    { name: 'side', type: "'top' | 'right' | 'bottom' | 'left'", default: 'top' },
    { name: 'align', type: "'start' | 'center' | 'end'", default: 'center' },
    { name: 'sideOffset', type: 'number', default: '4' },
    { name: 'alignOffset', type: 'number', default: '0' },
    { name: 'avoidCollisions', type: 'boolean', default: 'true' },
    { name: 'collisionPadding', type: 'number', default: '0' },
  ]}
/>

Prop ownership:

- `defaultOpen` and `disabled` belong to `Root` (`Trigger` also accepts `disabled`).
- `openDelay`, `closeDelay`, and `skipDelay` belong to `Group`.
- `side`, `align`, `sideOffset`, `alignOffset`, `avoidCollisions`, and `collisionPadding` belong to `Content`.

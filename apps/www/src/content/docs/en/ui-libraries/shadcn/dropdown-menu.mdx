## Grouped action composition (draft)

Group and Label provide a live accessible naming relationship; Separator and Shortcut are real passive parts. Shortcut only displays a hint and does not register a global binding. Decorative parts do not enter the action collection or add a press owner. The demo uses a 160px menu, grouped account/resources actions and a disabled API action. The real Invite users submenu is a separately pending protocol slice, not a simulated demo box. Checkbox/radio variants and complete native/GPUI, compiler, packed, visual and independent acceptance remain open.

## Destructive actions (draft)

<PrototypePreviewer demoId="demo-shadcn-dropdown-destructive" initialRuntime="wc" />

Edit/Pencil, Share/Share, Archive/Archive, and Delete/Trash follow the pinned upstream `DropdownMenuWithDestructive` composition. Each glyph uses its real fixed Lucide prototype with `size: 16`; Delete uses `variant: 'destructive'`. The final **Delete (disabled)** row is a local validation extension, separated from the upstream actions. It keeps Base's focusable-disabled behavior and cannot select or close the menu. Destructive interactions retain the destructive foreground with a 10% tint in light mode and a 20% tint in dark mode. Keeping that palette during press is a local feedback extension over the upstream focus recipe.

## Inset actions (draft)

<PrototypePreviewer demoId="demo-shadcn-dropdown-inset" initialRuntime="wc" />

The first group uses the upstream Copy/Cut/Paste action pattern: Copy and Cut have real 16px Lucide glyphs, while Paste uses `inset: true`. Actions explicitly uses `inset: false`. The local **More actions** group adds an inset Label and ordinary Rename Item to show both Label settings without substituting ordinary actions for upstream Checkbox, Radio, or Submenu parts. Item and Label inset default to `false`; `true` adds `pl-7` in this Shadcn recipe.

These are bounded visual recipes over Base behavior. Root, Trigger, Content, Item, Group, Label, and Separator remain real prototypes; the demos add no Web-only event logic. Group/Label naming, item selection, focus navigation, and disabled behavior still belong to Base. The existing My Account example above remains separate.

## Reference and evidence limits

This is an unofficial Proto UI projection. The action arrangements reference the statically inspected [shadcn examples at c2a67849be260701852b0977ba15eb5f3a0ce2a4](https://github.com/shadcn-ui/ui/blob/c2a67849be260701852b0977ba15eb5f3a0ce2a4/apps/v4/registry/bases/base/examples/dropdown-menu-example.tsx), specifically `DropdownMenuWithDestructive` and the bounded action portion of `DropdownMenuWithInset`. The inset example's Checkbox, Radio, and Submenu sections are outside this implementation.

Recipe loading, structure checks, and source-host renderer checks do not establish rendered visual parity. Cross-runtime browser paint, light/dark contrast on the actual Dropdown surface, real input/accessibility, native/GPUI, compiler, packed consumers, and independent acceptance remain incomplete. No screenshot or token assertion from another component supplies that evidence.

Readable recipes: [My Account](https://github.com/Proto-UI/Proto-UI/blob/main/apps/www/src/content/docs/zh-cn/demo-shadcn-dropdown-menu.demo.ts), [destructive actions](https://github.com/Proto-UI/Proto-UI/blob/main/apps/www/src/content/docs/demo-shadcn-dropdown-destructive.demo.ts), and [inset actions](https://github.com/Proto-UI/Proto-UI/blob/main/apps/www/src/content/docs/demo-shadcn-dropdown-inset.demo.ts).

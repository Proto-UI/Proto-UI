Virtual List decouples a complete logical key sequence from physical DOM nodes, creating item views only for the visible window plus overscan so large, variable-height lists stay fast. The examples on this page use the **Shadcn Rhea** style preset.

Currently available from workspace source; not yet included in the 0.2.0 stable release.

## Usage

Virtual List consists of `Root`, `Viewport`, and `Content`:

- The core model tracks `itemKeys`, `overscanItems`, `maxMaterializedItems`, revisions, and generation-bound commits.
- On the Web, `attachWebVirtualList` from `virtual-list/web` connects to the scroll viewport to measure variable item heights, maintain spacers, reuse keyed DOM rows, scroll to specific keys, and dispose listeners.

### Materializer lifecycle

- Each logical list allows one active materializer at a time. `attachWebVirtualList` acquires this lease automatically before creating nodes or listeners; dispose the existing materializer before attaching a replacement.
- Custom non-Web hosts can integrate through `acquireMaterializer(onRetired)` on the model (Web callers using `attachWebVirtualList` do not need to call it separately).
- Unmounting or disposing `Root` retires the active materializer, clears rendered rows and observers, and ignores late callbacks from the retired host. If initial setup fails, the lease is released automatically so mounting can be retried.

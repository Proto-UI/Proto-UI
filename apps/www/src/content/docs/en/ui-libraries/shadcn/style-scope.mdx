Style Scope propagates a Shadcn visual preset (`styleProfile`) through the logical Context tree so descendant components share one appearance without repeating `styleProfile` on every part. Each component keeps its own behavior and state. The examples on this page use the **Shadcn Rhea** style preset.

## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release.

## Usage

Import `styleScope` (or its alias `shadcnStyleScope`) from `@proto.ui/prototypes-shadcn/style-scope` (or the package root) and adapt it with the same Adapter used for its children:

```tsx
import * as React from 'react';
import { createReactAdapter } from '@proto.ui/adapter-react';
import { styleScope } from '@proto.ui/prototypes-shadcn/style-scope';
import { ShadcnCardRoot, ShadcnCardContent } from '@proto.ui/prototypes-shadcn/card';

const adapt = createReactAdapter(React);
const StyleScope = adapt(styleScope);
const Card = adapt(ShadcnCardRoot);
const CardContent = adapt(ShadcnCardContent);

export function ProjectCards() {
  return (
    <StyleScope styleProfile="rhea">
      <Card>
        <CardContent>Inherits Rhea from the outer scope.</CardContent>
      </Card>
      <StyleScope styleProfile="new-york">
        <Card>
          <CardContent>Inherits New York from the nearer scope.</CardContent>
        </Card>
      </StyleScope>
      <Card styleProfile="new-york-v4">
        <CardContent>This explicit Card choice takes precedence.</CardContent>
      </Card>
    </StyleScope>
  );
}
```

Composite `Root` components that publish a style scope (such as `Card`) automatically provide their active preset to their parts and nested Shadcn descendants. Outer layout and spacing remain in your application markup.

### Selection and inheritance

`styleProfile` is optional and defaults to `inherit`. Resolution follows three steps:

1. An explicit `styleProfile` set directly on the component.
2. The nearest ancestor style scope with a concrete selection.
3. The component's own compatibility default.

Changing a component or nested scope back to `inherit` withdraws its override and resumes inheritance. If neither the scope nor any ancestor selects a concrete preset, it publishes `{ style: null }` so each leaf retains its own default.

| Selection | Meaning |
| --- | --- |
| `vega`, `nova`, `maia`, `lyra`, `mira`, `luma`, `sera`, `rhea` | Recognized modern Shadcn style IDs; check each component's documentation for supported presets. |
| `new-york-v4` | Separate New York compatibility preset. |
| `new-york` | Alias automatically normalized to `new-york-v4`. |
| `inherit` or omitted | Inherits from the nearest scope, falling back to the component default. |

### Style isolation and CSS layer order

- Changing `styleProfile` updates visual styles only—it preserves the component instance, state handles, edited value, selection, and focus. Update the prop in place rather than remounting with a new `key`.
- Style Scope is a logical Shadcn Context boundary rather than a CSS reset, Shadow DOM boundary, or global theme store; consumers such as [Input Shell](/en/ui-libraries/shadcn/input-shell/) resolve their style from this channel independently of other families.
- When using named CSS layers, establish the layer order before loading the first relevant stylesheet: generated theme defaults → reset/base → `proto-ui` → explicit consumer layers.

## API

In addition to `styleScope`, `@proto.ui/prototypes-shadcn/style-scope` exports these authoring helpers and types:

| Export | Use |
| --- | --- |
| `setupShadcnStyleScope(def)` | Called during a composite prototype's setup to publish its active selection and inherit from ancestors. |
| `setupShadcnStyleSelection(def, compatibilityStyle, options?)` | Called during a consumer's setup to derive visual state for rules; `options.supportedStyles` restricts the presets that consumer supports. |
| `SHADCN_STYLE_SCOPE` | Singleton Context key carrying `{ style: ShadcnStyleId \| null }` (always import this exact key). |
| `SHADCN_STYLE_IDS` | Canonical list of recognized style IDs, including `new-york-v4`. |
| `normalizeShadcnStyle(value)` | Normalizes known IDs and aliases, returns `null` for `undefined`, `null`, or `inherit`, and throws on unknown IDs. |
| `ShadcnStyleId`, `ShadcnStyleChoice` | Canonical style ID type, and the selectable union including `new-york` and `inherit`. |
| `ShadcnStyleProps`, `ShadcnStyleContext` | Optional `styleProfile` prop shape and Context value shape. |

```ts
import { normalizeShadcnStyle } from '@proto.ui/prototypes-shadcn/style-scope';

const legacy = normalizeShadcnStyle('new-york'); // 'new-york-v4'
const inherited = normalizeShadcnStyle('inherit'); // null
```

When `options.supportedStyles` is set on `setupShadcnStyleSelection`, passing a preset not implemented by that component is rejected instead of silently substituted. Portalled overlays inherit the style scope of their logical owner rather than their physical mount container.

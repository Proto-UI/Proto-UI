Style Scope propagates a Shadcn visual preset (`styleProfile`) through the logical Context tree so descendant components share or switch appearance without repeating `styleProfile` on every part. The default examples on this page use the **Shadcn Rhea** style preset.

## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release. Import the generated `proto-ui-style.css` once at your application entry, then import `styleScope` from `@proto.ui/prototypes-shadcn/style-scope` (or the package root):

```ts
import {
  styleScope,
  SHADCN_STYLE_IDS,
  normalizeShadcnStyle,
} from '@proto.ui/prototypes-shadcn/style-scope';
```

## Usage

Adapt `styleScope` (or its alias `shadcnStyleScope`) with the same Adapter used for its children and wrap the subtree that should share a style preset:

```tsx
import * as React from 'react';
import { createReactAdapter } from '@proto.ui/adapter-react';
import { styleScope } from '@proto.ui/prototypes-shadcn/style-scope';
import { ShadcnCardRoot, ShadcnCardContent } from '@proto.ui/prototypes-shadcn/card';

const adapt = createReactAdapter(React);
const StyleScope = adapt(styleScope);
const Card = adapt(ShadcnCardRoot);
const CardContent = adapt(ShadcnCardContent);

export function ProjectCards() {
  return (
    <StyleScope styleProfile="rhea" className="contents">
      <Card>
        <CardContent>Inherits Rhea from the outer scope.</CardContent>
      </Card>
      <StyleScope styleProfile="new-york" className="contents">
        <Card>
          <CardContent>Inherits New York from the nearer scope.</CardContent>
        </Card>
      </StyleScope>
      <Card styleProfile="new-york-v4">
        <CardContent>This explicit Card choice takes precedence.</CardContent>
      </Card>
    </StyleScope>
  );
}
```

- **Host element and layout neutrality**: `styleScope` emits no host CSS of its own (`display: inline` as a Web Component custom element, wrapper element in framework adapters). Add `class="contents"` (`className="contents"` in React) when placing `StyleScope` inside flex or grid layouts so child flow remains uninterrupted.
- **Composite scopes**: Composite `Root` components that publish a style scope (such as [Card](../card/) and [Select](../select/)) automatically forward their resolved preset to internal parts and nested Shadcn descendants.

## Selection and inheritance

`styleProfile` is optional and defaults to `inherit`. Resolution follows three steps:

1. An explicit `styleProfile` set directly on the component.
2. The nearest ancestor style scope with a concrete selection.
3. The component's own compatibility default.

Changing a component or nested scope back to `inherit` withdraws its override and resumes inheritance. If neither the scope nor any ancestor selects a concrete preset, it publishes `{ style: null }` so each leaf retains its own default.

| Selection | Meaning |
| --- | --- |
| `vega`, `nova`, `maia`, `lyra`, `mira`, `luma`, `sera`, `rhea` | Recognized modern Shadcn style IDs; check each component's supported presets below. |
| `new-york-v4` | Separate New York compatibility preset. |
| `new-york` | Alias automatically normalized to `new-york-v4`. |
| `inherit` or omitted | Inherits from the nearest scope, falling back to the component default. |

### Component preset support

Consumers configured with `options.supportedStyles` reject presets they do not implement instead of silently substituting another style:

| Component | Supported `styleProfile` presets | Fallback when scope is `{ style: null }` |
| --- | --- | --- |
| [Button](../button/) | All 9 presets (`vega`–`rhea`, `new-york-v4`) | `rhea` |
| [Tabs](../tabs/) | All 9 presets (`vega`–`rhea`, `new-york-v4`) | `new-york-v4` |
| [Select](../select/) | All 9 presets (`vega`–`rhea`, `new-york-v4`) | `new-york-v4` |
| [Dialog](../dialog/) | All 9 presets (`vega`–`rhea`, `new-york-v4`) | `new-york-v4` |
| [Input Shell](../input-shell/) | All 9 presets (`vega`–`rhea`, `new-york-v4`) | `new-york-v4` |
| [Card](../card/) | `new-york-v4`, `rhea` | `new-york-v4` |

## Style isolation, lifecycle boundaries, and CSS layer order

- **In-place updates**: Changing `styleProfile` updates visual styles only—it preserves the component instance, state handles, edited value, selection, and keyboard focus. Update the prop in place rather than remounting with a new `key`.
- **Family isolation**: Style Scope is a logical Shadcn Context boundary rather than a CSS reset, Shadow DOM boundary, or global theme store; Shadcn consumers such as [Input Shell](../input-shell/) resolve presets from this channel without affecting other component families.
- **Dynamic ancestry and Portal boundaries**: Style Scope reads ancestry during creation, mount, update, and Context subscription callbacks. Live DOM reparenting across scopes, removing a provider without updating descendants, and logical-owner inheritance across native Portals are still evolving; keep consumers inside a stable logical scope and update `styleProfile` in place.
- **CSS layer order**: When using named CSS layers, establish the layer order before loading the first relevant stylesheet: generated theme defaults → reset/base → `proto-ui` → explicit consumer layers.

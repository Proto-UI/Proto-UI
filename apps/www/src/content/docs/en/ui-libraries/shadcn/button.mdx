## Installation

First [initialize your application](/en/start-here/quick-start/), then add the button component:

<InstallCommandCard
  commands={{
    npm: 'npx @proto.ui/cli@0.2.0 add wc shadcn-button',
    pnpm: 'pnpm dlx @proto.ui/cli@0.2.0 add wc shadcn-button',
  }}
  manager="npm"
/>

Replace `wc` with `react` or `vue` for those hosts. The CLI installs the matching `@proto.ui/prototypes-shadcn` and adapter packages and generates the local facade. Vue 2.6 (`>=2.6.0 <2.7`), the named `styleProfile` presets, the `icon-compact` size, and the `wrap` prop shown below require matching workspace CLI, adapter, and prototype source. The published 0.2.0 CLI supports `wc`, `react`, and `vue`.

## Usage

Each code example includes component registration or imports plus minimal example styles. Import the generated `proto-ui-style.css` once in your application entry point — no extra Tailwind configuration is required:

- **Web Components**: Render the generated `proto-ui-shadcn-button` custom element.
- **React**: Import and render the generated component directly.
- **Vue**: Use the generated single-file component.

### Style presets (`styleProfile`)

The examples on this page explicitly set `styleProfile="rhea"`. Supported presets are `vega`, `nova`, `maia`, `lyra`, `mira`, `luma`, `sera`, `rhea`, and `new-york-v4` (`new-york` is accepted as an alias). When omitted or set to `inherit`, the button reads the nearest [Style Scope](../style-scope/) and falls back to `rhea`.

### Sizes

Choose from `sm`, `default`, `lg`, `icon`, or `icon-compact` (a fixed `1.75rem` square, even when `wrap` is enabled).

For icon-only buttons, include a visually hidden text label (such as “Add”) and hide the decorative icon from the accessibility tree so assistive technologies announce a meaningful name.

## Common patterns

- **Navigation**: Use a native `<a>` element with a real URL and descriptive text, such as [Read Quick Start](/en/start-here/quick-start/):

```html
<a href="/en/start-here/quick-start/">Read Quick Start</a>
```

- **Asynchronous actions**: Track pending state in your application, drive `disabled` while work is in progress, and keep a clear accessible label. Pair with [Async Region](../async-region/) or [Live Region](../live-region/) when announcing progress.
- **Grouping actions**: Use standard layout containers for independent actions, or [Toolbar](../toolbar/) when you want roving arrow-key navigation.

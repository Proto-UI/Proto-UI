A vertically or horizontally stacked set of collapsible content panels with single or multiple expansion, controlled state support, and keyboard navigation aligned with the [WAI-ARIA Accordion Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/). The examples on this page use the **Shadcn Rhea** style preset.

## Installation

This component is available from workspace source. In your application, install the CLI, Shadcn prototypes and target adapter built from the same workspace revision, then initialize the project with that CLI. Run the locally installed CLI to generate the facade.

<InstallCommandCard command="npm exec -- proto-ui add wc shadcn-accordion" manager="npm" />

Replace `wc` with `react`, `vue`, or `vue2` to generate the local facade for your framework.

You can also import `accordionRoot`, `accordionItem`, `accordionHeading`, `accordionTrigger`, and `accordionContent` directly from `@proto.ui/prototypes-shadcn/accordion`.

## Usage

```tsx
import {
  ShadcnAccordionRoot,
  ShadcnAccordionItem,
  ShadcnAccordionHeading,
  ShadcnAccordionTrigger,
  ShadcnAccordionContent,
} from '@/components/proto-ui/react';

export function AccordionUsage() {
  return (
    <ShadcnAccordionRoot defaultOpenItems={['item-1']}>
      <ShadcnAccordionItem value="item-1">
        <ShadcnAccordionHeading level={3}>
          <ShadcnAccordionTrigger>Is it accessible?</ShadcnAccordionTrigger>
        </ShadcnAccordionHeading>
        <ShadcnAccordionContent>
          Yes. It adheres to the WAI-ARIA Accordion design pattern.
        </ShadcnAccordionContent>
      </ShadcnAccordionItem>
    </ShadcnAccordionRoot>
  );
}
```

### Anatomy

```text
AccordionRoot
└── AccordionItem
    ├── AccordionHeading
    │   └── AccordionTrigger
    └── AccordionContent
```

- **Root**: Manages the set of open item keys, expansion mode, and header navigation orientation. Nested `Root` instances keep independent state.
- **Item**: Represents one collapsible section and requires a unique, stable, non-empty `value`.
- **Heading**: Declares the heading level (`1`–`6`, default `3`). Place only the controlling `Trigger` inside `Heading`, and place persistent secondary actions beside it.
- **Trigger**: Derives expanded, disabled, and collapse-blocked state from `Item` and `Root`, managing `aria-expanded`, `aria-disabled`, and `aria-controls`.
- **Content**: Holds the collapsible panel body. Unmounts when closed by default; set `keepMounted` to keep the hidden node mounted and `region` to opt into a landmark region.

### Keyboard and accessibility

- `Tab` / `Shift + Tab`: Follows the natural tab sequence across enabled triggers and focusable elements inside open panels.
- `Enter` / `Space`: Toggles the focused item.
- `ArrowUp` / `ArrowDown` (vertical) or `ArrowLeft` / `ArrowRight` (horizontal, reversed in RTL) plus `Home` / `End`: Moves focus across enabled headers without changing open state. Set `loop={false}` to stop at the endpoints.
- Disabled headers are skipped during arrow-key navigation. When `allowEmpty={false}` prevents collapsing the last open item, its trigger stays focusable with `aria-disabled`.

### Methods and events (Root)

- `getOpenItems()`: Returns a copy of the currently open item keys.
- `openCount`: Number of open keys, including dormant keys awaiting mount.
- `requestOpen(value, open, reason?)`: Programmatically requests an open or close change.
- `openChange`: Emits `{ openItems, value, open, reason }` (`reason` is `'pointer'`, `'keyboard'`, or `'programmatic'`).

A vertically stacked set of collapsible content panels with single or multiple expansion, controlled state support, and keyboard navigation aligned with the [WAI-ARIA Accordion Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/). The examples on this page use the **Shadcn Rhea** style preset.

## Installation

This component is available from workspace source. In your application, install the CLI, Shadcn prototypes and target adapter built from the same workspace revision, then initialize the project with that CLI. Run the locally installed CLI to generate the facade.

<InstallCommandCard command="npm exec -- proto-ui add wc shadcn-accordion" manager="npm" />

Replace `wc` with `react`, `vue`, or `vue2` to generate the local facade for your framework.

You can also import `accordionRoot`, `accordionItem`, `accordionHeading`, `accordionTrigger`, and `accordionContent` directly from `@proto.ui/prototypes-shadcn/accordion`.

## Usage

### Anatomy

Compose `Root` → `Item` → `Heading` → `Trigger`, with `Content` as a sibling of `Heading`:

- **Root**: Manages the set of open item keys and header navigation orientation. Nested `Root` instances keep independent state.
- **Item**: Represents one collapsible section and requires a unique, stable, non-empty `value`.
- **Heading**: Declares the heading level (`1`–`6`, default `3`). Place only the controlling `Trigger` inside `Heading`; place any persistent secondary actions beside it.
- **Trigger**: Derives open and disabled state from `Item` and `Root`, and automatically links to its `Content`.
- **Content**: Holds the collapsible panel content. It unmounts content when closed by default; set `keepMounted` to keep the hidden node in place.

### Controlled and uncontrolled state

- **Uncontrolled**: Pass `defaultOpenItems` to set the initial open keys (read once on mount).
- **Controlled**: Pass `openItems` to manage the open keys externally. When the user interacts, `Root` emits `openChange` with payload `{ openItems, value, open, reason }` (`reason` is `'pointer'`, `'keyboard'`, or `'programmatic'`). Pass the updated `openItems` back to `Root` to commit the change.

Key behaviors:

- Duplicate input keys are deduplicated; `mode="single"` keeps the first unique key.
- Keys without a mounted `Item` stay dormant until that `Item` mounts; calling `requestOpen` for a missing key is ignored.
- In uncontrolled mode, removing an open `Item` retires its key. When `allowEmpty={false}`, the last remaining open item cannot be collapsed.

### Keyboard and accessibility

- `Tab` / `Shift + Tab`: Follows the natural tab sequence across enabled triggers and focusable elements inside open panels.
- `Enter` / `Space`: Toggles the focused item.
- `ArrowUp` / `ArrowDown` (vertical) or `ArrowLeft` / `ArrowRight` (horizontal, reversed in RTL): Moves focus across enabled headers without changing open state. Set `loop={false}` to stop at the first and last headers.
- `Home` / `End`: Moves focus to the first or last enabled header.
- Disabled headers are skipped during arrow-key navigation. When `allowEmpty={false}` prevents collapsing the last open header, it stays focusable with `aria-disabled`.
- `Content` is automatically labelled by its `Trigger`. Set `region={true}` to opt into a landmark region (use selectively when many sections can be open at once).

### Animation and layout

- Pair `keepMounted` with your own CSS or transition logic when animating panel height or opacity.
- Built-in styles wrap long labels, shrink inside narrow containers, and contain horizontal overflow within the panel.

### Other parts

- **Item**: `value: string` (required, unique non-empty key), `disabled?: boolean` (default `false`).
- **Heading**: `level?: 1 | 2 | 3 | 4 | 5 | 6` (default `3`).
- **Trigger**: No props; derives state from `Item` and `Root`.
- **Content**: `keepMounted?: boolean` (default `false`), `region?: boolean` (default `false`).

### Methods and events (Root)

- `getOpenItems()`: Returns a copy of the currently open item keys.
- `openCount`: Number of open keys, including dormant keys awaiting mount.
- `requestOpen(value, open, reason?)`: Programmatically requests an open or close change.
- `openChange`: Emits `{ openItems, value, open, reason }` when a state change is requested.

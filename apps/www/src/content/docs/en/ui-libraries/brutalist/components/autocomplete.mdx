Brutalist Autocomplete follows the Brutalist design contract (5px `rounded-base`, 2px black borders, DM Sans typography, and role-based hard shadows), pairing a single-line text input with a filtered suggestion popup and free-text submission.

## Installation

Currently available from workspace source (`@proto.ui/prototypes-brutalist/autocomplete`); not yet included in the 0.2.0 stable release.

## Usage

```html
<proto-ui-brutalist-autocomplete-root a11y-label="Framework">
  <proto-ui-brutalist-autocomplete-input
    placeholder="Search frameworks…"
  ></proto-ui-brutalist-autocomplete-input>
  <proto-ui-brutalist-autocomplete-trigger>Options</proto-ui-brutalist-autocomplete-trigger>
  <proto-ui-brutalist-autocomplete-content>
    <proto-ui-brutalist-autocomplete-item value="next" text-value="Next.js" keywords="react ssr">
      Next.js
    </proto-ui-brutalist-autocomplete-item>
    <proto-ui-brutalist-autocomplete-item
      value="astro"
      text-value="Astro"
      keywords="islands static"
    >
      Astro
    </proto-ui-brutalist-autocomplete-item>
    <proto-ui-brutalist-autocomplete-empty
      >No matching frameworks.</proto-ui-brutalist-autocomplete-empty
    >
  </proto-ui-brutalist-autocomplete-content>
</proto-ui-brutalist-autocomplete-root>
```

### Parts and behavior

- **Parts**: Compose `Root`, `Input`, `Trigger`, `Content`, `Item`, and `Empty`.
- **Depth and motion**: `Input` stays flat as an editable surface, `Trigger` uses a 4px raised shadow with press-settle feedback, `Content` uses a 3px foreground shadow, and active `Item` rows highlight with `bg-main` / `text-main-foreground`.
- **Filtering and submission**: Built-in filtering folds case and diacritics across `textValue` and `keywords`; set `filter={false}` for external filtering. Pressing `Enter` without an active match commits custom text while IME composition stays safe.

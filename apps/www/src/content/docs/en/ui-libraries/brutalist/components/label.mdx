Brutalist Label pairs explicitly with `Checkbox`, `Switch`, `Radio Group Item`, `Input`, `Textarea`, `Button`, `Toggle`, and `Toggle Group Item` to provide accessible naming and pointer activation without manual DOM IDs.

## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release.

- **CLI target**: `proto-ui add <react|vue|vue2|wc> brutalist-label`
- **Package exports**: import from `@proto.ui/prototypes-brutalist/label`

## Usage

### Independent naming and activation

- **`naming` (default `true`)**: Links the rendered `Label` as the target control's accessible name without duplicating hidden text.
- **`activation` (default `true`)**: Once paired, eligible clicks activate the target control in the same click turn—`Checkbox` and `Switch` follow their controlled/disabled rules, `Radio Item` delegates selection to its group, and `Input` / `Textarea` focus the editor (read-only editors still focus; disabled controls keep their name while ignoring activation). Set `activation={false}` for a naming-only label.
- **`selection` (default `'policy'`)**: Actionable labels suppress accidental text selection by default; set `selection="text"` if the label should remain copyable. Nested links/buttons, modified clicks, and drags are ignored, and unpaired labels never bind implicitly to nearby controls.

### Wiring an explicit association

Create one stable reference per pair with `createControlLabelRef()` from `@proto.ui/core` (one live `Label` and one live target in the same document/shadow root):

- **React / Vue / Vue 2**: Pass `instanceAssociations: { controlLabel: ref }` to both components (handled at the adapter layer, outside ordinary JSON props).
- **Web Components**: Call `setElementAssociations(element, { controlLabel: ref })` from `@proto.ui/adapter-web-component` on both the target control and the `Label`.

If the target already declares a non-empty `ariaLabel` or `labelledBy`, that name takes precedence; set `naming={false}` when you only want pointer activation.

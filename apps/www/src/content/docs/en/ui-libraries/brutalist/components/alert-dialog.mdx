Brutalist AlertDialog interrupts the user for critical or destructive confirmations. It traps focus inside a bold Brutalist panel, prevents outside-click dismissal, and focuses `Cancel` first by default.

## Usage

### Parts

AlertDialog is composed of `Root`, `Trigger`, `Mask`, `Content`, `Header`, `Title`, `Description`, `Footer`, `Cancel`, and `Action`:

- **Root**: Manages `alertdialog` semantics and open state via controlled `open` or uncontrolled `defaultOpen`.
- **Mask**: Modal backdrop that blocks outside-click dismissal.
- **Content**: Raised 5px-radius panel with 24px padding that traps focus and focuses `Cancel` when available.
- **Header / Footer**: Optional layout containers for the heading stack and right-aligned action buttons (which reverse-wrap cleanly when space is tight).
- **Cancel / Action**: `Cancel` and `Escape` request dismissal; `Action` emits `action` before requesting close so your application performs the confirmed operation.

### Controlled and uncontrolled state

- **Uncontrolled**: Use `defaultOpen` to initialize the dialog state.
- **Controlled**: Pass `open` and listen to `openChange` to commit state updates. Disabled commands do not activate.

Pass `open: boolean` to enable controlled mode.

### Other parts

- **Mask**: `passthrough?: boolean` (default `false`) and Transition props
- **Content**: Transition props
- **Trigger / Header / Title / Description / Footer / Cancel / Action**: No props

## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release.

- **Package exports**: import `fieldRoot`, `fieldLabel`, `fieldControl`, `fieldDescription`, `fieldError`, and `fieldValidity` from `@proto.ui/prototypes-brutalist/field`

## Usage

### Parts

- **Root**: Manages validation state (`invalid`, `errors`), `dirty`, `touched`, and effective `disabled`/`readOnly`/`required` policy. Contains one `Control`, optional `Label`, `Description`, and `Error`, plus any number of read-only `Validity` readers. Nested roots operate independently.
- **Control**: Hosts the value and text input. Custom value-bearing controls can integrate via Base's `asFieldControl` bridge and `asControlLabel().target(..., FIELD_LABEL_PAIR)` for label click focusing.
- **Label**: Names the control and focuses it on pointer activation when `activation` is enabled, ignoring drags, modified clicks, and nested interactive elements.
- **Description**: Optional selectable help text.
- **Error**: Displays `message` when provided, otherwise the active `errors` strings or a built-in English fallback. Unmounts content when closed by default (set `keepMounted` to keep it mounted while hidden).
- **Validity**: Passive status reader exposing `getValidity()`.

### Built-in validation and controlled state

- `validationMode` supports `'onBlur'` (default), `'onChange'` (waits until `compositionend` during IME input), and `'manual'`.
- Built-in checks cover `required`, `minLength`, and `maxLength` (measured in UTF-16 code units; optional empty strings skip length checks). `required` treats `null`, `false`, `""`, and empty arrays as empty, while `0` and whitespace strings count as filled without implicit trimming. Built-in flags are `valueMissing`, `tooShort`, and `tooLong`; external errors set `customError`.
- Pass `invalid` to control validation externally: completed checks emit `validityChange` so the owner can update `invalid` and `errors`.
- `resetValidation()` clears validation state and `touched` without resetting the field value or dirty baseline. Pair with `Form` when you need submission or full form reset.

### Async external validation

When `externalValidation` is `true`, passing built-in checks emits `validationRequest` with `{ requestId, value, reason }`. Resolve it by calling `resolveValidation(requestId, { invalid, errors })`. Stale results are automatically ignored if the value, control, or policy changes or a newer request starts.

### Accessibility

- Label, description, and error associations are wired automatically and cleaned up on unmount without manual DOM IDs; `aria-errormessage` is linked only while `invalid` is `true`.
- Web hosts sync `aria-required`, `aria-invalid`, `aria-busy`, and `aria-readonly`. `Error` does not create an implicit live region; combine with `LiveRegion` when live announcements are needed.

### Other parts

- **Label**: `activation?: boolean` (default `true`)
- **Description**: No props
- **Error**: `message?: string` (default `''`), `keepMounted?: boolean` (default `false`)
- **Validity**: No props

### Methods and events

- **Root methods**: `validate(reason?)`, `resolveValidation(requestId, result)`, `cancelValidation()`, `resetValidation()`, `focusControl(options?)`, `getValidity()`
- **Events**: `validityChange` (emits validation status and snapshot), `validationRequest` (payload `{ requestId, value, reason }`)

Brutalist Field pairs a form control with its label, description, error message, and validation state, supporting vertical and horizontal layouts, built-in constraints, and async external validation with 5px corners (`rounded-base`), 2px borders, and DM Sans typography.

## Installation

Currently available from workspace source. Import core parts and bound controls from `@proto.ui/prototypes-brutalist/field`:

```ts
import {
  fieldRoot,
  fieldLabel,
  fieldControl,
  fieldDescription,
  fieldError,
  fieldValidity,
  fieldTextarea,
  fieldCheckbox,
  fieldRadioGroup,
  fieldSwitch,
} from '@proto.ui/prototypes-brutalist/field';
```

## Usage

```tsx
import {
  FieldRoot,
  FieldLabel,
  FieldControl,
  FieldDescription,
  FieldError,
} from '@proto.ui/prototypes-brutalist/field';

export function ProfileField() {
  return (
    <FieldRoot required>
      <FieldLabel>Name</FieldLabel>
      <FieldControl placeholder="Jane Doe" />
      <FieldDescription>Displayed on your public profile.</FieldDescription>
      <FieldError />
    </FieldRoot>
  );
}
```

### Parts and validation

- **Root**: Manages validation state (`invalid`, `errors`), `dirty`, `touched`, `orientation` (`vertical` / `horizontal`), and effective `disabled`/`readOnly`/`required` policy. Nested roots operate independently.
- **Control & bound controls**: Defaults to a single-line text editor, or compose with `fieldTextarea`, `fieldCheckbox`, `fieldRadioGroup`, `fieldSwitch`, or custom controls bridged through Base `asFieldControl`.
- **Automatic accessibility**: Automatically links and cleans up `aria-labelledby`, `aria-describedby`, and (while invalid) `aria-errormessage` without manual DOM IDs.
- **Validation**: Supports `required`, `minLength`, `maxLength`, `validationMode` (`'onBlur'` / `'onChange'` / `'manual'`), controlled `invalid`, and `externalValidation`.

### Other parts, methods & events

- **Label**: `activation?: boolean` (default `true`)
- **Error**: `message?: string` (default `''`), `keepMounted?: boolean` (default `false`)
- **Description / Validity**: No additional props
- **Root methods**: `validate(reason?)`, `resolveValidation(requestId, result)`, `cancelValidation()`, `resetValidation()`, `focusControl(options?)`, `getValidity()`
- **Events**: `validityChange`, `validationRequest` (`{ requestId, value, reason }`)

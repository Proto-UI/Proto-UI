The Brutalist visual system follows [neobrutalism.dev](https://www.neobrutalism.dev/), pinned to [neobrutalism-components (`3306a802724874a85f93079702b2795370a279d4`)](https://github.com/ekmas/neobrutalism-components/tree/3306a802724874a85f93079702b2795370a279d4) under its MIT license. Proto UI maintains its own semantic implementation built on Base.

## Typography

The reference palette uses DM Sans by default rather than universal monospace or forced uppercase. Components bind their font roles through generated style tokens:

- Controls, menu items, descriptions, and body copy: `font-sans font-medium` (DM Sans 500)
- Dialog titles, Tabs triggers, and Toggle: `font-heading font-bold` (DM Sans 700)
- Common type scale: default labels at 14px/20px, Badge at 12px/16px, and Dialog titles at 18px with unit line-height and tight tracking
- Authored casing is preserved; code snippets and keyboard hints can use a monospace role

The package theme sets `--pui-font-sans` and `--pui-font-heading` to `"DM Sans", ui-sans-serif, system-ui, sans-serif`. This documentation site self-hosts the unmodified variable DM Sans font under its [copyright and SIL OFL 1.1 license](/fonts/dm-sans-OFL.txt). Prototypes never make network font requests; applications load DM Sans themselves and fall back cleanly to system sans-serif and host CJK fonts when absent.

## Geometry and nested surfaces

- Standard controls and panels: 5px `rounded-base` corners with a 2px black border
- Switch track/thumb and Scroll Area thumb: pill or circular geometry; Checkbox remains square
- Tabs List and nested Tabs Trigger each keep their own corner radius, separated by inset padding
- Card Header, Content, Footer, and Tabs Content do not add extra inner borders by default
- Scroll Area Root applies rounded overflow clipping while the viewport stays square and the host controls scrollbar geometry
- Spinner keeps a centered circular open ring

Rounded corners are an intentional part of this design language. Avoid overriding everything to sharp corners or wrapping every inner region in another bordered box.

## Depth and motion

Brutalist assigns shadow depth and press behavior by component category rather than applying one uniform shadow or lift rule:

| Category (components) | Rest depth | Hover / press feedback |
| --- | --- | --- |
| Elevated action control — Button, raised Surface, Dialog / Dropdown / Select / Collapsible Trigger, Accordion Item | 4px 4px hard black shadow | Translates `+4px, +4px` along the shadow axis and removes the outer shadow on press; no extra hover lift |
| Raised panel — Card, Dialog / Alert Dialog / Command Dialog / Drawer Content, Calendar | 4px 4px hard black shadow | Static surface with no press displacement |
| Anchored content panel — Dropdown / Context / Menubar / Navigation Menu Content, Autocomplete / Combobox / Select Content, Popover | 3px 3px hard foreground shadow | No hover or press motion; positioned by the overlay |
| Anchored content exception — Hover Card Content | No hard shadow | Keeps its 200ms enter/leave transition and overlay positioning |
| Flat selection control — Toggle, Tabs Trigger | No shadow, no offset | Toggle keeps `border-black` on hover/press and preserves its 2px inset active frame while pressed; unselected Tabs Trigger gains hover fill and border while selected triggers keep their color pair |
| Binary capsule control — Switch | No shadow on Root or Thumb | No hover shift; press keeps fill and geometry while the Thumb slides 20px with a 150ms transition |
| Editable surface — Input, Textarea, Number Field, Input OTP | Input / Textarea: no shadow; Number Field / Input OTP controls: 2px 2px border-colored shadow | No lift or press sink; displays focus ring and state styling |
| Passive label — Badge, Text, Label, Kbd | No shadow | No interaction motion |
| Loading placeholder — Skeleton | No shadow | Static placeholder with no pulse animation |
| Scroll chrome and Separator — Scroll Area parts, Separator | No shadow | No interaction motion; Root preserves rounded overflow clipping |
| Flat overlay — Dialog Mask | No shadow | 150ms fade on open and close |
| Flat interactive item — Dropdown / Context / Menubar / Select Item | No shadow | Background color change only, no lift or shadow change |

Grouping surfaces (Toolbar Root, Toggle Group Root, Toast Root) keep a 3px 3px foreground shadow as passive containers without press displacement.

Button-like controls use an instant press snap; Switch handles its 150ms Thumb transition independently. Toggle keeps its 2px inset active marker through press so active state never relies on color alone.

## Palette and dark mode

The default palette follows the reference blue theme: `#5294ff` primary fill, `#dcebfe` pale blue background, white neutral surfaces, and black text and borders. Built-in `canary`, `mint`, `lavender`, `coral`, and `sky` accent pairs are also available, each paired with black foreground ink.

Because the upstream style registry does not define a dark palette, Proto UI maintains a companion dark theme with dark surfaces, light body text, readable destructive ink, and theme-relative focus rings. Mounted components repaint directly from CSS variables; always update fill and foreground pairs together when customizing the theme.

## Delivery and accessibility

- **Theme tokens**: `BRUTALIST_THEME` defines Light/Dark colors, font roles, and corner radii. Run `proto-ui init --prototypes brutalist` to scaffold them into a project. When using `--no-styles`, provide the semantic variables and font loading yourself.
- **Focus and contrast**: Interactive controls render an offset focus ring with at least 3:1 contrast against adjacent colors. Tabs Content preserves native focus indication, and portaled overlays inherit theme and font variables automatically.
- **Readability details**: Select placeholders on the primary blue fill use black foreground ink to maintain at least 4.5:1 contrast in both light and dark modes. Textarea uses a theme-foreground border so the editable boundary keeps at least 3:1 contrast against adjacent surfaces in both themes.
- **License attribution**: Adapted visual recipes retain the upstream MIT copyright notice (Samuel Breznjak); redistributed DM Sans font files retain their SIL OFL 1.1 license.

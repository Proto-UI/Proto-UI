## Usage

### Parts

ContextMenu consists of `Root`, `Trigger`, `Content`, and `Item`:

- **Root**: Manages open state (`open` / `defaultOpen`), `disabled`, `closeOnItemCommit`, and initial focus entry.
- **Trigger**: Defines the context region. Opens on right-click, 600ms touch/pen hold within movement tolerance, or `ContextMenu` / `Shift+F10` while suppressing the native context menu. Regular left-clicks and scrolling behave normally.
- **Content**: Anchored menu panel positioned at the pointer location for right-click/long-press, or at the trigger region for keyboard triggers and programmatic `openContextMenu()`. Supports arrow navigation, typeahead, transitions, and collision avoidance.
- **Item**: Individual menu action supporting `disabled`, `value`, `textValue`, and `closeOnCommit`.

### Focus and controlled state

- Pressing `Escape` or committing an item closes the menu and restores focus to the trigger.
- Pass `open` for controlled mode: handled context triggers still prevent the native context menu while letting your application decide when to set `open={true}`.

Pass `open: boolean` to enable controlled mode.

### Other parts

- **Trigger**: No props
- **Content**: Supports Transition props, plus `side` (default `'bottom'`), `align` (default `'start'`), `sideOffset` (default `0`), `alignOffset` (default `0`), `avoidCollisions` (default `true`), `collisionPadding` (default `0`), and `excludeAnchorTranslation` (default `false`)
- **Item**: `disabled?: boolean` (default `false`), `value?: string` (default `''`), `textValue?: string` (default `''`), `closeOnCommit?: boolean` (inherits Root's `closeOnItemCommit` when omitted)

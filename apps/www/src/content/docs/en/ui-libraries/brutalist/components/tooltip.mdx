Tooltip displays concise contextual descriptions on hover or keyboard focus using anchored portal positioning, `Escape` dismissal, and automatic `aria-describedby` / `role="tooltip"` wiring. Brutalist styles `Content` as a 5px rounded neutral surface with a theme-adaptive 2px foreground border across Light and Dark modes.

## Installation

Use `@proto.ui/prototypes-brutalist/tooltip` and your host adapter from the same workspace revision. The React example adapts the exported prototypes directly with `@proto.ui/adapter-react`.

Initialize the Brutalist style sheet with the matching local CLI and import the generated `proto-ui-style.css` in the application entry.

## Usage

```tsx
import * as React from 'react';
import { createReactAdapter } from '@proto.ui/adapter-react';
import * as proto from '@proto.ui/prototypes-brutalist/tooltip';

const adapt = createReactAdapter(React);
const BrutalistTooltipGroup = adapt(proto.BrutalistTooltipGroup);
const BrutalistTooltipRoot = adapt(proto.BrutalistTooltipRoot);
const BrutalistTooltipTrigger = adapt(proto.BrutalistTooltipTrigger);
const BrutalistTooltipContent = adapt(proto.BrutalistTooltipContent);

export function Example() {
  return (
    <BrutalistTooltipGroup>
      <BrutalistTooltipRoot>
        <BrutalistTooltipTrigger>Hover</BrutalistTooltipTrigger>
        <BrutalistTooltipContent side="top">Add to library</BrutalistTooltipContent>
      </BrutalistTooltipRoot>
    </BrutalistTooltipGroup>
  );
}
```

### Composition

```text
TooltipGroup (optional)
└── TooltipRoot
    ├── TooltipTrigger
    └── TooltipContent
```

- `Group`: Shares delay defaults, warm-window skip timing, and active-tooltip coordination across sibling tooltips.
- `Root`: Manages controlled or uncontrolled open state and per-tooltip delay overrides.
- `Trigger`: Transparent trigger host that routes hover/focus events and manages `aria-describedby`.
- `Content`: Renders the 5px rounded neutral surface in a portal with theme-adaptive foreground border, anchored positioning, and `Escape` dismissal.

### Composing Tooltip on a Button

Keep a focusable button and its tooltip trigger on a single element rather than nesting a button inside a standalone `Trigger` (which creates two `Tab` stops). Compose `useTooltipTrigger()` alongside `asButton()`, then place the adapted button inside Tooltip `Root` next to `Content`:

```ts
import { definePrototype } from '@proto.ui/core';
import { asButton, type ButtonProps, type ButtonExposes } from '@proto.ui/prototypes-base/button';
import { useTooltipTrigger } from '@proto.ui/prototypes-base/tooltip';

export const tooltipButton = definePrototype<ButtonProps, ButtonExposes>({
  name: 'app-tooltip-button',
  setup() {
    asButton();
    useTooltipTrigger();
  },
});
```

- Button keeps its role, accessible name, click signal, disabled state, and single focus target; `useTooltipTrigger()` adds hover/focus intent and `aria-describedby`.
- Disabling Tooltip `Root` suppresses only the tooltip while keeping the button interactive; disabling the button suppresses both.
- When the button lives inside a `ShadowRoot`, use the [same-tree portal recipe](/en/ui-libraries/base/tooltip/#shadowroot).

### Events, States & Methods

- **Root**: Exposes read-only state `open`, event `openChange` (`{ open, reason }`), and methods `openTooltip(reason?)`, `close(reason?)`, `toggle(reason?)`.
- **Trigger**: Exposes read-only states `disabled`, `hovered`, `focused`, `focusVisible`, and method `focusSelf(options?)`.
- **Content**: Exposes read-only state `open` and Transition handles (`transitionState`, `isPresent`, `controls`).

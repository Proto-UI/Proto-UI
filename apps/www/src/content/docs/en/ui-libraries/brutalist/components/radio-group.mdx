Radio Group lets users choose one option from a mutually exclusive set. Its Brutalist presentation lays out 16px circular 2px-bordered options in a vertical grid (`grid gap-2`), marking the checked option with a single filled inner dot and an offset focus ring.

## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release. Import `Root`, `Item`, and `Indicator` from `@proto.ui/prototypes-brutalist` or `@proto.ui/prototypes-brutalist/radio-group` (workspace CLI target: `brutalist-radio-group`).

## Usage

### Anatomy

Radio Group is composed of `Root`, `Item`, and `Indicator`:

- `Root`: Manages the selected value, item ordering, roving focus, disabled/read-only state, and `radiogroup` accessibility semantics.
- `Item`: Renders each `radio` option with `aria-checked`, pointer/keyboard activation, and a constant resting circle surface.
- `Indicator`: Renders a single `size-2` filled circular dot (`aria-hidden`) when its parent `Item` is checked.

### Keyboard & Read-Only Behavior

- Arrow keys move roving focus across enabled items and select options; initial roving focus targets the checked item or the first enabled option.
- Setting `readOnly` keeps roving focus active while blocking value updates, whereas `disabled` removes focus participation as well.

### Form Composition

A standalone `Root` does not auto-register with Field or Form. To wire up required validation, label/description/error linkage, and reset support, compose `fieldRadioGroup` from `@proto.ui/prototypes-brutalist/field` inside `FormField`. See the [Form choice recipe](../../form/) for a full example. Calling `resetValue()` restores the initial creation value (or emits a change request in controlled mode).

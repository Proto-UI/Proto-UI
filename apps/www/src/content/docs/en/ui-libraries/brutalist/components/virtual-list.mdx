## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release. Import the prototypes from `@proto.ui/prototypes-brutalist/virtual-list` and mount Web rows through the `virtual-list/web` entry.

## Usage

### Logical Model & Web Materialization

- The host-neutral model manages `itemKeys`, `overscanItems`, `maxMaterializedItems`, revisions, and generation-bound commits.
- `attachWebVirtualList` from `virtual-list/web` measures variable item heights, manages spacers and keyed DOM row views, scrolls to a target key, and cleans up observers on disposal.

### Materializer Lifecycle

- Each logical collection grants one active materializer lease at a time. `attachWebVirtualList` acquires that lease automatically (other host implementations can call `acquireMaterializer(onRetired)` directly; Web callers do not need an extra outer lease).
- Attaching a second host while one is active fails without disturbing the current host—dispose the existing host before attaching a replacement.
- Unmounting or disposing `Root` retires the materializer, invalidates in-flight generations, and cleans up views and observers so late callbacks from an old host cannot affect a replacement. Initial render or observer setup failures also release the lease so you can retry cleanly.

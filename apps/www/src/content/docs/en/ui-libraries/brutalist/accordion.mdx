## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release.

- **CLI target**: `proto-ui add <react|vue|vue2|wc> brutalist-accordion`
- **Package exports**: import `accordionRoot`, `accordionItem`, `accordionHeading`, `accordionTrigger`, and `accordionContent` from `@proto.ui/prototypes-brutalist/accordion`

## Usage

### Parts

Compose `Root -> Item -> Heading -> Trigger`, with `Content` alongside `Heading` inside each `Item`:

- **Root**: Manages the set of open item keys, expansion mode, disabled state, and header navigation settings. Nested roots operate independently.
- **Item**: Wraps a single section and requires a unique, non-empty `value`.
- **Heading**: Provides the semantic heading level (`level` 1–6, default `3`). Place only the controlling `Trigger` inside `Heading`, and put persistent secondary actions alongside it.
- **Trigger**: Toggles its parent item on click or keyboard activation. Accepts no props of its own.
- **Content**: Renders the collapsible panel body. Unmounts content when closed by default (set `keepMounted` to keep it mounted while hidden).

### Controlled and uncontrolled state

- **Uncontrolled**: Pass `defaultOpenItems` to initialize open sections once.
- **Controlled**: Pass `openItems` and listen to `openChange` with payload `{ openItems, value, open, reason }` to update state. `reason` is `'pointer'`, `'keyboard'`, or `'programmatic'`.
- **Edge cases**: `mode="single"` keeps the first unique key supplied. Setting `allowEmpty={false}` prevents collapsing the last open section. Keys for items that mount later stay dormant until those items register.

### Keyboard and accessibility

- Enabled triggers and focusable elements inside open panels stay in the natural `Tab` order.
- Pressing `Enter` or `Space` on a trigger toggles its section.
- `ArrowUp` / `ArrowDown` (or `ArrowLeft` / `ArrowRight` when `orientation="horizontal"`, reversed in RTL) moves focus between enabled triggers, and `Home` / `End` jumps to the first or last trigger without changing open state.
- `Trigger` manages `aria-expanded`, `aria-disabled`, and `aria-controls`; `Content` is labelled by its trigger and can opt into a landmark region with `region={true}`.

### Other parts

- **Item**: `value: string` (required, unique, non-empty), `disabled?: boolean` (default `false`)
- **Heading**: `level?: 1 | 2 | 3 | 4 | 5 | 6` (default `3`)
- **Trigger**: No props
- **Content**: `keepMounted?: boolean` (default `false`), `region?: boolean` (default `false`)

### Methods and events

- **Methods**: `getOpenItems()` returns a copy of the open keys array; `requestOpen(value, open, reason?)` requests an open state change; `openCount` reports the count of open keys.
- **Events**: `openChange` emits `{ openItems, value, open, reason }` when a state change is requested.

Brutalist Accordion organizes collapsible sections with single or multiple open panels, combining Base Accordion semantics with 5px base corners, 2px borders, and theme-aware 4px hard offset shadows.

## Installation

<InstallCommandCard command="npx @proto.ui/cli@latest add wc brutalist-accordion" manager="npm" />

Replace `wc` with `react`, `vue`, or `vue2` to generate local facades, or import the five prototypes directly from `@proto.ui/prototypes-brutalist/accordion`.

## Usage

```tsx
import {
  BrutalistAccordionRoot,
  BrutalistAccordionItem,
  BrutalistAccordionHeading,
  BrutalistAccordionTrigger,
  BrutalistAccordionContent,
} from '@/components/proto-ui/react';

export function BrutalistAccordionUsage() {
  return (
    <BrutalistAccordionRoot defaultOpenItems={['item-1']}>
      <BrutalistAccordionItem value="item-1">
        <BrutalistAccordionHeading level={3}>
          <BrutalistAccordionTrigger>Is it accessible?</BrutalistAccordionTrigger>
        </BrutalistAccordionHeading>
        <BrutalistAccordionContent>
          Yes. It adheres to the WAI-ARIA design pattern.
        </BrutalistAccordionContent>
      </BrutalistAccordionItem>
    </BrutalistAccordionRoot>
  );
}
```

### Anatomy

```text
AccordionRoot
└── AccordionItem
    ├── AccordionHeading
    │   └── AccordionTrigger
    └── AccordionContent
```

- **Root**: Manages open item keys, expansion mode, disabled state, and header navigation orientation. Nested roots stay independent.
- **Item**: Wraps one collapsible section with `rounded-base` geometry, 2px borders, and a theme-aware 4px hard offset shadow. Requires a unique non-empty `value`.
- **Heading**: Sets the semantic heading level (`1`–`6`, default `3`) and wraps only its controlling `Trigger`.
- **Trigger**: Renders the bold `font-heading` main-accent bar with an inset high-visibility focus ring, press-frame feedback, and expanded bottom divider.
- **Content**: Renders body copy on `bg-secondary-background` using `font-sans font-medium`. Unmounts when closed unless `keepMounted` is enabled.

### Keyboard and accessibility

- Enabled triggers and focusable elements inside open panels stay in the natural `Tab` order; `Enter` and `Space` toggle the focused section.
- `ArrowUp` / `ArrowDown` (or `ArrowLeft` / `ArrowRight` when `orientation="horizontal"`, reversed in RTL) and `Home` / `End` move focus between enabled headers without changing open state.
- `Trigger` manages `aria-expanded`, `aria-disabled`, and `aria-controls`; when `allowEmpty={false}` blocks closing the last open section, the header stays focusable with `aria-disabled`.

### Methods and events (Root)

- **Methods**: `getOpenItems()` returns a copy of the open keys array; `requestOpen(value, open, reason?)` requests an open state change; `openCount` reports the count of open keys.
- **Events**: `openChange` emits `{ openItems, value, open, reason }` when a state change is requested.

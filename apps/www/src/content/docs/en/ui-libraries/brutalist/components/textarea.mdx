## Installation

Included in `@proto.ui/prototypes-brutalist@0.2.0`. Add it via the CLI target `brutalist-textarea`, or import directly from `@proto.ui/prototypes-brutalist/textarea`.

## Usage

### Input Behavior & Styling

- **Native editing semantics**: Supports controlled (`value`) and uncontrolled (`defaultValue`) modes, normalized `valueChange` and `change` events, IME composition-safe controlled value restoration, `focus()` and `blur()` methods, and accessible naming via `ariaLabel`, `labelledBy`, and `describedBy`.
- **Visual details**: Ships with an 80px minimum height, 12px horizontal / 8px vertical padding, `text-sm` line height, DM Sans 500 typography, and static accent text selection. Native resizing remains browser- or CSS-controlled without automatic height measurement.

### Reset & Form Composition

- In current workspace source, `resetValue()` restores the creation-time value in uncontrolled mode (or proposes it in controlled mode), remains callable while `readOnly` or `disabled`, and retires any active IME composition.
- To wire up Form labels, descriptions, error messages, and validation, import `fieldTextarea` from `@proto.ui/prototypes-brutalist/field`. See the [Form recipe](../../form/) for a full example.

Base Field pairs a single form control with its `Label`, `Description`, `Error`, and `Validity` readers, automatically managing ARIA relationships along with built-in and versioned asynchronous validation.

## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release. Import `fieldRoot`, `fieldLabel`, `fieldControl`, `fieldDescription`, `fieldError`, `fieldValidity`, and the `asFieldControl` / `asFieldTextControl` bridges from `@proto.ui/prototypes-base/field`.

## Usage

### Anatomy

Each `Root` groups one `Control` with an optional `Label`, `Description`, `Error`, and any number of passive `Validity` readers (nested `Root` instances stay isolated):

- **`Root`**: manages validation and interaction states (`invalid`, `pending`, `dirty`, `touched`, `filled`, `focused`, `disabled`, `readOnly`, `required`) and exposes `validate(reason?)`, `resolveValidation(requestId, result)`, `cancelValidation()`, `resetValidation()`, `focusControl(options?)`, and `getValidity()`.
- **`Control`**: renders a single-line text input by default, or use `asFieldControl` to integrate custom controls (such as checkboxes or radio groups) with field validation and label focus.
- **`Label`**: links `aria-labelledby` to the control and focuses it on pointer activation when `activation={true}` (default).
- **`Description`**: passive help text linked via `aria-describedby`.
- **`Error`**: links via `aria-errormessage` when invalid, rendering explicit `message`, current `errors`, or a fallback message. Unmounts content when closed by default (set `keepMounted` to keep it mounted and hidden). Compose a `LiveRegion` when spoken announcements are needed.
- **`Validity`**: passive reader exposing the current `getValidity()` snapshot.

### Built-in and async validation

- Built-in constraints support `required`, `minLength`, and `maxLength` (measured in UTF-16 code units), triggered according to `validationMode` (`'onBlur'`, `'onChange'`, or `'manual'`). `'onChange'` waits until IME composition ends (`compositionend`).
- `required` treats `null`, `false`, `''`, and empty arrays as empty (`0` and whitespace count as filled with no implicit trimming). Empty optional strings bypass length bounds.
- With `externalValidation={true}`, passing built-in checks emits `validationRequest` with `{ requestId, value, reason }`. Resolve it via `resolveValidation(requestId, { invalid, errors })`; stale results from changed values, newer requests, resets, or policy switches are ignored automatically.
- Pass `invalid` / `errors` for controlled validation: `validityChange` notifies your application so you can supply updated props. `resetValidation()` clears validation and `touched` without altering the control value or `dirty` baseline.

### Accessibility

Field automatically links and cleans up `aria-labelledby`, `aria-describedby`, `aria-errormessage`, `aria-required`, `aria-invalid`, `aria-busy`, and `aria-readonly` without requiring manual DOM IDs.

### Other parts

- **Label**: `activation` defaults to `true`.
- **Control**: accepts text input props: `value` / `defaultValue`, `placeholder`, `name`, `autoComplete`, and `ariaLabel` default to `''`; `disabled`, `readOnly`, and `required` default to `false`; optional `inputMode` and `enterKeyHint`.
- **Error**: `message` defaults to `''` and `keepMounted` to `false`.
- **Description, Validity**: no props.

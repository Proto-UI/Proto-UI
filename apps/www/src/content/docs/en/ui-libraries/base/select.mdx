`base-select` is a cataloged select-only compound prototype and the first Base family to formally define a value-class presentation part.

It follows the APG select-only combobox pattern: Trigger projects `combobox`, Content projects `listbox`, and Item projects `option`. The committed selection is persistent state; the active item while open is transient navigation state.

## Current-source installation and Usage

The Code panels use the current workspace's public package exports. Install `@proto.ui/cli`, `@proto.ui/prototypes-base`, `@proto.ui/prototypes-lucide` and the selected Adapter from the same reviewed source revision. For a source checkout, the repository's [pack-only flow](https://github.com/Proto-UI/Proto-UI/blob/main/scripts/release/publish.mjs) and [clean consumer installation](https://github.com/Proto-UI/Proto-UI/blob/main/scripts/release/consumer-smoke-cli.mjs) supply the local packages and their declared dependency closure. This page does not assert that the workspace version is published to npm; the [stable Quick Start](/en/start-here/quick-start/) describes the published-version route.

Each panel is a complete file for an existing application with a module bundler. React and Vue retain the application's existing mount entry. Vue 2 uses Vue `>=2.6.0 <2.7`.

Keep the generated `src/styles/proto-ui-style.css`: the examples import it for Proto UI's structural rules. Import it once if the application entry already loads it. Copy the entire panel for the chosen host. WC registers its own `app-base-select-*` elements and supplies `accessibleLabel`, `placeholder`, icon size and item values through `setElementProps` before connecting them. React passes `createPortal` from `react-dom` into `createReactAdapter` so React owns Content's portal. Both Vue examples register all of the components they use. Trigger's `accessibleLabel` keeps the control name independent of the selected value.

## Family Parts

- `select-root`: owns controlled/uncontrolled `open`, `value`, and `textValue`, and arbitrates change requests
- `select-trigger`: an independent command surface that projects combobox ARIA and handles keyboard/pointer opening
- `select-value`: renders `displayValue` or placeholder through explicit `run.update()` without owning input behavior
- `select-content`: composes `asOverlay`, `asTransition`, `asFocusRoving`, and anchor positioning
- `select-item`: projects an option, separates transient `active` from persistent `selected`, and submits selection requests

- `select-surface`, `select-viewport`, and `select-item-text`: explicit optional alignment structure
- `select-group`: passive container with its own accessible naming scope
- `select-label`: slot-preserving name for its nearest Group; it is not a control label or activation target
- `select-separator`: hidden, decorative, contentless separation

Group/Label/Separator also expose `asSelectGroup`, `asSelectLabel`, and `asSelectSeparator`. Hooks inherit semantic declarations; a caller using `asSelectSeparator` must return an empty renderer itself. Naming fails closed for missing or duplicate labels and remains isolated across nested Select roots. These parts do not own selection, collection or focus. Native accessibility acceptance is still pending; the GPUI peer currently omits Separator hidden-tree transport.

## Why It Matters

This family is not only an addition to the base library. It is also a probe for Proto UI's current value-component path:

- selected value text is defined by the prototype family itself
- the host app does not have to render that text manually
- value presentation can be refreshed through explicit update-driven re-render

That makes `select-value` a concrete `render-consumed-value` sample instead of a purely exposed-state sample.

## Current v0 Boundary

`base-select` currently includes:

- single selection
- pointer and select-only keyboard interaction, including arrows, Home/End, and typeahead
- Escape, Tab, outside-press dismissal, and appropriate focus restoration
- selected-item focus entry, with boundary fallback
- combobox/listbox/option ARIA relationships and selected state
- controlled values that emit requests without creating temporary success state
- a protocol-owned value presentation part

It does not yet include:

- form semantics
- native `<select>` parity
- editable combobox/search behavior
- scroll buttons and `ItemIndicator`
- form submission and hidden inputs
- multi-select

## API

Select is workspace source. For this workspace version, the CLI target is `base-select`. Use matching CLI and package versions; check the chosen release's availability before installing. Passing `open` or `value` selects controlled mode for that fact.

<ApiPropsTable
  headers={{ name: 'Prop', type: 'Type', default: 'Default' }}
  rows={[
    { name: 'defaultOpen', type: 'boolean', default: 'false' },
    { name: 'defaultValue', type: 'string', default: "''" },
    { name: 'disabled', type: 'boolean', default: 'false' },
    { name: 'readOnly', type: 'boolean', default: 'false' },
    { name: 'closeOnSelect', type: 'boolean', default: 'true' },
  ]}
/>

These props belong to Root. Trigger defaults `accessibleLabel` to `''`. Value defaults `placeholder` to `''`. Content accepts the Transition props and defaults `position` to `popper`, `side` to `bottom`, `align` to `center`, `sideOffset` to `4`, `alignOffset` to `0`, `avoidCollisions` to `true` and `collisionPadding` to `10`. Item defaults `disabled` to `false` and `value` and `textValue` to `''`; `closeOnSelect` has no default and falls back to the Root policy. Group, Label, Surface, ItemText, Viewport and Separator have no props.

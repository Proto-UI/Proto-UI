## Installation

Available starting in `0.3.0-rc.1` and later releases.

## Usage

Compose `Root`, `Viewport`, and `Content`:

- **Logical model and Web materialization**: `Root` manages `itemKeys`, item-count `overscanItems`, `maxMaterializedItems`, revisions, and generation-bound commits. On Web, `attachWebVirtualList` from `@proto.ui/prototypes-base/virtual-list/web` measures variable item sizes, maintains spacer elements and keyed DOM views, supports scrolling to a key, and cleans up observers on dispose.
- **Single materializer lease**: Each logical collection holds at most one active materializer lease. `attachWebVirtualList` acquires the lease before attaching spacers, rows, or listeners; attaching a second host fails without disturbing the active one, so dispose the existing host before attaching a replacement. Custom hosts can acquire a lease via `acquireMaterializer(onRetired)` (Web callers do not need to call it separately around `attachWebVirtualList`).
- **Retirement and retry**: Unmounting or disposing `Root` retires the active materializer—invalidating in-flight generations, cleaning up views and observers, and ensuring late refresh, scroll, measurement, or duplicate dispose calls from a retired host cannot revoke a newer replacement. If initial rendering or observer setup fails, the lease is released so the collection can be retried.

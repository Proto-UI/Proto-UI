## Installation

Available starting in `0.3.0-rc.1` and later releases. In the workspace, the CLI target is `base-dialog`.

## Usage

### Anatomy

- **`dialog-root`**: manages `open` state and provides shared context to child parts.
- **`dialog-trigger`**: opens or toggles the dialog on activation.
- **`dialog-mask`**: renders the backdrop overlay and follows open transitions. By default, it prevents default pointer-down actions on the backdrop so background interactions do not interfere with close-time focus restoration; set `passthrough={true}` to opt out.
- **`dialog-content`**: manages focus trapping, dismissal (`Escape` and outside press), and enter/leave transitions.
- **`dialog-title`**: automatically links to `dialog-content` via `aria-labelledby`.
- **`dialog-description`**: automatically links to `dialog-content` via `aria-describedby`.
- **`dialog-close`**: requests closing the dialog when activated.

### Alert mode and styling

- Set `alert={true}` on `dialog-root` to apply `role="alertdialog"` and disable outside-press dismissal while keeping `Escape` dismissal.
- For decorative visual layers, compose [Surface](/en/ui-libraries/base/surface/) to consume existing transition states.

### Other parts

- **Mask**: `passthrough` defaults to `false`, plus Transition props.
- **Content**: `focusEntry: 'auto' | 'content' | 'manual'` defaults to `'auto'`, plus Transition props. `'content'` initially focuses the Content surface without adding it to the Tab sequence; Tab still enters the dialog's controls. `'manual'` leaves initial focus placement to the consumer. The policy is read at each activation; changing it while open does not move focus. All three modes retain focus containment and restoration.
- **Trigger, Title, Description, Close**: no props.

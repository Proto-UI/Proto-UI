## Installation

The 0.2.0 stable package exports `@proto.ui/prototypes-base/scroll-area` for direct subpath import. For a ready-made CLI styled component, see [Brutalist Scroll Area](/en/ui-libraries/brutalist/components/scroll-area/) (`brutalist-scroll-area`).

## Usage

### Parts

- **Root** (1): Defines the scroll-area structure without managing scroll offsets or dimensions.
- **Viewport** (1): Manages the logical scroll surface and exposes normalized axes, position, visible ratio, direction availability, scrolling state, and resolved scrollbar mode while delegating DOM pixels, physics, and input gestures to the host.
- **Scrollbar** (0–2): Horizontal or vertical container for a custom scrollbar.
- **Thumb** (0–2): Interactive drag region inside `Scrollbar` whose geometry and drag movement map back through the host scroll engine.

Both `system` and `composed` modes share the same protocol; the default mode is resolved by the host adapter and design-language preference.

### Opt-in end-follow (`endFollow`)

For append-only feeds such as logs or chat streams, custom compositions using `asScrollSurface()` can opt into `endFollow` with `{ mode: 'while-at-end', axis: 'vertical' }`. You can observe per-axis `atEnd`, `endFollow.state`, and `endFollow.requestStatus`, and send `{ kind: 'to-end', axis: 'vertical' }` from a jump-to-latest control.

When active, the host tracks content growth while at the end, pauses when the reader scrolls away, coalesces rapid appends, and resumes on natural return to the end or an explicit jump request—without moving focus or taking over live regions. Base `Viewport` keeps `endFollow` off by default.

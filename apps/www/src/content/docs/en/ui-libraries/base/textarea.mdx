## Usage

### Controlled, uncontrolled, and IME composition

Value ownership is fixed at creation time:

- **Uncontrolled**: Pass `defaultValue` to seed the initial value once; subsequent edits stay local and unrelated prop updates preserve user input.
- **Controlled**: Pass `value` to treat edits as change proposals. During an active IME session, the native textarea preserves candidate text until `compositionEnd`, restoring the controlled `value` only if the caller declines the update.
- When updating unrelated props or synchronizing an unchanged value, the current cursor position and selection stay intact. Native selection handles, software keyboards, and clipboard menus remain host-managed.

### Native attributes, focus, and styled wrappers

- `disabled`, `readOnly`, `required`, `name`, `placeholder`, `autoComplete`, `minLength`, `maxLength`, `rows`, and `wrap` map directly to the native `<textarea>`, preserving the `textbox` role and mapping `ariaLabel`, `labelledBy`, and `describedBy`.
- Textarea renders no child slot—place labels and styling around the control. When authoring a styled wrapper with `asTextareaRoot()`, reuse `asTextareaRoot.modules` on the prototype definition.

### Reset and Field integration

- Call `resetValue()` to restore the initial value in uncontrolled mode (or propose it in controlled mode). Reset works even while `readOnly` or `disabled` and ends any active composition.
- For Field labels, descriptions, errors, and validation, import `fieldTextarea` from `@proto.ui/prototypes-base/field` (see the [Form recipe](../form/)).

Pass `value` to control the text value.

- **Exposed states**: `value`, `disabled`, `readOnly`, `focused`, `focusVisible`, `composing`.
- **Exposed methods**: `focusSelf()`, `blurSelf()`, `resetValue()`.
- **Events**:
  - `valueChange`: Follows native `input` with `{ value, composing, data, inputType }`.
  - `change`: Follows native `change` with `{ value }`.
  - `compositionStart`, `compositionUpdate`, `compositionEnd`: Each emits `{ value, data }`.

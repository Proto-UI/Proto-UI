Base Tooltip consists of Root, Trigger, and Content. Tooltip Group is an adjacent protocol in the same family and shares delay defaults, the warm window, and active-owner coordination across Roots.

- Initial pointer hover opens after `openDelay`, while reverse movement cancels the pending task.
- Keyboard focus opens immediately without waiting for the pointer delay.
- `closeDelay` lets the pointer move from Trigger into Content; Content itself must contain no focusable interaction.
- Trigger additively references the `role="tooltip"` Content through `aria-describedby` only while open.
- Escape enters Root's unified close request channel.
- Moving to a sibling during the Group warm window opens it immediately; the previous uncontrolled Tooltip ends perceptual presence without a visible exit overlap, and initial delay returns after `skipDelay`.
- Draft lifetime rule: when the current active Root unmounts or is disposed, its Group immediately returns to cold delay. Ordinary closure keeps the `skipDelay` window. A retained open Root registers again on remount; cleanup never clears a newer active Root, and a controlled Root that refused closure is not automatically reselected.

Portal is currently owned by Content's Overlay and renderer projection rather than a separate Base Portal prototype. Arrow remains outside the current Base guarantee until a governed geometry and positioning channel exists.

## Suggested acceptance path

1. Hover `Account` and confirm Tooltip appears after about 500ms; leaving early must not flash it.
2. With the first Tooltip open, move quickly to `Notifications`; the warm sibling should open immediately and the previous Tooltip should disappear with no visible overlap.
3. Let both remain closed for more than 700ms, then hover again and confirm the 500ms delay returns.
4. Use Tab to focus a Trigger and confirm immediate opening; Escape should close it while retaining Trigger focus.
5. Switch among Web Components, React, and Vue in the toolbar and repeat the interaction.

## Tooltip on a Button

A focusable command and Tooltip should share one subject. Compose the draft `useTooltipTrigger()` authored hook with the command behavior, adapt the resulting prototype, and place that component directly inside Tooltip Root alongside Content. Do not wrap a separately focusable Button in the standalone Trigger: that creates two Tab stops.

```ts
import { definePrototype } from '@proto.ui/core';
import { asButton, type ButtonProps, type ButtonExposes } from '@proto.ui/prototypes-base/button';
import { useTooltipTrigger } from '@proto.ui/prototypes-base/tooltip';

export const tooltipButton = definePrototype<ButtonProps, ButtonExposes>({
  name: 'app-tooltip-button',
  setup() {
    asButton();
    useTooltipTrigger();
  },
});
```

Button retains its role, name, click signal, disabled state and single focus owner. Tooltip adds hover/focus intent and the owned `aria-describedby` relation. Disabling Tooltip Root suppresses Tooltip while leaving the command available; disabling the command suppresses both. `useTooltipTrigger` takes no options and adds no outward exposes. It requires an existing focusable subject. Standalone `asTooltipTrigger` retains its original focus behavior and exposes.

For an existing styled prototype, use the same setup composition while preserving its render function: call the styled prototype's `setup(def)`, then `useTooltipTrigger()`, and return the captured render function from your `definePrototype`. Keep the styled prototype's static `modules` declaration. This shares one host and preserves the family's Button presentation; it is separate from the passive action-body styling used by the standalone demo below.

## API

Tooltip is workspace source. There is no public `proto-ui add` target. Passing `open` selects controlled mode.

<ApiPropsTable
  headers={{ name: 'Prop', type: 'Type', default: 'Default' }}
  rows={[
    { name: 'defaultOpen', type: 'boolean', default: 'false' },
    { name: 'disabled', type: 'boolean', default: 'false' },
    { name: 'openDelay', type: 'number', default: 'undefined' },
    { name: 'closeDelay', type: 'number', default: 'undefined' },
  ]}
/>

These props belong to Root. Trigger defaults `disabled` to `false`. Content accepts the Transition props and defaults `side` to `top`, `align` to `center`, `sideOffset` to `4`, `alignOffset` and `collisionPadding` to `0` and `avoidCollisions` to `true`. Group defaults `openDelay` to `700`, `closeDelay` to `100` and `skipDelay` to `300`.

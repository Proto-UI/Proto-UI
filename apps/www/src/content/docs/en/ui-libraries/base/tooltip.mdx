## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release (see [Quick Start](/en/start-here/quick-start/) for published versions). Base Tooltip is exported directly from `@proto.ui/prototypes-base/tooltip` and has no `proto-ui add` CLI target.

Install `@proto.ui/cli`, `@proto.ui/prototypes-base`, and your host Adapter (`@proto.ui/adapter-web-component`, `@proto.ui/adapter-react`, `@proto.ui/adapter-vue`, or `@proto.ui/adapter-vue2`; Vue 2 requires Vue `>=2.6.0 <2.7`) from the same source revision. For a local source checkout, use the repository's [pack-only flow](https://github.com/Proto-UI/Proto-UI/blob/main/scripts/release/publish.mjs) and [clean consumer installation](https://github.com/Proto-UI/Proto-UI/blob/main/scripts/release/consumer-smoke-cli.mjs).

After installing, run the local CLI to generate the structural stylesheet `proto-ui-style.css` (keep a single import if your app already loads it):

```sh
node node_modules/@proto.ui/cli/bin/proto-ui.js init --yes --no-interactive --prototypes shadcn
```

The React example passes `createPortal` from `react-dom` into `createReactAdapter` for overlay portalling; Web Components configure custom element inputs via `setElementProps`.

## Usage

### Interaction and group coordination

Compose `Root`, `Trigger`, `Content`, and an optional `Group`:

- **Hover and keyboard focus**: Initial pointer hover opens after `openDelay` (moving away cancels the pending timer), while keyboard focus opens immediately.
- **Close delay and accessibility**: `closeDelay` lets the pointer move from `Trigger` to `Content` (keep `Content` non-interactive). While open, `Trigger` automatically links and cleans up `aria-describedby` referencing `Content` (`role="tooltip"`). Pressing `Escape` dismisses the tooltip while keeping focus on `Trigger`.
- **Warm-window handoff**: Moving to a sibling tooltip within `Group`'s `skipDelay` window opens it immediately and closes the previous uncontrolled tooltip with no overlap; after `skipDelay` expires, initial delay resumes. Unmounting or disposing the active `Root` immediately resets the group to cold delay.

### Attaching Tooltip to a Button

Share one focusable element between a button and tooltip trigger by composing `useTooltipTrigger()` with `asButton()` instead of nesting a focusable button inside a separate `Trigger` (which creates two tab stops):

```ts
import { definePrototype } from '@proto.ui/core';
import { asButton, type ButtonProps, type ButtonExposes } from '@proto.ui/prototypes-base/button';
import { useTooltipTrigger } from '@proto.ui/prototypes-base/tooltip';

export const tooltipButton = definePrototype<ButtonProps, ButtonExposes>({
  name: 'app-tooltip-button',
  setup() {
    asButton();
    useTooltipTrigger();
  },
});
```

`Button` keeps its role, click behavior, disabled state, and single focus stop, while `useTooltipTrigger()` adds hover/focus intent and `aria-describedby`. Disabling the Tooltip `Root` suppresses only the tooltip while keeping the button usable; disabling the button suppresses both. To wrap an existing styled prototype, preserve its static `modules` declaration, call its `setup(def)`, call `useTooltipTrigger()`, and return its captured render function.

### Using inside a `ShadowRoot`

When the trigger lives inside a `ShadowRoot`, mount `Content` in the same shadow tree—an `aria-describedby` reference across a shadow boundary does not resolve to an accessible description.

Register an application-owned scene and overlay target via `registerWebPortalDestination` from `@proto.ui/adapter-base` before mounting (keep `overlays` inside `scene` and outside `Content`):

```ts
import { registerWebPortalDestination } from '@proto.ui/adapter-base';

export function createTooltipScene(container: HTMLElement) {
  const shell = document.createElement('div');
  container.append(shell);
  const shadow = shell.attachShadow({ mode: 'open' });
  const scene = document.createElement('div');
  const appMount = document.createElement('div');
  const overlays = document.createElement('div');
  scene.append(appMount, overlays);
  shadow.append(scene);
  const releasePortal = registerWebPortalDestination(scene, overlays);

  return {
    shadow,
    appMount,
    async dispose(unmount: () => void | Promise<void>) {
      await unmount();
      shell.remove();
      releasePortal();
    },
  };
}
```

Mount `Root`, the combined trigger button, and `Content` inside `appMount`, and load the generated CSS inside `shadow`. Call `dispose` on teardown so components unmount before releasing the portal registration.

## API

### Root

<ApiPropsTable
  headers={{ name: 'Prop', type: 'Type', default: 'Default' }}

  ]}

Pass `open` to control open state.

### Part Props

- **Trigger**: `disabled` (default `false`).
- **Content**: Accepts `Transition` props plus `side` (default `'top'`), `align` (default `'center'`), `sideOffset` (default `4`), `alignOffset` (default `0`), `collisionPadding` (default `0`), and `avoidCollisions` (default `true`).
- **Group**: `openDelay` (default `700`), `closeDelay` (default `100`), `skipDelay` (default `300`).

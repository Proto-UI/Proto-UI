A low-level presence state machine (`closed → entering → entered → leaving → closed`) that keeps views mounted while enter and leave animations run across CSS, React, Vue, and Web Components.

## Preview

### Imperative control

Drive the state machine imperatively through `controls` (typical cycle: `Enter → Complete → Leave → Complete`):

- **Enter**: Transitions from `closed` or `leaving` into `entering` (ignored when already entering or entered).
- **Leave**: Transitions from `entered` or `entering` into `leaving` (ignored when already leaving or closed).
- **Complete**: Advances `entering` to `entered`, or `leaving` to `closed`.

Control presence via the `open` prop: toggling `open` to `true` runs `entering → entered`, and toggling to `false` runs `leaving → closed` (clicking the box triggers the same toggle). Transitions auto-complete after `enterDuration` / `leaveDuration`, or earlier when a host calls `controls.complete()`.

## Installation

Available starting in `0.3.0-rc.1` and later releases (CLI target: `base-transition`).

## Usage

### State machine and view lifecycle

```text
transitionState: closed → entering → entered → leaving → closed
ViewIntent:      detached ↔ present
view epoch:      detached ↔ mounting ↔ mounted ↔ unmounting
```

`asTransition()` is a once-per-setup Hook exported from `@proto.ui/prototypes-base` that coordinates mounting through `run.lifecycle.setPresent()`:

- **Enter**: Sets `ViewIntent` to `present` first and enters `entering` only after the new view finishes mounting, preventing unready DOM flashes.
- **Leave**: Keeps the current view mounted throughout `leaving`, detaching only after completing into `closed`.
- **Restore**: Unmounting content when closed preserves the prototype instance, controls, and prop watchers so opening again creates a fresh view cleanly.

### Best practices

1. **Pair with CSS transitions**: `Transition` manages logical phase only—style `data-transition-state="entering"` and `data-transition-state="leaving"` for smooth motion.
2. **Optional host completion signal**: `enterDuration` and `leaveDuration` provide a reliable fallback; to synchronize with actual CSS timing, call `exposes.controls.complete()` on `transitionend` (which cancels any pending fallback timer):

```ts
el.addEventListener('transitionend', () => {
  exposes.controls.complete();
});
```

3. **Animate on initial mount**: Set `appear={true}` to play the enter animation on first render; otherwise the element starts directly in `entered`.
4. **Choose an `interrupt` strategy**:
   - `'reverse'` (default): Smoothly reverses mid-transition on rapid toggles (ideal for menus and tooltips).
   - `'wait'`: Finishes the current phase before transitioning (useful for multi-step panels).
   - `'immediate'`: Discards the in-flight transition and starts the next phase immediately.
5. **Drive state via `open` or `controls`**: Avoid mutating `transitionState` directly, and keep child DOM stable during `leaving` until reaching `closed` or real unmount.

`base-transition` governs a single element's presence lifecycle; parent/child exit coordination belongs to a separate boundary or group abstraction.

## API

### Root

<ApiPropsTable
  headers={{ name: 'Prop', type: 'Type', default: 'Default' }}

    { name: 'interrupt', type: "'reverse' | 'wait' | 'immediate'", default: 'reverse' },
  ]}

Pass `open` (`boolean`) to control presence.

### Imperative methods (`controls`)

- `enter()`: Starts an enter transition.
- `leave()`: Starts a leave transition.
- `complete()`: Completes the current transition and advances to the next settled state.

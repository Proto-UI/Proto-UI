## Anatomy

Checkbox is split into root and indicator parts connected through the anatomy system.

- **Root** (`base-checkbox-root`) owns canonical `checked`, emits `checkedChange`, and manages disabled/read-only policy and the independent `indeterminate` state.
- **Indicator** (`base-checkbox-indicator`) reads the root `checked` and `indeterminate` states through anatomy runtime access and reflects them for rendering. It does not own checkbox state.

The `base-checkbox` anatomy family uses a `contains` relation from root to indicator. A checkbox is expected to have at least one indicator, and may have more than one indicator when multiple visual surfaces need the same indicator semantics.

In the Web Components preview runtime, prototype IDs are registered with a `wc-` tag prefix: `wc-base-checkbox-root` and `wc-base-checkbox-indicator`.

## Indeterminate Behavior

`indeterminate` may be uncontrolled via `defaultIndeterminate` or controlled via `indeterminate`.

When an editable indeterminate checkbox activates, Root first clears or requests clearing `indeterminate` and emits `indeterminateChange`. Uncontrolled mixed state clears directly; a controlled owner accepts by passing `indeterminate={false}` back.

Root then requests the opposite of the canonical `checked` value at activation start and emits `checkedChange`. If the mixed-clear callback already commits a newer checked value, the older checked stage retires instead of reversing that new owner decision. Confirming only mixed=false while checked stays unchanged retains the original checked request. Disabled or readOnly blocks both value proposals.

## Read-only and explicit Form composition

Root accepts `readOnly`. It preserves focus while refusing value proposals; disabled also removes focus participation. Ordinary Root does not automatically register with Field or Form.

Use `fieldCheckbox` from `@proto.ui/prototypes-base/field` inside an explicit `FormField` to connect canonical values, required validation, Label/Description/Error relationships and reset. The [Form choice recipe](../form/) demonstrates controlled refusal, accepted changes, read-only focus, disabled groups and real owner replacement. `resetValue()` requests the instance creation baseline and never forces a controlled owner to accept it.

## API

Checkbox is workspace source. There is no public `proto-ui add` target. Passing `checked` or `indeterminate` selects controlled mode for that fact.

## Usage

### Anatomy

Checkbox consists of `Root` and an optional `Indicator`:

- **Root** (`base-checkbox-root`): manages `checked`, `indeterminate`, `disabled`, `readOnly`, and `required`, and emits `checkedChange` and `indeterminateChange`.
- **Indicator** (`base-checkbox-indicator`): reads `checked` and `indeterminate` from its `Root` for visual rendering. Multiple indicators can share the same `Root`.

In the Web Components preview runtime, these parts register as `wc-base-checkbox-root` and `wc-base-checkbox-indicator`.

### Indeterminate behavior

`indeterminate` can be uncontrolled (`defaultIndeterminate`) or controlled (`indeterminate`):

- Activating an editable indeterminate checkbox first clears (or requests clearing) `indeterminate` via `indeterminateChange`, then requests toggling `checked` via `checkedChange`.
- If your `indeterminateChange` handler already commits a new `checked` value, the pending toggle step is skipped rather than reversing your update.
- `disabled` and `readOnly` block both state change requests.

### Read-only and Form integration

- `readOnly` keeps the checkbox focusable while blocking value changes; `disabled` also removes it from the focus sequence.
- Standalone `Root` does not auto-register with a form. Inside an explicit `FormField`, use `fieldCheckbox` from `@proto.ui/prototypes-base/field` for value tracking, required validation, Label/Description/Error linking, and reset (see the [Form choice recipe](../form/)).

## API

### Root Props

Pass `checked` or `indeterminate` to control the corresponding state. `Root` and `asCheckboxRoot()` expose `checked`, `indeterminate`, `disabled`, `required`, `hovered`, `focused`, `focusVisible`, and `pressed`, plus `checkedChange` and `indeterminateChange`.

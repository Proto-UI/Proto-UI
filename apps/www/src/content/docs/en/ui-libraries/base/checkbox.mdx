## Anatomy

Checkbox is split into root and indicator parts connected through the anatomy system.

- **Root** (`base-checkbox-root`) owns `checked`, `checkedChange`, disabled behavior, the `indeterminate` state, and the `required` fact.
- **Indicator** (`base-checkbox-indicator`) reads the root `checked` and `indeterminate` states through anatomy runtime access and reflects them for rendering. It does not own checkbox state.

The `base-checkbox` anatomy family uses a `contains` relation from root to indicator. Indicators are optional, and multiple visual surfaces can read the same root state through separate indicators.

In the Web Components preview runtime, prototype IDs are registered with a `wc-` tag prefix: `wc-base-checkbox-root` and `wc-base-checkbox-indicator`.

## Indeterminate Behavior

`indeterminate` may be uncontrolled via `defaultIndeterminate` or controlled via `indeterminate`.

When an enabled indeterminate checkbox is pressed:

1. `checked` toggles on `press.commit` when uncontrolled, or is updated by the owner when controlled via `checkedChange` (`{ checked, indeterminate }`).
2. The root requests `indeterminate: false` by emitting `indeterminateChange`.
3. If `indeterminate` is uncontrolled, the root also clears its internal indeterminate state.
4. If `indeterminate` is controlled, the external owner must handle `indeterminateChange` and pass `indeterminate={false}` back in.

Disabled checkboxes do not change checked or indeterminate state on press.

## API

Checkbox is workspace source. There is no public `proto-ui add` target. Passing `checked` or `indeterminate` selects controlled mode for that fact.

    { name: 'disabled', type: 'boolean', default: 'false' },

    { name: 'defaultIndeterminate', type: 'boolean', default: 'false' },
  ]}
/>

These props belong to Root. Indicator has no props.

Root and `asCheckboxRoot()` expose `checked`, `indeterminate`, `disabled`, `required`, `hovered`, `focused`, `focusVisible`, and `pressed`, plus `checkedChange` and `indeterminateChange`.

The `required` prop initializes and updates one owned state, which also supplies the accessible required fact. It does not change the checked value or prevent unchecking. Native form constraint validation, submission, and Field validation remain responsibilities of an explicit composition; the atomic Checkbox does not create a hidden form input or install a Field binding automatically.

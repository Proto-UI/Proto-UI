Base Data Table builds stable sorting, global and per-column filtering, column visibility, pagination, and row selection on top of passive table structure. Supply records with unique `id` values; row slots map each index on the active page to the underlying record.

## Installation

Available starting in `0.3.0-rc.1` and later releases.

## Usage

### Header and body rows

- Place sortable column headers inside `DataTableHeaderRow`, and render body record slots with `DataTableRow` indexed for the current page.
- Each `Cell` renders its `columnKey` from the active record so sorting and pagination update cell content directly.

### Filtering, column visibility, page selection, and custom formatting

- **Filtering**: every non-empty `columnFilters` entry combines with Root `filter` before sorting and pagination run.
- **Column visibility**: `columnVisibility` hides matching `Header` and `Cell` views (removing them from sorting focus and accessibility output) while preserving their identity when shown again.
- **Page selection**: `requestPageSelection()` selects or clears only the current filtered page while preserving selections on other pages, and reports `pageSelection` as `'none'`, `'some'`, or `'all'`. `readOnly` blocks row and page selection while allowing sorting and pagination.
- **Custom cell rendering**: set `renderValue={false}` on a `Cell` to keep your own child elements while subscribing to its public `displayValue` state for custom formatting.

## API

### Root Props

Pass `sortKey`, `sortDirection`, `page`, or `selectedKeys` to control the corresponding state.

### Other parts

- **Row**: `index` defaults to `0`, `header` to `false`.
- **Cell**: `columnKey` defaults to `''`, `renderValue` to `true`.
- **Header**: `sortable` defaults to `true`.
- **Previous / Next**: accept Button props.

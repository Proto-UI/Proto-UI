Base Accordion provides unstyled disclosure behavior and accessibility semantics across five composable parts—`Root`, `Item`, `Heading`, `Trigger`, and `Content`—supporting both single and multiple expanded items.

## Installation

Currently available from workspace source; not yet included in the 0.2.0 stable release. In the workspace, generate host wrappers with `proto-ui add react base-accordion` (also supports `vue`, `vue2`, and `wc`), or import `accordionRoot`, `accordionItem`, `accordionHeading`, `accordionTrigger`, `accordionContent`, and the matching `asAccordion*` hooks directly from `@proto.ui/prototypes-base/accordion`.

## Usage

### Anatomy

Compose `Root → Item → Heading → Trigger`, with `Content` as a sibling of `Heading` inside `Item`. Every `Item` requires a unique, non-empty `value`.

- `Root` manages the set of open item keys; `Item`, `Trigger`, and `Content` derive their state from it.
- Nested `Root` instances maintain independent scopes.
- Keep only the controlling `Trigger` inside `Heading`, and place persistent secondary actions beside it.

### Controlled and uncontrolled state

- Pass `openItems` to control the expanded items externally. User or programmatic requests emit `openChange` with payload `{ openItems, value, open, reason }` (where `reason` is `'pointer'`, `'keyboard'`, or `'programmatic'`). Pass the updated `openItems` back to `Root` to commit the change.
- Omit `openItems` for uncontrolled usage and optionally provide `defaultOpenItems` to initialize the open keys once on mount.
- Duplicate keys are deduplicated, and `single` mode keeps the first unique key. Keys for items not yet mounted remain stored so items can mount progressively.

### Content mounting

Closed `Content` unmounts its content node by default. Set `keepMounted` to keep the node mounted and hidden while preserving child state. Closing a panel does not automatically relocate focus.

### Keyboard and accessibility

- Enabled headers and focusable elements inside open content remain in the natural Tab order.
- `Enter` and `Space` toggle the focused item.
- `ArrowUp` / `ArrowDown` (vertical) or `ArrowLeft` / `ArrowRight` (horizontal, reversed in `rtl`) move focus between enabled headers without changing open state. `Home` and `End` jump to the first and last enabled headers.
- `Heading` exposes the configured heading `level`; `Trigger` manages `aria-expanded`, `aria-disabled`, and `aria-controls`; `Content` is labelled by its `Trigger` and can optionally opt into a landmark role with `region={true}`.

## API

### Root Props

Passing `openItems` selects controlled mode. `Root` also exposes `getOpenItems()`, `openCount`, `requestOpen(value, open, reason?)`, and the `openChange` event.

### Other parts

- **Item**: requires a non-empty `value`; `disabled` defaults to `false`.
- **Heading**: `level` integer from `1` to `6`, defaults to `3`.
- **Trigger**: no props; derives state from `Item` and `Root`.
- **Content**: `keepMounted` and `region` both default to `false`.

Base Selectable Row owns one row's press, keyboard, focus and accessibility behavior. Its owner supplies an opaque `itemKey`, accepts selection proposals and performs activation effects. The row does not interpret a file path or navigate to a destination.

This prototype is **draft**. The RuntimeBox below uses the public `selectableRow` prototype; its owner accepts selection and displays activation requests. Adapter switching exercises the same authoring source on the Web host. The preview does not establish Compiler, native-host or assistive-technology conformance.

Use Tab to reach an enabled row, then Space to propose selection. Enter on **Assets** requests activation. On Web, double-clicking that row requests the same activation. The status text records the owner's accepted selection or requested action; this example has no filesystem route.

## Accepted selection and separate activation

`selected` is controlled owner state. Pointer press and Space emit `selectionChange` with `{ value: itemKey }`; they do not immediately change the row's accepted `selected` state. The consumer decides whether to accept the proposal and supplies the resulting value again.

Enter emits `activate` with the same payload only when `activatable` is true. It does not also propose selection. The `host:dblclick` path is an explicit Web host extension: the row has no portable double-press timer and makes no double-activation guarantee for hosts without that extension.

Enabled focused rows prevent Space's scrolling default. Activatable focused rows also prevent Enter's default. Repeated keyboard press commits do not repeat selection or activation.

## Row and collection responsibilities

The row projects the `row` accessibility role and the accepted `selected` and `disabled` states. Its name comes from its content, and its default slot preserves authored children. `disabled` suppresses selection, activation and `focusSelf()`, and removes normal focus participation. Disabling a row does not discard its accepted selection.

The surrounding collection supplies appropriate row and cell composition. Arrow movement, roving tab order, range selection and multi-selection belong to that collection owner. The preview demonstrates independently focusable rows with owner-accepted selection; it does not implement collection keyboard navigation.

Base provides no visual design language. The preview's layout, selection color and status text are website composition.

## Public authoring entries

```ts
import { selectableRow, asSelectableRow } from '@proto.ui/prototypes-base/selectable-row';
```

The source subpath also exports the default prototype, `SelectableRowProps`, `SelectableRowExposes` and `SelectableRowAsHookContract`. The package root exports the named entries. The prototype and hook share the same setup. Consumers handle semantic events without duplicating the row's keyboard or selection implementation in host listeners.

Selectable Row is workspace source and has no public `proto-ui add` target.

Exposed states are `selected`, `disabled`, `focused` and `focusVisible`. The public method is `focusSelf()`. Both `selectionChange` and `activate` carry `{ value: string }`, without native elements or application objects.

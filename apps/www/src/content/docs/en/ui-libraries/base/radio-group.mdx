## Usage

### Parts

- `radio-group-root`: Manages the selected value, item collection order, roving focus, group disabled/read-only state, and `role="radiogroup"`.
- `radio-group-item`: Declares an option `value` with `role="radio"`, derives `checked` and effective `disabled` state from `Root`, and emits selection requests.
- `radio-group-indicator`: Derives `checked` and `disabled` state from its nearest `Item` for visual feedback without owning focus or events.

### Controlled and uncontrolled

- Use `defaultValue` for uncontrolled mode; accepted requests update state and emit `valueChange` once.
- Pass `value` for controlled mode; interactions emit `valueChange` with the proposed value while external state remains authoritative.
- Empty and unmatched values are preserved rather than silently selecting the first option. Removing, disabling, or renaming the selected item leaves the `Root` value intact and restores checked state if a matching item returns.
- Keep `Item` values non-empty and unique within a group; if duplicates occur, only the first match appears checked and ambiguous selection requests are ignored.

### Keyboard, focus, and accessibility

Exactly one enabled `Item` participates in normal `Tab` order (the checked item, or the first enabled item if none is checked). Moving focus into the group does not automatically select an option.

- `Space`: Selects the focused enabled item and prevents page scroll.
- `ArrowRight` / `ArrowDown`: Moves focus to and selects the next enabled item (wrapping and skipping disabled items).
- `ArrowLeft` / `ArrowUp`: Moves focus to and selects the previous enabled item (wrapping and skipping disabled items).
- `Home` / `End`: Moves focus to and selects the first or last enabled item.
- `focusSelf()` moves focus programmatically without changing selection; pointer presses select only on completed commit.

Provide an accessible group name via `a11yLabel` (or host labeling). Each `Item` automatically sets `role="radio"`, `aria-checked`, and `aria-disabled`.

### Read-only and Form integration

- `readOnly` keeps keyboard focus navigation active while rejecting value changes; `disabled` also removes items from normal focus order.
- Standard `radio-group-root` does not auto-register with forms. To connect validation, Label/Description/Error linking, and form reset, use `fieldRadioGroup` from `@proto.ui/prototypes-base/field` inside a `FormField` (see the [Form choice recipe](../form/)). `resetValue()` requests returning to the instance's initial baseline value.

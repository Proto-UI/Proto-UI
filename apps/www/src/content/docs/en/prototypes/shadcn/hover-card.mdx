Hover Card displays a lightweight preview panel when a user hovers over or focuses a trigger, making it useful for profile cards and link previews. The examples on this page use the **Shadcn Rhea** style preset.

## Usage

Hover Card is composed of three cooperating parts:

- **Root**: Manages open state (`open`), open/close delays, and disabled state.
- **Trigger**: Tracks pointer hover and keyboard focus and sends open/close requests to Root.
- **Content**: Renders the floating panel, handles placement and collision avoidance, and keeps the card open while hovered.

### Controlled and Uncontrolled

- **Uncontrolled**: Set `defaultOpen` for the initial state and let Root handle hover, focus, and timers automatically.
- **Controlled**: Pass `open` and listen to the `openChange` event on Root to drive visibility from external state.

### Delays and Disabled State

- `openDelay` (default `700` ms) and `closeDelay` (default `300` ms) are cancellable, preventing flicker when moving quickly across the trigger or into the content panel.
- Negative or non-finite delay values fall back to the defaults.
- Set `disabled` on Root or Trigger to suppress hover and focus activation.

## API

The table below lists all props across Root, Trigger, and Content. `open`, `defaultOpen`, `openDelay`, and `closeDelay` belong to Root; `disabled` is supported on Root and Trigger; `side` through `collisionPadding` belong to Content.

### Exposed State, Methods, and Events

- **Root**: Exposes `open` state, `openHoverCard(reason?)`, `close(reason?)`, and `toggle(reason?)` methods, and the `openChange` event with payload `{ open: boolean; reason: string | null }`.
- **Trigger**: Exposes `disabled`, `hovered`, `focused`, and `focusVisible` state plus `focusSelf(options?)`.
- **Content**: Exposes `open` state.

# Whitepaper illustrations

The whitepaper SVGs are embedded as images and inherit the website's explicit light/dark color scheme. Full-size viewing stays in the site's themed dialog.

## Editing

User-authored Excalidraw exports: `whitepaper-information-channels.svg`, `whitepaper-lifecycle.svg`, and bilingual `whitepaper-component-boundary` and `whitepaper-translation-responsibility` SVGs. Website adaptations preserve the user's layout and wording while adding theme colors and an Adapter cutout mask. The original editable drawings remain with the author.

`node apps/www/scripts/generate-whitepaper-diagrams.mjs` generates sixteen SVGs: the eight bilingual anatomy, Switch activation, conditional consistency, and desktop evolution assets, plus eight responsive mobile counterparts. Edit that generator for those assets; it deliberately does not overwrite the user-authored drawings. Codex generated these diagrams and assisted with website integration and theme adaptations; the maintainer reviewed the original figures. Responsive counterparts require their own revision-bound render review.

Chapters 3, 4, 6 and 7 select their explicit `whitepaper-{figure}.mobile.{en,zh-cn}.svg` counterpart at viewport widths up to 639 CSS pixels through a `<picture>` inside the existing diagram button. Anatomy and Switch use 500×1740 canvases, conditional consistency uses 500×1920, and evolution retains its 500×1000 canvas. Each mobile asset shares its desktop asset's complete accessible description. Anatomy keeps its Root/Thumb ownership and Select boundary examples; Switch keeps one Root sequence and distinct Expose/Context recipients; consistency keeps independent condition-to-comparison mappings; evolution keeps concurrent work and alternative diagnoses. The fallback images retain their original alt text and desktop dimensions. Every mobile visible label uses at least 26 SVG units. Adding the six counterparts leaves all ten previously generated assets byte-identical. The browser's selected `currentSrc` and intrinsic dimensions determine the full-size Dialog source.

The 16 CSS pixel mobile article text target is a project-specific design goal, not a WCAG threshold or a guarantee for every viewport. A 318-pixel-wide image renders 26-unit labels at about 16.5 CSS pixels. Height-constrained landscape previews may be smaller and are recorded separately. Real localized light/dark page and Dialog renders, font/card bounds, responsive source changes and interaction checks decide acceptance; generator assertions alone do not establish readability or assistive-technology behavior.

## Review

Follow the [documentation diagram method](../../../../internal/agent-operations/diagram-design.md) when changing an illustration. Source-grounded meaning and an actual localized, themed render are separate requirements. A hand-drawn treatment is allowed, not required; repeated boxes and sentences are not a substitute for clear relations.

The original [17-asset inventory and disposition record](../../../../internal/records/2026-11-22-whitepaper-diagram-dispositions.md) binds the original fifteen files and the two mobile variants to their exact source, Git blobs, licenses and all canonical or retained-draft page references. Keep decisions preserve the diagram's stated relationships; they do not replace visual or accessibility acceptance. Recompute a source inventory with `node apps/www/scripts/whitepaper-diagram-inventory.mjs <full-commit-sha>`. The command reads only that commit's Git objects, rejects missing or duplicate asset dispositions, and writes JSON to stdout. The current source inventory additionally includes the six responsive anatomy, Switch and consistency counterparts, for 23 assets total; it identifies each mobile generator entrypoint separately. Preserve dated receipts at their actual revision.

The Switch activation figure is an editorial reading of the chapter 4 pseudocode. Root owns `checked`, explicitly emits `checkedChange`, updates Context, and requests its own Feedback refresh. Thumb receives Context and keeps derived display state. Horizontal arrows show channels across owners; their position does not require synchronous Context callback dispatch. The applicable catalog direction remains draft (`P-BASE-SWITCH`, `P-BASE-SWITCH-THUMB`, `C-STATE-0001`, `C-STATE-0005`, `C-CONTEXT-0010`, and `D-CONTEXT-NOTIFICATION-SCHEDULING-0001`).

## Handwritten Switch activation typography

The activation drawing uses deterministic, slightly irregular pen paths and handwriting typography, following the visual character of the authored information-channel drawing. Its graph, labels, owner boundaries, and editorial status are unchanged by that treatment. The marks are code-authored, not a claim that the figure was drawn by hand.

`apps/www/scripts/whitepaper-diagram-fonts.json` is the generator's frozen font input. It contains glyph subsets derived from **Excalifont 1.000** and **Xiaolai SC 3.11** at the same [upstream Excalidraw commit](https://github.com/excalidraw/excalidraw/tree/214cd6e6e8ac3ad6b68486aa7aa7241abdf9445f/packages/excalidraw/fonts) cited above. Each input shard is identified by filename and Git blob SHA, and each embedded subset has its own SHA-256 and Unicode coverage. The subsets are renamed `Proto Diagram Hand Latin` and `Proto Diagram Hand CJK`; glyph outlines are not redesigned. The Latin subset is embedded in both locales; the CJK subset is embedded only in Chinese. The assignment-arrow character `←` uses the system sans-serif fallback.

These derived fonts remain **SIL OFL 1.1**, with copyrights and full notices in [Excalifont-OFL.txt](licenses/Excalifont-OFL.txt) and [Xiaolai-OFL.txt](licenses/Xiaolai-OFL.txt). The surrounding repository license does not relicense the fonts. Source preparation used FontTools to merge the named upstream Xiaolai shards, subset the visible labels, rename family/name records, and encode WOFF2; no third-party drawing or non-public font source was copied.

Changing a visible label may require refreshing the subset from the pinned upstream fonts. Keep the source shard identities, font names, Unicode coverage, content hashes and licenses synchronized. `scripts/docs/test/generated-whitepaper-diagrams.test.mjs` rejects missing visible-label coverage and font-byte drift and regenerates both locales offline. The normal Node generator does not install or run a font tool.

## Exact-head browser evidence

After building production documentation, run `apps/www/scripts/capture-whitepaper-diagram-evidence.mjs` with `CANDIDATE_SHA` equal to the checkout's exact HEAD, an explicit `CHROME_PATH`, and an absolute `DIAGRAM_EVIDENCE_DIR`. `DIAGRAM_EVIDENCE_FIGURE` accepts five explicit profiles: `switch-activation` (the default), `evolution-feedback`, `conditional-consistency`, `component-anatomy`, and `information-flow-model`. Arbitrary assets, paths and URLs are not supported. The workflow runs the five profiles serially. The retained information-flow comparison is opened in canonical chapter 2; the retired draft article is not used as a production route.

Each selection captures eight core article cases (English/Chinese, light/dark, 390/1440 widths), their figures, and the existing page control's full-size themed Dialog. All four responsive profiles also exercise 639/640 breakpoint selection, resize before opening, repeated open/dismiss, history navigation and a height-constrained landscape case. The complete five-profile plan contains 120 cases and 36 font probes. It covers the sixteen generated assets and retained legacy figure; the six authored exports retain their separate actual-page review obligation. Article screenshots show the original viewport and may show only part of a tall figure; their metrics record viewport fit and header overlap. Dialog failure is a failure, never replaced by direct SVG navigation. Separate source-checked local SVG probes inspect text geometry and fonts for every selected variant: Switch now checks both its desktop and mobile embedded Hand Latin/CJK assets; the other three generated profiles check both of their system-font variants in both locales and themes. These probes are diagnostics, not the production full-size preview.

For the six authored exports, run `node apps/www/scripts/capture-authored-diagram-evidence.mjs` with the same `CANDIDATE_SHA`, `CHROME_PATH`, and `DIAGRAM_EVIDENCE_DIR` after the same build receipt is complete. It derives all eight canonical article references from the immutable inventory and captures light/dark at 1440×1000 and 390×844: 32 cases with separate article-viewport and complete figure-region PNGs. The `authored-exports/metrics.json` receipt binds source and built asset/page bytes, intrinsic dimensions, visible viewport geometry, header overlap, horizontal overflow, alt/caption text and PNG hashes. It retains every failed or unstarted case, refuses to overwrite an existing capture directory, and records `visualReview: pending`. The authored SVGs load only as the existing article images; this collector adds neither an SVG-document profile nor a new production preview path. Inspect those original captures for font, drawing and semantic quality. Actual preview interaction and assistive-technology acceptance remain separate observations.

Authored-image aspect ratios use the content box after subtracting the measured border and padding on all four sides; the tolerance remains `0.01`. Outer image bounds still determine visibility, header overlap and the complete PNG region. Both capture and receipt readback recompute the content box from the retained measurements, so a reported content size cannot hide a distorted image or invalid edge measurement.

Evolution's `figure-viewport.png` captures use natural scrolling to place the whole image below the actual site header when it fits. A taller image uses `figure-document.png`: a complete document-coordinate image region captured after scrolling to the document top, at the unchanged responsive viewport size. This is a document-region capture, not a single viewport view. No production styling, header visibility or image pixels are changed. The runner checks header intersection, complete outward-rounded image bounds, source and viewport stability, and PNG dimensions, and records the capture kind, scroll positions, rectangles and screenshot hash. The original article screenshot remains separate. Native document clipping uses the pinned Playwright 1.58.2 Chromium `fullPage` plus `clip` path; if the complete bounds cannot be captured faithfully, the case fails. Keep earlier occluded screenshots as failed evidence rather than replacing or relabeling them.

Outputs live under the selected figure's subdirectory. Screenshot names bind figure, selected asset variant, locale, theme, viewport, full candidate SHA and that asset's SHA-256; `metrics.json` records those bindings and failures. Switch remains the default profile. Every responsive capture identity names its selected variant and scenario; historical receipt names are preserved at their original source revision. The article's fallback `img` remains the locator, while its actual `currentSrc` and natural dimensions must match the explicitly allowlisted variant for that viewport. Built/source bytes must match for every variant, external browser requests are blocked, and unknown selections fail before asset reads or browser startup. A successful run does not replace human inspection of the captured screenshots or establish semantic approval. Historical screenshots are not evidence of a new candidate.

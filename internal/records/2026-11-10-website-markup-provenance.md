## Prepared executable boundary

`scripts/coverage-matrices/website-markup-provenance.mjs` extracts original response nodes with parse5 and records UTF-16 source ranges. It compares separately supplied native receiver facts, a response-body digest and a distinct navigation receipt. Identical response bytes from two navigations cannot substitute for each other's document lifetime. Nested previewers cannot lend their code receiver to an outer owner. Missing/duplicate/changed source members, changed original attributes, foreign/removed/non-DOM/ambiguous receivers, unknown insertion contexts and mismatched markup produce explicit unverified findings.

The finite highlighted-fragment shape permits only the current `pre/code/span` structure and a small declaration vocabulary. Unrecognized output is a review finding; it is not silently rehashed into an exception. This helper is **not used by the production checker**, is not a sanitizer, and never sets `sourceAdmission` to anything except `unverified`. Even a matching observation reports `servedSource: unobservable`. Supplied metadata is not authenticated browser execution, source authorship or review.

The source-reference fixture binds25 current direct producer/input/receiver/replacement-Copy files. It is a current-byte reference, not replacement historical evidence, a transitive dependency proof, an installed-package-byte receipt or proof of the server's source. Native execution must use independently frozen launcher/server/source receipts before any stronger source claim. A changed member requires review; do not mechanically regenerate this fixture to make a run green.

The new Node suite plans36 receipt/parser controls. These are explicitly supplied inputs. They retain empty-cleanup/static-icon equality controls and reject opaque/mutated snapshots, stale same-byte navigation receipts, altered producer attributes, missing sources and introduced executable/resource nodes or attributes. Existing **source** controls for static SVG, empty cleanup, opaque values, business/lexical shadows and promotion rejection remain untouched in `check-coverage-matrices.test.mjs`; the supplied receiver-descriptor controls are not claimed to prove arbitrary TypeScript data flow.

The new native suite plans17 cases:

## Profile versus cloning/template alternative

A narrowly bound profile could retain the current serialized-string path only after actual producer/source/receiver/lifetime proof and independent approval. Its reviewed membership must reject changed or unrecognized output. The study's source-reference and parser shape deliberately grant no such admission.

The alternative prepares highlighted SSR/template nodes and clones their DOM for later runtime selection; Copy feedback can retain authored glyph nodes. That changes insertion and ownership/lifetime responsibilities and must not erase SSR code, exact copy bytes, accessible names, focus, or transition cleanup. The native study makes a temporary, explicitly injected clone of actual code content and compares tree, exact raw data, displayed text, viewport tabindex, geometry and paint facts. It does not replace production controls. No alternative is selected before Main's actual rendering/content/Copy/lifecycle results, remaining Astro/retained-page evidence and independent review establish the applicable equivalence.

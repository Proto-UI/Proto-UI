# Dialog available-region geometry and transition property

On the current main UI code, the original Dialog available-space suite passed all four Brutalist journeys and failed all four Shadcn entries at the existing `transitionProperty !== 'all'` assertion. Those failures occurred in the first 390-to-390 check; they do not establish that this run observed later 430/320 interpolation.

The eight modern panel recipes specify `duration-100` without a transition-property token, leaving the computed property as `all`. New York already specifies `transition-opacity` with `duration-200`. The bounded repair places `transition-opacity` in the common Content geometry tokens so available-region position and size updates are not included in a generic transition. It preserves all nine recipes, their durations, independent fade/zoom keyframes and the logical 200ms enter/leave configuration.

The original nine live profile controls were extended without removing their existing identity, style-withdrawal, relation or open-owner assertions. On unchanged source, eight modern profiles failed and New York passed. With the common token, all 25 overlay-profile controls and both original Dialog tests passed. These are source-host/Rule controls, not native geometry proof. Exact-commit native outcomes are recorded separately with the original numeric checks, 150s deadline and historical classifier retained.

This follows the existing draft available-region geometry direction and does not claim complete upstream runtime parity or promote the family lifecycle. Independent historical probe calibration and the unrelated sidebar handback contract remain separate.

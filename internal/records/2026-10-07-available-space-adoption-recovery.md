# Available-space document-adoption refresh

Date: 2026-10-07. Finf [#872](https://github.com/Proto-UI/Proto-UI/pull/872), review [r4200878887](https://github.com/Proto-UI/Proto-UI/pull/872#discussion_r4200878887). Reconstructed against source baseline `86f2c0c52e370d703665028d8ef5cef45f0685a0`; this is a new verified recovery, not a claim that the interrupted local commit was recovered byte for byte.

`HC-AVAILABLE-SPACE-0001-OBSERVATION` already requires releasing the former document's observation before rebinding. The Web lease can do this on `requestUpdate`, but Positioning ignored the Runtime's updated notification. A retained Web Component's existing `adoptedCallback` requests a Runtime update; the current active available-space lease now receives that notification. The repair adds one call in `PositioningModuleImpl.onProtoPhase` and does not create a new polling loop, reset a terminal flag or acquire an inactive connection.

The module control verifies that an updated phase does nothing without a lease, refreshes an active lease without reattaching, and cannot refresh after disconnect or terminal teardown. The Adapter control runs the actual Web Component and Overlay/Positioning wiring. It adopts the connected host into another Document, supplies the existing Adapter's adoption callback, and observes the old document's probe disappear, one new probe appear, and the projected width change from 390 to 430. Closing releases the new probe; another adoption callback cannot revive that inactive lease. These widths are injected geometry. happy-dom's `adoptNode` does not invoke `adoptedCallback`, so the explicit callback is a disclosed harness notification, not native browser dispatch evidence.

The original shared four-Adapter fixture set a visual viewport width but left the required root-content geometry unknown at the DOM harness's default zero rectangle. Its four available-space cases failed identically on unchanged source and on the adoption repair. The fixture now supplies both root and viewport geometry and restores them afterward. The original 390px, resize, close and cleanup assertions remain intact. The host test that withdraws a genuinely unknown root box also remains intact; production does not gain a fabricated fallback.

With the corrected shared fixture and all new assertions preserved, the baseline produced **2 failures and 36 passes**; the repaired implementation passed **10 files and 38 tests**, covering all Positioning host/module tests and all four Web Adapter Positioning suites. The original fixture failures and the targeted adoption failures remain in the validation logs. Workspace TypeScript passes; catalog evidence integrity and lifecycle readiness pass **2 files and 93 tests**. This does not promote native, physical keyboard/occlusion or GPUI acceptance.

The current Runtime uses `mountPhase` for repeatable detach and emits the legacy `onProtoPhase('unmounted')` only during terminal disposal. No mounted-phase rearm was added: resetting Positioning's terminal guard from that notification could revive disposed callbacks.

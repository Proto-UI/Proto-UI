# Website typography projection, first bounded slice

Current user-directed implementation of #803 in #777. This is a dated record, not a new Base Typography guarantee. `C-FEEDBACK-STYLE-0003`, `C-TEMPLATE-0005`, and `C-PROTOTYPE-STYLE-CLOSURE-0001` remain draft. Official Base/Shadcn/Brutalist libraries have no general Heading/Text/Label Prototype to reuse. `SiteTypography` is an app-private experimental passive visual owner, like the existing app-only Link and Header surfaces.

## Ownership and runtime boundary

- `site-typography.proto.ts` owns family, role and compact-viewport typography using actual feedback tokens. No event, state, expose, a11y role, tabindex, pointer-events override, raw DOM, font request or native semantic ownership is added. Shadcn retains the site's existing system sans input; Brutalist uses canonical `font-sans`/500 and `font-heading`/700 from the accepted family theme. DM Sans does not supply Chinese glyphs.
- Native h1–h6/p/label/legend/anchor nodes, IDs, accessible names, label-for relationships, selected text and native links remain original DOM nodes. The adapter owns a passive visual surface around the original phrasing subtree. It never copies source text into a second VDOM or hidden fallback.
- `demo-types.ts` allows a host `span` box and an explicit Proto `rootTag: 'span'`. `demo-renderer.ts` passes that root to React/Vue/Vue2 and keys the component cache by both Prototype and rootTag. WC keeps its autonomous custom-element host, which is valid phrasing content. No div is inserted in p/label/headings. This does not add a Proto Template tag or change adapters' native control declarations.
- One page typography participant batches all targets in one framework renderer root and one runtime/prototype preparation. Each semantic text owner has its required real Prototype instance; there is no per-text scope controller, document observer, theme observer, module load or framework root. A 100-paragraph test asserts one batch/root and original text identity.
- The batch VDOM is immutable after preparation. Passive carriers may be borrowed into native owners only during synchronous activation. Before every framework teardown, carriers return to their actual original batch parent in original order. No props patch is issued while borrowed. Theme values update actual Prototype surfaces directly through the existing normalized theme channel. Same-generation rollback reactivates the retained real batch and transfers the same native text back.
- Source updates to text nodes are immediately visible without renderer work. Replacing native textContent/innerHTML invalidates the carrier lease; a new transaction reads the latest native nodes. A retired or failed batch cannot replay detached old source. One scope observer notices added/removed semantic targets; one media-query listener supplies compact viewport input.
- Homepage typography participates in the existing whole-page controller, including action groups, Header frame, Search and gallery, with the same generation and failed-publication rollback. Documentation has one independent `documentation-typography` scope, sharing the global preferred runtime and route family. It does not follow individual demo runtime overrides or add a new picker.

## Ownership-review repair within the first slice

Independent review found three P2 gaps in `7706556`: appended native sibling text could remain outside its real Typography slot; observing only a documentation root missed removal of that root itself; and a collapsed selection boundary expressed as a native p child offset changed meaning after wrapping. The original 15-case review probe was moved into `site-typography.ownership.test.ts` and reproduced six failures plus nine passing lifecycle controls before source repair. The initial positive 123-test packet therefore was not complete evidence for these boundaries.

The repair is confined to `site-typography.ts` and `site-typography-client.ts`. Refresh now detects any source sibling outside the active carrier and feeds the actual nodes through `sourceNodes` in native order; it never clones append/prepend/insertBefore content. Documentation observes stable Document ancestry, synchronously revokes the exact old registration before asynchronous cleanup, and validates registration identity so a retired owner cannot revoke a replacement. A settling transaction rechecks its scope to catch source additions whose observer already ran during preparation, including an initially empty scope.

Selection restoration snapshots the original adjacent source siblings at each element boundary. It locates those same nodes after source movement, mapping native element offsets into the new slot, back into a retained slot on rollback, and back into the native element on teardown. Renderer-owned empty containers resolve through their current native owner; source text-node offsets remain unchanged. Four real adapters cover start/interior/end collapsed boundaries, repeated replacement, failed publication rollback, carrier-edge and empty-slot caret cases. Explicit forward/backward endpoint fixtures supply only Happy DOM's known missing focusOffset getter; they exercise transfer, retained-candidate reactivation, entirely replaced native source and disposal. They establish the endpoint mapping algorithm, not real-browser range behavior. All nine independent positive lifecycle controls remain in the suite. Gallery/leaf-text expansion stays paused for source review.

## Passive homepage refresh and retained interaction state

A later whole-page review found that the first slice incorrectly sent viewport and source refresh through `controller.request({}, { force: true })`. The new `homepage-typography-state.test.ts` uses the real homepage coordinator, materializer, gallery composition, WC adapter and prototypes. Before repair, both desktop-to-compact and appending a native h2 replaced the actual gallery owners, cleared a 20-character draft and checked Switch, lost focus/caret, and advanced page generation 1 to 2 despite unchanged runtime/family. The earlier three ownership P2 repairs and their independent acceptance remain valid; they did not cover this whole-page interaction.

The correction stays in the app's homepage coordinator and passive typography participant. A viewport or source update prepares one replacement typography batch using the current page coordinates; it never requests another page generation or locks/remounts the gallery. The coordinator records the typography participant's explicit candidate identity, then updates the same candidate array owned by the current whole-page transaction. Theme updates, subsequent whole-page rollback and eventual disposal therefore follow the latest passive batch. Whole-page runtime/family changes keep their existing atomic controller and invalidate older local preparation through a separate epoch.

The typography participant exposes an app-private source revision based on native target/role identity, original source node order and compact viewport input. A prepared local batch is discarded if that revision changed; the next pass reads current native source without stale text replay. Only one passive batch can prepare at a time. After a failed attempt, the same input revision is not retried by the observer's own cleanup mutations; a genuine input change permits another attempt. Visibility is not part of semantic target discovery. No per-text renderer, controller or service is introduced, and Base and the global projection controller are unchanged.

The nine added strict tests retain the original two red assertions and cover local preparation/partial-activation failure, live draft input during a held passive preparation, newer source and viewport input, whole-page family supersession, whole-page publication rollback to the latest passive batch, source insertion during a real WC-to-React page transaction without an extra page commit, and destroy during local preparation. The intermediate failure injections also exposed and reproduced the cleanup-mutation retry before revision suppression. That focused packet passes 13 suites and 168 tests, including the original 155 and the existing real WC/React gallery integrations. Host media/theme values and bounded failure/delivery order are injected; actual gallery/framework owners are used. These remain host-unit results, not browser paint or viewport-layout evidence. Wider gallery/leaf typography migration remains paused.

A subsequent independent source-freshness review reproduced one further P2: an already-ready h1 whose authored `data-site-typography` changed from slogan to h2 retained the old role until an unrelated child-list mutation. Its other two probes, language plus complete textContent replacement and source insertion during failed cleanup, passed. The homepage observer now subscribes to attributes only through `attributeFilter: ['data-site-typography']`; it does not subscribe to generated typography metadata. Strict tests cover changing/removing a heading override, adding/removing an explicit marker on a pre-existing native span, original source node identity, retained gallery state, and exactly one materialization for each authored change after observer delivery settles. The independent original three probes pass after this single production configuration change; the two positive freshness probes are also retained in the formal suite. The final focused packet passes 13 suites and 173 tests.

## Tokens and evidence

`packages/cli/src/services/proto-style-css.ts` now lowers the canonical text-2xl/3xl/4xl/5xl and leading-tight/snug/normal tokens onto data-pui-style surfaces. The size scale is 1.5/1.875/2.25/3rem and unitless leading overrides are 1.25/1.375/1.5. The compiler preserves explicit leading after the text-size composite rule. This is evidence for the supported Web CSS translator only, not GPUI/Flutter/Qt support. `packages/cli/test/typography-tokens.test.ts` checks exact CSS and scope; `site-typography.test.ts` checks source token collection and one exclusive family/weight/size/color per role, including compact slogan/tagline. The website generator already unions app Prototype source into its generated stylesheet; no generated CSS is hand-edited.

Focused Happy DOM tests use real WC, React, Vue and Vue2 adapters; they cover repeated family/runtime replacement, carrier return before teardown, stable source/emphasis/link/input identity, label-for and heading hierarchy, text-caret identity and backward input selection, no duplicate IDs or new tab stops, failed publication rollback, dynamic source/language/content change, exact homepage generation, docs preference and cleanup. Old composition tests now explicitly expect the real Typography caption node, rather than hiding additional data-pui-root nodes with a filter. No icons barrel, package install, heavy build or local browser was used.

The Happy DOM selection implementation aliases focusOffset to anchorOffset, so noncollapsed and backward text-range preservation is explicitly reserved for real-browser evidence. Focused tests prove a text caret plus native input selection instead. Initial red evidence caught a conflicting font-sans/font-heading token recipe (repaired to one exclusive family token) and a stale control-caption test expectation (updated to the actual Prototype node). The initial native-link test also attempted Happy DOM default navigation; subsequent runs prevent default in the event probe and use no network navigation.

Happy DOM does not establish rendered font glyphs, visual quality, layout at 320/390px/desktop, light/dark screenshots, 200% zoom, RTL hit testing, or browser selection semantics. Exact integrated-SHA hosted Actions and screenshots remain required. In particular, real Chromium rendered-font evidence must distinguish DM Sans Latin from CJK fallback. These are pending acceptance evidence, not source-derived success claims.

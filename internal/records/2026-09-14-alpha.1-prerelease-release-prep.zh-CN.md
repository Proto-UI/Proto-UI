# `0.3.0-alpha.1` prerelease 准备与 bootstrap `latest` 门禁协调

## Context

当前用户选择以 `0.3.0-alpha.1` 作为完整 Proto UI package set 的快速测试发布，目标 dist-tag 为 `next`。这不是 stable 发布，也不要求删除 npm 在首次 bootstrap package 上自动保留的 `latest`。

## Observed facts

- `@proto.ui/adapter-vue2`、`@proto.ui/module-expose-event` 与 `@proto.ui/module-image-view` 的 `latest` 均仍指向 deprecated `0.0.0-bootstrap.0`。
- 这些 package 的 `next` 均指向已存在的 `0.3.0-alpha.0`，而不是 bootstrap 版本。
- npm 对唯一 bootstrap 版本的 `latest` 删除请求返回 `400`；不应为覆盖该 tag 单独发布 stable 或伪 release-train 版本。

## Decision

registry readiness 保持禁止 `bootstrap` tag 与 bootstrap `next`。当 `latest` 仍指向 bootstrap 时，只有该 bootstrap 已 deprecated，且它是唯一版本或 `next` 已解析到现存的非 bootstrap prerelease，门禁才通过。

该例外只描述 npm 的不可删除遗留 tag；真实 `0.3.0-alpha.1` 仍必须由完整 43-package release BOM、受保护发布 workflow、`next` 指向、Git tag 与不可变 snapshot evidence 完成后才能被记为发布。

## Follow-up

- 在受保护发布前重新运行 registry readiness、完整 rehearsal 与 consumer smoke。
- 发布后在独立 evidence 变更中记录 npm、tag、GitHub prerelease 与 snapshot 的事实；在此之前 `V-PROTO-UI-0010` 保持 `draft`。

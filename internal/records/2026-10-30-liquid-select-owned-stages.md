## Bounded website composition definition

A materialStage declaration belongs to an explicit ref-bearing div box. Existing box spread clones retain it. The common renderDemo entrance validates the full static tree before host ownership or DOM changes, skips its automatic outer scene for explicit stages, and attaches sources after actual refs commit but before the original setup. Framework tree, API identity, Tabs context, prototype selection semantics and setup remain unchanged. No component-name dispatch.

Each attachment borrows scope/flow/empty-overlay boxes and owns only its visible canvas, source lease, provider/destination registrations, observers, listeners and authored style values. It never moves or removes framework children. Rollback attempts every release and preserves primary and cleanup errors, including falsy throws. Restoration compares the current value and priority with the applied value; a different later write is preserved, but an equal-value later write is indistinguishable. These plans are trusted static demo declarations, not an arbitrary cyclic/untrusted-object parser. Existing scene creation remains supported.

Static v1 rejects nested stages, duplicate/aliased refs or targets, non-descendant targets, dynamicChildren and existing ancestor material providers. Non-stage dynamic behavior is unchanged. Cross-stage dynamic mutation is not implemented. Later registration rebinds eligible material sinks; an already-open portal retains its chosen destination and must not sample a retired source. Native epoch evidence remains required.

The original uncontrolled, disabled, controlled-request/Accept and RTL-long-label examples all remain. Status/Accept move before the controlled trigger. Layout reserves the measured popup footprint, not a fixed giant blank area. Upward collision or source-exiting placement retains the original guard/fallback rather than suppressing collision behavior.

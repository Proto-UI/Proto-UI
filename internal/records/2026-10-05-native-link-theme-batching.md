# Native-control batch theme sampling

This is a Website consumer optimization for #777 against `732e6f2769b7e1bb53d30c04fb02f579b36f0a61`. It preserves the draft `P-BASE-SURFACE` passive-owner boundary and `P-BASE-TEXT` content/passivity criteria. Public family Surface/Text, native anchors and their content leases remain the actual implementation. No Base, Adapter, recipe, copy, stylesheet or readiness-budget change is introduced.

## Change and provenance

The existing #816 mechanisms in `a8aef9a3e4a8d7ebc90f0f69f29b2daea2780f11` and `779c19fc5208a8da2839c1ca8be73155f305ab0d` provide the bounded starting point: one closed theme snapshot per initialization batch, one shared root/media observer, fingerprint-suppressed broadcasts and live sampling after initialization. Only that consumer mechanism is adapted. The #816 summary/nav-group and reading/emphasis changes are excluded; #777's anchor selector and recipe arguments are unchanged.

The initial root snapshot precedes every Surface/Text write in the batch. Duplicate initialization with no new native owners returns without reading a theme. Root class, data-theme, inline style and family changes, plus color-scheme media changes, each resolve once per notification and broadcast only a changed palette or family. Identical palette values do not suppress a real family replacement.

Live sampling is intentionally connected to the existing native-facts callback rather than adding a second document capture-listener layer. This preserves the old next-fact visibility of CSSOM changes when pointerup or blur arrives at window, and when aria-current/in-view changes publish facts. The first synchronous fact publication for every owner uses the initialization snapshot; later publications share an immediate first sample and at most one trailing sample if more facts arrive before its microtask. Coalesced facts still publish their visual state in order; the trailing sample reconciles any intervening CSSOM edit. The sampling flag is set before refresh. The callback stores the triggering owner's new facts before a changed-theme broadcast. Broadcast calls only visual `update` functions, never the fact publisher or sampling callback, so it cannot recursively sample. If the palette is unchanged, only the triggering owner's ordinary update runs. A changed palette updates every owner once for that broadcast; later individual fact changes still update their own presentation.

A trailing sample checks batch liveness and therefore cannot read or broadcast after release. Release first revokes batch sampling and disconnects root/media observation, then releases each fact bridge and native content. Queued replay keeps its existing binding-alive guard. A later initialization owns a fresh snapshot, and old idempotent release cannot revoke it. Sampling is per initialization batch, not a global theme cache.

## Review-driven timing correction

Independent review rejected the first frozen candidate: one immediate sample followed only by resetting its deduplication flag lost a CSSOM edit between two facts in the same task. With the real resolver and public WC Text, a pointerdown handler registered after the bridge inserted `:root{--pui-foreground:#ff0000}` into a stylesheet and then focused a second anchor. The root computed style and focus were correct, but the second Text remained `#222222` even after settlement. The original `732e6f276` per-fact implementation passed that comparison. Both an injected-palette and real-CSSOM regression failed on the first candidate before the repair.

The repair marks any coalesced facts dirty and performs one bounded trailing refresh at the already-scheduled microtask. Startup remains one pre-write root read. A synchronous interaction burst now permits two reads rather than enforcing the rejected one-read goal. This intentionally differs from the baseline's immediate reread after every fact: later same-task theme edits settle at the microtask tail rather than necessarily before that fact handler returns. No stable per-handler synchronous theme guarantee is claimed. The host-unit evidence checks settled palette and final per-owner pressed/current facts, a later microtask palette change, and immediate release canceling dirty trailing work. A real stylesheet `insertRule` plus actual `focus()` case verifies the public Text palette by Happy DOM's next frame callback; that scheduling check is not real browser paint evidence.

A bounded case in the existing `site-native-links.browser.test.ts` uses the normal Shadcn docs page and two already-enhanced visible sidebar anchors. A real pointerenter triggers a fixture CSSOM edit followed by native focus in that event; its first animation frame records the root token, actual public Text token/computed color and retained focused native owner. The usual source-bound capture is recorded. This test has no new readiness budget or timeout extension; execution and screenshot review remain separately reported.

## Hosted fixture precondition correction

The first hosted native-links run on `8b0f2d144e82464d2c03289bc7e7330b44e57490` passed its other nine cases but the new CSSOM case timed out while selecting a second inactive sidebar anchor. It never reached the CSSOM or first-frame assertion. Installed Starlight `SidebarSublist.astro` supplies `aria-current={entry.isCurrent && 'page'}`; this emits a false marker for inactive links. The existing runtime source contract and two passing navigation fixtures already distinguish `aria-current="false"` from `aria-current="page"`. The new selector incorrectly required absence of the attribute.

The fixture now uses the same `:not([aria-current="page"]):visible` predicate as those existing consumers. The source contract retains its false/page/absent negative controls and forbidden presence-only selector check, with its exact inventory updated from two to three consumers. No timeout, first-frame assertion, native-control implementation or Search oracle changes. A local contract run reproduced the selector rejection before this correction.

Any future case failure records the phase, sanitized route/href paths, actual sidebar marker values, counts and visibility, plus a current screenshot when possible, then rethrows the original error. The first failed case produced no DOM/trace artifact; successful sibling screenshots are not represented as that missing failure DOM. Real CSSOM/frame acceptance remains pending the corrected hosted case.

Independent review then identified a potential evidence-only disclosure path in the new catch: URL-bearing error strings and capture logging could retain credentials, query values or fragments. There is no evidence of an actual secret disclosure. The catch now reuses the existing `safeError` helper for primary, diagnostic and capture errors; `captureLinks` reuses `safeUrl` for its page URL. No parallel partial regex is introduced. New source-executing negative tests exercise the actual catch and capture function with same-origin HTTP URLs, credential-bearing URLs, WebSocket URLs and external URLs, assert sanitized persisted/logged outputs, and retain the original thrown error identity. Both tests were red before this correction.

# Documentation Contents command projection

This human-directed #777 consumer slice replaces the imported Starlight MobileMenuToggle with an application-owned fallback/mount. The upstream custom element is absent from the Header, so its native click/keyboard owner cannot duplicate the new Button activation. Existing native Sidebar links, routing and current-article behavior are unchanged.

`siteContentsNavigation` retains one directory-disclosure state owner. Its stable PageFrame initializer remains compatible with legacy consumers. The application owns `aria-expanded`, `aria-controls="starlight__sidebar"`, the body's `data-mobile-menu-expanded`, navigation mutual exclusion, outside/link closure, desktop collapse and Escape return focus. Command views bind generation-aware focus leases. Native fallback activation uses the native click route, including browser Enter/Space synthesis; enhanced WC uses only public CustomEvent activation, and React/Vue/Vue2 use the public callback projection. The Button, with an existing Lucide list icon child, owns semantic activation, disabled/focus/press behavior and all enhanced control paint. It is not nested inside another semantic Button.

The Contents participant joins the existing Docs Header surface controller. Both candidates prepare before either is published; failed preparation disposes successful siblings, initial failure retains the usable native fallback, and later failure retains the prior truthful committed generation. The existing runtime preference selects WC, React, Vue or Vue 2. Homepage ownership and independent Search/Theme/other Docs controls are not included in this bounded scope. This is not whole-document atomicity, a new Base protocol, or an admission of any draft Button contract.

Paint is a real migration. Shadcn uses the actual ghost icon Button, matching sibling Header command roles; field Select borders are unaffected. Brutalist uses the actual surface icon Button and its existing canonical rounded-base/2px-border/4px hard-shadow/DM Sans recipe, replacing the old site CSS square/3px shadow imitation. The app provides only a 44px target and layout. The SSR/failure native fallback is deliberately plain and does not claim family rendering. Without JavaScript the PageFrame hides the unused command and keeps the complete directory in document flow.

Node 24 socket-free focused tests exercise production-derived fallback markup, all four actual public renderers in both families, click/Enter/Space once, accessible name/relationships, disabled and staging/locked gates, fallback and deferred-focus lifecycle, mutual exclusion/outside/link closure, generation synchronization, first-load and later failure, and repeated initialization/cleanup. Theme helpers are test substitutes, and injected DOM keyboard events are host-unit evidence. These checks do not prove browser paint, accessibility-tree output, native fallback keyboard synthesis, clipping or physical hit-testing.

The existing homepage/native-link Actions journeys now target the active explicit command instead of the removed upstream element. A four-runtime/two-family browser journey adds real keyboard actions, target/hit/focus facts and screenshots with source SHA and dirty state under the existing homepage evidence artifact. It is authored but has not run locally: local browser/server/socket and heavy builds are excluded in this task. Exact integrated-SHA Actions execution and visual inspection remain required.

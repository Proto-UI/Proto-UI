## Narrow product change

1. Resolve `--site-default-font-sans` at `:root` from the existing ordinary site `--font-sans`; do not redefine that stack or introduce a font resource.
2. Provide an application-private `[data-site-font-scope]:not(:root)` author rule in the base layer, after family/projection defaults. Its input is `--site-font-sans`; it supplies the scope's font-family and Tailwind sans input.
3. Explicitly declare the existing Gallery section to use the independent root bank. No layout, family recipe, runtime ownership, or appearance choice changes.

Contract: the scope belongs on a descendant, not the root bank's node. An author must supply a complete literal or independent font bank, not a circular reference to this same scope's `--font-sans`. Same-node author scope wins over the family and projection defaults by specificity/order. Higher-layer utilities and authored inline font-family still win. An explicit nested family/projection may select its own font. This is an app-private convention, not a Prototype/runtime marker.

Static review found and corrected two earlier candidate issues before any run: root use could create a custom-property cycle, and an earlier/less-specific rule could lose to a same-node family or projection default. Browser proof remains required; source presence of a theme variable does not prove its compiled value.

## Actual first-frame result at the original head (2026-11-04)

The earlier unrun descriptions above are preserved checkpoints. The paired run 41483779188 compared the parent `d850c28a4` with the product candidate `026db20ca`; the author-boundary commit `caaedfc06` is the product change that answers it. The run at the actual original head `c3bda271a` (run 41619044360) is the current evidence: the original `browser-evidence` job reports `Tests 9 passed (9)` for the unchanged file `library-cards-first-frame.browser.test.ts` (sha256 `0321dc7b6eed1fa9660f9e5c5bd00e2e125f277b980c1bada12f9a6b39fa2ac1`), and the supplemental `font-author-boundary` job succeeds on the same head. The 1/9 candidate measurement therefore belongs to `026db20ca`, not to the original head.

The measured root cause is the family scope, not the Gallery. `apps/www/src/components/override/PageFrame.astro` publishes `data-site-family-scope` with `data-site-library-family="shadcn"`, and the new base-layer rule `[data-site-family-scope][data-site-library-family='shadcn']` gave the whole page the family font bank. The Base and Lucide card Text parts emit no font-family of their own, so they inherited that page-level family; the Shadcn Text part declares `font-family: var(--pui-font-sans, …)` itself, and Brutalist, Bootstrap and Liquid Glass receive their own `--pui-font-sans` from the Gallery theme block. The family font is a network font, so the held first frame drew the fallback and the enhanced frame drew the family face. That is why the strict held/enhanced equality failed for the eight cold cases with Base action 124.0625 → 120.609375 and Lucide title 84.703125 → 72.53125, action 137.109375 → 132.34375.

The product answer stays the Gallery scope. The Gallery section declares `data-site-font-scope` with `--site-font-sans: var(--site-default-font-sans)`, and the base-layer rule `[data-site-font-scope]:not(:root)` restores the site's own font bank for that subtree. The scope belongs on a descendant, its input is a complete bank rather than a reference back to this scope's `--font-sans`, the same-node author scope outranks the family and projection defaults by source order, and higher-layer utilities and authored inline declarations still outrank it. A source guard now keeps that order and the Gallery's own bank explicit, so a family default moved after the author scope cannot silently repaint the Gallery.

## RuntimeBox live demo refs: an unsettled shared contract (2026-11-04)

`apps/www/src/components/PrototypePreviewer/runtime-preview-surface.ts` replaces the setup-time `refs` snapshot with a live Proxy view over the renderer-owned membership, keeps the reserved surface refs unreadable and unwritable, keeps caller writes local, and freezes a retirement snapshot at cleanup. The reserved-ref rejection matches the recorded RuntimeBox boundary in `internal/records/2026-10-03-runtime-box-single-surface.md`, and the traps keep the JavaScript own-property invariants: a non-extensible target reports exactly its own keys, a live key is reported as a configurable own property, and a reserved write returns false, which is a TypeError in strict mode.

What remains unsettled is the shared contract, not the implementation. `DemoSetupContext.refs` is typed `Record<string, HTMLElement>` without a liveness statement, while `DemoRuntimeApi.getPublicInstance` documents the live lookup channel separately. A live `refs` view and a setup-time snapshot are different guarantees for every RuntimeBox consumer, and this record does not choose between them. The change is therefore disclosed as a shared-surface semantic change rather than a font change; the font-selected owned-surface class belongs to the projected node, not to the refs view, so the font work and this contract question stay separable.

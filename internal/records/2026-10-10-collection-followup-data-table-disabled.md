## Authority and the narrow repair

`DataTablePreviousProps` and `DataTableNextProps` alias ButtonProps. Draft `P-BASE-BUTTON` requires controlled disabled synchronization, truthful exposure, transient cleanup, focus-request rejection and activation suppression. Root's existing requestPage already rejects its disabled input. The owner-directed scope therefore merges **local or Root disabled only** into the one existing nested `as-button` state owner and reused privileged Focus handle. The wrapper checks the same source predicate before its own request, including local or Root input changed synchronously by the nested Button outward click. Root remains the only page owner; readOnly still permits paging. No second Button/Trigger, host access, timer, index inference or shared Module change is added.

No first/last-page disabled/tabstop policy is inferred from Root no-op normalization. That presentation remains a separately bounded choice. The existing Carousel/Resizable/Tree fixes from `0267e684` remain intact. The only production change in this follow-up is local `data-table/index.ts` pageControl.

## Definitions required before the other changes

- Carousel must choose whether Root index is a collection ordinal or authored stable identity, how omitted/duplicate/sparse indexes are admitted or diagnosed, and how insertion/removal/reorder and controlled values interact. Draft `C-AS-COLLECTION-ITEM-0001` supplies ordered metadata; it does not make that family-level choice. The earlier invalid default99 reconciliation also remains unresolved. No registration-completion timer/microtask is introduced.
- Resizable must define primary/secondary Panel identity, the status of omitted index, duplicate/invalid indexes, reorder and exactly-two-panel validation. Automatic order and explicit required identity are different compatibility decisions, so neither is silently chosen here.
- Header/Tree keyboard definitions must specify which focused/enabled/readOnly actions consume Space, repeat/modifier behavior and request timing. These parts use asTrigger, not asButton; draft `C-AS-TRIGGER-0001` explicitly leaves Focus/A11y policy to consumers. Draft `HC-DEFAULT-ACTION-0001` supplies cancellation capability, not a universal Space rule.
- Tree needs an accepted focus-recovery owner and target policy for a focused descendant hidden by controlled collapse, including nearest enabled ancestor versus another visible node, external/newer focus, root disable, graph invalidation and controlled rejection. The older September dual-anatomy non-selection recommendation is expressly non-normative and describes a different Tree, so it is not transplanted into the current implementation.

Public comparison is useful but does not settle those API choices. [W3C APG carousel](https://www.w3.org/WAI/ARIA/apg/patterns/carousel/) describes visible slide navigation; [window splitter](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/) distinguishes primary and secondary pane sizes. [APG keyboard guidance](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/) supports keeping focus visible after its target is hidden/removed, while its disabled-control examples allow pattern-specific focus conventions. [Treeview guidance](https://www.w3.org/WAI/ARIA/apg/patterns/treeview/) separates focus from selection; its Space discussion for multiselect models does not automatically define this single-select implementation. These sources were read only; no third-party implementation was executed.

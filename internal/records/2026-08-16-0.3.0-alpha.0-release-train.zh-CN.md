# 2026-08-16 `0.3.0-alpha.0` release train

> Internal record. Not normative. 本记录保存 0.3 首条 prerelease train 的开启背景、当前范围与后续发布边界；稳定发行身份由 `V-PROTO-UI-0009` 与 `D-PRERELEASE-STAGE-0001` 治理。

## 结论

维护者开启 `0.3.0-alpha.0` draft release train，使 0.3 开发中的 spec entity、Prototype 与其他经过评审的变化可以引用一个已声明的精确版本，而不再被 `check-version-governance` 以“未声明 0.3.0”阻塞。

0.3 当前仍允许架构调整、顶层 API 变化与新 feature，因此使用 `alpha`。核心范围与主要 API 收敛后才进入 `beta`；只有维护者认为版本可直接晋升 stable、仅待最终验证或 blocker 修复时才使用 `rc`。

## 当前范围

本准备分支只建立当前 `main` 上 40 个公开 package 的全局精确发行身份，不提前吸收其他工作区中尚未合入的新 package 或实现。后续合入的新公开 package 必须在真实发布前进入同一 release BOM，并完成 npm identity 与 Trusted Publisher 准备。

根 `VERSION`、当前 40 个公开 package manifest、release notes、BOM 与 launch governance 均投影为 `0.3.0-alpha.0`。本分支不执行 npm publish、不创建 tag、不移动 `next`，也不激活 V entity。

## 贡献者解阻

该 release train 合入后，面向 0.3 的贡献者 PR 应 rebase 到最新 `main`，并把新增实体的 `since` 与 revision version 精确写为 `0.3.0-alpha.0`。Roadmap 中的“v0.3”名称仍不是可替代 V entity 的版本声明。

## 发布后续

真实发布仍需通过完整 release rehearsal、registry identity preflight、受保护 npm environment 与独立 evidence PR。任何届时新增的公开 package identity 由对应实现任务负责准备；本 release-train PR 不执行外部 registry mutation。

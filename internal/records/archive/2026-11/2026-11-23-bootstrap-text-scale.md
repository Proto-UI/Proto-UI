# Restore Bootstrap Text's defined scalable metrics

The original general queue on `d0392fb3` exposed disagreement between the public Text journey and Bootstrap's pixel-scale implementation. Draft `P-BOOTSTRAP-2-3-2-TEXT-PROJECTION` already requires the standard named Text scale in rem, with the explicit 24.5px-at-16px-root 2xl exception, 20/14 normal leading and 40px-at-16px-root 2xl relaxed leading. Independently, `T-BOOTSTRAP-2-3-2-THUMBNAIL-RECIPE-0001-CASE-TEXT` requires actual family Text plus physical CSS to produce **sm-normal 14/20** and **2xl-relaxed 24.5/40** at that root size. The former sm implementation selected 11.9px. No definition is changed to accept that drift.

## Product and oracle repair

Bootstrap Text now uses its defined standard named size tokens, with **1.53125rem** for 2xl and **2.5rem** for 2xl relaxed leading. Its explicit 20/14 normal ratio is retained. The selected size remains passive presentation: native headings, paragraph roles, content and interaction ownership stay with callers. The theme-owned muted foreground follows the already adopted adaptation recorded in `2026-11-09-bootstrap-page-and-draft-badges.md`; it is not replaced with the older hardcoded #999.

The CLI Text physical-CSS oracle is reconciled to those existing definitions and the exact authored-source `proto` export condition for Base. It still checks all defined sizes, leading precedence and complete CSS support for every family. The independent four-Adapter Text journey is **unchanged**. The Thumbnail test file previously contained only the Surface case despite defining a separate Text case; it now creates the real Bootstrap Text under a native heading, changes the two defined size/leading pairs and checks exact physical declarations and retained native/child identity.

The draft family token bank is generated by the existing canonical `generate-draft-family-style-tokens.ts`, not edited by hand. Only Bootstrap's actual token closure changes; Liquid remains byte-identical. No compiler admission, style vocabulary or unsupported-token policy changes.

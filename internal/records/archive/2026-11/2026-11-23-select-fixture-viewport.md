# Select alignment fixtures retain the root viewport

The general CI failures in the Base and shadcn Select alignment-owner suites came from a shared geometry stub that applied the popup-sized default rectangle to `document.documentElement`. The current root-space observation therefore correctly saw a 180 by 32 containing region and clamped alignment to that artificial boundary. The fixture had not supplied the page viewport it intended to model.

Both fixtures now return the actual test window dimensions for the root element rectangle, `clientWidth` and `clientHeight`. Popup, trigger, value, item and scrolling measurements remain unchanged. In particular, the selected-label alignment assertions still require their original coordinate of 175; no expected result, clipping margin, readiness state or transaction budget changed. This follows the root-space input ownership of `C-ANCHORED-POSITIONING-0001` and the selected-value alignment behavior already asserted by these suites.

The original two Select suites and the concurrent Bootstrap projection regression passed **3 files / 58 tests / zero failed or skipped**. The Bootstrap file contains a separately reviewed conceal-barrier fixture correction, so the combined count is regression context and does not imply that this six-line change repairs that file. The [receipt](https://github.com/Proto-UI/Proto-UI/blob/cae25ae39f926e9556ec40fe2c7ed46a2025091f/internal/records/evidence/2026-11-23-select-fixture-viewport/receipt.json) records the precise source hashes, command, scope and complete compressed test output. This is controlled host geometry evidence; native browser positioning and release acceptance remain separate.

## Definition and implementation boundary

The four affected ControlLabel entities remain **draft**: [C-CONTROL-LABEL-0001](../../../../spec/contracts/C-CONTROL-LABEL-0001.yaml), [M-CONTROL-LABEL-0001](../../../../spec/modules/M-CONTROL-LABEL-0001.yaml), [HC-CONTROL-LABEL-0001](../../../../spec/host-caps/HC-CONTROL-LABEL-0001.yaml) and [T-CONTROL-LABEL-0001](../../../../spec/tests/T-CONTROL-LABEL-0001.yaml). They now state the bounded Rust nominal-reference, explicit-instance association, lease, naming and activation conditions. This does not expand the ECMAScript same-realm ABI into Rust or admit mixed compiled/GPUI Adapter pairs.

The compiler lowers the public `asControlLabel` operations generically. It does not select code by component name, source path, package, text or role. Complete, unchanged Base Button, Toggle and Label definitions are compiled through `compileFile`, including their actual import closure, into three independent crates. Their source hashes and complete inputs are in the [producer receipt](https://github.com/Proto-UI/Proto-UI/blob/cae25ae39f926e9556ec40fe2c7ed46a2025091f/internal/records/evidence/2026-11-23-sprint5-compiled-control-label/native05/source-receipt.json.gz). All fixtures share one content-compatible native SDK through the supported shared-SDK path; no generated Rust was edited.

`ControlLabelRef` is a nominal Rust identity carried through typed `InstanceAssociations`, not Props, JSON or a structural brand. The SDK owns weak participants, current pair identity and lifecycle leases. An old pointer or action request cannot survive association replacement, duplicate participation, detach, remount or disposal. The target retains its existing authored activation callback and its own disabled, controlled-value and focus decisions. A public action supplied the wrong actual native Window rejects before target work or native effects.

Naming projects an actual native `labelledBy` relation and preserves an explicit author name. The Label gets no independent Tab stop or keyboard behavior. Its activation settings default to false, matching the shared Module; Base Label explicitly enables its own policy. Both Label and target handles accept the shared legal setup/callback `sync` phases. Updating target settings does not turn the target into a Label or retire an otherwise current Label request.

The opaque native-child boundary refuses outer Label activation when the host cannot certify the child's interactive path. It preserves the child's own input, while ordinary Label text outside that child remains eligible. Native Anatomy pairing is still explicitly rejected. Authored focus retains the existing native deferred effect cycle: same-stack State or association reentry is not claimed as synchronous physical-focus notification.

Two further generic host prerequisites were exposed by consuming the unchanged real Base definitions:

- Plain native Text creates no selection controller. The compiler SDK now has the existing host's exact `user-select: none` and `-webkit-user-select: none` mappings. `auto`, `text` and other unimplemented values still produce explicit unmapped diagnostics. The separate native style test protects both sides of this boundary.
- A declared accessibility `activate` action enters the existing `press.commit` route. Under `C-A11Y-0001-F`, the declaration's event is the authored outward result, not a fabricated input or an instruction to emit directly. Original Button/Toggle disabled and controlled guards remain in their authored code. The callback lease binds the exact setup declaration and metadata, current mounted epoch, live owner and actual Window. Other admitted native routes retain their declared/default behavior; unknown action names still reject explicitly.

The source lowering explanation is updated in [control-label-native-lowering.md](https://github.com/Proto-UI/Proto-UI/blob/df54e9b7bb8f5cd8a110dfff1ab42980242dea5d/internal/compiler/control-label-native-lowering.md). Current Input, ToggleGroup, native Anatomy, mixed Adapter/compiled association, and canonical Qt/Flutter coverage are not asserted by this slice.

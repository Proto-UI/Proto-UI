# Sidebar fallback family radius

The independent review of the original Sprint 2 artifact found a real geometry difference: Brutalist enhanced sidebar rows have four **5px** corners; the original failed-script and no-JavaScript rows have four **0px** corners. The original native observations are retained byte for byte in the [evidence directory](https://github.com/Proto-UI/Proto-UI/blob/cae25ae39f926e9556ec40fe2c7ed46a2025091f/internal/records/evidence/2026-11-23-sidebar-family-radius/manifest.json), bound to `d0392fb3`, run `45146671689`, artifact `14805214684`. The broader 84-capture review is recorded separately in `2026-11-23-sprint2-site-visual-review.md`; the mobile no-JavaScript capture actually has a dark document and is not claimed as light-theme coverage.

`sidebar.css` already gives unenhanced anchor and summary rows `var(--site-brutalist-radius)`, the same authored **5px** family theme value used by the passive Surface after enhancement. An unlayered `border-radius: 0` group in `site-library-family.css` included both sidebar selectors and overrode that layered rule. This change removes only those two selectors from the square-corner group. The existing native elements, current marker, focus outline, hit targets and other navigation recipes remain under their original owners.

The original desktop and mobile Sprint 2 browser cases now additionally require all four Brutalist corners to equal **5px** in every existing mode. Their group/leaf equality, actual hit testing, native disclosure input, focus/identity observations, **32px/44px** minimum heights and **60-second** case deadlines are unchanged. This closes the prior oracle gap that allowed matching zero corners to pass within each mode.

# Require the published split surface marker for live paint ownership

The original general regression removed `data-pui-split-surface` from an already painted owned-decoration surface, then called the real WC update. Reuse incorrectly succeeded. The first immutable blueprint may precede the effects owner's initial marker publication, so its recorded marker can legitimately be absent. The existing one-way initial-publication allowance therefore cannot by itself prove that a later absent marker is still valid.

The current paint-owner predicate now checks the exact live surface marker after any projection has been applied. Before the first application, its existing staging behavior remains unchanged; after application, external marker removal invalidates physical reuse even if the initial snapshot also lacked that marker. All existing root-token, surface-token, style, blueprint, caller and lease checks remain. This enforces the current physical-view requirement of draft `C-FEEDBACK-STYLE-OWNED-TARGET-0001-LIFETIME` without changing draft status or introducing a new target capability.

Only one product guard changed. The original owned-decoration, split-effects and composed-prototype admission suites passed **3 files / 108 tests / zero failures or skips**, including valid initial/deferred publication and the original removal control. No test assertion changed. The [receipt](evidence/2026-11-23-split-marker-ownership/receipt.json) links the preserved original failure and complete candidate output. Native owned-decoration/compositor validation remains separate; this later guard was not included in S3 replay 06's frozen `a223be14` source.

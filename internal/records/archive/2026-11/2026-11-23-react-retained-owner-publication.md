# Publish an initially absent React owner after initialization

Two original failures shared one product cause: the retained Context provider lost its authored child before its first view, and the real React demo could not bind Input Shell/Control public instances inside an initially closed Dialog. The other three Web Adapters supplied those children correctly.

React starts its owner-aware Adapter with `shouldExist=false` until setup and created callbacks establish the initial ViewIntent. For an initially closed Overlay, initialization completes but that intent remains false. Updating the state to the same false value does not rerender React, so the render function never observes the newly established presence binding. Its existing retained-shell branch is never reached.

The Adapter now publishes owner initialization independently from the desired view state. After the owner session has completed initialization, React reconciles the existing hidden Overlay shell and authored children even if the initial intent is still false. This does not attach the parent's view or invoke its render/commit/mounted callbacks. The shared retained-owner test still requires zero parent mounts, exact child created/mounted reads of the nearer Context value, retained child Anatomy membership and isolation from the outer owner. The same public-instance test still opens, closes and reopens the real Dialog and checks actual bindings.

This implements the initial-reconciliation and retained-owner boundaries of `C-LIFECYCLE-0008-C/E/H/J`. Direct L1 consumers continue to follow their existing unmounting policy; the general lifecycle contract does not newly promise that all detached hosts retain child component instances. No test assertion or fixture was changed.

The focused original reproduction had **2 failed / 3 passed / 53 not selected**. The same selection after the repair had **5 passed**, with the same 53 unselected tests. The subsequent unfiltered nine-file regression passed **70 tests with zero failures or skips**, covering all four Context adapters, full public-instance tests, React L1 reconciliation, view reveal, Portal ownership and view-operation withdrawal.

## Cause and rejected shortcuts

Registration replay correctly treats an unproved earlier call as a possible same-name hook registration. In the actual Tabs setup, leading `def.props.define(...)` and `setDefaults(...)` made the later `asTabsTrigger()` result unknown. An in-memory AST control that removed both leading calls recovered the producer and its seven State handles. Keeping either call withheld that proof.

Treating literal Props arguments as globally harmless was unsound. Hooks can receive an already active Def, whose Props schema contains a validator; even literal defaults can execute that callback. A `definePrototype` spelling or export also does not establish that every invocation receives fresh modules. The repair therefore preserves the general source-summary refusal.

Four independently identified boundaries were retained as real counterexamples:

| Boundary | Observed rejected-candidate result | Resulting constraint |
| --- | --- | --- |
| A later setup parameter initializer registers a competing hook | 11 passed, 1 failed in the 12-case file | Exactly one setup parameter; no initializer or rest parameter |
| Shared Props defaults invoke an existing validator | 12 passed, 1 failed in the 13-case file | No fresh-Props authority for shared hook frames |
| A getter runs after Props initialization and before capture | 12 passed, 2 failed in the 14-case file, including the shared-validator failure | Check the complete interval up to the actual producer capture |
| One selector has both Template and newly projected Root uses | 18 passed, 1 failed in the 19-case file | Merge uses by target, not by string-set difference |

The interval correction alone produced 13/14, leaving the shared-validator counterexample red. Earlier 12/12, original 79/79, related 602/602 and 18/18 results remain historical observations of earlier candidates; they did not establish the final boundary.

## Explicit resource scenario

The new `projectStandardRuntimeRootStyleTokens` API models one explicit standard Runtime instance of a selected source's canonical default Prototype. Standard [Runtime construction](../../packages/runtime/src/instance/instance.ts) creates a new [Props kernel](../../packages/modules/props/src/kernel/kernel.ts) before setup, initially without schema, defaults or raw values. This is a scenario-specific resource projection. These Props-prefixed captures remain `unknown` in ordinary `createHookSourceSummaryContext()` queries.

Selection binds the actual factory, setup declaration and selected SourceFile object identity. It accepts a bounded name/setup configuration and stable default entry. Admission then requires the matching Def parameter, synchronous setup, closed literal Props data and the complete prefix before a direct producer capture. Unknown calls, getters, computed keys, spreads, escaped receivers, extra parameters and borrowed setup uses remain outside the proof. Unselected imported entries and hook bodies do not inherit the selected Root scenario.

Each projection owns a separate summary/module context, collector module cache, scope and graph-version tracking. Its tagged result contains immutable string tokens; producer values and capabilities are not merged into general queries. Controls exercise both query orders, replacement ASTs at the same path, and both file orders.

The actual Tabs chain uses closed Root Props initialization before the first capture. Review of the bounded Base Tabs/Core hook path found no additional Props validator installation there. That finding does not classify arbitrary hooks or Host callbacks as pure. Broader helper-call and Rule-condition work remains with #1759; this change supplies the bounded physical CSS resource scenario.

## Root and Template ownership

The ordinary collector still collects its existing resources. An additional pass runs only when a selected Root has a qualifying prefix and capture. It uses an independent inventory to collect Rule variants through the existing Root channel, then unions those final strings.

A token already present only on Template must also enter Root when a projected Rule uses the same string. Comparing global or per-source token sets lost that second use. The final implementation unions Root uses directly while retaining Template uses. The new collision control also checks that unrelated Template-only `italic` stays outside Root.

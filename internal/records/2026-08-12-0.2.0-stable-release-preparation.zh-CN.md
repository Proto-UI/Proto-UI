# 0.2.0 stable release train 准备记录

日期：2026-08-12

## 背景

`0.2.0-rc.7` 已于 2026-08-11 发布全部 40 个公开 package、Git tag、GitHub prerelease 与不可变 spec snapshot。对应的完整证据回填 PR #365 已于 2026-08-12 合入 `main`，merge commit 为 `118d26fd155ca0fcdaa8bb3527cfc6cb6f8e8844`。本准备分支已重放到该 commit 之上，#366 的 base 随后切回 `main`。较早的 #364 覆盖面较小，属于重复方案，不作为本 release train 的父级。

本记录描述稳定版准备方向，不宣称 `0.2.0` 已经发布。

## 稳定版身份

- 新增 draft `V-PROTO-UI-0008`，声明 exact version `0.2.0`、Git tag `v0.2.0`、stable channel 与 npm `latest` dist-tag。
- 根 `VERSION`、40 个公开 package manifest、workspace lockfile、launch governance release line 与 deterministic BOM 同步投射为 `0.2.0`。
- 双语 release notes 明确稳定版边界、升级方式与发布后证据回填要求。
- 主 README、Quick Start 与公共 RC Trial 在发布前继续指向已验证的 `0.2.0-rc.7`，避免把 draft 稳定版描述成已可安装版本。

## 发布前门禁

1. 已合入 rc.7 证据 PR #365，并将本准备分支重放到对应 `main` merge commit。
2. 将本准备 PR #366 的 base 切回 `main`，确认差异只包含 0.2.0 release train 及其 draft stable 状态投射。
3. 确认没有计划纳入 0.2.0 的未合入 feature PR；新增功能默认进入后续 release line。
4. 在 base 切换后的最终评审 commit 上重新运行完整 `release:rehearse`、`check:agent-doc` 与 `git diff --check`，并复核 40-package 数量与 `latest` stable channel。
5. 已核对 stable publish 会从 `0.2.0` 推导 `latest` 并为每个 package 执行 `npm publish --tag latest`；三个 deprecated bootstrap identity 当前残留的 `0.0.0-bootstrap.0` `latest` 不构成发布前阻塞，但仍须在发布后证据 PR 中确认它们已随 40/40 package 一并切换到 `0.2.0`。
6. 准备 PR 合入后，只能从 `main` 手动执行受保护 workflow：`mode=publish-all`、`profile=workspace`、`resume_published=false`、`include_approved_candidates=false`。

## 发布后证据

稳定版真实发布后，从最新 `main` 新建证据分支，核对 40/40 package、40/40 `latest`、tag commit、GitHub Release 类型与 assets、snapshot checksum/digest，再将 `V-PROTO-UI-0008` 转为 active。公共 README、Quick Start 与 release 状态只能在该证据 PR 中切换到 `0.2.0`。

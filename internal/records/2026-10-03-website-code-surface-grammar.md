# Website source surfaces: shared passive grammar

This is implementation and evidence context for #777 / #785, not a Base CodeBlock admission, a public package guarantee, or acceptance of the separate private ChatUI CodeBlock proposal (#517). The current user-directed scope is a consistent code/command presentation with the accepted real Copy control retained, decorative window controls removed, and a thinner installation toolbar. The local source baseline is `cb634abf3d2a90b4e37e57fc9e389ce64e359b24`.

## Inventory and minimum ownership

Before this slice, ordinary Markdown/MDX fences inherited ExpressiveCode's editor/terminal frame; InstallCommandCard owned a separate frame and padded toolbar; CodePanel owned a body divider plus overlaid Copy/expansion; CodeExample added its own frame and two independent host/file strips. The shared stylesheet unified source text but not this framing or row rhythm.

The smallest added owner is the app-only experimental `site-code-surface` Prototype. Its `frame` part owns the source-view border, radius and fill; its `toolbar` part owns the separator. Shadcn uses its theme radius and muted surface. Brutalist imports the existing canonical `BRUTALIST_PANEL_TOKENS`, so the independently reviewed family correction can flow through without another frozen square/monospace recipe in the website. The two families do not promise identical paint. The frame is not a new neutral Base identity, terminal emulator, editor, code renderer or interaction protocol.

Each native frame/toolbar has a separately rendered passive surface behind its stable content. The shared projection controller/materializer and explicit one-Prototype recipe own runtime/family generation and disposal. The passive mount is excluded from accessibility and pointer hit testing. Native `pre`/`code`, text nodes, browser selection and scroll surfaces are not moved, replaced, made inert or re-created during a visual switch. Independently projected decorations are not a page-wide atomicity claim.

Ordinary Markdown and standalone source views follow the page runtime preference and nearest accepted family coordinate. Embedded Previewer source follows the Previewer's committed runtime. A failed new projection retains its previous truthful coordinates; an initial failure leaves unframed, selectable native source. A later attempt can retry. Theme changes update the closed theme input instead of remounting source content. Removal/Astro lifetime cleanup revokes pending work.

Independent source review found a removed root could be reinserted while its old materialization was still pending, letting late cleanup erase the new handle's coordinates. Cleanup now synchronously revokes the current handle's root lease and detaches only its own passive mount before awaiting disposal. Late work stays confined to that detached mount; publication, rollback and failure metadata require current ownership. Real adapter tests cover startup and replacement races for all four runtimes, including the new paint node, native source node order, selection, focus and command listener after late cleanup.

Existing real Button owners remain unchanged for Copy, installation package-manager selection and CodePanel expansion. The logical Copy controller, exact payload rules, feedback/Clipboard lifetime, pending-click behavior, focus preservation and real glyph remain the previously reviewed implementation. CodeExample host/file controls remain their existing native roving-tab recipe: this slice aligns their surrounding toolbar and keeps their keyboard/source state, but does not claim they have migrated to PUI Tabs. A dummy passive skin is not used to disguise that remaining interaction work.

Lucide gallery Copy generates different snippets within its own modal; WikiTerm Copy copies prose inside a term popover. Their broader modal/popover and Copy migrations are explicitly outside this passive source-frame slice.

## Shared grammar and reference judgment

Current reference inspection used the actual [shadcn installation page](https://ui.shadcn.com/docs/installation), its [CodeBlockCommand source](https://github.com/shadcn-ui/ui/blob/main/apps/v4/components/code-block-command.tsx), and [neobrutalism.dev installation](https://www.neobrutalism.dev/docs/installation). They support a compact useful package-manager row, real Copy action and horizontally scrollable code. They do not establish Proto UI semantics, browser compatibility, or a requirement to reproduce each reference pixel. Family-owned appearance remains separate from this common information arrangement.

The website grammar uses one 44px minimum metadata/control row with zero extra vertical padding. Metadata, selected manager and trailing Copy share its center line. Existing manager targets retain at least 44px. The previously accepted Copy Button geometry remains owned by its actual family recipe, with room in the row rather than a competing CSS-sized button. Source body type and padding are common; source alone is monospace. Ordinary untitled fences have no manufactured metadata row. Real filenames remain visible, and terminal examples receive a useful localized label instead of decorative traffic lights. EC's existing post-preprocessing Copy payload is preserved, including terminal full-line comment removal.

CodePanel gets one source frame as a sibling of the RuntimeBox canvas. Inside CodeExample, only the outer source frame is painted; the file panels do not add nested borders. CodePanel's collapsed overflow presentation uses a content mask; expansion and native scrolling keep their existing owners. No global `overflow: hidden` conceals a composition sizing problem.

## Evidence and limits

Screenshot evidence records the actual checkout from `git rev-parse HEAD`, its dirty status, the requested candidate SHA and the workflow event SHA as separate fields. The shared Copy source-binding validator rejects a mismatched candidate or dirty CI checkout before browser startup. The workflow event SHA alone is not evidence of the checked-out candidate.

- The real four Web adapters and installed React/Vue frameworks exercise passive projection, source/text node identity, selection/focus preservation, family/theme changes, truthful failed-runtime retention, initial retry, late disposal and repeated initialization. Installed loaders replace CDN fetches only; these are not hosted network or pixel checks.
- HappyDOM does not inherit the fixture's custom properties into generated descendants. The test therefore declares its explicit theme-input map through a fixture stylesheet on all nodes while retaining the real resolver, watchers, materializer and adapters. This limitation and the initial failure remain in the work packet; the fixture does not supply expected paint.
- Real installed ExpressiveCode/plugin-frames rendering covers plain fences, filenames, unnamed/named terminal frames and `frame="none"`. It verifies useful caption structure, one Copy payload and unchanged native source structure. EC normalizes a final newline before the website hook, so engine-level expectations use that processed source; the existing direct payload tests still preserve arbitrary input exactly.
- The browser suite is explicitly registered with the runtime plan and isolated visual workflow. It checks actual passive paint and geometry for four runtimes/two family-input fixtures, light/dark changes, 390/320px layout, native host/file keyboard compatibility, no nested source frame and the installation toolbar. Existing Copy and code-surface journeys remain required.
- Actual candidate browser execution and fresh screenshots remain pending hosted Actions. Local structural tests do not establish visual acceptance, mobile hit testing, clipping, focus-ring visibility or hosted runtime loading.

The narrow Transition example composition repair is a separate small patch: its own app layout must wrap and bound its content rather than having CodeSurface or RuntimeBox clip the resulting page overflow. The original document overflow threshold remains unchanged.

# Source-known helper setup capability recovery

## Scope and authority

This record covers the CLI source-summary repair for ordered calls to source-known helpers from an authored Core setup. It is a development repair with bounded source evidence, not lifecycle activation, GitHub approval or complete compiler/native acceptance.

C-CORE-SYNTAX-0001-A/B locate the definition capability in the setup execution context. C-CORE-SYNTAX-0003-B/C identify the canonical function-valued setup entry. C-AS-HOOK-0001-A/C keep hook effects attached to the caller and do not grant ordinary wrappers a native identity. C-PROTOTYPE-STYLE-CLOSURE-0001-A requires proven state-selector visual assets to reach the official translation. These entities remain draft; no entity or original threshold is changed.

## Observed failure and repair

A canonical setup forwards its unchanged definition parameter to paint, calls an independently authored alpha hook, then calls a separate beta hook. Registration replay entered the earlier helper with an empty capability environment. Its ordinary host.rule call became opaque and the later beta() lost its own registration result. The reproduction distinguished inline calls from pre-bound results and retained exact owner/source observations.

The repair seeds only the proven immutable first parameter of the enclosing canonical setup, by its lexical declaration identity. Argument evaluation still decides what a helper actually receives. A foreign argument, shadow, reassignment or captured closure write does not inherit the capability.

A separate source-reference check withholds that seed when a named setup body also escapes through ordinary calls, aliases, stores, callbacks, returns or value exports. A named function expression has both an internal self binding and an external variable binding; both are compared through resolveReference using SourceFile and declaration identity. Unsupported factory-instance and ordinary object-member contexts remain unproved. No component name, parameter spelling, global proof cache or output-token expectation is added.

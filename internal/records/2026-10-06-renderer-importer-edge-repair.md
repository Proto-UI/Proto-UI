# Preserve importer ownership when an Adapter target is shared

Date: 2026-10-06. Baseline: PR #857 `27331cebfc30565fd70835c26a32c64f838c5ca6`.

Review [r4195077647](https://github.com/Proto-UI/Proto-UI/pull/775#discussion_r4195077647) exposed a remaining defect in the production module graph boundary. The earlier repair rejected foreign Adapter target modules outside the renderer closure, but a foreign importer could reuse an Adapter target already in that legitimate closure. In the actual emitted graph, an unrelated module co-located with the renderer dynamically imported the existing `packages/adapters/react/src/index.ts`; the baseline returned no issue. Earlier new-target mutations did not cover this same-target edge.

The repair retains the target-membership check and separately checks importer paths. It propagates forbidden dependency reachability backwards through resolved module edges, stopping at the exact reviewed renderer API. An emitted importer outside the renderer's owned module closure cannot acquire a framework/Adapter dependency through another route, even when the terminal target, a runtime module, or an intermediate barrel is already legitimately shared. The existing exact WC bridge-module exceptions remain placement-bound; this does not expand them. Missing provenance for any emitted module in a reviewed site's chunk closure now fails closed. Query-suffixed lookalikes are not the renderer API.

The graph traversal is cycle-safe and bounded by the recorded module/edge inventory. It checks dependency paths rather than arbitrary JavaScript execution or whether a tree-shaken source branch executes. The renderer's transitive dependencies remain renderer-owned under this finite profile; an unrelated co-located module does not become owned merely because it references the same target. Calling the reviewed renderer API remains the intended boundary.

The new 110 controls cover all five site owners, three importer placements, static/dynamic edges, already-owned Adapter/runtime/barrel targets, owner direct bypass, missing importer provenance, query lookalikes, and inert cycles through the renderer API. On the baseline, 105 new importer/provenance assertions fail and five inert controls pass. Some static placements were already rejected by the separate static shell wall; those are not newly escaped graphs. Independent actual-artifact controls separately confirmed four direct/cyclic-helper same-target paths accepted by the baseline and rejected by the candidate, alongside four renderer-API positives. Candidate: all 241 graph fixtures pass. Actual emitted graph mutations for renderer/runtime co-location and static/dynamic reuse each reject all five owners; the unmodified emitted graph passes. Full coverage/source and independent acceptance must bind the final candidate; prior green CI remains the baseline's result only.

The repair belongs to #857. Dependent PRs, including #775, incorporate the published commit through ordinary dependency merges rather than carrying separate checker forks. No audit-config profile, decoder policy, matrix disposition, or UI rendering behavior is changed in this increment.

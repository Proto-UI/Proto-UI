## 原始失败与离线恢复必须分开

第一次 `stream: false` 请求返回 HTTP 400：`Stream must be set to true.`，约 2.942 秒。只发出一个请求，其余三个 slot 未调用；未取得 usage 或费用，不按零计。

随后先修复显式 streaming 传输并做聚焦测试、真实 Chrome 控制与独立增量审查，再创建单独版本的四格执行计划。四个新请求仅改变 streaming 控制，任务与材料字节保持不变。限制为请求输出上限 8192、每请求 180 秒、整批 900 秒、响应原始字节上限 4 MB；客户端无重试。最初失败加这四个请求，共五次客户端 dispatch，至此结束本轮调用。

四个新请求均 HTTP 200、返回 `status: completed`、模型名和 usage；然而 terminal `response.completed.output` 全部为空数组。严格的原始接收器因此全部记录 `Empty participant text`。**五次 dispatch 的原始 accepted participant response 数为零。** 不将 HTTP 200 当成有效交付，也不改写原始 receipt。

完整 SSE 中另有 `response.output_item.done` 的已完成 assistant message。零新增模型调用的离线诊断从这些 completed message 的确切文本恢复输出，delta 拼接仅用于一致性校验，绝不作为输出来源。检查事件顺序、response/item/content ID、模型、完成状态、UTF-8、完整 framing、原始 hash/字节、计划请求绑定、usage 和逐层 done 一致性。

第一次离线恢复审查为 NO-GO：存在 model 类型验证和完整 orphan content part 被遗漏的问题。另建 v2 诊断副本，增加 exact content-key inventory 与非空字符串 model 校验；保留 7 个新增失败的 red 结果。修复后独立审查执行 **47/47 通过**，其中含四份真实流的离线回放，另有 7/7 额外负探针拒绝与 multipart 正控制通过。最终只对精确绑定的 v2 提取器给出 **GO — derived exploratory recovery only**，不批准主结果成功、正式准入、语义接受或额外调用。

四份恢复文本 v1/v2 字节完全相同。v2 policy 的核心与 v1 相同，差异是版本/修复元数据；该相同性由协调者核验，不宣称独立审查认证了单独的 v2 policy 文件。离线 browser 由协调者运行，协议审查者没有执行 wrapper/browser。两类证据不混合成更宽的批准。

## 模型与参数记录

显式请求：`model: gpt-6.1-sol`、`stream: true`、`store: false`、`tools: []`、`tool_choice: none`、`max_output_tokens: 8192`。没有显式选择 temperature、top_p、reasoning effort、service tier 或 seed。

四个 terminal 返回相同的参数元数据：reasoning `{context: all_turns, effort: medium, mode: standard, summary: null}`，`temperature: 1`、`top_p: 0.98`、`service_tier: default`、`truncation: disabled`、frequency/presence penalty 均为 0；`store: false`、`tools: []`、`tool_choice: none`、`previous_response_id: null`、`instructions: null`。无工具时返回 `parallel_tool_calls: true` 不表示发生工具调用。未返回 seed；不可变 upstream snapshot 未知。

重要限制：返回 `max_output_tokens: null`，与请求 8192 不一致，**不能声称供应商有效执行了输出 token 上限**。上述只是 provider-reported 参数，非供应商内部行为认证。`reasoning.context: all_turns` 是返回元数据，不表示客户端提供了其他聊天历史。网关配置 max retries 3、failover false；客户端 retries 0，实际 upstream retry 数未知。

原 ledger 对 temperature 的“未指定/默认未认证”表述保留；新增 `returned-parameter-audit-v1.json` 分开记录 request omission 与真实返回值，不追溯改写原记录。

## 隔离情况

每个请求均为新请求，没有 system/developer/父聊天、conversation、previous_response、工具、oracle、其他条件输出或反馈。blind discovery 仅含普通手写 specimen；blind implementation 无额外材料。knowledge-assisted 仅新增四份固定的 draft Tabs YAML，不包含实现、测试或 evaluator。独立审计将实际 request 与计划字节/hash 绑定；blind packet 中没有 Proto 标记。

这证明的是**本客户端发送内容与暴露能力的边界**。不能证明模型预训练从未见过 Proto UI、供应商没有隐藏指令/缓存/保留行为，或 assessor 完全盲化。语义审查材料隐去 condition 标签，但文本可透露所受知识指导，不能宣称完全 assessor blindness。审查者不接触 auth，不调用供应商。

blind 提出 14 条属性，assisted 提出 15 条。独立 fresh-context 审查逐条手工映射，所有 29 条各出现一次，另列四个 coherent Proto-only group；保存精确 UTF-16 citation 与源 hash。`validateCrosswalk` 返回 `citation-valid-unreviewed` / `not-admitted`，仅证明引用完整性，不自动批准语义标签。

| blind | 2 | 4 | 3 | 1 | 4 |

上述是整条 proposal 的手工分类，不是缺陷数或效果分数。四个额外 Proto-only group 不加入 29 条 denominator。数量或类别差异不证明更好的 discovery。

可行动的线索：两者都识别了主要的消费者交互不变量；panel focus entry 有相对 draft target 的条件性不足；四份 draft 文档未明确规定“未提交导航后，Tab 再进入时恢复 selected 还是 last-focused”的策略。这只是四文档范围的显式政策缺口，可能由未读取的 Focus contract 规定，不能宣称全仓库缺失。loop/manual/retained-panel 与 draft 默认值不同，不自动是 bug，因为存在相应配置选项。完整关系预算的 phase exclusion 与较窄 relationship targets 有来源限定的解释张力，未借实现或记录补造保证。

四个额外 draft 协议面为 same-domain/context isolation、导航方法与 Focus 成员事实所有权、disabled activation 不修改 activeValue、可靠匹配所需的有效非空 protocol value。它们不是普通 fixture 中已复现的 bug，也不是模型未履行当前任务的证据。

## 结论、后续与证据

本次得到真实的首轮计量、协议异常、两个实现的同分布局部观察以及可追踪的 discovery 线索。没有 causal Proto-specific value 结论：一个公共手写 Tabs 域、每格一次、知识量不匹配、缺少 matched-information control、语义拆分不同、候选覆盖不完整、primary protocol failure，均限制解释。每个 assisted 请求比对应 blind 多 **14,341 input tokens**；不能把额外知识收益直接归因于 Proto-specific 形式。

下一阶段先在正常接收路径严格支持完成 item 的组装与 terminal 一致性、扩展正负控制；再修正 oracle 误判/覆盖或明确排除；冻结输入、评测、重复顺序、设置和有界调用预算后才执行正式重复。独立 semantic oracle 仍是阶段目标，不是整个实验的终点。本轮调用已经停止，未触发额外付费运行。

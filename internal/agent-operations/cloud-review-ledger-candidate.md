## Historical inactive prototype boundary

The following sections describe the earlier dry-run/simulation layer and its original rollout proposal. For the current connector publisher, production-root support and enablement steps, use [the parent handoff](connector-review-parent-handoff.md); historical statements that no writer is supplied apply only to that earlier layer.

- `scripts/agent-operations/cloud-review-ledger.mjs` is a pure journal reducer and an unauthenticated receipt comparator.
- `scripts/agent-operations/local-cloud-review-ledger.mjs` stores/replays that journal in an explicitly initialized **local bare Git repository with no remotes**. It never initializes the production checkout or an origin branch. Reads pin a genesis and monotonically advance a checkpoint. Mutation uses `git update-ref <ref> <new> <expected>` for an atomic local compare-and-swap (CAS).
- `scripts/agent-operations/remote-cloud-review-ledger.mjs` implements the remote state protocol over an injected transport. Its supplied Git transport is read-only; local bare-Git push fixtures exercise the mutation boundary without contacting GitHub.
- `scripts/agent-operations/cloud-review-simulation.mjs` implements one-attempt fake exchange and simulation-only finalization. No live review publisher is supplied.
- `scripts/agent-operations/test/cloud-review-ledger.test.mjs` exercises local fixtures and real concurrent Node/Git processes. No test calls GitHub, a broker, or a review API.

The dry-run integration can perform authenticated read-only collection through the existing `gh` transport when available. There is no review POST, credential provisioning, publication switch, or change to active capability policy/CLI handoff schemas. Every returned publication decision is false. A staged intent is a **non-publishable candidate**, not a permission or a queue that an existing publisher may consume. It may retain an incomplete packet: only canonical binding is assessed here; recording it cannot make its evidence, CI, permission or human gates pass.

The proposed future integration is a state-provider adapter beneath the canonical guarded publication flow, coordinated with the existing [Poppy broker contract](../contracts/agent-operations/poppy-review-broker.md). It is not an independent publication system. Neither this module nor a connector call may replace `authorizeReviewSubmission` and final live collection. This prototype binds current-main input v3/packet v2. #509 is not an import, runtime or technical prerequisite for this version; its v5 changes are future schema/writer alignment if accepted. Do not claim v5 compatibility or silently remove its additional gates when integrating that version.

## Journal and lifecycle

Each Git commit contains exactly one `entry.json`; root identity, linear single-parent ancestry, command shape, transition validity, packet/input binding and resource budgets are rechecked on every read. Bounds are 2,048 commits and 8 MiB of replayed entries. Exceeding a bound fails before advancing the ref. There is no pruning/compaction or automatic reinitialization.

| Command | State effect and limit |
| --- | --- |
| `enqueue` | Retain delivery identity, reject reuse with different evidence, coalesce consecutive matching material digests, and retain the latest pending generation per PR. Event kind is an explicit hint, not authenticated webhook proof or authority. |
| `claim` | Acquire one repository-wide slot with a fresh process nonce; the nonce is permanently consumed. There is no time-based expiry or takeover. |
| `finishAnalysis` | Persist complete canonical input/packet and observation as the **last analysis**, not last publication, then release only the matching pending generation. Prior findings must be fully reconciled. A newly queued generation prevents stale completion. |
| `abandon` | Release an owned slot only before an intent; preserve pending work. The candidate has no writer, so no request can have been issued through it. |
| `stageIntent` | Bind the exact base/head/input/packet, recorded policy digest, principal, disposition and rendered body to a durable `unknown` intent. Always returns publication disallowed. The slot becomes permanently blocked in this candidate. |
| `stageSimulationIntent` / `finalizeSimulation` | The explicit simulation path may record a fake response and exact fake readback, persist last analysis, and release only its old pending generation. It never records actual publication. Ordinary intents cannot use this transition. |
| receipt comparison | Compare exact target, principal, commit, disposition, body and intent marker. Return unauthenticated candidate evidence only; never release the slot or claim remote success. |

The adapter generates the process nonce itself and refuses caller-supplied ownership. A fresh instance cannot adopt a prior instance's slot, even before an intent. One instance has at most one claim lifecycle. Enqueue may continue during an occupied/unknown slot, allowing coalescing without allowing another publisher. A failed CAS acknowledgement is `unknown`, disables all further mutations through that instance, and never retries. Another reader can inspect durable state but cannot assume ownership. A rejected stale revision detected before the mutation returns `conflict`.

For analysis, the reducer reuses `validateReviewPacket`, `verifyLiveReviewInput`, `computeReviewInputDigest`, `computeReviewPacketDigest`, `verifyReconciliation` and `renderReviewBody`. It checks the explicit autonomous/delegated-owner-event observation, owner identity and excluded PR author. The policy digest is recorded rather than independently attested. These are **supplied fixture observations**, not a replacement for live identity/permission verification. A future live collector must own them. The existing submission runtime and its evidence/debt, finding, human-gate, duplicate and successful-CI checks remain unchanged.

## Trust and unresolved integration limits

- The local adapter is a cooperative state protocol, not a sandbox. Git object hashes, caller declarations, owner nonces and the maintainer's responsibility statement are not signed runtime attestation. An account holder or process with equivalent filesystem/GitHub permissions can bypass the protocol.
- A pinned checkpoint detects subsequent resets for that reader. A fresh reader pinned only to genesis cannot detect an administrator rolling the ref back to an otherwise valid ancestor. The tests expose this limit rather than claiming tamper-proof history. Production policy must decide protected checkpoint/retention and same-account trust; no settings are changed here.
- Local `update-ref` expected-tip CAS is stronger than the connector's `force:false` fast-forward update parameter. The proposed remote protocol uses single-parent sibling commits, but the completed state-only trial below observed one sibling winner and a rejected stale update. That bounded result does not establish a generic expected-tip API or protect against equivalent account credentials.
- Ordinary staged intents remain permanently blocked, even with a matching supplied receipt. The simulation-only finalizer described below can finish a known fake exchange; it cannot unlock ordinary intents or establish real publication. A live authenticated transport/finalizer integration still needs validation. Unknown outcomes must never be cleared by timeout, missing-review inference or a restarted worker.
- The state adapter does not run a reviewer or independently evaluate evidence. The dry-run collector below adds live facts/revocation checks when its read transport is available; connector POST retry behavior remains untested. Exact canonical data can change after a read; GitHub review commit binding is not an atomic transaction over the full snapshot. No claim of exactly-once publication is made.
- All scheduled/Poppy/cloud automated writers must share the eventual slot/intent boundary or be explicitly excluded in an approved rollout. This candidate neither disables another writer nor asserts that such coordination exists.

## Inactive parent-reviewed pipeline

`cloud-review-dry-run.mjs` composes the existing canonical collector, submission gate and local journal. Its lifecycle is:

1. The coordinator explicitly enqueues a supported material-event hint in a local ledger. This does not authenticate a webhook or grant authority.
2. `CloudReviewDryRun.begin(pr)` collects canonical main-v3 input plus numeric viewer/author and commit-contributor identities, verifies current permission, and claims the global slot. It returns a copy of the snapshot and durable prior analysis to the parent reviewer.
3. The parent inspects the actual changes/evidence and supplies its own packet to `prepare(packet, assessment)` in the **same live instance**. No helper model constructs or decides the packet. Parent judgment cannot be replaced by a claimed model identity. This module does not provide a cross-process handoff/owner-adoption protocol.
4. Preparation re-collects live input and identity/permission facts, then invokes the unchanged canonical `authorizeReviewSubmission`. The real policy rejects the event scope. A private hypothetical policy with an explicit `autonomous` / `delegated-owner-event` source exercises the existing canonical gates; it never becomes active policy, a returned authorization or a writer credential. Extra cloud restrictions require complete evidence with no debt and no human gate, and reject the owner or any known commit contributor. Incomplete contributor identities fail closed with no inferred bot exception.
5. `prepare` stages an ordinary immutable unknown intent and returns its inspectable head/disposition/body request. The separate `simulate` method stages a marked simulation intent, performs another live canonical/identity/permission read after persistence, consumes the same owner's one-attempt token, and calls an injected fake exchange exactly once. Every returned `publicationAllowed` stays false; there is no default live publisher.
6. The read-only receipt inspector compares exact review ID, actor ID/login, head, disposition and body/intent marker without attributing a caller-supplied POST response. The simulation exchange instead holds its own successful response in memory, binds it to exact fake readback, and finalizes only a simulation intent as last analysis with `simulationReceipt`. It preserves later queued generations. Thrown/unbound responses, readback failure or uncertain finalization never retry; a restarted process cannot consume the old owner's attempt. Neither path claims actual publication or infers non-publication from absence.

The existing collector gained only an injected runner option, matching #509's transport seam. Its production defaults and canonical schema are unchanged. The cloud wrapper additionally rejects missing pagination flags and truncated collections. `begin`/`prepare`/`simulate` are synchronous library calls for a retained coordinator process, not a deployed worker or CLI that can resume in a fresh cloud run.

Tests exercise the real canonical collector/authorizer with GitHub-shaped synthetic read responses, a real local Git journal and a fake writer defined only in the test. Both APPROVE and finding-backed REQUEST_CHANGES pass the hypothetical gates. Identity spoofing/missing identities, owner/contributor work, pagination gaps, revocation, changed input, changed generation, duplicate review, incomplete evidence, human gates, spec changes and CI/assessment failure reject before staging an intent. Receipt field mismatches and missing POST response fail without releasing the durable unknown slot. Existing ledger tests retain prior-finding reconciliation and lost-acknowledgement coverage.

## Remote adapter and checkpoint contract

`RemoteCloudReviewLedger` accepts an explicitly initialized local bare cache, pinned genesis, explicit checkpoint and transport. It imports remote Git objects, replays the same bounded single-entry/linear journal, checks checkpoint ancestry, and refuses missing/corrupt/rewritten history. It never creates a remote ref or falls back to an empty ledger. `readOnlyGitLedgerTransport` fixes the repository to `https://github.com/Proto-UI/Proto-UI.git` and ref to `refs/heads/proto-ui-review-ledger`; it has **no publish method**. The proposed production ref has not been created.

An injected mutation transport receives one validated single-parent candidate and its expected revision. Tests implement it using a non-force push to a temporary local bare repository. A sibling winner makes the stale candidate non-fast-forward. Any unacknowledged/rejected update or inconsistent readback stops that instance permanently; only read-only reconciliation remains. The adapter never rebases/retries or treats Git non-force update as a generic expected-tip API. A supplied checkpoint must survive outside the disposable cache and advance durably between runs; the adapter returns it but does not invent an external storage provider. A fresh worker can finish later work after a completed simulation baseline, but cannot adopt an interrupted owner.

The runtime transport/test seams are cooperative interfaces, not authentication credentials. A malicious caller with equivalent filesystem/account access could supply fabricated reads or execute a direct API call. Only the explicitly delegated coordinator may wire the eventual live transports, after the activation boundary is admitted. No workflow receives authority from a callback, mode label or candidate output.

## Remaining activation changes and bounded verification proposal

Before asking to enable publication, an implementation review must establish all of the following:

- Bind the current authoritative main collector/authorizer/writer together. #509 is future alignment if accepted, not a prerequisite to exercising main-v3. Preserve every canonical gate and reconcile its additional v5/DCO/prior-publication rules when that version becomes authoritative.
- Provide a supported authenticated full collector and a retained coordinator channel through which the parent can inspect evidence and return its packet. Verify the final write uses the same authenticated owner and binds `commit_id`; prove one invocation and no automatic POST retry. A copied response/task ID must never unlock state.
- Wire the implemented remote journal protocol to an explicitly authorized non-force Git mutation transport and the actual guarded writer; its shipped transport remains read-only. A proposed production location is `refs/heads/proto-ui-review-ledger` in `Proto-UI/Proto-UI`, **not created or authorized here**. Pin its genesis and an independently retained monotonic checkpoint for fresh-run rollback detection, or explicitly retain the fail-closed single-process limit. Specify retention/resource-budget handling before activation; never silently reset on exhaustion.
- Admit an exact delegated-owner event scope in canonical policy/handoff validation and the trusted invocation boundary. Bind repository, principal, parent reviewer, eligible event kinds and author exclusions. A declaration in workflow/PR text cannot supply webhook provenance. No arbitrary workflow receives authority. User responsibility and equivalent account access remain a cooperative trust boundary, not signed runtime attestation.
- Route every automated cloud/scheduled/Poppy publisher through the same global slot, or explicitly pause/exclude the other writers in the approved rollout. Unknown intent must stop all publishers indefinitely while enqueue/coalescing remains safe. The current prototype does not claim this coordination exists.

Only after those blockers are removed, propose one explicitly named disposable PR, owned by a different verified principal, and one exact-head parent-approved packet for a **maximum of one review POST**. First run read-only/dry-run collection and veto controls; then separately authorize that one disposition, persist intent, issue once, and authenticate response plus readback. Any ambiguous result stops publication with the intent retained; no retry or timeout takeover. Further dispositions, refs or actors require their own bounded plan. This proposal is not permission to perform the test.

Disable/rollback must pause event delivery and close writer admission before another claim, preserving journal/checkpoint and any in-flight unknown intent. Do not delete/reset the ledger, retract reviews, retry pending POSTs or restart an older writer automatically. Inspect an in-flight operation read-only; retain uncertainty until an independently justified recovery decision. No implementation, credential, security or automation change is made by this document. The parent manages future automation only after integration readiness. DCO signing still requires identity/certification confirmation.

## Review decision

The semantic gate is complete: preserve active `C-PROPS-0009` and correct two public previews plus both directly related stale PropsKernel comments. Review round one returned `misleading` with confidence `0.99`; the maintainer approved the exact additional comment scope. After correction and Node 22.23.2 validation, review round two returned `adequate` with confidence `0.99` and found the implementation eligible for automated completion. Technical remediation is therefore complete. Integration remains a separate pending human decision.

## Behavioral delta

Before the change, both public previews grouped `missing`, `provided-empty`, and `invalid` input and then showed one unconditional `prevValid`-first fallback order. After the change, they state that `missing` skips `prevValid` and uses `setDefaults` -> declaration `default` -> `null`, while provided-empty or invalid input entering fallback uses `prevValid` first. Runtime behavior remains unchanged.

The missing-only helper comment moved from the stale `prevValid`-first description to the defaults-only order already implemented by `pickFallbackMissingOnly()`. The top-level `prevValid` field comment now states that only provided-empty or invalid fallback uses that cache and that missing always skips it.

## State transitions

| Input transition | Previous public projection | Revised public projection | Runtime delta |
| --- | --- | --- | --- |
| valid provided value -> `missing` | Can be read as retaining `prevValid` | Releases the host value and uses defaults-only fallback | None |
| provided value -> provided-empty or invalid entering fallback | Uses `prevValid` before defaults | Uses `prevValid` before defaults | None |
| any fallback chain exhausts valid candidates | Ends in canonical `null`, except `empty: "error"` | Unchanged | None |

No failure, recovery, cleanup, or retry state changes: the implementation path is not being modified.

## Change and impact map

The semantic implementation surface is limited to page-owned structured preview data in the English and Chinese Props pages and two comments in the same PropsKernel. `SpecContractPreview` is an indirect renderer, not a change target. Active authority, executable fallback logic, test mappings, and focused tests are explicit exclusions.

Separately, the independently reviewed dispatch-time working tree contained three coordination artifacts: the finding update, mission update, and this packet. Close adds only the atomic migration from `mission-queue.yaml` to `runs.yaml`. The semantic baseline also predates already committed Phase 0 Skill and governance infrastructure. Those operational differences are not part of the three-path semantic implementation inventory and must not be used to claim inventory exhaustiveness.

The main observable effect is reader-facing: withdrawing a host prop will no longer be documented as if it could preserve the prior valid host value. Unknown occurrences outside the verified mission slice remain separate follow-up candidates.

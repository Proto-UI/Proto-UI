likelyRootCause: >-
  EventKernel.bindAll performs target resolution and listener attachment in the same loop. EventModuleImpl tracks only a whole-module isBound boolean, so an exception can create a state that is partially bound internally but appears wholly unbound to capability-change recovery.


impact: >-
  A failed bind can retain a host listener and dispatcher closure until an explicit retry, unbind, or disposal. Capability recovery alone leaves the registration set incomplete. The normal official Web path reduces immediate user-visible risk, but the behavior weakens cleanup and transparent-rebinding guarantees and is especially relevant to partial, delayed, or future non-Web host capability provisioning.


suggestedAction: >-
  Make binding transactional by pre-resolving every registration target before adding listeners, or roll back listeners attached during the failed attempt. Add a Module contract test covering mixed semantic-redirect and host-bound registrations, target-unavailable failure, zero residual listeners, and successful capability recovery. Clarify whether bind atomicity is required by the draft Event capability before promoting its conformance entity.

# Agent Harness Dogfood Coverage Matrix

Status: authoritative M0 coverage ledger for [#514](https://github.com/Proto-UI/Proto-UI/issues/514), dated 2026-08-28. Parent program: [#513](https://github.com/Proto-UI/Proto-UI/issues/513).

This file is the single repository-owned matrix for the intended `apps/agent-harness/**` interface. It is a non-normative planning and evidence ledger: cataloged `spec/**` entities remain authoritative, and every entity named below is currently `draft` unless its own file says otherwise. A `ready`, `research`, or `blocked` row does not authorize a new Base semantic, Module, Host Capability, composition package, or implementation.

## M0 decisions and ownership boundary

- **Primary production host:** React 19 through the public `@proto.ui/adapter-react` entry. The application ships one UI host. WC and Vue runtimes belong in focused equivalence fixtures for reusable extracted work, not in the production bundle.
- **Production design path:** the Brutalist family is the initial internal dogfood design language. A row can consume only cataloged/implemented entries; missing Brutalist projections stay linked gaps rather than being recreated in app CSS.
- **Ordinary consumer path:** application components consume public prototype/design-language entries, approved initially-private composition entries, or `apps/agent-harness/src/prototypes/**` app-local Proto UI entries. Ordinary UI does not import Core, Runtime, Modules, raw Adapter internals, or private prototype implementation files.
- **Reviewed integration allowlist:** only `apps/agent-harness/src/bootstrap/proto-ui-host.ts` may import the public `@proto.ui/adapter-react` host constructor. Focused test harnesses under `apps/agent-harness/test/hosts/**` may import public WC/React/Vue adapter entries and Runtime test types. Expansion requires [#533](https://github.com/Proto-UI/Proto-UI/issues/533), a matrix row, and review.
- **App Maker ownership:** sessions, threads, runs, messages, content parts, tool calls, approvals, artifacts, persistence, transport, retries, fixture clocks, and service orchestration remain application-owned. Proto UI controls emit semantic requests such as `session.select`, `prompt.submit`, `run.stop`, `run.retry`, `tool.inspect`, `approval.resolve`, and `artifact.open`; rendering never executes those operations.
- **Generic semantic ownership:** keyboard, focus, scroll, collection, input/IME, dismissal, form, accessibility state, and reusable visual feedback stay in Proto UI. App glue may translate semantic events to domain commands but may not recreate those state machines.
- **Forbidden UI ownership:** no assistant/chat/Agent UI runtime, third-party headless primitive, accessible interaction hook library, virtualizer, dropzone, resizable, Tree, form, dialog, popover, or command-palette package may own an eligible interface path. Infrastructure engines are allowed only in the explicit exempt rows below and may not own their surrounding controls.

The initially-private ChatUI direction is constrained by [#500](https://github.com/Proto-UI/Proto-UI/issues/500), merged design record [#501](https://github.com/Proto-UI/Proto-UI/issues/501), and [`internal/records/2026-08-24-chatui-composition-package-decision.zh-CN.md`](../records/2026-08-24-chatui-composition-package-decision.zh-CN.md): Message and Code Block are independent composition entries, not shadow Base subjects; Composer remains separately gated.

## Row schema and state meanings

Each surface has one stable ID and one target class. “Proto UI chain” names current catalog evidence and the intended design path; it does not promote a draft entity. “Host evidence” distinguishes the React production path from WC/React/Vue equivalence required only when a slice becomes reusable.

- `dogfooded`: executable application journey and current evidence exist.
- `app-local-proto`: deliberately classified as application-local Proto UI; it does not imply neutral Base ownership or completed implementation.
- `ready`: current cataloged surfaces can support the bounded implementation, subject to its linked implementation Issue.
- `research`: the ownership/boundary still needs a checkpoint.
- `blocked`: a named semantic or implementation prerequisite is not complete.
- `native/static`: the host owns complete passive/native behavior; surrounding UI remains governed.
- `infrastructure-exempt`: a non-UI engine/service is exempt with an owner and re-review trigger.

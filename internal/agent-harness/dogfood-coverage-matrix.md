# Agent Harness dogfood coverage matrix

Status: authoritative for Agent Harness dogfood planning at repository commit 3b29193950327ed0ee24d86b61f10d9dedf016aa; non-normative for Proto UI semantics.

Parent tracker: [#513](https://github.com/Proto-UI/Proto-UI/issues/513). Matrix task: [#514](https://github.com/Proto-UI/Proto-UI/issues/514).

This is the single repository-owned coverage matrix for the planned apps/agent-harness application. It classifies intended user-facing surfaces and the infrastructure immediately behind them. It does not implement the Harness, admit a new Base subject, create a Host Capability, authorize a private ChatUI implementation, or promote any catalog lifecycle.

The catalog remains authoritative for Proto UI meaning. At this baseline, every P, T, M, and HC identity named below is draft unless a cell explicitly says otherwise. A-REACT-18-19-0001, A-WEB-COMPONENT-0001, A-VUE-3-0001, and A-VUE-2-0001 are active Adapter profiles. A draft entity is current cataloged direction, not a stable guarantee. Uncataloged or none means exactly that; the matrix never manufactures an entity to fill a cell.

## Production host decision

The recommended primary production host for apps/agent-harness is React 19 through the active A-REACT-18-19-0001 profile, whose governed peer range is React >=18.2.0 <20. This is a non-normative application decision owned by #514. It must not be extrapolated to [#420](https://github.com/Proto-UI/Proto-UI/issues/420), whose website program independently chooses generated Web Components.

Production uses one design-language family: Brutalist. A row may consume a cataloged draft Brutalist projection, consume a Base surface where no Brutalist projection exists, or remain blocked/research with design: none cataloged. It must not silently fall back to shadcn, ship parallel design-language families, or describe an app-local visual recipe as a cataloged projection.

Ordinary application UI consumes approved generated/public/private Proto UI React facades. WC and Vue 3 are focused equivalence fixtures for reusable surfaces, not parallel production shells. Vue 2 is active compatibility evidence for the website demonstration matrix, but this Harness ledger does not require it as a production host or routine equivalence fixture. App-local Agent-domain prototypes need React production evidence; they require WC/Vue 3 fixtures only if later extracted into a reusable composition or prototype.

## State vocabulary

- dogfooded: implemented in the Harness with current evidence.
- app-local-proto: classified as an app-local Proto UI prototype; this is not implementation evidence.
- ready: the owning cataloged surface exists and the row can enter a Harness implementation slice, subject to its listed lifecycle and dependency limits.
- research: ownership or the portable slice still requires an issue ruling.
- blocked: the intended owner is known but a prerequisite is not yet admitted or implemented.
- native/static: the browser or authored document node owns the complete behavior and no independent Proto UI information path is justified.
- infrastructure-exempt: an approved engine or App/backend service may provide non-UI infrastructure but cannot own surrounding reusable UI semantics.

No row is dogfooded at M0 because apps/agent-harness does not yet exist. A later change may move a row only when its Evidence cell links current, reproducible evidence.

## Consumer and ownership boundary

### Normal consumer path

Ordinary files under apps/agent-harness/src must import UI only from:

1. generated React facades under apps/agent-harness/src/proto-ui/components;
2. reviewed public Proto UI package facades;
3. reviewed initially-private dogfood facades, such as the future @proto.ui/compositions-chatui entries, only after their own issues authorize implementation.

The sole initial raw Adapter integration allowlist is apps/agent-harness/src/proto-ui/bootstrap.tsx. It may import @proto.ui/adapter-react and the exact approved public/private prototype entries required to build facades once. It may not import Runtime internals, Core authoring APIs, Modules, Host Capabilities, Adapter internals, or private implementation files. No other ordinary UI path may import any raw layer. Any expansion needs a matrix row, a linked issue, an owner, an expiry or re-review trigger, and #533 enforcement coverage.

WC and Vue dependencies belong only to focused evidence fixtures. The production bundle must contain one React host path, one intended design-language family, and no accidental Web Component or Vue shell runtime.

### App-owned data and services

The App Maker owns sessions, messages, Agent identity, run/tool/approval truth, streaming, usage, artifacts, files, revisions, validation, authorization, persistence, navigation, network, clipboard, storage, downloads, backend transport, and audit. Service calls occur only after a Proto UI semantic event or through an explicitly reviewed infrastructure boundary. Rendering, mounting, prop synchronization, replay, remount, and visual effects never send, stop, retry, approve, deny, upload, delete, patch, or navigate.

### Forbidden UI ownership

The following are forbidden under ordinary Harness UI paths:

- third-party chat, assistant, Agent UI runtimes, or component kits;
- third-party headless primitives or accessible interaction hooks that replace Proto UI behavior;
- third-party virtualizer, dropzone, resizable, Tree, form, dialog, popover, tooltip, menu, or command-palette UI acting as semantic owner;
- copied source from such libraries under application directories;
- direct Core, Runtime, Module, Host Capability, raw Adapter, raw prototype, or private implementation imports outside the one reviewed bootstrap path;
- raw keydown, pointer, focus, blur, click-outside, dismissal, roving-focus, selection, Textarea/Input value, IME, or ARIA mutation state machines;
- raw scroll position, geometry, observer, anchoring, windowing, or resize state machines in ordinary UI;
- render or mount effects that execute Agent actions.

Infrastructure engines listed as infrastructure-exempt may compute or render their narrow domain. ## Matrix update rules

1. Every new routed/page-level/exported user-facing surface adds or reuses exactly one stable harness.family.surface row in the same change.
2. No unknown or unclassified row may merge.
3. Every research or blocked row links a live issue and named owner role.
4. Every exemption records reason, owner, limit, and re-review trigger.
5. A temporary raw import or semantic escape records a removal issue and expiry/re-review trigger; bootstrap.tsx is the only initial raw Adapter exception.
6. Removing a surface removes or closes its row and updates both totals tables.
7. A row moves to dogfooded only when `Path` binds an existing implementation and `Evidence` binds an existing file under `internal/agent-harness/evidence/**` with explicit `Build:`, `Browser:`, `Accessibility:`, `Lifecycle:`, and `Design:` results proportional to its contract. The evidence file itself records those five dimensions plus exact `Commit:`, `Environment:`, `Fixtures:`, `Commands:`, and `Results:` fields.
8. Reusable compositions/prototypes require real WC, React, and Vue fixtures where their approved contract claims those Adapters. React production success alone is not non-Web conformance evidence.
9. The matrix never amends spec lifecycle or ownership. Catalog drift is reported and reconciled rather than silently reclassified.

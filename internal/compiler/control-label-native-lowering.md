# Control Label source lowering and IR 7

The source regression was compiler coverage drift. The Button protocol added valid ControlLabel target participation that invokes its existing activation operation. The compiler independently rejected the public hook at import admission; weakening the Button definition would have hidden that missing implementation. Label and Toggle also exposed older, independent source-language gaps when the same real definitions were used as compiler consumers.

## Shared semantic boundary

The compiler admits `asControlLabel`, `label`, `target`, `sync`, the target request's `source`, and `isCurrent`. Both explicit instance refs and declared anatomy pairs remain generic operations. A component name, package path, DOM ancestor, text match, or target role does not select the implementation. The target callback retains its own disabled/controlled/focus and activation decisions.

The four implemented browser source profiles receive `instanceAssociations` independently of portable Props. React and Vue use that dedicated framework input; custom elements use an instance property and reject an attribute string or `setProps` transport. Association changes reach the host before an unchanged raw-Props snapshot can return early. Undeclared participants reject a non-null association without loading an unused ControlLabel helper.

In the Web implementations, Core, Runtime and independently generated graphs use the versioned same-realm opaque-ref and pair services. The generated host helper implements the capability directly and imports no Proto Runtime, Module, Prototype or Adapter. Naming belongs to the target and composes with its existing accessible-name ownership. Foreign semantic objects are not reinterpreted as locally branded A11y handles.

Vue2 can attach its nonenumerable `__ob__` metadata to an otherwise valid association wrapper. A Vue2-only boundary discovers the actual framework's Observer constructor using its trusted `observable` function, verifies the observer's identity and back-reference, and removes only that internal metadata. The shared validator still rejects foreign keys, symbols, fake observer objects and forged refs. Reading `controlLabel` from the original wrapper preserves reactive tracking and accessor behavior.

## Checked source language and compatibility

Current IR 7 retains checked callable signatures, per-call default expressions, conditional expressions and ordinary lexical closure identity. A callback parameter may be captured or returned. The shared source/portable analysis follows known calls through aliases, parameters and returned closures and checks effects in their actual lifecycle context. A setup-only operation reached from a mounted callback is rejected; a pure callback transported through the same closure is admitted. Unknown host functions do not acquire callable authority. Defaults retain left-to-right, missing-or-undefined evaluation at the call. These forms lower to target values and functions, not an emitted interpreter.

The parser also admits static public ControlLabel selection values, enum Props, closed-graph imported data declarations and the public `renderer.r.slot()` alias. Imported type files actually used by a checked signature participate in the source identity. Missing unused type-only imports remain erasable. Native resolved-Props types use conservative declaration/default-layer facts so strict generated types reflect proven non-null values rather than casts that suppress errors.

Input IR explicitly marked schema 5 is rejected. Old source should be recompiled to produce IR 7. Legacy event/control type labels may still be normalized by proven provenance inside a structurally valid current-schema input; that behavior is separate from schema compatibility.

## Reached support and project publication

A standalone program without reached ControlLabel operations emits no ControlLabel helper. For a project containing both participating and ordinary components, the publisher verifies canonical support bytes and chooses one shared reached capability closure. A component that did not reach the capability supplies no association getter and allocates no ControlLabel host owner. Modified support bytes still conflict; the publisher does not silently overwrite consumer edits.

Tests cover real Button, Toggle and Label definitions in all four browser profiles, strict complete generated graphs, ordinary framework imports, cross-output and mixed Runtime/generated pairing, callback/default signature rejection, anatomy declarations, conditional type integrity, helper omission, and mixed-project artifact collision controls. Executed command results belong in the accompanying source-bound repair record.

## Remaining explicit boundaries

The draft `gpui-source-v1` explicit-association slice has a separate Rust nominal boundary. Complete unchanged Base Button, Toggle and Label inputs compile through `compileFile` to independent crates using one content-compatible shared SDK. `ControlLabelRef::new` and its clones enter typed `InstanceAssociations` constructor/update inputs; the existing constructors default to no association. The reference is not a portable `Value`, JSON payload, structural brand or serialized identity. This does not implement the ECMAScript same-realm ABI or mixed compiled/GPUI Adapter pairing.

The native SDK owns weak participants and exact current pair leases. It projects a derived `labelledBy` relation to the actual rendered Label node, keeps explicit author names, routes activation through the target's existing authored callback, and retires old pointer/action work across replacement, detach and disposal. The actual Window supplied to an action must match the pair's current view before authored target work or native effects run. The visible Label has no independent keyboard action or Tab stop. Its native activation action is separate from naming. Native framework consumers and source receipts are retained separately from Adapter execution and physical OS or assistive-technology delivery.

The host cannot certify the interactive path inside an external `native_view` child. Pointer input from that actual child boundary therefore leaves child input intact and refuses outer Label activation with a bounded diagnostic; ordinary Label text outside the child remains eligible. Native Anatomy-descriptor pairing is explicitly rejected. Authored focus still uses the existing native effect cycle; a same-stack State/association reentry control is not synchronous physical-focus notification evidence. Candidate-bound Rust and native framework execution remain required; source emission alone does not close these conditions.

Plain native Text does not create a selection controller. The shared compiler SDK therefore honors the existing host's bounded `user-select: none` mapping, including its WebKit spelling, while retaining explicit unmapped diagnostics for `auto`, `text` and other unimplemented values. The separate native `style_mapping` consumer checks that boundary. It does not implement native text selection or establish selection fidelity for an external native child.

The same actual Base inputs also require the generic native accessibility `activate` action. Under `C-A11Y-0001-F`, its declared `event` is metadata for the authored outward result, not a new event input. The compiler SDK maps the native Click action to the existing `press.commit` route and leaves disabled/controlled guards, State writes and outward emission in the original prototype. Other supported native action routes retain their current declared/default input mapping; unknown names still fail explicitly. The production callback lease binds the exact setup declaration, metadata, native Window and committed view epoch, with no public runtime declaration/removal API. Its independent `a11y_activation` consumer uses unchanged Button/Toggle source and manual SDK negative controls; that framework bridge evidence remains distinct from physical assistive-technology delivery.

Qt, Flutter and SSR registry profiles remain unimplemented; admission does not turn them into no-ops. ToggleGroup Root/Item already exceeded the compiler's checked language subset before this regression: array/record and capability mutation, queued callbacks, loops and dynamically obtained expose functions require independent language work. Their existing rejection remains visible and is not counted as compiled Group coverage. Runtime ToggleGroup behavior is a separate implementation and evidence path. The actual Input definition also remains rejected at its dynamic module requirements declaration; this change does not claim compiled Input coverage.

Parameter defaults are evaluated per call and checked in the caller phase. Their captured identities participate in the same imported-IR provenance checks as function bodies. Executable defaults inside callable type metadata and direct reads of a current or later uninitialized parameter are unsupported in this bounded subset. A closure created by an earlier default may capture a later parameter, whose value is read only when the closure is called.

The existing private Web Component hydration experiment has an explicit `controlLabelHydration: 'client-only'` option. It emits the real browser host implementation and accepts the dedicated association property on the hydrated client. Server association inputs and anatomy-derived pairing are rejected; the server can render an unpaired declaration without transporting an opaque ref. The default direct SSR entry and all public SSR profile admission remain unsupported for ControlLabel. This option preserves the existing experimental Button SSR regression coverage and is not public SSR completion.

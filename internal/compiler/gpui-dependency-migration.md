# GPUI dependency migration preparation

This maintained contributor guide prepares a later change of GPUI source. It does not admit a new GPUI release, restore the retired `gpui-source-v1` compiler, or certify a standalone native build. The observations below were checked on **2026-11-24**. The [Compiler README](../../packages/compiler/README.md) owns supported usage; [atomic lowering and completion](atomic-lowering-completion.md) owns the broader Compiler acceptance boundary.

## Upstream observation

- The independent `zed-industries/gpui` repository contains only a README at [commit `8d31300b294f6acc0c5809888bd2ff29e0bb7648`](https://github.com/zed-industries/gpui/tree/8d31300b294f6acc0c5809888bd2ff29e0bb7648). There is no Cargo manifest or implementation in that tree. Its README says "See you in a few weeks." The [release list](https://api.github.com/repos/zed-industries/gpui/releases) and [tag refs](https://api.github.com/repos/zed-industries/gpui/git/matching-refs/tags/) were empty when checked; those endpoints must be checked again before adoption.
- The official [registry index](https://github.com/rust-lang/crates.io-index/blob/master/gp/ui/gpui) still ends with non-yanked `gpui` **0.2.2**, published 2025-10-22. The [0.2.2 package](https://docs.rs/crate/gpui/0.2.2) is an older release, not the announced extraction. Replacing the existing commit with it is not this migration.
- The [Zed README at `990491f0ea12ceab57a6174436795f5819ed2c67`](https://github.com/zed-industries/zed/blob/990491f0ea12ceab57a6174436795f5819ed2c67/crates/gpui/README.md) already uses `gpui_platform::application()` and platform-specific features. Its [GPUI manifest](https://github.com/zed-industries/zed/blob/990491f0ea12ceab57a6174436795f5819ed2c67/crates/gpui/Cargo.toml) still declares `0.2.2`. Equal package versions therefore do not establish equal APIs between the monorepo, a fork, and the published package.

## Source identity and API capability

The historical v1 module `packages/compiler/src/gpui-dependency.ts` owned the legacy default source and its derived Cargo/profile strings prior to the clean-slate 0.4 compiler rebuild ([#1809](https://github.com/Proto-UI/Proto-UI/issues/1809), see [v2 compilation spec](v2-compilation-spec.md)). Changing a GPUI source location does not establish host compatibility.

| Source | Identity to retain | State of this preparation |
| --- | --- | --- |
| Existing monorepo | `https://github.com/zed-industries/zed` + full commit `62e5991dd0f0c8a3af8d5e7e9c4652490d468db8` | Existing default; preserve its generated bytes and original evidence scope. |
| Independent repository | Exact `zed-industries/gpui` Git URL + full resolved commit | Future candidate only; the observed repository cannot supply a Cargo dependency. |
| Registry package | Registry index URL + exact resolved package version + lockfile checksum | Future candidate only; no upcoming version number is assumed. |

Current AST-generated components can use `gpuiDependency: "workspace"` to inherit the application-owned GPUI dependency. Historical consumers may still own a shared SDK; its graph checks remain applicable to those consumers and do not imply that the current AST compiler emits that SDK. The compiler default pin in `packages/compiler/src/targets/gpui.ts` and the application's actual Cargo identity are separate facts; record both. Check the full resolved graph as well as manifest declarations.

Select native API capabilities independently: Element/IntoElement behavior, cached path IDs, text-selection notifications, focus, input, accessibility, platform initialization, and window/font backends need their own evidence. `gpui-modern-element-api` does not imply `gpui-text-selection-notification`. A renamed repository, matching version string, or successful dependency resolution does not prove any of these capabilities.

## Inspect a candidate dependency graph

Run these commands from the repository root with Node 24. Set the manifest variable to a real consumer containing the generated shared SDK. The checker resolves manifest and output paths relative to your invocation directory, then runs Cargo from the manifest's directory so the consumer's `.cargo/config.toml` and ancestor workspace configuration are discovered. The receipt records that Cargo working directory. Candidate variables below are deliberately unset: fill them only after checking an actual upstream artifact.

```sh
node scripts/gpui/check-cargo-graph.mjs \
  --manifest-path "$GPUI_CONSUMER_MANIFEST" \
  --git https://github.com/zed-industries/zed \
  --rev 62e5991dd0f0c8a3af8d5e7e9c4652490d468db8

node scripts/gpui/check-cargo-graph.mjs \
  --manifest-path "$GPUI_CONSUMER_MANIFEST" \
  --git https://github.com/zed-industries/gpui --rev "$CANDIDATE_GPUI_COMMIT"

node scripts/gpui/check-cargo-graph.mjs \
  --manifest-path "$GPUI_CONSUMER_MANIFEST" \
  --registry "$GPUI_REGISTRY_INDEX" --version "$CANDIDATE_GPUI_VERSION" \
  --platform-registry "$GPUI_PLATFORM_REGISTRY_INDEX" \
  --platform-version "$CANDIDATE_GPUI_PLATFORM_VERSION"
```

The two primary selectors are mutually exclusive: `--git` with `--rev`, or `--registry` with `--version`. The retired `--profile` selector is rejected; this independent graph checker imports no compiler or legacy SDK identity. Explicit dependency arguments do not establish native API admission. An independent platform selector is either `--platform-git` with `--platform-rev`, or `--platform-registry` with `--platform-version`. Providing either pair requires exactly one reachable `gpui_platform` package.

A Git source defaults any present platform crate to the same URL and commit; without explicit platform options, its presence is optional. Registry packages may release independently: a present `gpui_platform` requires its own explicit source/version. Its version is never inferred from `gpui`. An ordinary index URL expects `registry+<URL>`; for crates.io use `https://github.com/rust-lang/crates.io-index`. Alternatively pass the full `registry+<URL>` or `sparse+<URL>` source ID returned by [Cargo metadata](https://doc.rust-lang.org/cargo/commands/cargo-metadata.html). These source IDs are opaque and Cargo-version-dependent: retain `cargoVersion` and match the actual identity rather than inferring it from the download protocol or a registry's friendly configuration name. CLI version arguments are complete versions, without `=`, ranges, or `*`.

The [graph checker](../../scripts/gpui/check-cargo-graph.mjs) uses full `cargo metadata --locked --all-features`, without a platform filter. It rejects duplicate GPUI/SDK identities and source/version mismatches. `--no-deps`, lockfile text searches, unavailable dependencies, and skipped work cannot yield a pass. `--output` writes a receipt and retained metadata; use a new output path for each attempt. Graph evidence does not certify compilation, every feature combination, native input, or physical devices. Preserve failed receipts as failed evidence.

### Verdant

At [Verdant `ac0402289e335d9a8228b4e056fb95320482458a`](https://github.com/OpenGreendam/verdant/tree/ac0402289e335d9a8228b4e056fb95320482458a):

The fork supplies used Wayland touch and text-selection notification capabilities; their replacement must be verified before removing that source.
- [compiler.pin.json](https://github.com/OpenGreendam/verdant/blob/ac0402289e335d9a8228b4e056fb95320482458a/frontend/proto-ui/compiler.pin.json) v3 binds Compiler `4e499ae25e825e130e740f16af66d70b23a743cf`, separate upstream/workspace GPUI revisions, and a single content-bound SDK. All native units inherit workspace.
- [workspace-gpui.mjs](https://github.com/OpenGreendam/verdant/blob/ac0402289e335d9a8228b4e056fb95320482458a/frontend/proto-ui/tools/lib/workspace-gpui.mjs) admits only Git + 40-hex revision for the workspace identity and resolved graph. A registry migration requires source-aware admission; retain alias, target, duplicate-package, feature, and shared-SDK checks.
- [build-proto-ui.mjs](https://github.com/OpenGreendam/verdant/blob/ac0402289e335d9a8228b4e056fb95320482458a/frontend/proto-ui/tools/build-proto-ui.mjs) requires both GPUI revision fields and compares Compiler profile/dependency versions to `git:<upstreamGpuiRevision>`. Update that schema and comparison for registry support together with the real workspace pin, lockfile, and fresh receipts. Preserve `--check` versus `--check-retained`; regenerate rather than editing outputs.

Keep the session/protocol dependency graph free of GPUI and native SDK dependencies. Rerun the [native workflow](https://github.com/OpenGreendam/verdant/blob/ac0402289e335d9a8228b4e056fb95320482458a/.github/workflows/frontend.yml): fresh generation, source mutation, graph checks, headless session, three-platform GUI/SDK builds, and the same build's packaged Linux X11/Wayland input scenarios. The [platform acceptance obligations](https://github.com/OpenGreendam/verdant/blob/ac0402289e335d9a8228b4e056fb95320482458a/frontend/docs/PLATFORM-ACCEPTANCE.md) separately cover system IME, physical touch, full screen readers, and actual Windows/macOS windows. Historical passes do not certify a new dependency.

## Future activation checklist

- [ ] Verify the independent repository contains buildable crates, or the intended registry release exists; retain the exact source and publication evidence.
- [ ] Record GPUI and platform identities independently, applicable Rust/toolchain requirements, features, licenses, and any retained fork delta.
- [ ] Verify Element APIs, text-selection notifications, focus/input/accessibility and platform startup against the actual candidate; retain unsupported cases explicitly.
- [ ] Resolve a clean locked consumer graph with one GPUI and one shared SDK; reject mixed old/new sources, hidden aliases, local patches, and missing platform requirements.
- [ ] Regenerate SDK/components, lockfiles and provenance with the reviewed Compiler; check source and generated-byte changes without manual generated-file edits.
- [ ] Complete Compiler and native SDK tests, real authored consumer journeys, platform builds and required actual-window input checks at the candidate source.
- [ ] Update Verdant's producer schema/admission and fresh receipts; execute Shenko's React generation/browser regression for the adopted Compiler.
- [ ] Review source, API, artifact and evidence changes together before making a new source the default; retain unexecuted platform obligations.

## Rollback checklist

- [ ] Retain the last accepted Compiler/app commits, GPUI sources, Cargo lockfiles, SDK content hashes, generated artifacts and receipts before activation.
- [ ] Restore those coordinated source selections and regenerate/restore their matching artifacts; do not mix a previous SDK with new-source generated crates.
- [ ] Recheck the restored locked graph and affected consumer behavior, and record the failed candidate and rollback result without rewriting historical evidence.

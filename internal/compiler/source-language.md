# Closed source language

This is the private compiler's admission contract, not a published TypeScript or host support claim. Input source is parsed and resolved inside the supplied graph; the compiler never imports or evaluates an input module.

## Binding identity and normalization

Semantic authority belongs to a resolved declaration. A name alone does not grant a capability. An imported core type or factory keeps its identity through local aliases and named re-exports. A local declaration with the same spelling remains an ordinary local declaration. This includes `FocusRequestOptions`: it is a focus options schema only when its binding resolves to that export of `@proto.ui/core`.

A contiguous chain of erased type assertions, with optional parentheses, may retain the original checked expression when an intermediate view is `unknown` and the final nominal capability type is exactly the original checked type. Every intermediate assertion must independently pass admission. The compiler emits the original expression once, so portable IR validates that expression without an `unknown`-to-capability conversion or source-only proof. This rule does not recover authority from an unknown parameter or binding, substitute a different capability, upgrade State ownership, or remove readonly field protection. Generic arguments remain subject to the existing core type projection; an assertion does not establish a new generic API guarantee.

A setup function may be a method, declaration, arrow, function expression, or a static alias of one of those functions. Importing or re-exporting that function does not change its lexical owner. Its free bindings resolve in the function's source module. Calls to module functions also retain that owner.

Module aliases are admitted for static functions, admitted package symbols, and checked finite static data. The compiler checks cycles and reads before initialization. A scalar alias is not silently converted into a live binding: `const saved = mutable` has snapshot semantics and currently requires an explicit supported initializer.

### Inert module cycles and static callable selection

A runtime import cycle is admitted only when every participating module has a complete declaration table and contains inert function declarations/expressions, immutable literal data, or the static callable selections defined here. Mutable module storage, static Core factories, accessor objects, wildcard export cycles, arbitrary initializer calls and a back-edge into a partially discovered declaration table retain an explicit refusal. This does not admit arbitrary ESM execution. Once the complete source graph exists, immediate initializer reads are checked in ESM dependency depth-first postorder and authored statement order. A function declaration is initialized at linking; a lexical function expression, data constant, alias and `export default value` snapshot remain uninitialized until their own statement. References inside an uncalled function body are deferred. Direct cross-module reads before initialization, including a default-export snapshot of an otherwise hoisted function, receive PUI1008.

An immutable module binding may select `condition ? moduleFunction : undefined` (or two module functions, in either order). Each branch must name an existing source function or unshadowed `undefined`; the function signatures must satisfy the binding's explicit type. The condition must be a boolean literal, a reference to an initialized immutable literal boolean, or a literal-only scalar membership expression. Mutable snapshots, arbitrary calls, callable containers and owner-created closures are excluded. The compiler checks the condition's real expression and declaration type, selects the known static branch, and retains a reference to the real module function or `undefined` in checked IR. It does not fabricate a function body, execute the helper, or publish an exposure from an unselected helper. The whole supplied source graph remains in provenance.

The portable validator independently admits only an immutable reference chain rooted at checked module functions or `undefined`, with a compatible callable/optional-callable type. An unbound alias, owner capability, mutable cell, arbitrary initializer or forged type retains a diagnostic. Native module partitioning follows the alias dependency, so an alias to a helper requiring the current owner remains in that owner together with its real helper. Setup-only effects reached through optional calls and a default export remain setup-only. This current-source admission does not by itself accept a historical private IR candidate.

Unannotated callback parameters can be constrained by a resolved operation's receiver capability and argument schema. A property spelled `focusSelf` on an ordinary object supplies no such authority. Conflicting constraints are rejected.

Dormant bodies do not acquire host-admission or emitted-code obligations. A direct call to an unshadowed, explicitly typed callable parameter can still contain a closed type contradiction when every argument is a scalar or array literal. The frontend checks that limited evidence without executing or lowering the body. This retains an array-versus-Boolean-rest argument error while permitting legal scalar/spread calls and continuing to defer unknown expressions, nested functions and host references. It is not a complete TypeScript body checker.

## Explicit external source identities

File and project compilation may receive a bijection from canonical external source-tree roots to stable identifiers. The loader verifies that each root is a directory, roots are disjoint from the project and one another, and identifiers are unique. Logical source identity uses that root identifier together with the original relative package/file path; manifest and unresolved lookup identity use the same mapping. Physical dependency and resolution inventories remain unchanged. The mapping neither supplies source bytes nor authorizes another import: package `proto` exports, local-edge boundaries and source admission still apply. Two installed copies are not coalesced by package name, version, content, or a caller-supplied duplicate identifier. A logical-location collision is rejected. Moving an explicitly identified closed source tree can therefore preserve generated bytes without weakening physical source ownership.

## Erased type graph

Finite data aliases and interfaces may be imported, renamed, re-exported, or namespace-qualified inside the closed graph. Type resolution checks duplicate declarations, ambiguous star exports, and cycles. It reads the source bytes of the required type declarations without admitting their file as executable code. Unused type-only imports do not require source bytes. The file compiler loads the syntactically required local type edges as well as executable source edges.

Every source file used by semantic resolution is included in provenance. Source bytes are provenance, not an executable fallback for unsupported syntax.

When an erased type query selects a value through a barrel, the file loader follows named and star value re-exports and local export lists that forward imported bindings. For example, `import type {Renamed} from './barrel'` can resolve `(typeof Renamed)[number]` through `export {IDs as Renamed} from './values'` or `import {IDs as Local} from './values'; export {Local as Renamed};`. These dependencies supply source bytes for resolution. Runtime admission follows its own dependency edges.

The erased expression `(typeof CONST_TUPLE)[number]` may select the exact union of a module `const` literal tuple's scalar elements. The binding must resolve to its authored declaration in the closed graph, including renamed imports and named or unambiguous star re-exports. Its initializer must be an array literal asserted `as const`, without a widening declaration annotation; elements are string, number, boolean or null literals (including signed numeric literals). Parentheses and an outer `satisfies` wrapper do not change that identity. Duplicate alternatives collapse and an empty tuple selects `never`. No input initializer is executed. A nearer lexical value binding cannot be replaced with a module binding. This tuple-selection rule does not admit runtime-produced arrays, mutable or widened declarations, element references, spreads, holes or nested containers. Reaching a declaration solely for this erased query does not admit its module as executable code.

Separately, a value query may use an already checked lexical value, its finite members, or finite static data in an already admitted runtime module. `ReturnType` may select a checked ordinary callable result or the registered result of a nominal Core operation. A nongeneric module function may supply its source-declared signature without executing it; the eventual function body still undergoes normal source and IR validation. These queries neither load an erased-only module as runtime code nor recover capability authority from an unknown value. Finite `keyof`, mapped fields, literal-key selection and `Pick`/`Omit` over ordinary records retain field permissions. `Pick` of a nominal Core handle requires every requested key to be a declared public member and retains the original nominal handle identity; it is a checked type view, not a restriction of that handle’s authority or a security boundary.

The ordinary `NonNullable<T>` utility removes only the checked domain's null and undefined alternatives. It retains false, zero, empty strings, readonly fields, nested nullability and nominal handle ownership. Authored aliases resolve before the builtin name. Opaque unknown/any inputs remain unsupported because this type grammar has no nonnull-unknown representation; the annotation cannot manufacture a value or capability proof.

## Finite string membership

Separately from dynamic finite-string membership below, a direct array literal of finite scalar literals may call `includes` with one scalar literal. Strings, finite numbers (including signed zero), booleans and null are compared using SameValueZero without coercion; an empty literal array produces false. Every operand and type view is checked before the result is folded to a boolean literal. No input code executes. Holes, spreads, getters, proxies, custom receivers, identifier elements/search operands, optional calls, type arguments and `fromIndex` are outside this static proof. This rule does not grant membership support to a dynamic numeric or boolean array and does not introduce a new runtime intrinsic.

A nonempty literal string array asserted `as const` retains the exact string-literal types of its checked elements in executable IR. Each element is still validated against its literal value after serialization. An unasserted array keeps ordinary widening; erased type-query resolution alone does not supply the executable receiver proof.

`array.includes(search)` over a checked array accepts exactly one operand, including unknown, and returns boolean. The finite-string guard below requires a nonempty finite union of string literals; ordinary broad string, numeric and object membership use the same native operation without obtaining that guard proof. `fromIndex` and authored sparse arrays remain unsupported. Native JavaScript SameValueZero performs no coercion; only equal strings can match a finite string receiver domain. Receiver and search evaluate once in that order, including for an empty runtime array; an admitted optional collection call retains its nullish short circuit.

At this comparison boundary only, a single erased assertion to a finite string-literal union may be removed from the search expression. IR retains the actual operand and checked type; the assertion grants no provenance. Portable validation independently checks receiver domain, arity and result through the shared intrinsic rule. Assertions elsewhere retain their existing proof requirements.

A true direct guard refines an immutable searched binding to the receiver's checked element domain. Mutable cells, member reads, calls and saved booleans do not acquire this proof; false branches exclude nothing. Shared JavaScript emission uses native membership for Web targets. GPUI explicitly rejects this intrinsic; Flutter and experimental Qt have no native acceptance evidence for this extension. Source admission alone establishes neither target support nor downstream component completion.

## Native String conversion

An unshadowed `String()` or `String(value)` admits zero or one checked data or opaque `unknown` operand and returns a string. Local declarations and imports named `String` remain ordinary bindings. Optional calls, spread arguments, constructor syntax and known callable or owner-capability operands remain unsupported. This bounded admission does not erase callable or capability fields into data.

JavaScript targets emit the native `String` call, preserving missing versus undefined operands, null, signed zero, non-finite numbers, arrays, object coercion order, string-hint conversion and abrupt completion. An unknown operand remains opaque: conversion grants no field or capability authority. Coercion can invoke user code, so both frontend and portable validation invalidate mutable flow observations; an unused conversion remains executable. Portable IR independently checks arity, operand domain and result type.

Runtime-backed React and browser source profiles share this native lowering. The bounded draft [scalar contract](../../spec/contracts/C-COMPILER-SCALAR-0001.yaml) admits zero or one checked scalar operand on GPUI and the pure Rust data artifact: string, number, Boolean, null or undefined, including their checked literal alternatives and unions. `String()` produces `''`; `String(undefined)` produces `'undefined'`. Native structured or opaque `unknown` conversion remains unsupported. Direct Qt/Flutter String experiments still reject this intrinsic. Source admission, generated Rust data execution and mounted GPUI evidence are separate; none establishes component completion or a stable profile.

This intrinsic does not broaden profile-specific public method signatures. React and Vue3 source methods still require checked public value signatures. An internal helper accepting `unknown` and an exposed method accepting `unknown` are separate admission questions. Source admission of raw Props reads does not establish target admission of watcher operations. The four browser source profiles admit keyed `props.watchRaw` and the resolved/raw all-key watchers. Vue2's former all-key target rejection is retained in the Sprint 2 red receipt; current generated consumers verify snapshot diffs, raw-all/keyed/resolved ordering, cancellation and terminal disposal against C-PROPS-0011/C-PROPS-0012. Raw snapshots remain host-specific escape-hatch observations, not portable resolved Props.

## Finite style tables and Rule environment facts

Module static data may contain template strings whose substitutions are independently admitted static data. A flat local `const` table can supply compile-time style tokens or `Object.keys` enumeration only when the entire block proves that its container neither escapes nor mutates. Scalar member reads are permitted; aliasing the container, passing it to another function, method calls, writes and deletes invalidate this proof. A local binding blocks a same-named module table. Builtin `Object.keys` requires an unshadowed `Object`, retains ECMAScript own-key order and duplicate-key behavior, and rejects `__proto__`. Reads before a local table's initialization are not unrolled.

A direct one-parameter arrow in `finiteList.forEach` can use the same finite loop expansion as `for...of`, provided it has no async modifier, default/rest parameter or abrupt return/break/continue. Substituted literal ternaries are decided at compile time. Other iteration retains its explicit diagnostic. None of this executes authored source, introduces a runtime iterator or changes the prototype's behavior by its name.

A declaration-time conditional inside a Rule callback may use the existing native `Set.has` operation when its receiver has a checked, non-nullable Set type and both receiver and search are pure captured expressions. The callback's own parameters and local declarations cannot supply either operand. The source lowering preserves the actual membership call and checks both Rule branches through the ordinary declaration path; it does not execute source or replace the Set with a component-specific lookup. Same-named ordinary methods, mutating collection operations, optional calls, spreads and effectful operand calls remain outside this lifting boundary. This is a bounded composition of the existing Set intrinsic and declaration-time captured choices, not a general helper-purity proof or a new Rule observer.

Rule conditions admit the fixed `colorScheme` and four `preference.*` inputs from `C-RULE-COLOR-SCHEME-0001` and `C-RULE-PREFERENCES-0001`. Pure condition structure and token precedence remain `C-RULE-WHEN-0001`; each target emits an ordinary predicate, not a Rule interpreter. Four browser source profiles acquire only reached native document sources while mounted. One document color source observes root class/data-theme and the system query. Preference queries are shared per document/key and readable only through an active paired source; missing/ambiguous facts stay `unknown`. Leases precede fresh style reconciliation, environment notifications request style reevaluation only, and detach/dispose release them before stale work can run. Existing sampled Meta reads remain separate. These contracts stay draft, and this slice does not admit Rule Meta on GPUI, Qt, Flutter or SSR profiles.

The real full Base/Shadcn/Brutalist Button sources are consumed without edits by all four browser source profiles. Their ordinary children, dynamic environment styles and disabled projection are checked independently of generic language fixtures. Keyed raw watcher checks retain `Object.is` union-key diffs, callback-window identity, raw-before-resolved order, warnings and cancellation. The returned disposer is an ordinary void callable; it does not reacquire setup authority. These concrete consumers do not establish support for other untested prototype families or backends.

## Bounded numeric conversion, rounding and text length

The same draft [scalar contract](../../spec/contracts/C-COMPILER-SCALAR-0001.yaml) governs an unshadowed `Number()` or `Number(value)` with zero or one checked scalar operand. An omitted operand yields positive zero; explicit undefined yields NaN. Null, Booleans, numbers and numeric strings retain ECMAScript conversion behavior, including signed zero, whitespace, radix prefixes and invalid-input NaN. Structured values, unknown, callables and owner capabilities have no admitted coercion on this bounded path. Extra operands, optional calls and constructor syntax remain unsupported. Local or imported bindings called `Number` or `Math` retain their own identity.

`Math.round(value)` and `Math.floor(value)` each require one checked number. Rounding preserves source-language negative ties toward positive infinity, signed zero, non-finite values and precision-limit integers; it does not reuse Rust's different negative-tie rule. The `.length` of a checked string counts UTF-16 code units, so an astral character contributes two. It grants neither numeric/Boolean member access nor a missing record field. Each operand evaluates once, and independently supplied IR rechecks the same operand and result domains.

The five implemented source profiles have compilation regressions for this slice; the pure Rust data regressions execute generated crates and retain any required language-support dependency. Finite public-data boundaries still reject non-finite values at their own ingress or egress. The [test mapping](../../spec/tests/T-COMPILER-SCALAR-0001.yaml) keeps mounted GPUI evidence separate and does not infer Qt/Flutter support from the common parser or lower-level helper presence.

## Fresh-target own-data assignment

An unshadowed `Object.assign(target, ...sources)` is admitted for a direct fresh record literal or a direct `new Error(message)` target, followed by zero or more direct finite record literals. Every target entry must have a checked pure-data value. A direct finite source may also declare the static zero-parameter getters defined below when their results are pure data. Copying reads those getters at the native assignment boundary. Arbitrary references, spreads, getter targets, setters, dynamic keys, callable or capability values, arrays, scalars and nullish sources remain unsupported. An aliased, asserted, frozen or readonly target is not a freshness proof. A field named `__proto__` is excluded from every participating record because assignment can invoke an inherited setter instead of defining an own data property. Optional calls remain unsupported. A local or imported `Object` binding is an ordinary binding and grants no intrinsic authority.

All target and source expressions evaluate once, left to right, before native assignment copies properties. Sources copy in order; the last source containing a key supplies its value. The result is the original target, with nested object identity retained. A record result has the final finite data fields. An Error result remains an opaque exception: adding diagnostic data does not grant typed catch fields, callable provenance or a new capability. Native Get/Set behavior and abrupt completion remain observable; assignment is not replaced with object spread. The operation conservatively invalidates mutable flow observations and remains executable even when its result is unused.

Portable IR independently validates every argument and rechecks the direct fresh target and finite own-data sources before deriving the result. An `exception` type annotation alone cannot authorize mutation of a caught or aliased value. Runtime-backed React and the four browser source profiles lower the operation to native JavaScript `Object.assign`. GPUI and the direct Qt/Flutter experiments explicitly reject it; source admission does not establish support for those targets or complete a component's acceptance.

## Functions and hook installation

Runtime Anatomy role selectors (`has`, `partsOf`, and the ordered `partsOf`, `indexOfSelf`, `prevOfSelf`, `nextOfSelf` queries) accept a literal role or a checked finite union of nonempty string literals. A helper formal such as `role: 'trigger' | 'content'` retains that finite proof; the emitted native query receives the actual argument once and selects that role in the current family/domain. Source admission and portable IR use the same finite-string-key validation already used for declared event selectors. Broad `string`, empty-string alternatives, nullable or mixed non-string domains remain unsupported by this bounded compiler admission. This does not broaden setup subscription keys, declaration keys, family identity, query phases or the limited Part View surface, and does not promote the draft Anatomy contracts.

An ordinary function creates a lexical closure. Creating, returning, aliasing, or passing that closure does not execute its body and does not begin a setup or callback lifecycle. Defaults run at the call, from left to right, when an argument is missing or `undefined`. Captures identify declarations, including later declarations, rather than relying on the spelling of a name. Creating a closure before a captured `const` is initialized is allowed. Direct reads or writes before a lexical declaration's initialization receive a diagnostic in this finite subset; this check belongs to the current function's execution scope and does not reject a deferred closure capture. Portable validation checks the same initialization order from IR bindings. Ordinary block shadowing remains legal, and function declarations retain their hoisted initialization.

Source admission may defer a local function's body and default expressions only after a conservative binding-use proof shows that every reference belongs to the same unused declaration closure. The declaration's synchronous function shape, parameter names and explicit parameter/return types are still checked. An already initialized private `const` alias can join that closure; a forward lexical read cannot. A call, public escape, record/property use, mutable alias use or unclassified reference demands the complete real body. Explicit outer binding type annotations and type assertions retain their ordinary admission obligations. The analysis conservatively counts same-spelled names in nested scopes and types, which may retain extra work but cannot remove a real lexical use. Full source bytes, spans and source hashes remain unchanged; no dummy callable IR is emitted for the deferred declaration. Imported modules, exports and static definition descriptors still receive their ordinary checks. This is a bounded source-admission proof, not source rewriting or general JavaScript dead-code elimination.

Fixed operation result signatures participate in forward binding inference without running the initializer. For example, a Context subscription returns an ordinary `() => void` cancellation function; a deferred callback may capture that later binding, and the function may be aliased or stored in a mutable local. Receiver and argument dependent result types still require their checked bindings.

Known ordinary calls are checked in the execution context of the actual call. Source admission and portable IR validation share one static traversal of lexical bindings, callable arguments, defaults, aliases, returned closures, and record members. Registered callback signatures establish their execution context; merely returning or storing a callback does not. Hook capture discovery uses the same traversal, so adding an alias or a closure factory cannot drop direct state declarations from a capture. Mutable lexical cells and record fields retain callable provenance, including aliases and nested records. Setup applies definite writes in order; conditional and exceptional paths retain each possible store. Registered callbacks and every setup-returned render function are checked against one shared store until their effects stabilize, because an owner may execute them repeatedly in different orders. An outward event declaration alone does not require data-object provenance: when every actual emit omits its payload or directly supplies `undefined`, callable and phase analysis still runs without the additional JSON aggregate tracking. Any other payload expression, including a call or alias whose declared type is `void`, retains the complete data-provenance check in both source and portable IR. This conservative decision scans module, hook, default-parameter and nested callable bodies; it does not infer safety from an event name or a payload type annotation. The store includes hook registration state and each capture frame: a conditional installation remains only possibly installed, and exception paths retain registration that preceded a failed setup. Public records and callable return values remain outward roots when later callbacks replace a field. A definite overwrite before a call can remove an earlier dangerous function. A type annotation cannot grant new lifecycle authority.

Callable fingerprints retain field positions, closure environments, and mutable storage identities. Separate setup-time factory calls remain separate; recursive or repeated callback analysis joins only the corresponding invocation allocation sites. Fixed host callable signatures, including public callable parameters, are explicit external contracts. Outward argument analysis keeps actual checked argument and record-field types. An untracked value whose checked type is pure data is a data fact rather than unresolved callable provenance, while a stored closure, record, cell or capture is always traversed whatever the checked type says, so a later alias write cannot hide an effectful callable behind an omitted or narrowed field. Callable-bearing fields still require effect analysis. A data fact belongs to the value that carries it, so each alternative of a union keeps its own facts and the union's type never reclassifies a value. Unresolved source callable provenance or an exceeded finite analysis boundary produces a diagnostic; it is not accepted as an empty capture. These are compile-time proofs: the emitted program retains ordinary target calls and the existing owner/lifecycle guards.

All parameter bindings exist before any default is evaluated. A direct read of the current or a later uninitialized parameter is rejected in this finite subset; a delayed closure may capture that parameter's binding. Immutable saved predicates can carry flow facts. A closed single-expression predicate may be inlined only over stable operands and strict comparisons, Boolean operators, `typeof`, or the admitted non-coercing `Number.isFinite` intrinsic. An annotation such as `value is number` alone supplies no proof. A saved cell or mutable member observation cannot prove the value after a write. Calls that can mutate a captured binding or object, synchronous host writes, and exception paths invalidate the affected observations; a fresh guard or an immutable value snapshot can establish a new proof. Known synchronous read-only functions preserve observations. Creating a closure does not execute its body or establish that its captures will retain their current values when called.

Scalar const facts can resolve static declaration keys, literal metadata properties and Rule choices; ordinary reads retain their binding identities and captures. A proven absent optional callee still evaluates once and skips all call arguments. A `typeof` object guard supplies only an opaque object view, including the null alternative. A compatible `Record<string, unknown>` view permits unknown-valued member reads; it does not establish a finite data schema or any callable/owner member.

A nonoptional computed member read can use a proven immutable scalar key without erasing its lexical read. An ordinary checked helper evaluates the original receiver and index once, in order, then reads the proven field. The retained index argument preserves captures and initialization checks. This lowering does not apply to optional access, whose nullish receiver must skip index evaluation.

Readonly field permission remains attached through aliases and assertions; an object spread produces a new mutable top-level record. Readonly is a write permission on a view, so writes through a mutable alias invalidate observations of the same field. The frontend and portable validator derive that conservative field-write footprint from the checked semantic graph. Retained source and unused module helpers do not contribute effects. Object entries and spreads are checked in their left-to-right evaluation order.

Closed ordinary helpers may specialize a parameter to the caller's complete checked record shape. Every declared field must remain compatible, and the generated signature retains all additional callable/capability fields and readonly permissions. This permits a visual helper to borrow a subset of a real capture's handles without pretending that the remaining authority disappeared. Ordinary aliases, assignments, casts, and unknown parameters do not acquire this exception. Specialization records the actual structural signature and does not change authored-hook installation identity.

A closed helper's declared interface may also describe a subset of an already checked nominal handle. Each field must match a declared capability member or a simple method signature from the shared operation table, including receiver ownership and value type. The helper body and portable IR retain the actual nominal parameter, and distinct nominal payloads receive distinct helper specializations. Callback-bearing or argument-dependent method signatures without a corresponding proof remain unsupported. Structural records and unknown or nullish values cannot acquire nominal authority from this interface compatibility check; phase and ownership checks still apply to every reached operation.

A known immutable local helper with required ordinary parameters may retain a nominal argument through the same interface proof. Inference discards the preliminary graph and rechecks the original closure, all calls and aliases with the retained parameter; it neither clones that closure per call nor wraps the runtime module. Shared callable provenance must establish a closed graph with no escape of the retyped helper to open callers. Every later call must match the same retained nominal signature. Mixed nominal payloads, mutable helper bindings, explicitly typed callable variables, optional/default/rest parameters, unresolved recursion and open callers remain unsupported on this bounded local path. This exception does not apply to ordinary casts, assignments or unknown values.

A closed authored-hook options expression can likewise retain the concrete shapes of generic `unknown` slots, including callback inputs and outputs. The caller expression is lowered once, with contextual parameter types and inferred callback results; explicit result annotations still constrain those results. The hook body is then checked against the resulting complete options shape. Concrete declared fields, optional absent fields, callback arity, and readonly permissions remain checked. Specialization is lexical and does not change the declared hook name or its once-per-owner installation and capture rules. This is not a cast that grants authority to an opaque runtime value. A contextual `void` return on an ordinary callback permits its ignored data result; the independently checked call still rejects hiding a callable or capability result behind that view.

Checked Props validators retain their actual closures. Native JavaScript hosts first validate the declared data schema and range, then call the validator; a false result or exception rejects that candidate before fallback resolution continues. Repeated declarations cannot remove or replace an existing validator identity, and a failed multi-key declaration leaves the previous declaration set intact. Callable analysis checks retained validators in both setup and later update contexts. Other native targets explicitly reject reached validators until they implement that invocation and fallback behavior; the public Qt and Flutter emitter entries apply the same declaration check to their emitted closure.

Optional/defaulted and final array-valued rest parameters retain their invocation semantics. A dynamic argument spread is admitted only after every fixed parameter, into a checked rest tail, or at a nominal public-method boundary. Portable IR records the spread positions and rechecks iterable element types, callable provenance, and public-value restrictions. Native JavaScript preserves argument evaluation order, optional-call short-circuiting, receiver identity, and one evaluation of each source argument. Other targets explicitly refuse reached spread calls until they implement these semantics. Mutable parameters lower to local cells; their writes do not mutate a caller's binding.

### Ordinary object getters

An object literal may declare a getter with a static identifier or string name and no parameters. The checked record retains its real function body and an `accessor: 'get'` entry; its field carries the getter's return type, a readonly permission and the same accessor fact. Object creation does not call the getter. Every member or indexed read invokes it; an object spread or an admitted direct finite `Object.assign` source invokes source getters while copying and produces ordinary writable data fields. An optional spread field that is absent cannot replace an earlier getter, so its possible accessor behavior remains checked. A function that always throws can have a declared non-void result: it completes abruptly instead of manufacturing a return value. Setter declarations, `this`, computed getter declarations and numeric-name syntax gain no new admission; a string name such as `'1'` remains a static string.

A getter read invalidates affected mutable flow facts and participates in callable-effect analysis as a real call. A primitive result snapshot can cross the public boundary; an object still containing getters cannot, and a structural type view cannot erase the accessor fact. A static module getter object may return finite data and remain shared, but it cannot depend directly or through a helper/default on owner-local operations. Such an object cannot silently become a fresh copy per owner.

Portable validation independently checks accessor tags, zero parameters, return types, readonly fields, flow and callable effects. The current IR8 shape adds optional accessor tags; a reader without this extension rejects the unknown fields. This does not migrate or accept the separate historical private IR10 candidate. The four browser source profiles and Runtime-backed React emit native JavaScript getters. A reached getter remains explicitly unsupported by GPUI (PUI4003), the Qt/Flutter profiles (their existing PUI4001 boundary), and the pure Rust data-expression selection.

`defineAsHook` and `defineHook` are explicit installation boundaries. This compiler follows the current Core contracts rather than extending them by component name. An as-hook takes no invocation options and installs once by its declared hook name per owner. A second source declaration with the same hook name remains a different lexical declaration but shares that runtime installation identity. Projection runs after capture. A capture contains the states directly contributed by the installation and its raw exposed methods. Nested hooks retain separate child results and projected handles. The capture's `getState`, `getMethod`, `getAsHook`, and `getAsHookHandle` perform read-only lookup and can be used after setup; invoking a returned method is checked in its actual execution context. Raw captured methods can be used synchronously during projection or setup. Returning or explicitly exposing one to a public caller establishes a callback boundary. The runtime's Expose registry may also retain a registered raw method's public entry, so its body is retained by demand analysis and that entry keeps the owner callback guard; capture lookup does not itself call the method. Analysis of this implicit raw entry keeps ordinary effects before a guard and treats an illegal-phase host operation as an exceptional completion, including authored catch/finally successors. Explicit source calls through a projected or publicly returned method still receive the ordinary strict phase diagnostic. Guarded and strict executions do not share analysis cache entries.

Copying a capture's public facade or renaming one of its lookup functions preserves the lookup's actual installation identity. Callable analysis follows that owner to its methods and child installations; the lookup itself does not invoke a returned method. Unknown lookup keys conservatively include every possible target and the absent result. These are internal facts derived from the checked installation graph, not serialized claims or authority inferred from an ordinary object's property name. Source-free validation rederives them before accepting the graph.

### As-hook `stateHandles`

The runtime collects the installation's named state handles when setup ends and freezes the resulting record. `getState(key)` reads the same record. Both lookups project owned or borrowed handles as borrowed views and preserve read-only observed handles.

- **Focus facts.** A reached `def.expose.state` can explicitly introduce a named observation from `asFocusable()` into the current capture. The capture uses the Focus state declaration name even if the public expose key differs. Calling `asFocusable()` alone only contributes a child entry.
- **Definite presence.** With a single source declaration for the hook name, a named state is definite when every successful setup completion declares or introduces it. The checked callable-flow graph follows ordinary helper calls and their actual arguments. Alternative normal and returned paths intersect their guaranteed state names; a conditional or zero-iteration loop therefore cannot grant presence merely because one branch declares a state. `try`/`catch`/`finally` retain their normal and exceptional completions. A path that throws out of setup produces no result. Nested hook contributions remain separate from the current installation.
- **Field types.** A definite state is a required field. Other admitted states are optional fields. The handle type preserves the same write authority in either case.
- **Record type.** At least one definite state makes the record required. An installation without named state contributions yields `undefined`.
- **Target support.** Native support objects expose the same frozen `stateHandles` record beside `getState`, for every target that lowers `capture.getState`. A target without it keeps an explicit unsupported diagnostic.

The capture schema remains the upper bound described above. This rule only identifies the subset of that schema that a single winning declaration is certain to produce.

`defineHook` additionally retains its options type, mode, setup API, and configurator. Setup receives `(def, options, api)` and can return render or void. The configurator receives `(api, options, tools)` and returns void. The API's store belongs to the installation. `once` skips later installations, `multiple` creates separate installations, and `configurable` runs setup once and configure on the initial and later calls. Warn and conflict are callable fields supplied by the installation runner. They are not new compiler operations. Hook arguments, including omitted options, preserve source evaluation order. The ordinary setup-time creation of an exposed method does not execute that method during setup; calling it later uses the owner's active lifecycle guards.

An options callback contributes to the capture frame in which it actually executes. Capture inference follows the caller's checked closure environment through aliases and ordinary factories; creating the callback does not execute it. A descriptor's capture schema is the union of possible direct contributions across the closed graph, including possible same-name once winners. It is an upper bound, so a key can remain absent from a particular installation and lookup stays optional. Incompatible types for the same captured state or method receive an explicit diagnostic. Each installation retains its own values, raw method environments and child records; the schema does not merge live captures or flatten a child's state into its parent. Source parsing may use a checked statement prefix to infer a later lookup's type, but the complete graph independently rederives the schema before source admission and portable IR validation. A definite once winner excludes later skipped option initializers from this derivation.

An authored package participates through the same closed graph as local source, using an explicit `proto` package export or a `sourceImports` mapping. The compiler has no packaged Transition operation, injected Transition prop table, or replacement Transition implementation. Its machine, projection, event declarations, and public methods are derived from the supplied authored source.

Rule declarations retain serializable prop, state and meta dependency identities. `eq` is strict equality, and `gte` requires a finite numeric literal threshold and a finite numeric current input without coercion. A supported target emits direct predicates; an unavailable host-meta provider receives a diagnostic. React DOM source currently provides the bounded mounted default-web color-scheme, viewport-width and fixed preference sources. No serialized Rule evaluator or component-name dispatch is emitted.

A pure captured ternary inside a `when` or style `intent` callback is lifted to the setup declaration point, producing an ordinary conditional over separately checked Rule declarations. Captured references, ordinary data member reads, negation and strict/boolean comparisons are allowed for this lifting; callbacks, assignments and builder-local captures are not. Each branch retains its original source range and is validated even when another branch is selected. A checked local immutable style table can be read through its actual initializer; unknown, recursive or executable style data remains rejected.

Rule style operands may also reference checked `StyleHandle` values supplied through ordinary helper parameters or record members. Portable IR stores those expressions in a separate binding table and requires each reference to resolve to the semantic style-handle type. JavaScript source emission evaluates each state and style binding once at declaration installation, preserving its identity when the caller later changes an ordinary record field. Native targets without this operand lowering reject the reached Rule explicitly. Only installed declarations contribute live host-meta leases.

A single-argument trusted `tw(condition ? first : second)` call lowers to an ordinary conditional over two independently checked static style handles. The checked condition executes once at the original call point; both token branches must remain finite static strings. This admits finite authored style choices without a runtime token factory or an interpolated-token escape.

A style token written as a module constant may be `<static string list>.join(<string literal>)`, folded like other module data. A state handle that a binding receives from a member read or a helper call is observed through that binding: rules may use it, and its identity is the binding site, exactly as for a handle read from a capture. Ordinary String conversion follows the separate bounded target rules above; a type assertion or module constant does not expand them.

Trusted module `tw` declarations may refer to immutable module string constants, including inside closed style-handle tables. They use the same checked token extractor as setup declarations; no authored initializer or function is executed. Rule builder arguments may spread a literal list after captured conditional choices are lifted. Each selected builder argument keeps its original order; unknown iterables, holes and dynamic spreads remain rejected.

Reached module bindings are shared by instances of the generated artifact. A `const` preserves binding identity; it does not imply that a finite data object's fields are deeply readonly. Static scalar/null/array/record initializers and references to other checked module data retain the author's finite field types and shared object identity. A checked scalar module `let` read in such an initializer snapshots the value at that source position; a later scalar write does not rewrite the initialized container. Explicit `Readonly` and `Object.freeze` views remain readonly. Shared `let` requires a scalar initializer and finite declared storage; later writes must satisfy that same schema. Shared unknown data, arbitrary runtime factory calls, and containers that can retain an owner's callable or capability are rejected. Static nominal declaration composites use readonly views. Source-free validation independently checks both the static initializer tree and its storage permissions.

A checked `Object.freeze` array retains its original identity and gains a readonly outer array view; its elements are not recursively frozen. The operation is emitted as native JavaScript, so a write through an older mutable alias still throws. Frozen primitive module arrays can supply ordered spreads, finite enum options and static loop keys, including through imports and re-exports. Recognizing the builtin does not suppress initialization checks on its operands. A setup-time freeze of an existing array reads its current contents instead of replaying its initializer. Shadowed global names, opaque operands, optional builtin calls and explicit builtin type arguments receive ordinary diagnostics.

A static string-array `join` folds to one string literal. Ordinary dynamic `join` is a checked native array operation. Module aliases retain their resolved declaration identity, including imports and re-exports; a nearer binding cannot borrow another module's proof. A direct array spread may flatten primitive literals, while a dynamic checked Array/Set/string spread uses native iteration and evaluates the source once. Nested records, arrays, closures, and handles keep their identities rather than replaying a shared initializer. Enum declarations still require nonempty finite literal options.

A local `const` or `let` may use flat object binding patterns with static keys, or flat array binding patterns with numeric positions. A nontrivial initializer is evaluated once into a compiler-named binding. Source ranges and lexical identities remain attached to the authored pattern. Reads use the actual field/element type, including a possibly missing array element. Defaults, rest elements, nested patterns, computed object keys and module-scope patterns keep explicit diagnostics.

Required nonempty flat object parameter patterns use the same checked static field reads at function entry. Their local bindings remain mutable, and field snapshots run from left to right before the authored body. A function using this lowering cannot also contain parameter defaults or rest parameters, which would require a separate evaluation-order proof. Empty patterns require a separate object-coercibility check and remain unsupported, as do nested, computed and defaulted fields and array parameter patterns.

`Extract` and `Exclude` select complete members of a finite checked union using structural type constraints. Selection does not project away extra fields, callbacks, owner handles or readonly permissions. Each actual union alternative must satisfy an allowed constraint alternative; this is compile-time type selection and establishes no runtime guard or new authority.

Ordinary local array literals are writable; explicit readonly annotations and const assertions restrict their views. Checked array iteration/transformation operations, Array.at/from, Set membership/mutation, and Map lookup/mutation lower to native JavaScript. Reduce currently admits finite data elements and a finite data accumulator; it checks the callback's return against the accumulator and retains the native initial-value and empty-array behavior. Sort requires a writable array of finite data and a checked numeric comparator; it preserves the original array identity. Map currently requires explicit or contextual finite data key/value types and an empty constructor; it cannot store private callable or owner authority. Collection mutations invalidate affected flow observations, and callable-bearing arrays/Sets retain element provenance through callbacks and aliases. An immutable array binding, including a checked nominal snapshot list, can carry a guarded positive-length fact until a potentially mutating call invalidates it. Native profiles retain their existing finite-data array representation, while reached new collection operations or authority-bearing arrays without a lowering receive explicit diagnostics.

Typed JavaScript declarations preserve each checked array's element domain and mutable or readonly view instead of relying on TypeScript literal widening. A checked filter predicate's result refinement is rederived during portable validation and retained at the emitted filter result; the native filter still executes once with the original callback. Emission folds strict comparisons or nullish choices only when the relevant operands are actual scalar literal syntax after erased type views. Specialized but observable reads keep their original evaluation order and actual JavaScript comparison, even when their checked types cannot overlap.

The bounded ECMAScript value table also admits checked scalar Number conversion and Math operations, their enumerated non-writable finite numeric constants, finite Intl.NumberFormat options and results, RegExp literals/test, and the declared string operations used by authored formatters. Constants require the same unshadowed global binding proof as calls and become their exact finite numeric value. Native constructors and methods preserve their target behavior; the compiler does not evaluate input code or inject a component-specific formatter. AggregateError returns an opaque exception and preserves its checked iterable/error order. Opaque `unknown` is never treated as checked data by these new operations; Number cannot implicitly invoke an object conversion callback, and Intl options or AggregateError elements cannot conceal owner values behind unknown fields. A checked TypeError constructor likewise preserves the native exception identity and optional string message. Unshadowed `console.warn` accepts only checked scalar arguments, preserves the native diagnostic in source order, returns void, and remains effectful; it cannot export an object, callable or owner handle. Arbitrary constructors, classes, setter accessors, Proxies, and unregistered globals remain outside this admission.

A state handle received through a member or helper retains its identity and ownership. Core `State<T>` is the Owned/Borrowed/Observed union; Observed never gains write authority and Owned never gains watch authority. A checked native `in` test may refine the declared State method surface. Ordinary object property-presence tests grant no new callable or capability field. Rules may observe checked scalar handles through their actual lexical binding.

A checked `run.lifecycle` member may retain the original runtime module identity as an internal nominal value. Its `setPresent` method shares the existing callback/owner permission and ViewIntent effect of `run.lifecycle.setPresent`; it grants neither disposal nor host-view authority. The four Web source profiles transport their real module object. Vue creates that object only when the module member is reached. An indexed type derived from the real Core `RunHandle` may name this value, but a structural object, assertion or serialized member claim cannot manufacture it. A public method cannot receive this module, directly or nested in a record, collection or callable; shared source and cold-IR admission enforce that input boundary. Other lifecycle members, including draft `captureViewOperation`, and first-class module use on unimplemented targets remain explicitly unsupported. This does not establish every local structural-helper or full native lifecycle combination.

Finite enum values are derived from the actual `state.enum` declaration and its checked literal option list. Immutable aliases and closed helper returns preserve that fact. A static helper parameter may retain it only when every direct caller provides a proven enum; a helper escaping as an ordinary function value has no such closed-call proof. Mutable handle holders, recursive or unproven returns, and unconstrained state parameters keep their scalar result type. Source-free validation independently rederives these facts from the executable module graph instead of trusting a serialized enum claim. A string state with validation options remains a string state.

A `for (const x of <static list>)` statement is unrolled at compile time. A static list is one of:

- an array literal of string or number literals;
- a module binding that resolves to such an array;
- `Object.keys(<module object literal>)`.

The body is repeated once per element, and each read of `x` becomes that element's literal. Each copy keeps the authored range. Nested static loops unroll inside each copy; literal-only branches select their authored arm. Local declarations retain a separate lexical block for each static iteration. An unlabelled `continue` in such an iteration lowers to a return from an ordinary synchronous iteration closure, preserving dynamic conditions and `try`/`finally`. Nested functions and nested loops keep their own jump targets. Static substitution respects nested lexical blocks, catch bindings, loop bindings and destructured parameters; a shadowed name retains its own binding and initialization rules. A static iteration combining that normalization with an outer return, break or labelled jump is rejected. Flat literal tuple loops and literal `Object.entries` loops retain every initializer once before their bodies; this supports heterogeneous state/style values without evaluating them in the compiler.

Other checked `for (const value of iterable)` loops execute at runtime over an Array, Set, or string. `while` loops retain their condition/body order. A counting `for` with one initialized `let` index lowers to a local `while` and keeps its increment after the body; capturing that mutable index in a nested closure, redeclaring that index inside the body, or using break/continue in this normalized form, is explicitly rejected. Loop flow/provenance analysis conservatively joins iterations and retains zero-iteration paths. No termination or fixed iteration-count claim is made.

Style tokens also fold `TABLE[key]`, where the key is static and `TABLE` is a static object literal, and template literals over static strings.

A definition descriptor may state `modules: <hook>.modules` when `<hook>` resolves to a static `defineHook` or `defineAsHook` declaration. The requirements are read from that declaration's own descriptor, so a family projection reuses its base hook's Module declarations without restating them, and a duplicate declaration is still rejected. A shared mutable binding's declared type must remain finite data; `unknown`, functions, execution handles, and mutable containers carrying them cannot be used to retain an owner's closures beyond that owner's lifetime. The portable IR validator applies the same restriction before emission. A static module function can still create and return an ordinary closure to the current owner, and a local mutable binding can hold a capability or callable value. This restriction concerns the shared storage boundary rather than the spelling or declaration location of a function.

Structural width subtyping may omit additional pure-data fields. A type annotation, assertion, callable signature, return annotation, or assignment cannot erase additional callable or owner-capability fields from the compiler's runtime shape proof: the JavaScript object still contains those fields. Such authority-hiding views receive an explicit diagnostic in this private subset. A view retaining every authority-bearing field remains legal. This rule also prevents a finite-data module slot from retaining an owner closure under a narrower record schema; portable IR is checked by the same assignability rules.

Readonly field and collection permissions likewise survive ordinary aliases, defaults, calls and erased assertions. The read-only finite-data projection used to validate a semantic operation's borrowed input cannot authorize an ordinary mutable view. Literal evidence is limited to the actual literal, fresh record or fresh array expression; a reference retains its complete checked shape instead of recovering a narrower initializer or projecting away its write restrictions.

Context input aggregates also check evaluation order: an earlier retained shared record or array cannot rely on its checked shape across a later potentially effectful operand. Source admission and portable IR apply this conservative check to provided values, direct updates and inline updater return expressions, including eager operands under assertions, spreads, intrinsics and ordinary calls. Fresh records and arrays of directly copied scalar values do not retain shared object identity. Finite scalar-only object and array spreads likewise discard the source container identity; nested objects remain shared. Checked Number and Math intrinsics do not themselves invalidate the proof, while their operands still contribute effects. A semantic operation whose shared contract has no arguments or callback and only reads State or resolved Props is likewise a snapshot observation; evaluating its receiver still contributes all ordinary effects. Other intrinsics and unknown ordinary calls remain conservatively effectful. Short-circuit operands follow their mutually exclusive result paths rather than retaining a discarded left value across the right operand, and a checked scalar result retains no object identity. This is a bounded aggregate-expression check, not a helper-purity proof or general alias and `finally` flow analysis.

An explicitly `unknown` module-helper parameter retains the helper's own guard obligation. A checked scalar argument does not specialize that parameter below its empty or fallback domain. A finite data container may retain its complete checked shape together with nullish alternatives, including every readonly field and collection permission; its full shape participates in helper identity. Callable or owner-bearing arguments retain their complete authority identity. This bounded specialization does not turn arbitrary unknown values into data or supply a member-access proof without a guard.

## Evaluation boundary

Static member reads on the compiler's coarse `record` marker return `unknown` in both source admission and portable IR validation. Raw Props snapshots (`run.props.getRaw()`, renderer raw reads, and raw watcher snapshots) use this opaque boundary: a read does not prove key presence, acquire the resolved declaration's type, or materialize a default. The marker also represents opaque watcher metadata; it is distinct from a finite structural record or object, whose missing-member checks remain enforced. An opaque member supplies no callable or owner capability. Member writes still require a declared mutable ordinary field, including through aliases; this read rule grants no write permission or dynamic-index support.

Top-level runtime calls remain limited to statically admitted declarations. Aliasing a factory preserves this rule; it cannot make an arbitrary function or effectful initializer safe. A source file reached only for an erased type can contain runtime syntax without that syntax being executed or emitted. Once the same file is reached as a runtime dependency, runtime admission applies normally.

The compiler's normalization tests compare semantic IR after removing spans and source provenance, and separately verify that the complete source graph remains recorded. These tests cover declaration renaming, import aliases, re-exports, local type shadowing, setup normalization, and effectful-source rejection.

## Recursive authored functions

The current target-operation analysis has no blanket `PUI4005` rejection for ordinary recursive helpers. This implementation fact does not establish recursion support for every target. Recursive authored-hook installation remains a separate, rejected operation.

Source and portable-IR admission check callable effects before target emission. Their finite analysis follows known calls, analyzes deferred callbacks in their declared context, and revisits mutable callable stores. Re-entry into an active invocation returns unknown provenance; exceeding the call-work or capture-fingerprint boundary produces an admission diagnostic. This is not a proof of termination, a target stack bound, or a general proof that every recursive program can be emitted.

Each callable-analysis pass also has a deterministic resource envelope: at most 128 active checked invocations and 16,777,216 counted store-entry, joined-field and fingerprint visits. Store copies and joins consume that envelope before allocating their result; a small call graph cannot repeatedly copy an expanding store until the entry worker is killed. The existing 8,192 new-state worklist and capture-fingerprint limits remain independent. These are private analysis limits, not limits on legal authored behavior. Exhaustion produces an explicit unsupported-admission diagnostic with a source span identifying the current analysis context; it neither emits an approximate program nor establishes that the authored program is invalid. A demand-only traversal marks the incomplete proof opaque so unvisited functions and host support stay conservative. Each pass starts with its own envelope, including when the same worker compiles subsequent entries or profiles.

Target demand uses the traversal in a different mode. An opaque or cyclic invocation reports to the demand observer, and `checkTargetOperations` conservatively visits all remaining module, setup and hook bodies after dead-value pruning. It retains their functions and checks their operations and required host capabilities. This prevents an opaque edge from justifying support elision; it is not a substitute for callable-effect admission or target lowering. An unreachable body is not by itself an opaque edge.

A retained source branch can contain an authored-hook call which the closed demand proof establishes cannot execute. Such a call does not name an omitted hook definition: source emission retains its checked result type and argument evaluation in an explicit unreachable-call failure, as it does for uninvoked ordinary function bodies. This is not an empty hook implementation or an executable fallback. Unknown invocation paths invalidate the elision proof and retain the actual hook and its required support.

The implemented source profiles are React DOM, Vue3, Vue2, Web Components and GPUI. Qt, Flutter and the SSR profiles remain unimplemented in the public target registry; their direct emitter entry points are private experiments with additional admission limits. The GPUI ordinary-values fixture includes forward and mutual recursion, but its source and retained historical executions do not certify every native profile or a later candidate. Per-target compilation and consumer execution of the admitted recursive forms remain required evidence. A phase violation detected in a recursive callback is still rejected; this document does not claim exhaustive phase-safety or native execution proof.

## Mixed semantic value unions

`joinValueTypes` retains distinct non-data alternatives as `value-union` instead of rejecting them at the branch. Assignment checks require every actual alternative to satisfy the expected type; an expected union accepts an alternative through a compatible member. Separate runtime-shape checks prevent structural annotations from hiding callable or owner-capability fields. Member access checks each alternative. A call requires matching checked callable signatures across the possible non-nullish alternatives; optional-call syntax may omit only the nullish alternatives.

Those frontend and portable-IR rules do not by themselves establish correct emission of every union. JavaScript type projections, public callable projection, GPUI native values, Qt values and Dart types each have their own representation. Their branch choices, identity, nullish handling, callable lifetime and native casts require target-specific evidence. The Dart admission limits below still apply to each union member. No complete cross-target union review or consumer result is asserted here.

## Bounded material shader declarations

`feedback.material.shader` is the setup-only draft operation defined by `C-FEEDBACK-SHADER-PRESENTATION-0001` and `HC-FEEDBACK-SHADER-PRESENTATION-0001`. It registers one immutable, budgeted graph on the existing material channel, with explicit opaque fallback and an owned-pixels or explicitly bound owned-scene source. The first profile accepts only versioned copy and tint passes over top-left, linear-sRGB, premultiplied RGBA8 data. It does not admit author shader text, raw host textures, page capture or implicit history.

Runtime snapshots ordinary own-data declarations and selects their actual passes. The four native Web source profiles accept inline graphs and proved immutable local/module aliases, including pure finite-data factories reached through renamed imports and re-exports. Checked IR binding identities resolve aliases; static arguments, left-to-right defaults, own members, finite records/arrays, unary expressions, selected conditionals and constant local returns can construct the graph. The existing source type rules still apply: a graph binding may need an explicit `ShaderPresentationDeclaration` annotation to retain its discriminants. No author JavaScript is executed by this proof.

The proof rejects container mutation and escaping aliases, including a sibling alias of an exposed nested container. Effectful or recursive helpers, mutable cells, getters, unknown call targets and unproved expressions remain unsupported. Arithmetic and scalar conversion intrinsics are not evaluated by this shader-specific proof. These are explicit compiler coverage gaps, not new restrictions on public Proto semantics. The validated snapshot becomes direct `upload`, `copy` and `tint` calls in authored dependency order. A guaranteed abrupt factory retains its exception and cannot create a shader host for a following unreachable declaration.

GPUI, Qt and Flutter shader targets remain unsupported. The native module contains neither a graph interpreter nor Runtime/Adapter imports; the reached WebGL2 host atom and exact first-party kernel digests accompany it. Unreached pass methods, kernels and uniform support are removed at compile time. Multi-entry project output verifies every original support file against that entry's canonical closure before sharing the project's reached kernel union; modified or missing support is rejected. The canonical host source digest and each specialized output digest remain separately recorded.

An owned-scene source contains only `{ kind: 'owned-scene', slot: 'mainScene' }`. The application explicitly creates a host capability with `createWebShaderHost({ ownedScenes: { mainScene: lease } })` and passes it as the Runtime Adapter's `shader` option. A native scene module exports `createShaderHost` with the same protocol and `createComponent(optionalHost)`; ordinary/default exports remain unconfigured and retain opaque fallback. These factory exports and their reserved names occur only when scene capability is reached. Host capabilities are not Props, attributes, serialized IR, Context payloads or instance associations. The actual application source remains separately owned.

The first scene provider borrows the read side of `CanvasBackdropLease`. It independently copies its opaque sRGB8 frame, decodes and quantizes into linear premultiplied RGBA8, and applies the whole source texture to normalized surface UV. This is not an in-app-backdrop crop or a renamed backdrop receipt. Every source frame must fit the shader extent, texel and total source-plus-passes budget. Current scope follows composed ancestry through the actual Documents, ShadowRoots and slots. Source revision, canvas/scope identity, reparenting, revocation and replacement retire stale work; late decode rechecks the frame even before an observer has flushed. Subscribe/getter/cleanup failure and synchronous acquisition reentry retain bounded cleanup and fallback. The host only unsubscribes and never disposes the application lease.

The scene implementation is an explicit application-selected host capability. Ordinary Adapter bundles retain no scene provider implementation, and an undeclared/unmounted shader never acquires a source. Ordinary physical paint also omits diagnostic readback; the explicit diagnostic `createWebShaderDevice` keeps its read API. Source size, retained output, actual initialization calls and hardware performance remain separate measurements. Current browser and cost receipts are recorded in `internal/records/2026-11-24-sprint4-owned-scene-shader.md`.

Shader material is currently exclusive with shared/private material and presence/resident-motion declarations because those combinations do not yet have atomic paint ownership. The physical provider keeps real children and input targets, publishes a decoded image as the root background, and retains its opaque fallback on failure. Root/Document/view/revision retirement, partial allocation and context-loss cleanup belong to the host lease. Actual shader execution, CPU-oracle comparison, ordinary native consumer imports and Runtime consumer tests have separate evidence; none of those fixture results substitutes for adoption in shenko, OpenGreendam or Verdant.

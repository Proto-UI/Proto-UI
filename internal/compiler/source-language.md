# Closed source language

This is the private compiler's admission contract, not a published TypeScript or host support claim. Input source is parsed and resolved inside the supplied graph; the compiler never imports or evaluates an input module.

## Binding identity and normalization

Semantic authority belongs to a resolved declaration. A name alone does not grant a capability. An imported core type or factory keeps its identity through local aliases and named re-exports. A local declaration with the same spelling remains an ordinary local declaration. This includes `FocusRequestOptions`: it is a focus options schema only when its binding resolves to that export of `@proto.ui/core`.

A contiguous chain of erased type assertions, with optional parentheses, may retain the original checked expression when an intermediate view is `unknown` and the final nominal capability type is exactly the original checked type. Every intermediate assertion must independently pass admission. The compiler emits the original expression once, so portable IR validates that expression without an `unknown`-to-capability conversion or source-only proof. This rule does not recover authority from an unknown parameter or binding, substitute a different capability, upgrade State ownership, or remove readonly field protection. Generic arguments remain subject to the existing core type projection; an assertion does not establish a new generic API guarantee.

A setup function may be a method, declaration, arrow, function expression, or a static alias of one of those functions. Importing or re-exporting that function does not change its lexical owner. Its free bindings resolve in the function's source module. Calls to module functions also retain that owner.

Module aliases are admitted for static functions and admitted package symbols. The compiler checks cycles and reads before initialization. A scalar alias is not silently converted into a live binding: `const saved = mutable` has snapshot semantics and currently requires an explicit supported initializer.

Unannotated callback parameters can be constrained by a resolved operation's receiver capability and argument schema. A property spelled `focusSelf` on an ordinary object supplies no such authority. Conflicting constraints are rejected.

## Erased type graph

Finite data aliases and interfaces may be imported, renamed, re-exported, or namespace-qualified inside the closed graph. Type resolution checks duplicate declarations, ambiguous star exports, and cycles. It reads the source bytes of the required type declarations without admitting their file as executable code. Unused type-only imports do not require source bytes. The file compiler loads the syntactically required local type edges as well as executable source edges.

Every source file used by semantic resolution is included in provenance. Source bytes are provenance, not an executable fallback for unsupported syntax.

When an erased type query selects a value through a barrel, the file loader follows named and star value re-exports and local export lists that forward imported bindings. For example, `import type {Renamed} from './barrel'` can resolve `(typeof Renamed)[number]` through `export {IDs as Renamed} from './values'` or `import {IDs as Local} from './values'; export {Local as Renamed};`. These dependencies supply source bytes for resolution. Runtime admission follows its own dependency edges.

The erased expression `(typeof CONST_TUPLE)[number]` may select the exact union of a module `const` literal tuple's scalar elements. The binding must resolve to its authored declaration in the closed graph, including renamed imports and named or unambiguous star re-exports. Its initializer must be an array literal asserted `as const`, without a widening declaration annotation; elements are string, number, boolean or null literals (including signed numeric literals). Parentheses and an outer `satisfies` wrapper do not change that identity. Duplicate alternatives collapse and an empty tuple selects `never`. No input initializer is executed. A nearer lexical value binding cannot be replaced with a module binding. This bounded rule does not admit standalone `typeof`, qualified value queries, other index types, runtime-produced arrays, mutable or widened declarations, element references, spreads, holes or nested containers; these retain PUI1020 diagnostics. Reaching a declaration solely for this erased query does not admit its module as executable code.

## Finite string membership

A nonempty literal string array asserted `as const` retains the exact string-literal types of its checked elements in executable IR. Each element is still validated against its literal value after serialization. An unasserted array keeps ordinary widening; erased type-query resolution alone does not supply the executable receiver proof.

`array.includes(search)` is admitted for a checked array whose element type is a nonempty finite union of string literals. It accepts exactly one operand, including unknown, and returns boolean. Optional calls, `fromIndex`, sparse arrays, broad string arrays, numeric arrays and object membership remain unsupported. Native JavaScript SameValueZero performs no coercion; only equal strings can match this receiver domain. Receiver and search evaluate once in that order, including for an empty runtime array.

At this comparison boundary only, a single erased assertion to a finite string-literal union may be removed from the search expression. IR retains the actual operand and checked type; the assertion grants no provenance. Portable validation independently checks receiver domain, arity and result through the shared intrinsic rule. Assertions elsewhere retain their existing proof requirements.

A true direct guard refines an immutable searched binding to the receiver's checked element domain. Mutable cells, member reads, calls and saved booleans do not acquire this proof; false branches exclude nothing. Shared JavaScript emission uses native membership for Web targets. GPUI explicitly rejects this intrinsic; Flutter and experimental Qt have no native acceptance evidence for this extension. Source admission alone establishes neither target support nor downstream component completion.

## Native String conversion

An unshadowed `String()` or `String(value)` admits zero or one checked data or opaque `unknown` operand and returns a string. Local declarations and imports named `String` remain ordinary bindings. Optional calls, spread arguments, constructor syntax and known callable or owner-capability operands remain unsupported. This bounded admission does not erase callable or capability fields into data.

JavaScript targets emit the native `String` call, preserving missing versus undefined operands, null, signed zero, non-finite numbers, arrays, object coercion order, string-hint conversion and abrupt completion. An unknown operand remains opaque: conversion grants no field or capability authority. Coercion can invoke user code, so both frontend and portable validation invalidate mutable flow observations; an unused conversion remains executable. Portable IR independently checks arity, operand domain and result type.

Runtime-backed React and browser source profiles share this native lowering. The bounded draft [scalar contract](../../spec/contracts/C-COMPILER-SCALAR-0001.yaml) admits zero or one checked scalar operand on GPUI and the pure Rust data artifact: string, number, Boolean, null or undefined, including their checked literal alternatives and unions. `String()` produces `''`; `String(undefined)` produces `'undefined'`. Native structured or opaque `unknown` conversion remains unsupported. Direct Qt/Flutter String experiments still reject this intrinsic. Source admission, generated Rust data execution and mounted GPUI evidence are separate; none establishes component completion or a stable profile.

This intrinsic does not broaden profile-specific public method signatures. React and Vue3 source methods still require checked public value signatures. An internal helper accepting `unknown` and an exposed method accepting `unknown` are separate admission questions. Source admission of raw Props reads does not establish target admission of watcher operations. The four browser source profiles admit keyed `props.watchRaw`; Vue2 retains explicit rejection of `props.watchAll` and `props.watchRawAll`. The other browser profiles' existing all-key target entries are separate from this keyed consumer acceptance.

## Finite style tables and Rule environment facts

Module static data may contain template strings whose substitutions are independently admitted static data. A flat local `const` table can supply compile-time style tokens or `Object.keys` enumeration only when the entire block proves that its container neither escapes nor mutates. Scalar member reads are permitted; aliasing the container, passing it to another function, method calls, writes and deletes invalidate this proof. A local binding blocks a same-named module table. Builtin `Object.keys` requires an unshadowed `Object`, retains ECMAScript own-key order and duplicate-key behavior, and rejects `__proto__`. Reads before a local table's initialization are not unrolled.

A direct one-parameter arrow in `finiteList.forEach` can use the same finite loop expansion as `for...of`, provided it has no async modifier, default/rest parameter or abrupt return/break/continue. Substituted literal ternaries are decided at compile time. Other iteration retains its explicit diagnostic. None of this executes authored source, introduces a runtime iterator or changes the prototype's behavior by its name.

Rule conditions admit the fixed `colorScheme` and four `preference.*` inputs from `C-RULE-COLOR-SCHEME-0001` and `C-RULE-PREFERENCES-0001`. Pure condition structure and token precedence remain `C-RULE-WHEN-0001`; each target emits an ordinary predicate, not a Rule interpreter. Four browser source profiles acquire only reached native document sources while mounted. One document color source observes root class/data-theme and the system query. Preference queries are shared per document/key and readable only through an active paired source; missing/ambiguous facts stay `unknown`. Leases precede fresh style reconciliation, environment notifications request style reevaluation only, and detach/dispose release them before stale work can run. Existing sampled Meta reads remain separate. These contracts stay draft, and this slice does not admit Rule Meta on GPUI, Qt, Flutter or SSR profiles.

The real full Base/Shadcn/Brutalist Button sources are consumed without edits by all four browser source profiles. Their ordinary children, dynamic environment styles and disabled projection are checked independently of generic language fixtures. Keyed raw watcher checks retain `Object.is` union-key diffs, callback-window identity, raw-before-resolved order, warnings and cancellation. The returned disposer is an ordinary void callable; it does not reacquire setup authority. These concrete consumers do not establish support for other untested prototype families or backends.

## Bounded numeric conversion, rounding and text length

The same draft [scalar contract](../../spec/contracts/C-COMPILER-SCALAR-0001.yaml) governs an unshadowed `Number()` or `Number(value)` with zero or one checked scalar operand. An omitted operand yields positive zero; explicit undefined yields NaN. Null, Booleans, numbers and numeric strings retain ECMAScript conversion behavior, including signed zero, whitespace, radix prefixes and invalid-input NaN. Structured values, unknown, callables and owner capabilities have no admitted coercion on this bounded path. Extra operands, optional calls and constructor syntax remain unsupported. Local or imported bindings called `Number` or `Math` retain their own identity.

`Math.round(value)` and `Math.floor(value)` each require one checked number. Rounding preserves source-language negative ties toward positive infinity, signed zero, non-finite values and precision-limit integers; it does not reuse Rust's different negative-tie rule. The `.length` of a checked string counts UTF-16 code units, so an astral character contributes two. It grants neither numeric/Boolean member access nor a missing record field. Each operand evaluates once, and independently supplied IR rechecks the same operand and result domains.

The five implemented source profiles have compilation regressions for this slice; the pure Rust data regressions execute generated crates and retain any required language-support dependency. Finite public-data boundaries still reject non-finite values at their own ingress or egress. The [test mapping](../../spec/tests/T-COMPILER-SCALAR-0001.yaml) keeps mounted GPUI evidence separate and does not infer Qt/Flutter support from the common parser or lower-level helper presence.

## Fresh-target own-data assignment

An unshadowed `Object.assign(target, ...sources)` is admitted for a direct fresh record literal or a direct `new Error(message)` target, followed by zero or more direct finite record literals. Each record entry must have a checked pure-data value. Sources are ordinary own enumerable data properties; arbitrary references, spreads, accessors, dynamic keys, callable or capability values, arrays, scalars and nullish sources remain unsupported. An aliased, asserted, frozen or readonly target is not a freshness proof. A field named `__proto__` is excluded from every participating record because assignment can invoke an inherited setter instead of defining an own data property. Optional calls remain unsupported. A local or imported `Object` binding is an ordinary binding and grants no intrinsic authority.

All target and source expressions evaluate once, left to right, before native assignment copies properties. Sources copy in order; the last source containing a key supplies its value. The result is the original target, with nested object identity retained. A record result has the final finite data fields. An Error result remains an opaque exception: adding diagnostic data does not grant typed catch fields, callable provenance or a new capability. Native Get/Set behavior and abrupt completion remain observable; assignment is not replaced with object spread. The operation conservatively invalidates mutable flow observations and remains executable even when its result is unused.

Portable IR independently validates every argument and rechecks the direct fresh target and finite own-data sources before deriving the result. An `exception` type annotation alone cannot authorize mutation of a caught or aliased value. Runtime-backed React and the four browser source profiles lower the operation to native JavaScript `Object.assign`. GPUI and the direct Qt/Flutter experiments explicitly reject it; source admission does not establish support for those targets or complete a component's acceptance.

## Functions and hook installation

Runtime Anatomy role selectors (`has`, `partsOf`, and the ordered `partsOf`, `indexOfSelf`, `prevOfSelf`, `nextOfSelf` queries) accept a literal role or a checked finite union of nonempty string literals. A helper formal such as `role: 'trigger' | 'content'` retains that finite proof; the emitted native query receives the actual argument once and selects that role in the current family/domain. Source admission and portable IR use the same finite-string-key validation already used for declared event selectors. Broad `string`, empty-string alternatives, nullable or mixed non-string domains remain unsupported by this bounded compiler admission. This does not broaden setup subscription keys, declaration keys, family identity, query phases or the limited Part View surface, and does not promote the draft Anatomy contracts.

An ordinary function creates a lexical closure. Creating, returning, aliasing, or passing that closure does not execute its body and does not begin a setup or callback lifecycle. Defaults run at the call, from left to right, when an argument is missing or `undefined`. Captures identify declarations, including later declarations, rather than relying on the spelling of a name. Creating a closure before a captured `const` is initialized is allowed. Direct reads or writes before a lexical declaration's initialization receive a diagnostic in this finite subset; this check belongs to the current function's execution scope and does not reject a deferred closure capture. Portable validation checks the same initialization order from IR bindings. Ordinary block shadowing remains legal, and function declarations retain their hoisted initialization.

Fixed operation result signatures participate in forward binding inference without running the initializer. For example, a Context subscription returns an ordinary `() => void` cancellation function; a deferred callback may capture that later binding, and the function may be aliased or stored in a mutable local. Receiver and argument dependent result types still require their checked bindings.

Known ordinary calls are checked in the execution context of the actual call. Source admission and portable IR validation share one static traversal of lexical bindings, callable arguments, defaults, aliases, returned closures, and record members. Registered callback signatures establish their execution context; merely returning or storing a callback does not. Hook capture discovery uses the same traversal, so adding an alias or a closure factory cannot drop direct state declarations from a capture. Mutable lexical cells and record fields retain callable provenance, including aliases and nested records. Setup applies definite writes in order; conditional and exceptional paths retain each possible store. Registered callbacks and every setup-returned render function are checked against one shared store until their effects stabilize, because an owner may execute them repeatedly in different orders. The store includes hook registration state and each capture frame: a conditional installation remains only possibly installed, and exception paths retain registration that preceded a failed setup. Public records and callable return values remain outward roots when later callbacks replace a field. A definite overwrite before a call can remove an earlier dangerous function. A type annotation cannot grant new lifecycle authority.

Callable fingerprints retain field positions, closure environments, and mutable storage identities. Separate setup-time factory calls remain separate; recursive or repeated callback analysis joins only the corresponding invocation allocation sites. Fixed host callable signatures, including public callable parameters, are explicit external contracts. Outward argument analysis keeps actual checked argument and record-field types. An untracked value whose checked type is pure data is a data fact rather than unresolved callable provenance, while a stored closure, record, cell or capture is always traversed whatever the checked type says, so a later alias write cannot hide an effectful callable behind an omitted or narrowed field. Callable-bearing fields still require effect analysis. A data fact belongs to the value that carries it, so each alternative of a union keeps its own facts and the union's type never reclassifies a value. Unresolved source callable provenance or an exceeded finite analysis boundary produces a diagnostic; it is not accepted as an empty capture. These are compile-time proofs: the emitted program retains ordinary target calls and the existing owner/lifecycle guards.

All parameter bindings exist before any default is evaluated. A direct read of the current or a later uninitialized parameter is rejected in this finite subset; a delayed closure may capture that parameter's binding. Immutable saved predicates can carry flow facts. A saved cell or mutable member observation cannot prove the value after a write. Calls that can mutate a captured binding or object, synchronous host writes, and exception paths invalidate the affected observations; a fresh guard or an immutable value snapshot can establish a new proof. Known synchronous read-only functions preserve observations. Creating a closure does not execute its body or establish that its captures will retain their current values when called.

Readonly field permission remains attached through aliases and assertions; an object spread produces a new mutable top-level record. Readonly is a write permission on a view, so writes through a mutable alias invalidate observations of the same field. The frontend and portable validator derive that conservative field-write footprint from the checked semantic graph. Retained source and unused module helpers do not contribute effects. Object entries and spreads are checked in their left-to-right evaluation order.

`defineAsHook` and `defineHook` are explicit installation boundaries. This compiler follows the current Core contracts rather than extending them by component name. An as-hook takes no invocation options and installs once by its declared hook name per owner. A second source declaration with the same hook name remains a different lexical declaration but shares that runtime installation identity. Projection runs after capture. A capture contains the states directly contributed by the installation and its raw exposed methods. Nested hooks retain separate child results and projected handles. The capture's `getState`, `getMethod`, `getAsHook`, and `getAsHookHandle` perform read-only lookup and can be used after setup; invoking a returned method is checked in its actual execution context. Raw captured methods can be used synchronously during projection or setup. Returning or explicitly exposing one to a public caller establishes a callback boundary. The runtime's Expose registry may also retain a registered raw method's public entry, so its body is retained by demand analysis and that entry keeps the owner callback guard; capture lookup does not itself call the method. Analysis of this implicit raw entry keeps ordinary effects before a guard and treats an illegal-phase host operation as an exceptional completion, including authored catch/finally successors. Explicit source calls through a projected or publicly returned method still receive the ordinary strict phase diagnostic. Guarded and strict executions do not share analysis cache entries.

### As-hook `stateHandles`

The runtime collects the installation's named state handles when setup ends and freezes the resulting record. `getState(key)` reads the same record. Both lookups project owned or borrowed handles as borrowed views and preserve read-only observed handles.

- **Focus facts.** A reached `def.expose.state` can explicitly introduce a named observation from `asFocusable()` into the current capture. The capture uses the Focus state declaration name even if the public expose key differs. Calling `asFocusable()` alone only contributes a child entry.
- **Definite presence.** With a single source declaration for the hook name, a named state declared or introduced by a direct setup statement is definite if every normal completion passes through that statement. A conditional, loop, `try`, nested function, or earlier reachable `return` leaves presence conservative. If setup throws, no result is produced.
- **Field types.** A definite state is a required field. Other admitted states are optional fields. The handle type preserves the same write authority in either case.
- **Record type.** At least one definite state makes the record required. An installation without named state contributions yields `undefined`.
- **Target support.** Native support objects expose the same frozen `stateHandles` record beside `getState`, for every target that lowers `capture.getState`. A target without it keeps an explicit unsupported diagnostic.

The capture schema remains the upper bound described above. This rule only identifies the subset of that schema that a single winning declaration is certain to produce.

`defineHook` additionally retains its options type, mode, setup API, and configurator. Setup receives `(def, options, api)` and can return render or void. The configurator receives `(api, options, tools)` and returns void. The API's store belongs to the installation. `once` skips later installations, `multiple` creates separate installations, and `configurable` runs setup once and configure on the initial and later calls. Warn and conflict are callable fields supplied by the installation runner. They are not new compiler operations. Hook arguments, including omitted options, preserve source evaluation order. The ordinary setup-time creation of an exposed method does not execute that method during setup; calling it later uses the owner's active lifecycle guards.

An options callback contributes to the capture frame in which it actually executes. Capture inference follows the caller's checked closure environment through aliases and ordinary factories; creating the callback does not execute it. A descriptor's capture schema is the union of possible direct contributions across the closed graph, including possible same-name once winners. It is an upper bound, so a key can remain absent from a particular installation and lookup stays optional. Incompatible types for the same captured state or method receive an explicit diagnostic. Each installation retains its own values, raw method environments and child records; the schema does not merge live captures or flatten a child's state into its parent. Source parsing may use a checked statement prefix to infer a later lookup's type, but the complete graph independently rederives the schema before source admission and portable IR validation. A definite once winner excludes later skipped option initializers from this derivation.

An authored package participates through the same closed graph as local source, using an explicit `proto` package export or a `sourceImports` mapping. The compiler has no packaged Transition operation, injected Transition prop table, or replacement Transition implementation. Its machine, projection, event declarations, and public methods are derived from the supplied authored source.

Reached module bindings are shared by instances of the generated artifact. This finite source subset admits static module functions, pure scalar module initializers, and immutable literal data.

Immutable literal data is a `const` whose initializer is written in literal syntax: scalars, `null`, array and object literals of such data, references to other module bindings, and `<static string array>.join(<string literal>)`. Type wrappers (`as const`, `satisfies`, assertions) are erased. Because every instance shares the binding, the compiler stores it as a read-only view at every depth: a member write through it, or through any alias of it, is a write to a read-only field and is rejected. Arrays of records have no read-only element form and are not admitted. A `join` of literal strings is folded into one string literal at compile time; a `join` whose receiver or separator is not static is rejected. Nothing else in the initializer is evaluated when the artifact loads, and a `let` binding remains scalar-only. The portable IR validator accepts such a binding only when its initializer is a literal data tree and its stored type is read-only at every depth.

An array value spread may flatten an inline array or a checked immutable module array whose elements are primitive literals. Module identity follows the resolved declaration, including imports and re-exports; a nearer lexical binding cannot borrow that proof. Nested module-array spreads preserve order, duplicates and empty arrays. Flattening creates a fresh outer array while retaining the original readonly shared binding. Replaying records, nested arrays, member reads or computed elements from a shared initializer would duplicate identity or evaluation, so those reference spreads remain unsupported. Array annotations, assertions, function return types and readonly views alone do not establish a checked initializer; dynamic calls, conditional arrays and mutable containers remain unsupported by this rule. Enum consumers still require nonempty finite string options. This executable value rule does not broaden the separate erased `(typeof CONST_TUPLE)[number]` initializer grammar.

A local `const` or `let` declaration may use an object binding pattern with static keys: `const { a, b: c, 'data-k': d } = source`. Each name is declared as a read of that field. When the source is not a plain identifier, it is evaluated once into a compiler-named binding, so its effects and value are not repeated. The synthesized declarations keep the authored pattern's source ranges, so diagnostics and binding identities refer to the pattern. A missing field is reported against its element. Defaults, rest elements, nested patterns, computed keys and module-scope patterns keep explicit diagnostics until they have their own definition.

A style token written as a module constant may be `<static string list>.join(<string literal>)`, folded like other module data. A state handle that a binding receives from a member read or a helper call is observed through that binding: rules may use it, and its identity is the binding site, exactly as for a handle read from a capture. Ordinary String conversion follows the separate bounded target rules above; a type assertion or module constant does not expand them.

A `for (const x of <static list>)` statement is unrolled at compile time. A static list is one of:

- an array literal of string or number literals;
- a module binding that resolves to such an array;
- `Object.keys(<module object literal>)`.

The body is repeated once per element, and each read of `x` becomes that element's literal. Each copy keeps the source range of the identifier it replaces. Nested static loops unroll inside each copy. An `if` whose condition compares only literals is decided at compile time: only the taken branch is lowered. An unrolled body may not declare bindings. Any other `for...of` keeps the unsupported-statement diagnostic. Nothing is iterated at run time.

Style tokens also fold `TABLE[key]`, where the key is static and `TABLE` is a static object literal, and template literals over static strings.

A definition descriptor may state `modules: <hook>.modules` when `<hook>` resolves to a static `defineHook` or `defineAsHook` declaration. The requirements are read from that declaration's own descriptor, so a family projection reuses its base hook's Module declarations without restating them, and a duplicate declaration is still rejected. A shared mutable binding's declared type must remain finite data; `unknown`, functions, execution handles, and mutable containers carrying them cannot be used to retain an owner's closures beyond that owner's lifetime. The portable IR validator applies the same restriction before emission. A static module function can still create and return an ordinary closure to the current owner, and a local mutable binding can hold a capability or callable value. This restriction concerns the shared storage boundary rather than the spelling or declaration location of a function.

Structural width subtyping may omit additional pure-data fields. A type annotation, assertion, callable signature, return annotation, or assignment cannot erase additional callable or owner-capability fields from the compiler's runtime shape proof: the JavaScript object still contains those fields. Such authority-hiding views receive an explicit diagnostic in this private subset. A view retaining every authority-bearing field remains legal. This rule also prevents a finite-data module slot from retaining an owner closure under a narrower record schema; portable IR is checked by the same assignability rules.

## Evaluation boundary

Static member reads on the compiler's coarse `record` marker return `unknown` in both source admission and portable IR validation. Raw Props snapshots (`run.props.getRaw()`, renderer raw reads, and raw watcher snapshots) use this opaque boundary: a read does not prove key presence, acquire the resolved declaration's type, or materialize a default. The marker also represents opaque watcher metadata; it is distinct from a finite structural record or object, whose missing-member checks remain enforced. An opaque member supplies no callable or owner capability. Member writes still require a declared mutable ordinary field, including through aliases; this read rule grants no write permission or dynamic-index support.

Top-level runtime calls remain limited to statically admitted declarations. Aliasing a factory preserves this rule; it cannot make an arbitrary function or effectful initializer safe. A source file reached only for an erased type can contain runtime syntax without that syntax being executed or emitted. Once the same file is reached as a runtime dependency, runtime admission applies normally.

The compiler's normalization tests compare semantic IR after removing spans and source provenance, and separately verify that the complete source graph remains recorded. These tests cover declaration renaming, import aliases, re-exports, local type shadowing, setup normalization, and effectful-source rejection.

## Recursive authored functions

The current target-operation analysis has no blanket `PUI4005` rejection for ordinary recursive helpers. This implementation fact does not establish recursion support for every target. Recursive authored-hook installation remains a separate, rejected operation.

Source and portable-IR admission check callable effects before target emission. Their finite analysis follows known calls, analyzes deferred callbacks in their declared context, and revisits mutable callable stores. Re-entry into an active invocation returns unknown provenance; exceeding the call-work or capture-fingerprint boundary produces an admission diagnostic. This is not a proof of termination, a target stack bound, or a general proof that every recursive program can be emitted.

Target demand uses the traversal in a different mode. An opaque or cyclic invocation reports to the demand observer, and `checkTargetOperations` conservatively visits all remaining module, setup and hook bodies after dead-value pruning. It retains their functions and checks their operations and required host capabilities. This prevents an opaque edge from justifying support elision; it is not a substitute for callable-effect admission or target lowering. An unreachable body is not by itself an opaque edge.

The implemented source profiles are React DOM, Vue3, Vue2, Web Components and GPUI. Qt, Flutter and the SSR profiles remain unimplemented in the public target registry; their direct emitter entry points are private experiments with additional admission limits. The GPUI ordinary-values fixture includes forward and mutual recursion, but its source and retained historical executions do not certify every native profile or a later candidate. Per-target compilation and consumer execution of the admitted recursive forms remain required evidence. A phase violation detected in a recursive callback is still rejected; this document does not claim exhaustive phase-safety or native execution proof.

## Mixed semantic value unions

`joinValueTypes` retains distinct non-data alternatives as `value-union` instead of rejecting them at the branch. Assignment checks require every actual alternative to satisfy the expected type; an expected union accepts an alternative through a compatible member. Separate runtime-shape checks prevent structural annotations from hiding callable or owner-capability fields. Member access checks each alternative. A call requires matching checked callable signatures across the possible non-nullish alternatives; optional-call syntax may omit only the nullish alternatives.

Those frontend and portable-IR rules do not by themselves establish correct emission of every union. JavaScript type projections, public callable projection, GPUI native values, Qt values and Dart types each have their own representation. Their branch choices, identity, nullish handling, callable lifetime and native casts require target-specific evidence. The Dart admission limits below still apply to each union member. No complete cross-target union review or consumer result is asserted here.

## Private Flutter capture boundary

The current Dart host's authored-hook result is an opaque `Object`. Identity comparisons, aliases and ordinary function results can carry that representation; they do not imply that the object implements capture methods. Capture annotations lower to `Object`, including when a callable returns the capture.

The direct Flutter emitter diagnoses capture lookup (`getState`, `getMethod`, `getAsHook`, `getAsHookHandle`), custom handle projection, configuration/repeated-installation modes, invocation options and setup installation-API parameters that its host/lowering does not implement. The emitter currently invokes only hook setup and supplies its owner parameter. Accepting these additional paths would otherwise omit authored work, call nonexistent methods, or reach an invalid Dart type. These diagnostics expose unresolved coverage of the shared hook definitions; they do not narrow those definitions or complete a 0.3 capability. Emission-only identity cases also leave actual Dart analysis and native execution unproven.

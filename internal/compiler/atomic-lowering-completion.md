# Compiler implementation sequence

The [foundation contract](../../spec/contracts/C-COMPILER-FOUNDATION-0001.yaml)
owns language and execution rules. This checklist projects its criteria into
engineering work; it adds no language rules or approval gates. The
[decision](../../spec/decisions/D-COMPILER-FOUNDATION-0001.yaml) retires the former
implementation and compatibility-directed work. No implementation below is
claimed complete by the foundation PR.

## First delivery sequence

1. **Frontend and values.** Reuse the TypeScript program/checker, resolve real
   bindings and transitive helper bodies, and build typed component HIR plus
   behavior IR. Implement the declared binary64, checked-integer, Unicode,
   immutable-composite and Option/Result boundaries. Reject source-invalid forms
   separately from missing compiler capabilities.
2. **A complete reactive slice in React and GPUI.** Lower declarations, typed
   captures, automatic dependencies and the same state/derived/action trace into
   ordinary components using mature target AST tooling. Include controlled
   inputs, public readonly state and host style composition; a static element
   alone does not complete this slice.
3. **Transactions and host effects.** Execute the independent commit, failure and
   queued-reentry traces. Separate state publication from real view commit and
   respect synchronous input deadlines. Keep support in actual modules/crates.
4. **Lifetime, Context and owned async.** Implement keyed child retention,
   terminal removal, logical provider changes and portals, every-await segment
   boundaries, task policies and retirement. Run the exact independent await
   trace in both initial targets.
5. **Existing prototype authoring and consumers.** Inventory the current
   `.proto.ts` sources by semantic operation and migrate them to the explicit
   0.4 authoring phases. Preserve independently defined user behavior rather
   than old syntax, parser restrictions or generated bytes. The foundation PR
   does not rewrite those author APIs. Use
   [application scenarios](application-consumers.md) to drive meaningful slices.
6. **Complete Vue 2, Vue 3 and Web Components.** Lower the same accepted semantics
   through ordinary host components and real consumers. Missing operations and
   target implementations remain explicit work; no fallback or component-name
   fast path counts as support.

The [conformance entity](../../spec/tests/T-COMPILER-FOUNDATION-0001.yaml) supplies
independent expectations for each step and records all new implementation
routes as missing. Add actual executable paths as they are implemented; neither
an old pass nor agreement between two new backends establishes correctness.

Measure cold, warm and incremental compilation separately. Also separate source,
shared support, retained production artifacts, initialization and interaction
costs. Establish comparable baselines before assigning budgets. Report the
actual capability denominator and failures with each delivered slice; ordinary
implementation details do not require another user questionnaire.

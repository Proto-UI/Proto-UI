# Compiler implementation sequence

The [foundation contract](../../spec/contracts/C-COMPILER-FOUNDATION-0001.yaml) owns language and execution rules. This checklist projects all **28** criteria into implementation work; it adds no language rules or approval gates. The [decision](../../spec/decisions/D-COMPILER-FOUNDATION-0001.yaml) retires the former compiler implementation and compatibility-directed compiler work. It does not retire Adapter delivery. The [authoring contract](../../spec/contracts/C-COMPILER-AUTHORING-0001.yaml) and [complete input examples](authoring-surface.md) fix an explicit input before frontend and lowering work grows around guesses.

M1, M2 and M3 are engineering increments of the first React/GPUI delivery. **Owned async remains in this first delivery through M3.** None of these headings is evidence of completion, and a criterion that appears in M1 can still require additional traces in M2/M3. Later target work carries the same semantics to Vue 2, Vue 3 and Web Components.

## Start with shared input and analysis

Establish the versioned authoring export, the shared TypeScript program/checker and the common source-closure inventory. Review the readonly Badge, controlled Toggle and Context/owned-async Tabs inputs against their independent cases before specializing frontend support. Actual resolved bindings and helper bodies determine meaning; do not execute setup, substitute declarations for implementations or build a second lint whitelist.

The [lint contract](../../spec/contracts/C-COMPILER-LINT-0001.yaml) supplies stable rule identities and separate `sourceValid`, `analysisComplete` and selected-target `compilable` results. Keep the entire official-library and registered-consumer inventory visible from the start, including legal-but-unimplemented operations and unverified intake. A stage implements a visible subset; it does not remove the rest from the denominator.

## M1: readonly and controlled reactivity in React and GPUI

- [ ] Resolve the two first examples and their real helper closures with the controlled prelude, Proto type/domain checks, explicit phases, component HIR and typed behavior CFGs.
- [ ] Implement automatic prop/state dependencies, scalar/value rules and pure derivation invalidation. Keep equality, reactive sameness, Unicode and explicit absence/result boundaries in the value tests even when a visual example is simpler.
- [ ] Deliver the fixed-mode controlled Toggle's actual/request distinction, initializer lifetime, typed captured handles, segment reads/writes, successful publication and queued public requests. Include the needed failure, reentry and disposal behavior in this same slice; an activeChange callback cannot observe a partial transaction.
- [ ] Lower the same inputs through mature target AST tooling into ordinary React and GPUI components, including typed public projections and pure host style composition. Both targets must run independent consumer traces.
- [ ] Implement the same authored input on the Adapter path and bind both paths to identical source/helper digests. The Adapter result is not the expected-result oracle.
- [ ] Record native type/build results, independent behavioral evidence, source positions and an initial comparable measurement baseline. Keep all unreached or unimplemented capabilities explicitly missing.

A static element or readonly Badge alone does not complete M1. The controlled Toggle requires `CONTROLLED`, the applicable `TRANSACTIONS`, `CAPTURES`, `FAILURE`, `REENTRY`, `EFFECTS` and `LIFETIME` behavior already here. These cannot be placed entirely in M2 while reporting M1's controlled scenario as complete.

## Complete criterion map

All suffixes below refer to `C-COMPILER-FOUNDATION-0001-<suffix>`. The table assigns the starting work and the completion extension; it does not split or weaken the normative criterion. The final target column applies to each row: Vue 2, Vue 3 and Web Components repeat the applicable native consumer and source-compatibility checks with their own real host bindings.

| Criterion | M1 starting requirement | M2 / M3 completion extension | Remaining three targets |
| --- | --- | --- | --- |
| `LANGUAGE` | Real TS binding/type infrastructure, actual helper bodies, no author execution | M2/M3 analyze all added phases and reached operations | Same language and binding invariance |
| `VALUES` | binary64, bool conditions, explicit conversion, checked integer boundaries, immutable values | Carry the same domains through composition and async/host boundaries | Same typed values and failure behavior |
| `EQUALITY` | Distinguish numeric equality from reactive sameness, including NaN and signed zero; compare declared composites/handles correctly | Preserve semantics through Context and task invalidation | No host-address or native-operator shortcuts |
| `TEXT` | Well-formed String, scalar traversal and explicit text/encoding boundaries | M3 complete reached host conversion and typed error paths | Native UTF-8/UTF-16 boundaries preserve the same text rules |
| `RESULTS` | Distinguish optional input presence and business Option; handle Result as data | M2 failure propagation; M3 typed async/host results | Same typed outcomes without generic JS exceptions |
| `PHASES` | Declarations, instance initialization, pure derivation, action and owned connections | M2 composition/lifetime phases; M3 task/effect boundaries | Same valid source and phase diagnostics |
| `IR` | Typed component HIR, CFG, closures and target AST for the first inputs | M2 Context/topology; M3 state machines and all effect classes | Reuse verified IR rather than rescan author text |
| `COMPLETE` | Fully lower every reached operation in the delivered slice | M2/M3 close the full first-target operation inventory | Complete lowering for each selected target; no fallback |
| `CAPTURES` | Typed environments, per-instance identity and current-view reads; surviving writable captures obey transactions | M2 shared mutable-capture/rollback cases; M3 retained async environments | No hidden JSON, copied source or foreign VM |
| `DEPENDENCIES` | Automatic props/state/helper dependencies and pure cycle diagnostics | M2 reactive Context/topology; M3 fresh post-await reads | Same invalidation and observed results |
| `CONTROLLED` | Actual/request split, delayed/rejected input and fixed-instance schema | M2 separately declared transition policies and composition | Owner acceptance remains authoritative |
| `TRANSACTIONS` | Pending writes, read-own-writes, derived current view and atomic publication | M2 multi-instance/domain cases; M3 every-await segmentation | Same publication order and isolation |
| `FAILURE` | Needed abort/discard behavior for first actions and staged effects | M2 handled/unhandled and post-commit failure; M3 resumed-segment failure | No fake rollback of earlier external effects |
| `REENTRY` | Queue callbacks triggered by first action publication; ordinary helpers stay synchronous | M2 nested/domain ordering; M3 input-deadline separation | Same observable commit order |
| `ASYNC` | Preserve ownership/effect slots in IR and report absent support honestly | M3 owned tasks, every await, all three policies and cancellation are required first-delivery work | Repeat ready/pending/task-policy traces |
| `EFFECTS` | Classify local writes and queued public requests; preserve their commit order | M2 composition order; M3 observation, command and deadline host paths | Real target event deadlines and bound host operations |
| `VIEW-COMMIT` | Keep state commit distinct from render; never claim false view completion | M3 generation/revision acknowledgements, supersession and availability | Real framework/host acknowledgements per target |
| `CONTEXT` | Retain typed Context operations and missing analysis in the full inventory | M2 nominal keys/logical providers/portals; M3 post-await provider reads | Same logical ancestry independent of physical mount |
| `LIFETIME` | Instance initialization, captured-handle ownership and terminal connection cleanup | M2 keyed topology and distinct hide/detach/move/dispose; M3 task/wait retirement | Native lifecycle implements the same logical identity |
| `EXTERNS` | Typed boundary metadata and honest missing-binding diagnostics | M3 real reached atomic bindings, outcomes and target checks | Each required target has a real implementation |
| `PUBLIC` | Typed readonly projections, actions and controlled requests | M2 component composition; M3 typed async results and failures | Ordinary typed host interfaces |
| `STYLE` | Pure reactive appearance reads the component's own interaction projections | Extend reached host appearance while preserving semantic ownership | No second interaction owner or private-state polling |
| `EMISSION` | Real React and GPUI ASTs, mature printers and ordinary imports | M2/M3 extend native emission to all reached semantics | Vue 2, Vue 3 and Web Components use real native source paths |
| `SUPPORT` | Only reached real module/crate primitives; no shipped IR/setup interpreter | M2 transaction/Context support; M3 task/resource support with attributable cost | Share bounded support without dumping it into each component |
| `DIAGNOSTICS` | Shared frontend, stable IDs, actual spans/call chains and three result dimensions | Expand semantic analysis and all missing/invalid/extern/host distinctions | Target facts identify the selected profile |
| `CONFORMANCE` | Independent readonly/controlled traces for both targets and Adapter | M2 composition traces; M3 complete accepted foundation trace suite | Each backend passes independently, not by agreement alone |
| `SOURCE-COMPATIBILITY` | Verified common entry/helper bytes and full destination inventory | M2/M3 expand verified migrations and delivered-capability regression gates | Same authored source with explicit target host bindings |
| `MEASUREMENT` | Record cold/warm/incremental and first consumer baselines; do not set guessed budgets | M2 track composition cost; M3 complete equivalent-semantics baselines and budgets | Target-native comparisons with the same semantic scope |

## Vue 2, Vue 3 and Web Components

After the first complete React/GPUI paths, lower the same accepted semantics through ordinary components for the remaining three targets. Each target repeats independent value, transaction, lifecycle, Context, async, effect, view and source-compatibility traces. It supplies real target AST/printer integration and bindings, not a declared mapping or a route back to the Adapter. Preserve all five targets in reports throughout implementation.

The [foundation tests](../../spec/tests/T-COMPILER-FOUNDATION-0001.yaml), [lint tests](../../spec/tests/T-COMPILER-LINT-0001.yaml) and [authoring tests](../../spec/tests/T-COMPILER-AUTHORING-0001.yaml) are the evidence sources. Add actual executable paths and source-bound receipts as routes are implemented. A partial frontend, syntax-only example, old pass or agreement between two new backends does not establish the remaining evidence.

Measure cold, warm and incremental compilation separately, together with source, shared support, retained production artifacts, initialization and interaction costs. Report the actual capability denominator and failures with each delivered slice. Ordinary implementation choices do not require another user questionnaire; evidence determines which concrete development checkboxes can be marked complete.
